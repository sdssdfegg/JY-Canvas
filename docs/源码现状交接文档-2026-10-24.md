## 1. 项目一句话定位

- **这是什么**：一款**本地运行的 AI 图像创作 / 虚拟换装（outfit try-on）桌面软件**。用户上传模特图 + 服装图，调用本地 AI 服务生成换装 / 改色 / 精修结果；另有“快捷生成”“批量生成”“提示词助手”等能力。
- **交付形态**：前端 React + 后端 Node 本地服务，**打包成单文件 EXE（SEA 单可执行文件）分发**给客户，客户机上不依赖联网即可跑（AI 调用走本地服务 / 本地模型或本地配置的 KEY）。
- **目标用户**：需要批量产出电商 / 社媒换装图的个人或小团队（非开发者）。
- **技术栈**：前端 **React 19 + Vite**，**没有用任何 CSS 框架**（全靠自写 CSS + 一套设计令牌变量）；后端 Node（Express 风格路由）+ 若干 AI 能力模块（pose / quality / master-fit / analysis）。
- **当前版本**：产品版本 **5.0.0**（真相源在 `build.config.json.productVersion`）；`package.json` 的 `11.0.0` 是**内部 npm 包版本**，**不要动它**。

## 3. 核心领域模型（先看这个，否则看不懂代码）

### 3.1 词汇表

| 词 | 含义 |
|---|---|
| **板块 / 页面（page）** | 换装工作流里的“工作面板”，如 快捷生成 / 批量生成 / 服装改色 / 精修。用户可新建、改名、锁、删、拖拽排序。持久化在 IndexedDB `jingyin-outfit-workflow-pages-v1`。 |
| **任务（task）** | 一次生成请求。带历史，持久化。刷新页面时 `readTaskHistory()` 会把“运行中”任务恢复为 detached（所以刷新后 running 恒为 0，别断言它）。 |
| **结果卡（result card）** | 生成出的图片，以卡片展示；主画廊卡 / 批量结果卡已 memo 化。 |
| **参考图（reference）** | 换装时的模特图 / 服装图等输入素材。 |
| **改色（recolor）** | 改变服装颜色的能力，有**新旧双轨**（见 3.3）。 |
| **换装（try-on / outfit）** | 核心：把服装图“穿”到模特图上。 |
| **精修（retouch）** | 局部回贴 / 修复类能力。 |
| **提示词助手（prompt assistant）** | 提示词模板功能（模态，不切视图）；模板数据**永不可清**（封装红线③）。 |

### 3.2 换装工作流是怎么跑的

1. 用户在某个**板块（page）**里上传参考图 → 填提示词 → 发起**任务（task）**。
2. 任务经 `server/routes/outfit.routes.js` 路由到对应 AI 能力（pose / quality / master-fit…），生成**结果卡**。
3. 结果卡支持：预览（点卡打开 `ResultPreviewModal`）、拖拽平移、滚轮缩放、批量下载。
4. 多板块切换由 `useOutfitPageSwitch` 管理；板块数据异步 hydration（**E8 草稿 hydration 是异步的**，测试必须轮询等它出现）。
5. 持久化：板块集来自 `localStorage` 页面集；板块草稿来自 IndexedDB（不在 localStorage）。

### 3.3 改色双轨（极易误删，务必读懂）

- **新轨**：`recolorPart` / `recolorUpperLayer` + `RECOLOR_*` 常量（前端活跃）。
- **旧轨**：`settings.garmentParts` 等；前端 `isRecolorWorkflow` 恒为 false（**已死，但代码保留不删**）。
- **🔴 服务端 `recolorWorkflow` 由“页面名”判定**（`outfit.routes.js:202-205`），**仍然生效**——用户的“服装改色”页正走它。所以**旧轨服务端路径绝不可删**。

### 3.4 任务级上传引用必丢（已知行为，非 bug）

任务历史经 `sanitizeTaskHistoryItem` 白名单恢复时，**任务级上传引用（modelItem/clothingItem）必被白名单丢弃**。想让“重试 / 重刷”按钮渲染，正确注入口是**页面级 modelImages/clothingImages 补 File + 任务带 modelImageId/clothingImageId**（hydrate 按 id 补回），而不是在任务级塞 file。

## 4. 数据持久化与“用户态”边界（🔴 高危区）

> **铁律**：浏览器 `localStorage` / `IndexedDB` 里的**板块与设置是用户有意状态**。探针与更新**严禁清空 / 还原默认 / 重设**；只清理探针自建的临时对象。代码回滚靠 git，用户数据靠用户自管。

| 存储 | 键 / store | 说明 |
|---|---|---|
| IndexedDB | `jingyin-outfit-workflow-local-v1` / store `state` / key `page-draft` | 板块草稿（**不在 localStorage**，`localStorage.clear()` 清不到它）。 |
| IndexedDB | `jingyin-outfit-workflow-pages-v1` | 板块集（新建/改名/锁/删持久化）。 |
| IndexedDB | `jingyin-outfit-workflow-deleted-modes-v1` | 删页留痕（防误补建，V110）。 |
| IndexedDB | 任务历史 store | 任务历史（白名单恢复，见 3.4）。 |
| localStorage | 各类 UI 设置键 | 设置；板块集来源。 |
| 封装种子 | `dist/seed/manifest.json` → SEA 内嵌 | 提示词模板 + 页面状态随包发；缺失硬失败；**含 apiKey 的键须剥凭据**。 |

**探针操作纪律（第 8.3 节详述）**：探针 profile 的 IDB store 形状可能与 app 不一致（app 建 `keyPath:"key"`、记录 `{key,value,updatedAt}`），错形状 `put` 会同步抛 `DataError` 挂死。注入前必须**形状自感知**；跑完必须**清污**。

## 5. 开发宪法速览（源自 AGENTS.md，动手前必读）

1. **派单纪律**：判断好方案后直接产出交付物，不要把决策点抛回 owner 确认（例外：不可逆删除 / owner 明确要求先看方案）。
2. **逐字搬迁 + 引用方直改**：拆函数时**原样搬**，调用方**直接改引用**，**不留 re-export 壳**（同 RF-080/081/082 先例）。
3. **搬运丢参检查（🔴 已两次出事故）**：搬闭包 / handler 后，必须比对“被搬函数的全部入参”和“调用方实参”（`git show <commit> | grep "^- "` 看删行里有没有参数名）。历史丢过 `files` 和 `previewPan`。
4. **size-ratchet（体量棘轮）**：要求“净行数增量 = 0”——重构抽取不能让总代码量涨。抽取 / 改名前必跑；`regressions=[]&&improved=[]` 不许 `--update`。
5. **文档漂移门禁**：改完代码必须同步配套物再提交（移动/拆文件 → 跑 `frontend-duplication-check.mjs --update` 等刷基线）。**文档只用仓库相对路径，禁止写死本机绝对路径**（会被 `docs-path-check.mjs` 判红）。
6. **文档存放纪律**：根目录只保留 5 份常设 md；新执行单建 `docs/执行单/进行中/`，交付当天移入 `docs/执行单/已完成/<YYYY-MM>/` 并回填 `docs/执行单/README.md` 台账（台账是唯一索引，不更新等于白做）。
7. **删除操作纪律（safe-delete 劫持）**：本机 bash 的 `rm` 被劫持进回收站。要真删只能用 `/usr/bin/rm -rf <绝对路径>` 或 PowerShell `Remove-Item -Recurse -Force`；node 脚本删文件需 `CODEBUDDY_SAFE_DELETE_ENABLED=0 node xxx.mjs` 或 `spawnSync('/usr/bin/rm',...)`。禁止裸 `rm`。
8. **Git 不 push（owner 裁定）**：本地 main 累积，未推远程；提交时**排除 `seed/manifest.json`**（用户态）。（注：远程是 GitHub JY-Canvas/main，但 agent 沙箱连不上 github.com，push 必须由 owner 在自己终端执行。）
9. **构建用项目自带 Node**：`runtime/node/node.exe`（v24.9.0）跑 `发布工程/build.mjs --version v5.0.0`，不要用其它 Node。

| 目的 | 命令 |

### 6.2 门禁由什么组成

- `check-syntax`：语法扫描（当前 293 个文件）。
- `eslint`：0 error 是硬要求（有 1 条历史基线 warning，别动它）。
- `frontend-duplication-check`：重复代码基线（当前 `duplicates=[]`；**新文件入圈要 `--update` 刷基线并写理由**，否则判红）。
- `size-ratchet-check`：净行数增量 = 0。
- `dead-export-check`：导出但未使用的符号检查（V5.0-013 引入，去 export 清理靠它兜底）。
- `run-all` 还包含若干静态 / 浏览器断言脚本；`--fast` 只跑纯静态类。

### 6.3 已知 flake（别误判为回归）

`history-repair-check` 在全量长跑下偶发失败（30s 服务健康等待在负载下超时），**单独复跑全绿、二次全量对照即可**，勿据此改代码（该脚本走服务端历史修复路径，与本仓库前端重构无因果链）。判定“与本次改动无关” = 单独复跑 + 二次全量对照。

## 8. 历史教训 / 已知坑（接手方最该看的“避坑指南”）

### 8.1 渲染期 TDZ 铁律（🔴 首屏白屏级事故源）
移动状态声明 / 抽 hook 时，必须全文件 grep **执行时序**（渲染期消费点 vs 事件期消费点）。`hoisted function 声明 → hook 解构` = 必须 grep 渲染期消费点（V5.0-010 曾因此 outfit 壳挂载失败）。**纯函数工厂 hook（内部无 React hook）可自由上移，零顺序影响**。ErrorBoundary 跨视图保持 error 态（多视图同报一错先怀疑传播）。**ref 晚绑定要区分“取函数”与“执行”**：`() => ref.current?.()` 才是调用语义（`() => ref.current` 只取引用）。

### 8.2 双层导航模型（🔴 测试定位坑）
- `.navItem` = **主壳**导航（AppSidebar：快捷生成 / 提示词助手[模态不切视图] / 批量改尺寸 / 批量生成 / outfit 嵌入壳）。
- outfit 嵌入壳 `.outfitWorkflowEmbedded` 另有**内侧边栏**（WorkbenchSidebar）。
- **dev 默认视图 = quickgen ⇒ outfit 壳不在 boot 时挂载**；E8 草稿 hydration 异步 ⇒ 板块断言必须轮询等它出现（P6 cards=N 才是终态证据）。

### 8.3 浏览器探针纪律（验证换装交互必读）
- 探针 profile 的 IDB store 可能被旧探针建成 out-of-line（无 keyPath），而 app 建的是 `keyPath:"key"`、记录 `{key,value,updatedAt}`；错形状 `put` 同步抛 DataError 挂死 → 注入前**形状自感知**，错则 `deleteDatabase` 重建。
- 初始 active 页来自 localStorage 页面集、**不是 IDB 注入草稿** ⇒ 域断言前必须显式点目标 chip。
- 探针跑完必须**清污**（app 页 deleteDatabase + store 复核为空），否则后续期望“默认板块”的 check 会败。但**清污后仍败 ≠ 污染**（V5.0-010 清污后仍败才深挖出真 TDZ）。
- 滚轮 / 鼠标事件注入：先轮询等目标元素 rect 就绪（img 未加载时 rect 过小致鼠标打空，表现为“同一份代码首跑 PASS、复跑 FAIL”的抖动）；滚轮后轮询等终态值取代固定 sleep；缩放断言用 `parseScale()` 数值比较（`includes('scale(1)')` 会误匹配 `scale(1.12)`）；鼠标路径失败降级 `el.dispatchEvent(new WheelEvent('wheel',{deltaY,bubbles:true,cancelable:true}))`（React 委托**必须** bubbles:true）。
- `.composerField:not(.composerNote) textarea` 会撞更早的空 textarea（OutfitComposer 有 3 个 .composerField）→ prompt 读取用 `.composerPromptCol textarea`。`.recolorPartRow` 有两个 `.outfitIntentChips` 子元素 ⇒ 部位 chips 选择器须 `:first-of-type`。

### 8.4 其它
- **CRLF 纪律**：`.gitattributes` eol=lf；改存量必须全文件归一，`git diff --ignore-cr-at-eol --numstat` 复核。
- **源码扫描型断言遇代码位移**：文件搬迁后须把新落点纳入扫描面。
- **dev 冷编译 ~16s vs CLI 180s 硬上限**：探针必须两阶段（warm-up 再跑真实段）；所有异步等待一律轮询，禁用固定 sleep。
- **outfit 侧事件不可见**：`src/outfit-workflow.jsx` 有个 `const [, setEvents] = useState([])` 值被丢弃，批量页不渲染事件条；验证用户可见提示读 `.composerStatus`。

## 12. 决策框架（面对一个需求，如何判断是否安全 / 值得做）
