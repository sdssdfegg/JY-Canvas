## 3. Agent / Skill 架构现状（从代码回答）

1. **是否形成完整 Agent + Skill 运行体系？** 否。形成了「单次总策划 + 声明式 Skill 资产 + 确定性编译器」的**雏形**：Agent 无调度/无状态/无工具；Skill 是"静态资产文件 + 源码内短指令"，无独立触发与执行机制；编译器是老代码（17 槽位），未按方案 §6 三层规则重构。**完整运行体系 = 方案阶段 C/D/E，尚未施工**。
2. **Agent 如何工作**：见 §2.4。输入 = settings + 图片 + 空选时的 skillPack；上下文来自一次性 instruction；输出 = plan JSON + 平级 planning。
3. **Skill 类型**：静态提示词资产（SKILL.md）+ 动态条件注入（8 directive 进模型 instruction）；两者内容**不同**（md 完整 vs 源码紧凑），靠 phrase 双命中门禁保证不脱钩；无独立 trigger/execute。
4. **多 Agent**：无（唯一 planner.md；ai-canvas-agent 属另一功能）。
5. **冲突/重复注入/上下文丢失**：
   - 无运行时冲突检测器（仅各 SKILL.md 文档级「冲突处理」段）。
   - 无显式重复注入去重代码；靠条件注入（空选才挂）+ marker 唯一门禁（`detail-v2-assets-check.mjs:137`）。
   - 上下文丢失：仅契约声明（Schema `integrityLocks`、execution-flow :32「不得整段丢失」），**无运行时实现**；`:23/:34` 明注"只声明顺序，不实施加载器"。
   - 已实证的"重复注入"是真问题：全局真实性规则在 17 槽位中 5 处复现（D-REV-06 P1-7）。
6. **提示词优先级关系**：全局系统提示词（skillModuleV2 directives/constraints）→ Skill 提示词（8 directive + 4 校准，同一次 instruction）→ 单次任务提示词（settings + selectedSections + 屏数）→ 模块提示词（SCREEN_MODULES/INDUSTRY_SKILLS，确定性编译期插入）。**当前优先级靠字符串拼接顺序，无冲突仲裁机制**；方案 §5.4 有优先级设计，未实现。
7. **能否支撑更复杂电商详情策划？** 数据契约层基本具备（9 顶层键 + 8 Skill 资产），**执行层不具备**：编译链未解耦、行业路由双路径、质检截断、无对话态消费。结论：骨架可复用，能力需阶段 C/D/E 落地。
