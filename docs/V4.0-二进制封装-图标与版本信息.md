# 二进制封装：启动器图标与版本信息（务必留档）

> 目的：**防止后续重新封装时 exe 丢图标**。每次出包前照本文核对，出包后跑一次校验脚本。
> 适用：`D:\源码开发\静音AI画板v4.0源码` → 发布目录 `D:\源码开发\静音AI画板（v5.0）`

## 1. 图标的唯一来源

| 项 | 值 |
|---|---|
| 图标源文件 | `public/app-avatar.ico`（101,782 字节） |
| 是否入库 | 已 git 跟踪（`git ls-files public/` 可见），**不要删、不要改名** |
| 同名 webp | `public/app-avatar.webp`（前端 UI 头像用，与 exe 图标无关） |
| 打包内引用 | `scripts/secure-win-release.mjs` 第 33 行 `const iconFile = path.join(rootDir, "public", "app-avatar.ico")` |

## 2. 图标是怎么进 exe 的

`scripts/secure-win-release.mjs` 第 7/8 步（约 321–352 行）：

1. `copyFile(process.execPath, releaseExe)` —— 先复制当前 node.exe 当壳；
2. 调 rcedit 注入资源：
   - `--set-icon public/app-avatar.ico`
   - `--set-version-string FileDescription/ProductName/CompanyName(静音AI)/InternalName/OriginalFilename/LegalCopyright`
   - `--set-file-version` / `--set-product-version`
3. 再用 postject 注入 SEA blob（`NODE_SEA_BLOB`）。

rcedit 可执行文件：`node_modules/rcedit/bin/rcedit-x64.exe`（x64）/ `rcedit.exe`；依赖声明 `devDependencies.rcedit ^5.0.2`。

## 3. 三个会让 exe 没图标的坑（按出现概率排序）

1. **在非 Windows 上跑打包脚本**。
   脚本第 323 行是 `if (process.platform === "win32") { ...rcedit... }`，Linux/macOS/WSL 下整段**静默跳过**，
    exe 照样生成、照样能跑，只是没有图标和版本号。→ 必须在 Windows 上执行 `node scripts/secure-win-release.mjs`。
2. **`public/app-avatar.ico` 不在了**（误删、改名、`.gitignore` 误伤）。rcedit 会直接失败，脚本抛错中断（不会静默），
   但如果不看日志只看到目录里有旧 exe 就容易误判成功。
3. **`node_modules` 重装后 rcedit 缺失**。同理会报错中断；若有人"为了跑通"把 rcedit 调用注释掉，图标就没了——**不要注释**。

补充：版本号/产品名可用环境变量覆盖，`JINGYIN_WIN_RELEASE_NAME`（默认 `静音AI画板（v5.0）`）、
`JINGYIN_WIN_PRODUCT_NAME`（默认 `静音AI画板`）、`JINGYIN_WIN_PRODUCT_VERSION`（默认 `5.0.0`）、`JINGYIN_WIN_RELEASE_DIR`。

## 4. 出包后校验（一条命令）

```bash
node scripts/verify/release-icon-check.mjs
# 或指定 exe：
node scripts/verify/release-icon-check.mjs "D:\源码开发\静音AI画板（v5.0）\静音AI画板.exe"
```

脚本做的事：读取 `public/app-avatar.ico` 中间 512 字节作为指纹，在 exe 二进制里搜这段字节。
命中（offset > 0）= 图标确实嵌进 PE 资源；未命中 = 没图标，检查上面三个坑。
同时打印 exe 大小、ico 大小，便于留档。
