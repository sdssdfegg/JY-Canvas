真·根因（V142 由 tabbit 浏览器探针实测坐实）：结果画廊网格的行轨道被锁死—— 探针读到 grid-template-rows: 96.25px 96.25px 96.25px 96.25px（4 行）、 grid-auto-rows 未生效，而这个 96.25px 与卡片实际高度无关。卡片真实高 = 轨道宽 × 4/3（75% 缩放时 176px）⇒ 每张卡溢出本行约 80px、压住下一行 = 上下重叠。 这唯一解释了「百分比越大叠加越厉害」：缩放只放大卡片高（176→340px），而被锁死的行高不跟着变。

修复：在两边共用的网格上加 grid-template-rows: none（置空显式行轨道）+ grid-auto-rows: max-content （隐式行按卡片真实高自动撑开）⇒ 行高恒 = 卡片真实高，行步进恒 = 行高 + 12px。 实测：修复前 rows=96.25px×4 / 重叠 28 处；修复后 rows=176px×4 / 重叠 0； 缩放 75%→145% 全档位重叠恒 0（行步进 188/212/235/259/281/305/329/352）。

⚠️ 已证伪的上一个假设（留档以免重犯）：V139/V141 曾把根因归为 content-visibility:auto + contain-intrinsic-size:auto 260px（离屏卡按 260px 估计占位）。探针实测两边结果卡的这两项都已是 visible / none，但重叠依旧 ⇒ 该归因不成立。教训：CSS 归因必须由探针实测 computed 值坐实，不能只靠读源码/注释静态推断。

操作：拖动「缩放百分比」「容器内容宽」「结果图数量」即时读数；切「破坏态」复现旧重叠（并且能验证 「缩放越大重叠越狠」），切回「修复态」各排高度差≈0、纵向间距恒 12px、重叠=否。
