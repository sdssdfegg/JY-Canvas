# REFACTOR-新功能开发规范.md · 新功能落地必读

> **定位**：本轮重构止血之后，防止再次长出 8000 行巨石的**长效约束**。
> **适用**：任何"新增功能 / 新增页面 / 新增一大块交互"的开发，**不只是重构**。
> **配套**：`REFACTOR-冷启动.md`（重构开工入口）、`REFACTOR_TICKETS.md`（唯一契约）。
> 制定依据：本项目实证 —— `src/main.jsx` + `src/outfit-workflow.jsx` 曾达 **20222 行（80.5%）**，
> 截至 2026-10-03 已降至 **18207 行（71.0%）**。本文写的是**怎么不再涨回去**。

---

## 0. 先搞懂大文件是怎么长出来的（本项目的实证病因）

| 病因 | 实证 |
|---|---|
| **① 新功能默认往主组件里堆** | 每加一个功能 = 加几个 `useState` + 几个 handler + 一段 JSX。单次都很"合理"，几十次之后就是 8000 行 |
| **② 复制粘贴比抽象省事** | 两侧（main / outfit）同逻辑各写一遍，且**改名**（`addReferenceRewriteFiles` ↔ `addDetailFiles`），人眼和早期门禁都看不见 |
| **③ 纯计算逻辑混在组件里** | 几何换算、坐标变换、blob 拼接这类**与 React 无关**的代码写在组件内，既无法单测也拖长组件 |
| **④ "这个功能只有一处用到"** | 用到不等于该内联。**判断标准是"它引用了什么"，不是"它被引用几次"** |

**判据**（本项目反复验证）：一个函数该不该外移，看的是**它函数体里的自由标识符属于哪个域**，
不是看它名字像不像属于某个域，也不是看它有没有被复用。

---

## 1. 硬红线（超过即违规，必须在评审时说明）

| 指标 | 红线 | 说明 |
|---|---|---|
| **单文件行数** | **≤ 600 行** | `src/` 下任何 `.js/.jsx`。超过必须拆，不接受"就多 50 行" |
| **主组件文件** | `main.jsx` / `outfit-workflow.jsx` **只减不增** | 🔴 新增代码**原则上不得**进这两个文件。它们现在 7418 / 10789 行，是待拆对象不是容器 |
| **单函数行数** | **≤ 60 行** | 超过说明它做了不止一件事 |
| **组件内 `useState` 数量** | **≤ 12 个** | 超过说明该组件承担了多个职责，应拆子组件或抽 hook |
| **组件内顶层函数定义数** | **≤ 15 个** | 超过说明该组件里藏着一整个域的业务逻辑 |
| **复制粘贴块** | **≥ 10 行相似即禁** | 用 `block-clone-advisory` 实测，见 §5 |

⚠️ `main.jsx` / `outfit-workflow.jsx` 目前**本身是超标的**（历史债）。
**它们的红线是"不许再涨"**，不是"必须立刻降到 600 行"—— 那是线 B 重构的活。

## 2. 新功能落地的标准流程（5 步，顺序不能颠倒）

### 第 1 步 · 定域：这个功能属于哪个域？
从现有域里选，没有就**新建域目录**，不要塞进"杂项"：
```
src/features/{savedir, canvas, preview, result-queue, video, local-edit, auth, upload, detail}/
```
🔴 **禁止因为"只有一处用到"就内联到组件里。**

### 第 2 步 · 分层：把代码分成三类，分别放不同地方
| 类别 | 判据 | 落点 |
|---|---|---|
| **纯函数** | 不读组件 state、不调 setter、无 React 依赖 | `src/shared/*.js`（跨域复用）或 `src/features/<域>/<xxx>.js`（域内） |
| **域逻辑** | 需要读/写本域 state | `src/features/<域>/` 下的**工厂** `createXxx(deps)` |
| **编排 / 胶水** | 横跨多个域、串起整条流程 | 留在组件里（**这部分本来就该在组件里**） |

### 第 3 步 · 写工厂，不要写 hook（除非真的需要 React 生命周期）
**本项目定型形态 = 普通工厂**（成功率最高、行为零风险）：
```js
// src/features/<域>/<xxx>.js
export function createXxx(deps) {
  const { aState, setAState, addEvent, SOME_CONST } = deps;   // 解构保持同名
  function doSomething() { /* 函数体从原处逐字搬来，一字不改 */ }
  return { doSomething };
}
```
- **不 import React**、无 `useState/useCallback/useMemo` ⇒ 不需要处理依赖数组，不会引入行为差异。
- **deps 解构保持同名 ⇒ 调用点零改动**。
- 调用方在组件里 `const { doSomething } = createXxx({ ... });`（每次 render 调一次，语义等同组件内 `function` 声明）。
- **只在工厂内部互调的函数不要放进返回值的调用点解构**（会被 `no-unused-vars` 点名）。
- 同域的**后续批次追加进既有文件**，不要每批新建文件（新建会触发 019 扫描范围漂移，要划账）。

### 第 4 步 · 接线
组件里只保留：`import` + 一次工厂调用 + 解构。删掉被搬走的函数定义。

## 3. 目录约定与归属规则

```
src/
├── shared/         跨域复用的纯函数/常量。零 React 依赖、零 state 依赖
│                   ⚠️ 优先塞进既有 shared 模块，别新建文件（新建会触发 019 划账）
├── features/<域>/  按业务域组织。纯函数 + 工厂都放这里
├── components/     纯展示组件（props 进、JSX 出）
└── main.jsx, outfit-workflow.jsx   ← 编排层，只减不增
```

🔑 **选落点看"目标模块已经依赖了什么"，不是"语义上最像什么"**
（实证：url→File 的函数落在 `shared/result-image.js`，因为它**本来就 import 了 `../api/assets.js`**，
而不是落在语义更贴的零依赖 `image-input.js`）。

🔴 **新增 `src/features/**` 或 `src/shared/**` 文件后，必须手工给
`scripts/verify/frontend-duplication-baseline.json` 划账**（加 `scanScope.files` + `fileCount`），
否则 019 判"扫描范围漂移"红。**绝不动 `duplicateCount`。**

## 4. 复用时的三条铁律（本项目用真金白银换来的）

1. **发现同逻辑不同名，先判"字节一致 / 语义等价 / 已分叉"**。
   **已分叉（两侧行为不同）必须停手报人，不得擅自统一。**
2. **差异首选处置是「参数化」，不是「不搬」也不是「统一成某一侧」**。
   两侧各传自己的原值 ⇒ 行为逐字不变。**严禁统一成任一侧**（那是收窄，会让在用的路径静默失败）。
   （实证：`#35 enabled`、`#16 fallbackToItem` 都是参数化解决的。）
3. **"补全方向"可直接做**：多出字段但不改判断分支 ⇒ 取多的那版。

## 5. 必须过的门禁（改完就跑，不要等最后）

```bash
node scripts/verify/frontend-duplication-check.mjs   # 019 跨文件同名/克隆
node scripts/verify/import-path-check.mjs             # import 路径有效性
node scripts/verify/block-clone-advisory.mjs          # 块级克隆（≥10 行），排产前必跑
node tmp/lint.mjs                                     # ESLint 全仓（**裁判**）
npx vite build                                        # 打包
```
- **ESLint 是清依赖的裁判**：`no-undef` 点出漏搬的自由标识符，`no-unused-vars` 点出孤儿 import
  与多余解构。**肉眼看不出来的，它每次都能点出来。**
- 改前后逐条比对：`node tmp/lint-diff.mjs HEAD`。
- 「有门禁 / 全绿 / 零重复」**必须实测**，不许说。

## 6. 常见违规 ↔ 正确写法

| ❌ 违规写法 | ✅ 正确写法 |
|---|---|
| 新功能直接在 `main.jsx` 里加 `useState` + handler | 新建/追加 `src/features/<域>/`，组件里只留工厂调用 |
| 几何/坐标/字符串处理写在组件内 | 抽成纯函数进 `shared/` 或域模块 |
| 两侧各写一遍相似逻辑 | 抽到 shared，两侧各自调用；差异用**参数化** |
| 因为"只有一处用"就内联 | 按**自由标识符属于哪个域**判断归属 |
| 抽 hook（`useXxx`）处理纯逻辑 | 用**普通工厂** `createXxx(deps)`（无依赖数组风险） |
| 新增 `src/features/*.js` 后直接提交 | 先给 019 基线**划账**再提交 |
| 把工厂返回值**全部**解构到调用点 | 只解构调用点真用到的（其余会 `no-unused-vars`） |

## 7. 越线了怎么办

1. **文件超 600 行**：按域拆。先跑 `node scripts/dev/domain-fn-list.mjs <file> <start> <end> <域名>`
   看函数明细，再按 §2 第 2 步分层。
2. **不确定能不能搬**：跑 `node scripts/dev/domain-coupling.mjs`
   —— 平均引用域数 **≤1.0 且只碰本域 ≥70%** ⇒ 可抽；**≥1.5 或纯函数 <30%** ⇒ 是编排层，不要抽。
   ⚠️ **每抽完一个域必须重测**（画布域抽完 1.07 → 1.75，剩下的变成编排层了）。
3. **不确定是不是同一个东西**：**停手报人**，不要猜。（已分叉却强行统一 = 静默改行为）
4. **门禁红了**：先归因，**禁止 `--update` 掩盖**；确认是真债就修，是误报就修误报的根因
   （实证：lint-ratchet 曾因根目录一个游离副本 `verify/` 凭空多出 48 组假阳性）。

---

## 8. 一句话总结

> **新功能一律先进域目录，主组件只做接线。**
> 判断归属看函数体引用了什么，不看它被引用几次、也不看名字像什么。
> 有差异就参数化，绝不统一成某一侧。改完让 ESLint 当裁判，别让眼睛当裁判。
