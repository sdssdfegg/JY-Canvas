## 5. 全程纪律（沿用并固化你这批的做法）

1. **零功能变更**：任何"顺手改行为"都是违规。发现 bug ⇒ 记录另开单（刀 3 修掉 `getAsFile()=null` 那个 latent bug 属于**统一时的必然副作用**，已在 commit 写明，不算违规）。
2. **每步先 diff 再动**：判定必须写明「字节一致 / 语义等价 / 已分叉」；**已分叉 ⇒ 停手汇报**。
3. **旧实现当对照组**：把改前实现抄进脚本跑入参矩阵（刀 4 = 200 项、刀 5 = 56 项，均 0 失败）。⚠️ 被测函数若用 `Date.now()` 造 id，**先固定时钟再比对**，否则误报。
4. **改 `.jsx` 必跑 `vite build`**；涉及服务端 import 的前端模块用 release 同款 esbuild 打 bundle 验证。
5. **两个方向的孤儿核查**：搬 A 时既查"还有谁用 A"，也查"A 的调用方是不是也在搬走之列"。
6. **门禁数字变化必须解释**：`--update` 划账时写明是"消掉"还是"新增共享文件进入视野"，避免被误读成抹平债务。
7. **报"0 重复"必须写明是"同名层面 0 重复"**（§0.9 第 19 条）。
