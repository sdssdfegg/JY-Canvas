# 高保真 AI 换装能力体系（v5.0）— 子系统状态文档

> 本目录是换装能力体系的**专项状态层**（单一事实源之一）；全局工单仍走 `docs/执行单/`，两者不重复、不互覆盖。
> 主控文档 = 《工程实施总纲与 AI 长期执行规范》V1.0（2026-10-22，仓库外用户持有的四份纲领文档之一）。
> 建立日：2026-10-22（V128 执行单 §1.1）。

## 目标（一期）

输入 A（目标模特图）与 B（服装参考图），保留 A 的人物身份/身体比例/姿态/头发/手部/裸露皮肤/构图/背景，将 B 的服装款式/版型/颜色/材质观感/图案/关键细节迁移到 A；重点降低胸部鼓包、肩宽/腰围扩大、衣身臃肿与版型漂移；同款服装跨模特跨批次复用一份服装档案，减少颜色与图案漂移。

## 目标架构（逻辑九层，不等于九个服务）

| 层 | 职责 | 状态 |
|---|---|---|
| 画板交互层 | A/B 选择、参考图类型、版型、颜色保真、人体保真、质量模式、反馈 | 改造（复用现有面板） |
| 换装任务域 | 任务创建、状态机、幂等、取消、重试、预算、恢复 | 新增/改造 |
| Prompt 编译层 | 固定规则 + 服装档案 + A 人体约束 + 单次指令，版本冻结 | 改造（复用现有前端编译/服务端权威构建） |
| 视觉预处理 | 输入检查、人物/服装分析、可编辑区/保护区、置信度 | 扩展（先评估现有 pose/quality/master-fit） |
| 模型 Adapter | 统一内部请求 → 各模型/中转格式；能力声明三态 | 复用/扩展（现成基座：`server/channel-config.js` 能力目录 + `server/channel.js` 适配） |
| 服装档案 | SKU、标准参考图、颜色基准、版型、图案、版本 | 新增（本地文件 + JSON 索引） |
| 后处理 | 非编辑区恢复、边缘融合、服装区域 CIELAB/ΔE 校色 | 新增 |
| 质量评估 | 规则指标 + 视觉裁判 + 人工反馈 + 失败标签 + 分级 | 新增 |
| 观测与历史 | 请求日志、版本、成本、耗时、资产引用 | 改造（扩展 generation.jsonl，不另建） |

## 宪法红线（总纲 §11，违反即打回）

前端零 API KEY 记录；遵守包内生图信息记录限制、模板保留、用户资产不误删；新智能层只依赖 shared/api/lib 与自身目录，不反抓 outfit 内部实现；不引入 Python 服务/PostgreSQL/独立对象存储/另一套队列（先 ADR + 用户批准）；不凭模型名/上传成功/单张成功推断能力。

## 新代码样式约定（V131 立，2026-10-22）

1. **换装体系新增 UI 的 CSS 一律建 feature 分区文件**（如 `src/features/outfit/tryon.css`，由该 feature 的入口 jsx 导入），**禁止**往 `src/styles.css` / `src/outfit-workflow.css` 追加——两个全局文件已冻结为存量（V131 只做了死规则清理，不做增量）；
2. 类名加 `tryon` 前缀命名空间，防与存量词汇表撞名；
3. 分区文件头注格式照 `src/features/outfit/outfit-intent.css`（写明「不塞进全局文件，避免和其它分区互相影响」）；
4. 不采用 CSS Modules 类名重命名——探针依赖全局类名（V131 取证）；隔离靠「分区文件 + 前缀」而非编译期改名；
5. 删除样式前必须做三重验证：词边界零 JSX/JS 引用 + 零探针引用 + 无动态拼接（`X-${var}` 家族，实例：`task-${status}`/`drop-${placement}`/`ui-button--${tone}`）。
