# ADR-001：维持现有 Node/Electron 内聚架构，不引入独立视觉服务

> 状态：**草案**（2026-10-22 起草，T-001）｜ 待办：E6 视觉分析实验补证 + 用户批准
> 格式：总纲 §14 七要素（背景/选项/证据/决定/代价/回滚/批准人）

## 背景

高保真换装能力体系需要视觉预处理（人物/服装分析、区域/掩膜）、任务编排、后处理与质检。存在两种架构选择：在现有画板服务内长智能层，或引入独立视觉服务（如 Python 分割服务）。

## 选项

- **A. 维持现有 Node/Electron 内聚架构**：智能层作为现有服务内的 feature 域，复用现有中转适配、并发槽、JSONL 日志、文件落盘；
- **B. 引入独立视觉服务**（Python + 专用分割/姿态模型）：画板通过 HTTP 调用，获得更强的分割能力与语言生态；
- **C. 混合**：核心链路留 Node，仅分割外调独立服务。

## 证据（P0-A 实测，EVIDENCE.md）

1. 传输层已具备多图/mask 通道/编辑端点与按模型能力目录（S2/S3/S5/S16）——无需新建调用体系；
2. 并发槽、JSONL 日志、history 落盘、result-cache TTL 均已存在且可扩展（S10/S11/S12/S14）；
3. 视觉分析三 AI（pose/quality/master-fit）已在中转链路内可用（S13）——分割能力待 E6 实证，但**调用通路无需新建**；
4. 需求侧（总纲 §2）明确：任务逻辑解耦 ≠ 运行时拆服务；性能/隔离/部署需求有证据前不拆。

## 决定（草案）

**选 A**：智能层落在现有服务内（模块化单体/feature 域），依赖方向守既有纪律（只依赖 shared/api/lib 与自身目录）。若 E6 证明现有视觉分析无法提供可靠区域信息，且 Node 侧无可行替代，再以本 ADR 的修订程序评估选项 C——**不默认走 B**。

## 代价

- Node 侧做图像形态学/CIELAB 运算需自实现或引轻库（过体量棘轮 + ADR-008 审查）；
- 单进程故障域扩大 → 用任务状态机 + 恢复扫描缓解（state-machine.md §2.3）；
- 未来若必须拆服务，迁移成本 = 把 feature 域接口改为 HTTP 边界（契约已按逻辑接口定义，见总纲 §6）。

## 回滚

智能层为新增目录 + 新增路由，拆除即回滚；不动现有链路（v4.0 标签保底）。

## 批准人

待用户（人类授权人）。批准条件：E6 实验结论 + P0 退出报告一并审。
