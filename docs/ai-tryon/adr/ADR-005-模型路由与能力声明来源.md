# ADR-005：模型/渠道路由策略与能力声明来源

> 状态：**草案**（2026-10-23 起草，T-002）｜ 待办：P0-B 模型对照数据 + 用户批准
> 格式：总纲 §14 七要素。

## 背景

换装体系需要按模型/线路声明并查询能力（多图数、Mask、尺寸、seed、限流），并按参考图类型/品类/质量模式选择模型。存在两种来源：扩展现有 channel 能力目录，或新建一套换装专属能力配置。

## 选项

- **A. 扩展现有能力目录**：`server/channel-config.js` 的按模型能力结构（maxInputImages/maxPromptLength/maxImageBytes/supportedSizes…）+ `server/channel.js` 读取器，增加换装语义字段（mask 支持、seed、双图理解证据状态）；
- **B. 新建换装能力配置**：在 ai-tryon 域内自建一套 model+route 能力矩阵，与现有目录平行；
- **C. 混合**：目录留传输层能力，换装语义层自建。

## 证据（EVIDENCE.md）

1. 现有目录已按模型声明传输层能力且**越界即拒**（`channel-config.js:277` `imageCount > maxInputImages` 拒绝）——链路已在用（S2/S16）；
2. 目录与上游 3.0 routing catalog 逐字对齐、V11 补齐了两个能力字段——**它是全链路的单一能力事实源**（channel-config.js 头注）；
3. 平行新建必然造成「同一能力两个真相源」——正是本仓重复记账表（V11维护文档/02）要防的病。

## 决定（草案）

**选 A**：换装语义能力（mask/seed/双图理解）作为**新字段扩展进现有目录**，三态标注（SUPPORTED/UNSUPPORTED/UNKNOWN，interfaces.md §2）；读取经 `resolveModelCapabilities` 统一出口。模型**选择策略**（按参考图类型/品类/质量模式路由）的策略参数另存策略版本文件，由 P0-B 基线数据驱动、用户批准后启用。

## 代价

- 改能力目录影响全链路（所有用它的路由）→ 只增字段不改现有语义；新增字段的消费方仅换装域；
- 换装语义字段的上游证据依赖 P0-B 实测——未实测前一律 UNKNOWN，不进主路径。

## 回滚

目录为纯数据+读取器；删字段即回滚；v4.0 标签保底。

## 批准人

待用户。批准条件：P0-B 能力矩阵结论 + 本 ADR 随 P0 退出报告一并审。
