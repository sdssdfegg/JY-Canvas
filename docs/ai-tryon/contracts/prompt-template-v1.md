# 契约：分层 Prompt 模板 V1（换装）

> V1.1 §7 + 需求说明 §8 的落地版。原则：**沿用现有前端编译/服务端权威构建链路，不另起一套提示词系统**；新增的是换装专用分层模板、版本号与结构化服装属性。
> 版本：prompt-template-v1（2026-10-22 起草，T-001）｜ 状态：待 P1 施工评审 + P0-B B 组实验校验。

## 1. 四层结构

| 层 | 内容 | 维护要求 |
|---|---|---|
| 固定规则 | A 决定人体和画面；B 决定服装属性；不得把 B 模特身材迁移给 A；非目标区域尽量不变 | 版本化；变更前跑回归样本 |
| 服装档案 | 品类、版型、颜色、领型、袖型、衣长、图案、材质与关键细节 | 由档案生成（P2），允许用户修正 |
| 目标模特约束 | 人物身份、身体比例、姿势、皮肤、头发、手部、构图与背景 | 尽量利用现有视觉分析结构化输出（E6 结论前不得假定有分割） |
| 单次任务指令 | 本次换装的服装、参考图类型、编辑范围和输出规格 | 每任务动态生成并记录 |

## 2. 模板 V1 全文（B 组实验用此文本）

任务：将服装参考图 B 中的服装自然地穿到目标模特图 A 上。参考职责：A 决定人物身份、脸部、身体比例、姿势、手臂和手部位置、头发、构图、背景及整体光线；B 只决定服装本身的款式、版型、颜色、图案、材质观感与结构细节。人体保护：保留 A 的人物身份和身体比例，不要复制 B 中模特的胸部体积、肩宽、腰围、腹部形态、手臂粗细或姿势。不得为了容纳衣服而无依据地改变 A 的身体轮廓。版型保真：按 B 的真实版型还原服装。合身款不能生成成宽松款；宽松款保留设计余量，但不要额外制造不合理的空腔、鼓包或夸张膨胀。区分衣服自身的褶皱与人体体积，不要把阴影误当成人体结构。细节保真：尽量保持领口、肩线、袖长、袖口、门襟、纽扣、口袋、下摆、Logo、印花和格纹的相对位置与比例。颜色以 B 的服装区域为参考，不要随意改色。编辑范围：仅修改完成换装所必需的区域。脸部、头发、裸露皮肤、手部、背景及其他非目标区域尽可能保持 A 原样。若当前接口的局部编辑/Mask 已通过实测，优先使用对应区域约束；若无效，则使用已验证的兜底流程。输出要求：生成真实自然、结构合理、边缘干净的换装结果；不要增加不存在的服装部件，不要改变人物身份，不要改变背景，不要生成额外文字或水印。

> ⚠️ 最后两句是**双分支句**：Mask 有效（E1 结论）走区域约束分支；无效走兜底分支。P0 结论出来后二选一固化进模板，并升 template-v2。

### 2.1 双分支句固化结论（2026-10-26，E1 实测后）

**裁定：固化到「已验证的兜底流程」分支**（v1 保留为历史/实验基线，v2 为固化版）。

依据（详见 `../EVIDENCE.md §三-A`，E1 共 12 例全部 http 200，TT2.5 + Origin `silent-tt25-line-06`）：

1. **掩膜链路端到端接通**——探针上传（`scripts/ai-tryon/p0-probe.mjs:322-324`）+ 服务端多部件转发（`server/channel.js:339` / `:378`）均生效，「发了被丢弃」不成立；
2. **粗掩膜（躯干椭圆）未呈现较「无掩膜」的量化增量**——s01 三模式（无 / 服装掩膜 / 人体掩膜）逐张比对，均成功换装且人物身份、脸、手、发、白底背景无漂移；
3. **基础换装靠 A+B 双图输入已能保身份/保非编辑区**——`e1-none-*` 对照组本身即产出合格结果，无需掩膜兜底；
4. **精确人体保护掩膜属 P3**（EVIDENCE S6 / S33 既定归属），当前无证据支持在模板里写死区域/掩膜约束。

> 🔴 因此 v2 固化措辞 = 「本任务采用已验证的兜底流程：不附加区域/掩膜约束，依靠 A+B 双图输入保持人物身份、姿势与非编辑区域一致。」
> 代码落点：`prompts/server/outfit-prompt-template.js`（`PROMPT_TEMPLATES["prompt-template-v2"]`）。
> **挂载策略**：默认 `DEFAULT_PROMPT_TEMPLATE_VERSION = null`（不挂载）⇒ 生产提示词与历史契约逐字一致，P0 生命线零风险；是否切到 v2 需先跑基线/回归样本评测（总纲 §4.1），不在本单自动生效。

## 3. 版本与冻结

- `prompt_template_version`：模板标识 + 内容哈希（改动即升版）；
- 每任务冻结所用版本，写入 TryOnTask 与日志（总纲 §6：任务运行时冻结所使用版本）；
- 变更纪律：模板变更必须先用基线/回归样本评测，再升版（总纲 §4.1 小步提交）。

## 4. 接入点（现有链路，P1 只做挂载）

- 前端编译：现有 `buildUserPromptOnly` 链路（V110 口径：前端拼装用户原话，服务端权威校验）；
- 服务端：`/api/generate-outfit` 的 prompt 校验处（`outfit.routes.js` payload.prompt）；
- 分层结构在**服务端**组装为最终文本（固定规则 + 档案 + 模特约束由服务端补，前端只带单次指令与用户修正）——与「服务端最终构建为准」一致（总纲 §6 buildTryOnPrompt）。

## 5. A/B 组口径（P0-B 实验）

- A 组 = 用户当前设置里的提示词原文（真现状基线）；
- B 组 = 本模板 V1 全文；
- 两组同样本同参数对照，量化「结构化约束单独能改善多少」（总纲 §7.1 B 组目的）。
