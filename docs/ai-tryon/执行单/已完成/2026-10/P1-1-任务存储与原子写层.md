## 1. 改动要求

### 1.1 新增 `server/ai-tryon/task-store.js`
- 落点：`data/ai-tryon/tasks/<task_id>.json`（任务快照）+ `data/ai-tryon/tasks/index.json`（任务索引）。
- **临时文件 + 原子替换**：写时先 `<task_id>.json.tmp` → `fs.rename` 覆盖，沿用 `generation-logger.js:19` 写法。
- **索引单写入器串行化**：所有 index 变更经一个串行队列（Promise 链），防并发写坏（总纲风险表「JSON 并发写入」行）。
- **损坏尾部容忍**：读 `<task_id>.json` 时 `JSON.parse` 失败 → 回退读 `.bak`；index 损坏 → 重建（扫 tasks 目录）。

### 1.2 零依赖叶子纪律（🔴 铁律）
- 只依赖 `node:fs/promises` + `server/core/app-paths.js`；**禁入特性模块群**（V121-R2 TDZ 教训：启动/恢复链路模块被 rollup 打包后初始化期 TDZ 会白屏且 build EXIT=0 抓不到）。
- 任务记录字段 = `tryon-task.md §1` 全集；P1 不实现的字段（如 `garment_profile_id`、`quality_report_id`）**可空但结构在位**。

### 1.3 导出最小 API
`readTask(id)` / `writeTask(task)`（原子）/ `appendAttempt(id, attempt)` / `listTasks(filter)` / `updateStatus(id, status, ctx)`。
