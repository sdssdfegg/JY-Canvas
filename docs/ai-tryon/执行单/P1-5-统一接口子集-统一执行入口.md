## 1. 改动要求

### 1.1 新增 `server/ai-tryon/execution.js`
落地 `interfaces.md §4` P1 子集：
- **`createTryOnTask(payload)`**：校验 → 持久化（P1-1 `writeTask`）→ 置 `CREATED→VALIDATING→READY_TO_GENERATE`（P1-4 `transition`）；冻结输入引用/模型策略/预算（tryon-task.md §4 冻结规则）。
- **`generateTryOn(task)`**：调用前 `resolveModelCapabilities`（P1-2）能力检查 + `checkBudgetBeforeCall`（P1-4）预算门 → `outfit-skill.js` 权威提示词 → 经 `channel.js`（`:102/:180/:216/:385/:482/:607/:730`）出海 → 落 attempt/结果资产引用（P1-1 `appendAttempt` + P1-3 日志字段）。
- **`retryOrRoute(report, errorClass, budget)`**：有限、可解释下一动作——限流/网络/超时→有限指数退避（先沿用现有线性回退 `baseLoop`，指数退避可选增强）；参数/权限→**不重试**；质量→仅策略允许时有限修复；**不得无限循环**。

### 1.2 复用（不重写）
- `channel.js` 适配层、`image-error-policy.js` 分类、`outfit-skill.js` 提示词、`history-store.js` 落盘；并发仍走现有 `IMAGE_CONCURRENCY_LIMIT=5`（runtime-config.js:35）+ `image-concurrency.js:15-29`（S14）。

### 1.3 模型差异不隐藏
- `resolveModelCapabilities` 返回 `UNKNOWN` 的能力**不进主路径、不伪装成 SUPPORTED**（interfaces.md §2 + 总纲 §6.1）。
