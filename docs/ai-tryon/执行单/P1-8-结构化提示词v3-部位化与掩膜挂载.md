# P1-8 · 结构化提示词 v3：部位化「保持不变」+ 掩膜区域约束挂载

> 状态：进行中 ｜ 分支 `feature/p1-8-outfit-prompt-v3` ｜ 上游：P1-7（模板挂载与版本冻结）
> 契约：`docs/ai-tryon/contracts/prompt-template-v1.md`（§1 四层 / §2 模板全文 / §3 版本冻结）
> 用户裁决（2026-10-27）：往结构化提示词方向靠，**结构里必须包含用户原有提示词的部位保留语义**，
> 掩膜（服装区 / 人体区）可以加进来。

## 1. 背景：为什么之前「挂载了也没有任何变化」

P1-7 交付了模板系统与 v2，但**真实出海链路根本没经过模板层**：

- 真实路径：`server/routes/outfit.routes.js:302` / `:383` 直接调 `buildOutfitPrompt(payload)`；
- 模板层只在 `server/ai-tryon/execution.js` 的 `buildTryOnPrompt()` 里装配，
  而 `buildTryOnPrompt` 全仓**无任何生产调用点**（仅 P1-6 `route-inlay.js` 用了 `createTryOnTask` 做任务登记）。

⇒ 即便把 `DEFAULT_PROMPT_TEMPLATE_VERSION` 改成 v2，前端也**不会有任何变化**。
本单第一要务就是把挂载点接到真实链路上。

## 2. 用户原始语义（必须包含，不可丢）

> 换上衣就得描述图1的下装保持不变，换下装就是图1的上装保持不变，鞋子不用说。

这与前端既有口径**完全一致**（`src/shared/outfit-intent.js:434 outfitKeepText`）：

1. **鞋子永不写进「保持不变」**——批量换装是半身图，写"图1的鞋子保持不变"会让模型去补一双鞋；
2. **选中连衣裙时，上装/下装都不再写「保持不变」**——连衣裙本身是一件式上下装，再说自相矛盾。

服务端零依赖叶子不能 import `src/shared/**`（V121-R2 零依赖叶子纪律），
故在模板模块内**同口径重实现**，并由 verify 脚本断言两边对关键 case 输出一致（防漂移）。

## 3. 设计

### 3.1 新增 v3（参数化模板）

v1 / v2 保持原样不动（只增不改）。v3 在 v2 基础上新增两处**变量槽**：

| 变量槽 | 取值来源 | 说明 |
|---|---|---|
| `replaceClause` | `outfitIntent.parts` | "本次只更换图1的{上装/下装/连衣裙/鞋子}。" |
| `keepClause` | `outfitIntent.parts` | "图1的{下装/上装}保持不变。"（口径见 §2） |
| `maskClause` | `maskMode` | `none` / `garment` / `body` 三选一 |

变量槽在 `parts` 为空或 `maskMode` 缺省时**自动省略整句**，不产生空句或多余标点。

`templateHash` 只对**模板规则文本**取哈希（不含变量值）——变量值随任务变，
但模板版本标识必须稳定，否则「版本冻结」失去意义。

### 3.2 挂载点（真实链路）

`outfit.routes.js:302` / `:383` 的 `buildOutfitPrompt(...)` 结果，再过一层
`withPromptTemplate(payload, text)`（新增，prompts/server 层导出）：

- 模板解析为 null ⇒ **原样返回，逐字一致**（P0 生命线零风险）；
- 模板命中 ⇒ 按契约 §1 装配「固定规则层 + 任务指令层」。

### 3.3 掩膜默认策略（裁决）

用户判断「目测没有 BUG」，但 E1 实测**掩膜未见量化增量**（ADR-002 暂定 B 语义兜底）。
⇒ **能力加进来、默认不开**：`maskMode` 缺省按 `none`（沿用已验证兜底句），
由前端后续显式传 `maskMode=garment|body` 开启。理由：加一句未被证明有效的区域约束，
有可能改变已稳定的出图行为；能力可用 ≠ 默认启用。用户要在真实 app 里试过后可一句话切默认。

### 3.4 默认挂载版本（裁决）

`DEFAULT_PROMPT_TEMPLATE_VERSION = "prompt-template-v3"`。

- 生效范围被**收敛到带合法 `outfitIntent` 的批量换装分支**（`workflowMode === "outfit"`），
  其它 workflow（快捷生成 / 批量生成 / **局部回贴** / 精修 / 改色…）变量槽为空 ⇒ 退化为 v2 同款固定规则，
  且这些分支本身不带 outfitIntent，模板层按既有逻辑不注入；
- 回滚 = 把这个常量改回 `null`，一行、无需改其它代码。
