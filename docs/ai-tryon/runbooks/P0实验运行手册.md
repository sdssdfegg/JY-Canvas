# Runbook：P0 模型能力实验运行手册

> 适用：V128 §1.5 / `scripts/ai-tryon/p0-probe.mjs`。原则：**先 dry-run，再冒烟，后分组跑；触顶即停；KEY 不落盘。**

## 0. 前置条件（缺一不可）

1. 本地服务已起（默认 `http://127.0.0.1:8787`；端口不一致用 `--base` 指定）；
2. 中转 KEY 在用户设置页已配置且线路可用（KEY **由用户在本机保管**，不发给任何人）；
3. ≥4 组样本已放 `docs/ai-tryon/eval/samples/<ID>/`（`a.jpg`=模特 A、`b.jpg`=服装 B）并登记 `eval/样本登记表.md`；
4. `eval/p0-cases.json` 的 `prompts.A` 已填入**用户当前设置里的提示词原文**；
5. E1 掩膜：对每个样本跑一次 `--make-coarse-mask <ID>`（或手工放置更精确的掩膜）。

## 1. 标准流程

```bash
cd D:/源码开发/静音AI画板v4.0源码

# ① dry-run：校验样本/配置/预算，不发起任何调用（不需 KEY）
node scripts/ai-tryon/p0-probe.mjs --dry-run

# ② 冒烟 1 次（验链路；占用预留配额）
JINGYIN_PROBE_API_KEY='用户的KEY' node scripts/ai-tryon/p0-probe.mjs --only E0

# ③ 生死题：Mask 语义（12 次）
JINGYIN_PROBE_API_KEY='...' node scripts/ai-tryon/p0-probe.mjs --only E1

# ④ 双图忠实度 + A 组基线（16 次）
JINGYIN_PROBE_API_KEY='...' node scripts/ai-tryon/p0-probe.mjs --only E2

# ⑤ 尺寸/可复现性（7 次）
JINGYIN_PROBE_API_KEY='...' node scripts/ai-tryon/p0-probe.mjs --only E4

# ⑥ B 组结构化 Prompt 初探（12 次）
JINGYIN_PROBE_API_KEY='...' node scripts/ai-tryon/p0-probe.mjs --only E5

# ⑦ 汇总
node scripts/ai-tryon/p0-probe.mjs --report
```

KEY 规矩：仅 `JINGYIN_PROBE_API_KEY` 环境变量运行时传入；脚本禁写盘/禁进日志（meta.json/response.json 已脱敏）；跑完 `unset` 或关终端即可。

## 2. E1 判读决策树（Mask 生死题）

对每个样本比较三张结果（无 mask / garment 掩膜 / body 掩膜）：

1. **有 mask 的结果被约束在掩膜椭圆内、椭圆外与原图一致** → Mask 语义有效（白=可编辑区）→ P3 走 Mask 通道；记录有效边界精度；
2. **有 mask 与无 mask 结果几乎一样、整图都被重绘** → 传输成功但语义无效 → **ADR-002 走兜底路线**（语义编辑 + 原图恢复/合成）；
3. **椭圆外被改动而椭圆内保留** → 语义是「白=保护区」（与假设相反）→ 仍算有效，但 P3 需反转掩膜语义；
4. 结果不稳定/时有效时无效 → 记录波动率，按「无效」做路线决策，另记低置信度结论。

判读完成后：更新 `EVIDENCE.md` 实验索引 + 出 ADR-002 草案。

## 3. 预算与停止条件

- 硬顶 50（`p0-cases.json` 的 `cap`）；每次调用前检查，触顶即停并列出未跑用例；
- 任何单步连续 3 次 FAIL（http 5xx/超时）→ 停跑，先查线路与服务状态，剩余配额留待修复后；
- 冒烟不过 → 禁止跑后续组（先修链路，不烧配额）。

## 4. 结果归档（每组跑完必做）

1. `eval/results/<caseId>/`：`meta.json`（脱敏元数据）+ `response.json`（脱敏响应）+ `result-*.png/jpg`（结果图）；
2. 按 `eval/人工评分规则.md` 在每个结果目录补 `score.md`（六维打分 + 分级 A/B/C + 失败标签）；
3. 回填 `EVIDENCE.md` §三 实验索引与结论；
4. 更新 `STATUS.md`（完成项/阻塞项）。

## 5. 常见问题

| 现象 | 处理 |
|---|---|
| dry-run 报缺样本 | 放文件或先 `--make-coarse-mask` |
| 报 `prompts.A 仍是 TODO` | 填入当前提示词原文 |
| `missing_channel`（http 400，快速返回） | **服务端强制要求 `channelId`**（`server/channel.js:199`），空串即拒。探针已内置按模型默认渠道解析；若手工 POST 必须显式带 channelId |
| http 401/403 | KEY 无效或未传环境变量（检查 `JINGYIN_PROBE_API_KEY`）；`forbidden_channel` = 渠道被禁 |
| `channel_model_mismatch` | channelId 与 model 不匹配，换成该模型的公开渠道 |
| http 502（上游网关错误） | **上游该线路/家族故障**，非我方问题；换线路重试。2026-10-26 实测 TT2.5 云枢+Origin 均 502 时，香蕉系正常 ⇒ 属上游家族 outage |
| `channel_timeout`（http 504） | 上游未在阈值内返回，**瞬时故障可重试**。E2 中 `e2-tt25-s04-r1` 504 后同参 r2 成功 |
| http 413 | 图片超大——能力目录 maxImageBytes 见 `server/channel-config.js`，压缩样本 |
| 连接失败 | 服务未起或端口不对（`--base`） |
| 结果图下载失败 | 不影响主记录；手动从 response.json 的 URL 取 |

## 6. 渠道口径（2026-10-26 用户裁定 + 实测）

- **`tt-image-2.5` → Origin `silent-tt25-line-06`**（第二个渠道）。用户明确「不用云枢」；云枢 `silent-tt25-line-05` 实测 502。
- **`nano-banana-pro` → 云枢 `silent-pro-line-01`**。实测 8/8 成功、均 ~41.9s。
- 探针 `scripts/ai-tryon/p0-probe.mjs` 内置 `DEFAULT_CHANNEL_BY_MODEL`，**按模型自动解析默认渠道**，用例文件无需逐个写 `channelId`（如需覆盖，在用例对象上加 `channelId` 字段即可）。
- 换渠道前先确认该渠道在 `server/channel-config.js` 中**非隐藏、非禁用**（隐藏渠道服务端仍接受，但不该作为默认）。
