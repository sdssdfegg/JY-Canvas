## 1. 修改前真实根因及代码位置
- 位置：`server/detail-middleware.js:631-642 deriveQCTaskContextKeys`（2026-11-18 QC OR/AND 单修引入）。
- 原逻辑：`explicitRequest = QC_EXPLICIT_REQUEST_PATTERN.test(userText) && !QC_PLAIN_EDIT_PATTERN.test(userText)`。
- 根因：正向模式含"质检"/"检查详情"等宽泛词，**无否定意图排除**；`QC_PLAIN_EDIT_PATTERN` 只挡"把/改/将…"开头修改句，挡不住"不要/别/不用…"。→ "不要质检""别做质检了"误激活 QC（补充核验实测 3 例）。
- 附带发现（同入口边界）：正向模式缺口语化"帮我检查一下详情""先帮我检查一下"，任务书 B 组要求触发但原实现会漏。

## 2. 最小修复方案
- 新增 `QC_NEGATION_PATTERN`：否定词（不要/不用/不必/不需要/无需/别/请勿/暂不/先不/这次不/取消/不做/不再）**必须紧邻 QC 动作词**（中间只允许 做/进行/执行/来/再/先 + 一次/一下 等连接词）才判为拒绝 QC。这样：
  - "不要质检"→排除；"别做质检了"→排除；"不用检查详情"→排除；
  - "不要修改，先帮我检查一下"→"不要"紧邻的是"修改"不是 QC → 不排除，仍触发（不误伤）。
- `explicitRequest` 增加 `&& !QC_NEGATION_PATTERN.test(userText)`。
- 正向模式补入口语化明确审查：`检查.{0,4}详情`、`帮我检查(一下)?(这套)?详情`、`先.{0,4}检查(一下)?(详情|这套)?`——均带明确审查对象或"先…检查"语义，不误伤"帮我检查一下背景改成蓝色"。
- **按钮信号 `buttonClicked` 保持最高优先**，完全不受自然语言否定排除影响（同时成立不抵消）。
