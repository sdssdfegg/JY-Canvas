# 取证结论：9屏为何只剩4屏（第三节）

用羽绒服完整资料 + `count=9, countMode=fixed` 抓各阶段：
| 阶段 | 实测 | 判定 |
|---|---|---|
| countMode/count | fixed / 9 | ✅ 用户明确指定 |
| 规划请求屏数语义 | 原只有 `screenCount:9`，**无 countMode、无"深度策划N屏"指令** | ❌ 缺陷A2 |
| 原始屏级任务（本地兜底 buildLocalScreenTasks） | **4 个**：identity / ingredient / applicableScope / usage（按"事实类别=1任务"粗粒度） | ❌ 根因A |
| screenTitles | 9（按 count 生成） | 正常 |
| 去重/合并/空屏检测前 | 4 任务 | — |
| 后处理 | 4 任务 → 屏5-9 无任务 → 空屏 → conflict | 后处理本身没错 |

**结论：情况 A（Planner/本地兜底原始产出只有4项），不是情况 B（后处理过度合并）。** 两个子根因：
- A1：本地兜底按"一个事实类别=一屏"的粗粒度生成，从不深度细分（使用方法的多步骤、适用范围的不同对象、洗涤方式/条件、保温/保冷等都没拆开）。
- A2：规划请求（detail-ai.js）没把 countMode 传给模型，也没有"fixed 时深度策划 N 个独立任务"的明确指令——即使有 KEY，AI 也缺少驱动。

之前8屏重复 vs 现在9屏剩4：旧版为填满屏数用 sellingList 轮流取原始资料 → 重复；上一轮改成"内容不足标空屏"后不再重复，但没补上"深度策划"→ 只剩4。**两个问题的正确解法是深度策划填满，而不是退回重复或停在空屏。**

# 交付 1：修复报告（P0 深度策划 + 去重校准）
- **深度挖掘与合理细分**（`expandLocalTasksForFixed`，仅 fixed 调用）：
  - 使用方法 → 按真实步骤拆成有独立认知目标的屏（取用/接触/刷洗/擦拭/干燥），每步带 `cognitionGoal`，不是换说法。
  - 适用范围 → 按衣物织物 / 家居织物两组拆（不同对象不同需求）。
  - 洗涤保养 → 洗涤方式 vs 水温条件拆（怎么洗 vs 什么条件洗）。
  - 性能效果 → 保温 vs 保冷拆（不同使用价值）。
  - 每条细分必须基于真实事实内容、有独立认知目标；无认知目标的步骤不细分。auto 模式不调用此函数（保持粗粒度，不为凑数强行扩屏）。
- **规划请求加强**（detail-ai.js）：input 传 `countMode`；instruction 在 fixed 时明确"用户指定 N 屏是策划目标，充分挖掘内容价值形成 N 个独立认知任务，允许合理细分复杂内容，不得换说法/换背景凑数、不得虚构；充分策划仍不足才说明缺口"；auto 时明确"自主屏数不设固定目标"。
- **去重校准**：不再按事实字段/卖点文字判重，改按 `cognitionGoal` 去重（相同认知目标=换说法，合并；相同事实不同认知目标=保留）；空屏 leftover 判定按事实 token 覆盖，避免被细分过的整条事实重复补进多个空屏。
- **保留**：所有已确认机制（见页首）。

# 交付 3：候选任务、合并理由与屏数决策
- 候选来自结构化事实 3 类 + 商品名；identity 恒 1 屏。
- 适用范围 5 个对象 → 按"衣物 vs 家居"合并为 2 组（不同使用需求），不是5个对象各一屏（避免机械）。
- 使用方法 5 个动作 → 每步有独立操作目的/视觉教学价值，细分为 5 屏（符合任务书 4.2 合理细分）。
- 成分 1 组不拆（只是列表，拆开无新认知）。
- 合计 1+1+2+5 = 9，恰好满足 fixed 9 屏，无需冲突。
- 去重按 cognitionGoal：5 个步骤认知目标各异，均保留；未出现相同目标重复。

## 六问回答
- 之前8屏为什么重复？——旧版为填满屏数用 sellingList 轮流取原始资料，无深度内容。
- 现在为什么只剩4屏？——上一轮去掉重复填充，但本地兜底仍按"事实类别=1任务"只产4任务，无深度细分。
- Planner不足还是后处理过度合并？——**Planner/本地兜底产出不足（情况A）**，后处理没错；附带规划请求缺 countMode 语义（A2）。
- 如何不编造支持指定屏数？——按真实内容的独立认知目标合理细分（步骤/对象/方式条件/性能指标），不虚构、不换说法。
- 如何防去重压制深度策划？——按 cognitionGoal 去重，不按事实字段/卖点文字；相同事实不同任务保留。
- 固定模式能否完成用户屏数？——资料支持时能（羽绒服9/9）；资料不足时充分细分后仍标真实缺口，不空屏凑数（服装8→5有效+3空+冲突）。
