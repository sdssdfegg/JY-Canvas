## 0. 给 Owner 看的结论（白话）

**你要的"别让模型背着整套规矩做每一屏"，这次从根上改了。**上次真机那三屏的毛病——清洁剂却出现模特展示、写"奶渍蛋白类"、写"棉/沙发/窗帘床垫"、每屏重复一大段同样的规矩、画面任务全是空话——我一个个查到了源头，然后改了软件的处理方式。

**查到的根源（大白话）：**
- "模特穿着展示"：程序里有个开关，一旦用了人物模式就无条件写这句话，根本没看卖的是不是清洁剂。
- "棉/奶渍/沙发窗帘床垫"：是 AI 想出来的卖点，程序**原样抄进**了说明书，没检查有没有证据、该不该说。
- "每屏重复一大段"：整套规矩在每一屏都完整写了一遍。
- "画面任务空泛"：AI 没给具体画面时，程序回退到固定套话。

**改完的效果（我用同样的脏数据再喂一遍验证）：**
- 清洁剂不再出现模特；"棉/奶渍/沙发窗帘床垫"被拦下、改成保守说法；整份质检清单不再塞进做图说明书（改成一句精简的画面自检）。
- AI 想的和程序用的是分开的：想归想，只有查过、准了的才进说明书，而且每句都能查到从哪来。
- 新加了 87 项自动检查（含 12 组"故意改坏"的测试），全量 85 项、构建都通过。

**但有一件我没法替你做**：真正的"AI 按新规矩想 + 实际出图好不好"——需要你在软件里带 KEY 真跑一遍。当前环境没有可用 KEY、软件服务也没开，我按你的规矩标成**待验收**，没跑、没用假数据冒充。报告里给了对照清单和真机步骤。

## 2. 阶段二：Skill Activation Contract（任务书第四节）

### 2.1 落点
`server/detail-v2-control/skill-activation.js`（新增，工程机制层）。

### 2.2 八字段语义（全部落地，非仅文档）
`activation_conditions` / `exclusion_conditions` / `required_context` / `execution_mode` / `output_contract` / `downstream_usage` / `prompt_injection_policy` / `conflict_priority`——`validateActivationContracts()` 运行时校验每项齐备（门禁 H1）。

### 2.3 四种执行模式
`mandatory` / `conditional` / `optional` / `inactive`，运行时枚举（H2）。

### 2.4 触发机制（工程实现）
- `evaluateActivation()` / `evaluateAllActivations()`：基于 contextKeys（行业、事实等级、用户要求）逐能力判定，输出 decision + injectToPrompt + auditReason（**可审计每项为什么激活/未激活**）。
- 默认触发表 `BASE_ACTIVATION`：商品真实性=mandatory；模特/结构/效果/成分/行业包=conditional；缺条件即 inactive。
- 正式配置的 `skillActivation` 可覆盖触发表（专业值由 ChatGPT 交付，工程不发明）。

**实测（门禁 H3-H8 / H19-H22）**：清洁产品模特 inactive、不注入；商品真实性 mandatory；服装+明确人物任务时模特 conditional 且注入；有效果证据才激活效果能力；护肤品不触发 cleaning；未知产品无行业包激活。

## 3. 阶段三：提示词动态组装（任务书第五节）

### 3.1 落点
`assemblePromptLayers()`（skill-activation.js）+ middleware 槽位改造。

### 3.2 四层实现
| 层 | 实现 | 状态 |
|---|---|---|
| A 全局共享 | `globalLines=[globalLock]` 仍逐屏拼（生图按屏独立请求的架构约束），但商品真实性等核心约束保留 | 未做"全局只写一次"硬改造（见 §7 未解决） |
| B 本屏任务 | `screenLines=[本屏卖点, 画面任务]`，卖点经事实边界校验、画面任务取本屏策划 | ✅ |
| C 条件指令 | `conditionalLines` 仅触发的能力进入（模特等） | ✅ |
| D 内部质检 | `internalAudit=[qualityChecklist]` 只存数据层，`finalInstruction` 不含；槽位改为精简 `【画面自检】` | ✅ |

### 3.3 关键改造（middleware）
- 模特槽 `:708`：触发判定未激活时输出"本屏无模特…"，不再无条件 modelPolicy。
- 卖点槽 `:702`：用 `sellingForPrompt`，命中 `noGeneralization`（奶渍/蛋白类/可水洗内衣/沙发窗帘床垫等）时改保守表达。
- 质检槽：整份清单从生图提示词移除，改 `【画面自检】` 一句；全文保留 `qualityChecklist` 供审计。
- 材质（`aiInsight`）：只取 L1(visible) 事实，L3(mustNotClaim) 不进"真实材质/颜色"——**修复了真机"棉"错误（F-1）**。

## 4. 阶段四：输出与编译边界（任务书第六节）

### 4.1 四类输出区分
`skill-activation.js` 的契约字段 `downstream_usage` / `prompt_injection_policy` 区分 internal_analysis / planning_output / generation_instruction / audit_rules；`assemblePromptLayers` 保证 D 层（质检）不进 `finalInstruction`。

### 4.2 编译授权
`compileWithAuthorization(entries, admittedTaskIds)`：每段指令必须有 sourceField 或 sourceTaskId，且任务须 admitted；否则丢弃并记审计（H14/H15）。
- middleware 每屏 prompt 对象新增 `skillActivation` / `sellingBoundary` / `promptLayers` 审计字段（不进生图文本）。

### 4.3 不把 Skill 原文/分析全文拼进提示词
卖点、画面任务经转换后进入；消费者洞察、营销策略、质检清单全文均不进生成指令（H12/H13）。

## 9. 对后续八个 Skill 的统一接入规范

1. 每个 Skill 必须在 `skillActivation` 提供八字段契约（缺一不可，`validateActivationContracts` 判红）。
2. `execution_mode` 四值之一；默认 conditional/inactive，**禁止无条件 mandatory**（除商品真实性等全局保护）。
3. 触发条件用 contextKeys 声明式表达，由产品身份/行业/事实等级/任务/用户要求推导；不得工程硬编码"某行业必开某能力"。
4. 输出四分：internal_analysis / planning_output / generation_instruction / audit_rules；只有 generation_instruction 经编译转换后进入提示词。
5. 未经 `admittedTaskIds` 授权的任务不得进提示词；每段指令须有 sourceField/sourceTaskId（可审计）。
6. 质检/审计规则不进生图提示词，只在数据层与审计层执行。
7. 新增 Skill 须同步：注册表 + 触发表 + 门禁 phrase + 统一测试库案例（沿用 V220 四处同步纪律）。
8. 工程验证只证明机制；专业质量须经 G4/G5 验收，工程通过不代替质量通过。
