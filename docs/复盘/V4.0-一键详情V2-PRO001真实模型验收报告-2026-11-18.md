## 4. 失败问题（必须修）

### F-1 🔴 未确认材质"棉"被写进最终提示词（高优先级）
- **现象**：构造 aiPlan 中"棉"标为 `mustNotClaim`（L3 未确认），但三屏提示词仍输出`真实材质/颜色：棉`。
- **根因**：`server/detail-middleware.js:592`（`aiInsight` 行）把 `analysis.materialHints` 与 `colors` 直接拼进"真实材质/颜色"；而 `mergeAiAnalysis:198` 令 `materialHints` 直接取 AI 的 `product.materials`（本例=["棉"]），未按 L1/L2/L3 过滤。`planning.facts` 里"棉"已标 mustNotClaim，但编译链没消费这个分级。
- **影响**：与真机 V220 反馈的"棉"错误完全同源；把使用对象材质（衣物棉）误写成商品包装材质，且是 L3 未确认信息进最终提示词——直接违反 V2-PRO-001 §2.2/§2.3 与 §5.3。
- **建议修复**：`aiInsight` 材质段只拼 L1（visible）事实；L2 标"图片观察"，L3（mustNotClaim）不进"真实材质/颜色"；并按六类信息维度把"使用对象材质"与"包装材质"分列。属 V2-ARCH-003 数据契约改造项，需单独立项、配负向对照。

### F-2 ⚠️ 编译链未消费准入结果 / 编译审计（差距，非失败但需补）
- **现象**：准入（`admitTasks`）与审计（`createCompilerAudit`）在 `buildV2ControlReport` 里运行，但结果是**旁挂**在 `group.v2Control` 供验证；17 槽位文本本身没有引用 `admittedTaskIds`，`audit.record` 调用 0 次。
- **证据**：`gapEvidence.编译文本引用admittedTaskIds=false`、`编译文本引用v2Control=false`。
- **影响**：PRO-013（编译器未授权任务拦截）、PRO-014（提示词污染审计）的"编译器必须拒绝未授权任务"**尚未真正落地到编译文本**——当前只是能算出准入状态、能报告审计基线，但没用它过滤/追溯每一句提示词。
- **建议修复**：阶段 E 编译约束——17 槽位每段指令写入时调用 `audit.record({text, sourceField/sourceTaskId})`，`admittedTaskIds` 过滤模块指令与画面任务；无来源段丢弃并记 `unauthorizedAdded`。需碰核心编译链，按 R1 串行单独立项。
