## 二、生产配置（真实，非内存夹具）
`professional-content-v1.json` 的 `cleaning` 包内新增：
```json
"subCategories": [{
  "id": "laundryStain", "industryId": "laundryStain", "industryName": "衣物去渍",
  "extends": "cleaning",
  "positiveSignals": ["衣物去渍", "衣领净", "领口去渍"],
  "professionalValues": { "allowedIndustries": ["cleaning"], "outputRequirements": "专注衣物去渍场景，禁止厨具卫浴规则" },
  "noGeneralization": ["衣物去渍不得扩为所有织物"]
}]
```
- extends 指回父包 cleaning（继承链）；professionalValues.outputRequirements 子类目专属，覆盖父值（继承白名单字段）；noGeneralization 子专属。
- 信号词用"衣物去渍/衣领净/领口去渍"——特意避开父包常见词"血渍清洗剂"（曾因"血渍清洗"过宽误命中 H16/H18 的 cleaning 场景，已修正为专属词），保证不污染父行业识别。

## 三、生产识别入口（独立，不改 P1-1）
- `resolveSubCategory(text, parentPackId, config)`（index.js）：包内二级匹配；子目 extends 必须等于父包 id（跨父类目子目被拒，记 crossParentRejected）；多子目同分→confidence=medium（冲突降级）；单子目命中→high；命中后调 `resolveInheritedPack` 得继承链。
- `resolveIndustrySkill`（middleware:412）：P1-1 判为父包后，若该包有 subCategories 则调 resolveSubCategory 增强；命中则把 resolution 替换为 `ruleSource=industrySubCategory / decisionPath=subcategory_signal_match / parentPackId=父包`，并挂 preResolvedInherited。
- `applyConfidenceToRules`：识别 preResolvedInherited，复用继承链；`subCategorySingleSignal` 门槛用子目 evidence.positive 长度（子目专属信号）判充分性——≥2 才加载子专属，<2 降父公共。
- `applyIndustryResolution`：子目场景以父包做 allowedIndustries 准入，outputRequirements 从继承的 professionalValues.outputRequirements 取（子专属覆盖父）。
