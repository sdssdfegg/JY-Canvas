## 1. 本阶段完成了什么

在阶段 1 的独立工作区基础上，建成阶段 2 的完整能力：

- **三条真正独立的创作模式路径**：`IntakeArea` 按项目 `mode`（创建后不可变）分派 `mode-a/GuidedIntakePanel`（A 引导）、`mode-b/AssistedIntakePanel`（B 辅助）、`mode-c/DirectPromptPanel`（C 直接），各自独立文件。模式 C 面板与服务端 `mode-c.js` 经 grep 确认**零 planner / skill / 策划模块 import**，从代码依赖上杜绝「自动改写用户提示词」。
- **模式 C 四份边界 + 分屏边界识别**：`rawPrompt` 落库后只读、`tidyVersion` 可选默认关、`diff` 可核对、`frozenPrompt` 仅用户确认后写入（生成端只读它）。P3 补强纯函数 `splitIntoScreens`，按空行 / 序号 / `/// 屏 N`（含全角、英文 screen、中文数字屏号）约定切出 `screens[]`，**原文不改、不调 AI、零 import**；`parseModeCTidy` 返回 `screens` / `tidyScreens` / `structure{rawScreenCount, tidyScreenCount, boundaryShift}`，UI 新增「屏结构识别」展示区。口径：解析/切屏属阶段 2，批量生成属阶段 4。
- **商品资料与三类参考图**：`ProductDataPanel`（fields + text 随项目保存）、`ReferenceImagesPanel`（上传带 `role` + `label`，`product` / `visualStyle` / `contentStructure` 职责标注，服务端白名单校验，非法值 400 拒绝），重新打开可还原。
- **模型与渠道选择（Owner 新裁决）**：三个独立下拉（推理模型 / 图片模型 / 渠道）在同一配置区，选项取 `CANVAS_REASONING_MODELS` 与 `getAppConfig().routing → channelsForModel` 联动，配置随项目保存。切换选项**真实改变出站请求**：`textModel` 进 `chat body.model`，图片 model / channelId 进 `/api/images` 的 FormData。
- **KEY 红线修正（Owner 原则）**：删除详情创作里唯一的第二处 KEY 输入框，apiKey 改由 state hook 照现有范式从 `STORAGE_KEY` + `normalizeApiKeyInput` 读取；全仓 `type="password"` 归零，无 KEY 时提示去设置页填写，不在此处输入。
- **目录契约延续**：前后端同名 `intake/` 业务区，已在 V199 单 §5 + 两份 feature `README.md` 三处登记；分类原则、跨区只经 state/api 出口、启动链路零依赖叶子、排查顺序与切割原则全部沿用 V198 §2。
- **额外修复（真机冒烟发现）**：后端不可用或代理返回 HTML 时 `caps` 变畸形对象、`caps.text.endpoint` 崩溃，已加 `capsReady` 形状校验 + 存储可选链兜底。静态门禁抓不到这类缺陷，只有 public 首启动冒烟能暴露。

3. **智能整理目前是约定式纯解析**：`splitIntoScreens` 按空行/序号/标记切屏，不调 AI；`tidyVersion` 目前只做排版归一（合并连续空行），`boundaryShift` 因此通常为 false（属安全网，信息量有限）。AI 生成整理版是阶段 3 评估项，届时接口不变即可替换。

## 6. 已知问题和风险

- **全量门禁 9 项环境性失败**：与本单改动零交集，按项目纪律单跑定性、未刷基线掩盖、未改门禁判据、未做局部加固。项目实际提交口径为 `--fast`。
- **基线连续四次刷新**：每次合法且有备份 + reason，但棘轮敏感度随刷新次数下降；阶段 3 建议尽量少新增 `src` 文件，避免无谓刷新。
- **参考图资产目录无自动清理**：`data/detail-studio/assets/` 独立于 7 天 TTL 的 `data/results`，是有意的用户资产保护取舍；但也意味着长期累积，需在阶段 6 导出/删除能力中提供**显式**管理入口，不引入自动清理。
- **`tidyPrompt` 与 `splitIntoScreens` 的语义差异**：前者改空白、后者只切不改；两份结果并列返回，下游消费时须明确「生成只认 `frozenPrompt`」，避免误用 `tidyVersion` 直接出图。
- 模式 C 分屏约定目前覆盖空行 / 序号 / `/// 屏 N`，用户若用其他自定标记会退化为单屏；阶段 3 可扩充约定或提供用户自定义分隔符，但不引入 AI 自动改写。
