## 1. 本阶段完成了什么

建成了「详情创作」**独立工作区**并跑通基础闭环：

- 左侧导航新增「详情创作」入口，点击后由独立 `React.lazy` 分支加载独立视图；切走即退出，与旧「一键详情/主图」完全并行。
- 工作区具备**项目维度**：可新建项目（名称 / 创作模式 / 备注）、查看列表、点击重新打开、修改并保存基础信息。项目级数据以服务端为准，不依赖浏览器页面状态。
- 服务端建立独立路由与独立持久化目录，接通现有统一文本模型链路与现有 `/api/images` 图片生成体系，并提供「能力自检」面板做连通性验证。
- **按 Owner 追加要求落地了目录分类契约**：前端 `constants / state / components / styles`、服务端 `store / model / probe` 二级分类，两份 feature 根 `README.md` 写明分类原则、各目录职责、后续阶段业务区归属表、排查顺序与切割原则。

- **全量门禁 9 项失败，与本单改动零交集**：`scripts/verify/` 下除本单刷新的两份基线 JSON 外零脚本引用 `detail-studio`；失败脚本无任何 navItem 索引定位逻辑，新增导航项不会导致探针偏移。
  - 浏览器探针 5 项（`error-boundary` / `modal-shell` / `composer-stable-height` / `ai-canvas-inspector-browser` / `outfit-intent-request`）：浏览器回执无法解析或控件值 undefined，属本无头环境既有现象。
  - 自建实例 2 项：`http-mock` 单跑仍失败 1/75，唯一失败项是「tt-image-2.5 其余渠道按价格升序」（渠道价格 `LK-1K/0.12` 排在 `sub/0.13` 后，既有渠道排序断言）；`generation-failure-path` mock 上游未生效（全部落 401 invalid_api_key）。
  - 存量/环境 2 项：`lint-ratchet` 报的 3 个 `no-unused-vars` 全在既有 `scripts/verify/*.mjs`（本单文件 ESLint 0/0）；`release-icon` 明确「exe 不存在：仓外 v5.0 路径」。
  - 处理：按纪律单跑定性（已跑 `http-mock` / `release-icon` / `lint-ratchet-mirror`），**未刷基线掩盖、未改门禁判据、未做局部加固**。项目实际提交口径 `--fast` 59/59 全绿。
- 新增文件让 `frontend-duplication` fileCount 154→161、`size-ratchet` main.jsx 1588→1596 / App 1287→1293 / storage-store.js 278→279，均为合法新增，已按 R6 授权先备份快照再 `--update --reason` 刷新，刷新后完整门禁复验通过。
- public 启动链路风险已控制：`store/` 与 `model/` 保持零依赖叶子，浏览器实测首屏 `rootChildren=1`，未复现历史 TDZ 白屏。

## 7. 是否影响旧模块

**不影响。** 旧 `src/features/detail/**`、`server/routes/detail.routes.js`、`server/detail-middleware.js`、渠道配置 / 网关 / 并发 / KEY 体系全部零改动。`main.jsx` 仅追加 1 个 lazy 声明 + 1 个 `activeView` 分发分支；`storage-store.js` 仅追加 1 个图标 import + 1 个 navItem；`server/app.js` 仅追加 1 行 import + 1 行注册且未改既有顺序。浏览器逐个点开旧详情 / 换装 / 快捷生成三视图均正常渲染、无致命错误文案。

## 8. 是否复用现有模型 API 和数据体系

**全部复用，未引入任何第二套。** 文本走 `server/core/ai-chat-shared.js#postChatCompletion` → 单网关 `/chat/completions`，KEY 经 `resolveApiKey` 只在请求内存活、不落盘不回显；模型名集中在 `server/features/detail-studio/model/model-config.js` 一个适配点（本期沿用 `gpt-5.6-luna`、不开放选择）。图片走现有 `src/api/images.js#generateImages` → `POST /api/images`，`routingFields` 保证 channelId 合法。项目数据只落本地服务端 `data/detail-studio/projects/`，不进 `seed/manifest.json`、不进 `data/results`（7 天 TTL）、不进安装包种子；public 首启导入种子后项目列表仍为空，已实测。`routing-check` 210 项 0 失败、`noSecondProvider=true`、`gatewayCount=1`。
