## 4. Agent / Skill 架构现状（重点）

### 4.0 结论先行

**当前不存在 Agent 运行时、Skill 运行时注册表、生产 Tool 执行入口、服务端规划编排器。** 真实形态是：

> **4 个规划函数 + 静态 import 的提示词资产 + 前端按钮顺序驱动 + `project.json` 落盘传递 + 确定性生成任务状态机**

V207 审查报告自身判定「没有任何真 Agent……所有角色都是常量 + 提示词字符串 + 同一个 `postChatCompletion` 调用」（`docs/架构审查/V207/V207-01-现有智能执行架构审查报告.md:40`）。`tool-registry` / 7 Tool / P5 Agent 决策 / Skill 注册表 / Model Adapter / Context 闭环**均属 V207 目标架构设计，绝大多数仍是设计**。

**规划层没有服务端编排器**。四步是 4 个互不调用的独立 HTTP 端点，由**前端按钮顺序**驱动；批次间数据不通过函数参数链，而是落盘 `project.json` 的 `planning` 字段，每步开头重新 `getDetailStudioProject(id)` 读全量项目再确定性重建上下文。

### 4.3 Agent 是否真正执行任务

**否 —— 只产出结构化 JSON / 提示词文本，不执行任何影响世界的操作**。持久化由路由负责（`analyze-strategy.js:188`、`director-visual.js:235` 注释明写「持久化由调用方负责」），出图由 `/api/images` 完成，编译/冻结/版本/任务全为确定性代码。**没有任何 `tool_calls` / `function_call` 运行时调用**。
