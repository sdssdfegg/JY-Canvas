## 1. 缺陷与根因（已实证，不必重查）

切换到「快捷生成」标签页时浏览器报「内存不足 / Out of Memory」。根因链：

`loadHistoryResults()` 全量回载历史 → `main-canvas-board.jsx` 全量 `map` 无虚拟化 → 每个 `CachedImage` 的 `[src]` effect **无条件** `preloadDisplayImageUrl()`（`new Image()` + `image.decode()`）绕过 `<img loading="lazy">` → 大量高分辨率原图近同时解码 → 标签页 OOM。

沙盒实测（≥100 条压力数据，模拟真实量级：172 文件 / 534 MB、单张最大 9.5 MB、最大 5334×7997）：修复前首屏渲染 **240 个 `<img>`**、**全部带真实 src**（离屏 1×1 占位完全失效）、预加载 `new Image()` 并发 **720**（视口内仅 ~56），解码位图峰值理论 ≈1.4 GB。

## 2. 修复方案（三道，逐条对应根因）

| 层 | 改动文件 | 做法 |
|---|---|---|
| P1 预加载门控 | `src/shared/ui/cached-image.jsx` | 新增全局预加载调度器：`MAX_CONCURRENT_PRELOADS=4` 并发上限 + FIFO 队列；仅 `IntersectionObserver` 判定进入视口（`rootMargin:200px`）才入队；`src` 变化 / 卸载取消未完成任务；**去掉 `image.decode()` 强制解码**，只留 `onload`。保留 `DISPLAY_IMAGE_CACHE` LRU300、`loading=lazy`/`decoding=async` 默认值、`client-result-display-ready` 埋点、失败回退 `onError`。 |
| P2 渲染层限量 | `src/features/main-app/panels/main-canvas-board.jsx` | `quickGalleryItems` 数据层零截断；仅渲染「最近 `visibleTail`=30 张」（`slice(startIndex)`）；顶部「加载更早的记录（已显示 N / 共 M）」按钮逐步展开。与 `main.jsx:638` 的 `scrollTop=scrollHeight` 自动滚底兼容（只滚到底部最新 30 张，不会把全部条目拉进视口）。 |
| P3 门禁固化 | `scripts/verify/quickgen-image-budget-check.mjs` | 静态源码断言：CachedImage 预加载已门控（并发上限 + 队列 + 视口门控 + 无强制 decode）、画廊渲染限量（visibleTail + slice + 加载更多）、数据层未截断；**带 4 条负向对照**（旧坏写法判红 / 新好写法判绿）。注册 `run-all.mjs` 的 `ORDER` + `FAST_ORDER` 双数组，按基线棘轮上线（新增范围零存量违规）。 |

红线全部守住：数据层 `loadHistoryResults` / `storage-store.js` / 服务端 `/api/history` 读取分支**无任何 slice 截断**；`main.jsx`、八文件禁改清单、`server/core/history-store.js`、旧 `detail-main` 零改动；无新依赖、无第二套 Provider/KEY。
