## 遇到的意外 / 与设计单不一致处（共 5 项）

### ① 🔴 S5 触发循环依赖（§7 停手条件 1），已修根因至 0

S5 搬入后 `crop-rect-resize.js` 新增 `import { ratioValue } from "./LocalEditModal.jsx"`，与既有边形成 2 环：

```
crop-drag.js → crop-rect-resize.js → LocalEditModal.jsx → crop-drag.js                        （环1）
crop-drag.js → crop-rect-resize.js → LocalEditModal.jsx → LocalEditCropOverlay.jsx → crop-drag.js （环2）
```

**处置**（未按字面"回滚该批"，而是修根因，已达 cycle=0）：
`ratioValue` 是纯比率工具，定义从 `LocalEditModal.jsx` 迁入 `crop-rect-resize.js`；
`LocalEditModal.jsx` 改为顶部 `import { ratioValue } from "./crop-rect-resize.js"` + `export { ratioValue };` 重新导出。

> ⚠️ 关键细节：第一版写成 `export { ratioValue } from "./crop-rect-resize.js"`（重导出），ESLint 报 `ratioValue is not defined`——重导出**不会**把名字引入本文件作用域，而 LocalEditModal 内部仍在用。改为 `import` + 无 `from` 的 `export {}` 才同时满足"内部可用"+"对外仍可导出"。
> 因是重导出，`main.jsx` / `outfit-panels.jsx` 从 LocalEditModal 的 import **无需改动**。

### ② 🔴 JSX 盲区：S8S9 抽取器漏加 main re-import（vite build 抓不到）

抽取器判定"main 是否仍需引用"用 `isReferencedIdentifier()`，它**不命中 JSX 元素名**（`<DetailUploadZone/>` 是 JSXIdentifier 非 Identifier）⇒ `mainReImports` 为空。
但 main.jsx 仍有 **5 处 JSX 使用**（`DetailUploadZone`×4、`QuickCropViewportModal`×1）。此处 vite build **不会报错**（undefined 组件只在运行时崩）。

**处置**：手工补 `src/main.jsx:76`
`import { DetailUploadZone, QuickCropViewportModal } from "./features/crop/quick-crop-panels.jsx";`

> 这是抽取器对"组件类搬运"的通用盲区，后续同类单需照此人工复核。
