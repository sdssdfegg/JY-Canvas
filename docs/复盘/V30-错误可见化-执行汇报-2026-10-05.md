## 3. §3 改造内容（已提交 `766d2c5`）

只动 `server/core/generation-logger.js`，**+47 / −1**。

### 3.1 让 ③ 可见（核心）

`writeGenerationLog` L32 由 `.catch(() => {})` 改为把错误落到 `runtime-errors.log`：

```js
await appendTaskTextLog(entry).catch((error) => {
  reportTaskTextLogFault(entry, error).catch(() => {});
});
```

新增 `reportTaskTextLogFault(entry, error)`，落盘字段：
`stage="task-text-log-write-failed"` / `requestId` / `endpoint` / `error` / `bucket` / `suppressed`。

**四条硬约束逐条满足：**

1. ✅ **主流程不受影响** —— `.catch()` 保留；注入实测 4 次请求**全 HTTP 200**（见 §4）
2. ✅ `writeRuntimeFaultLog` 同文件 L211 起、`export function` 声明（有提升，无 TDZ）
3. ✅ 内层也 `.catch(() => {})`，不制造新的未捕获拒绝（本身返回的 promise 永不 reject）
4. ✅ 无循环 —— `writeRuntimeFaultLog` 只写 `runtime-errors.log`，不碰 `appendTaskTextLog`

### 3.3 节流（防故障放大）

按 `error.code` 分桶，**同类错误最多每 60 秒落 1 条**，期间次数累加进 `suppressed` 字段。
理由：本函数在出图关键路径上，磁盘满时会把一次故障放大成日志风暴。
