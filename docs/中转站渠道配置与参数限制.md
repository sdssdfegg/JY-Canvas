# 中转站渠道配置与参数限制手册

> 适用：154 中转站（`/opt/jingyin-silent-gpt-image-adapter/`）+ 前端源码（真实源码在 `D:/源码开发/静音AI画板v4.0源码`）
> 最后更新：2026-10-30（LK 渠道打通 + LK-1K / LY满血版 改名 + LK 质量限档之后）

---

## 1. 架构总览：谁调谁（**配错方向会死循环**）

```
画板前端
   ↓
New API 聚合网关（api.jingyin.online，3001 端口，进程 new-api-custom，SQLite 库 /opt/new-api/data/one-api.db）
   ↓  渠道 id=8「静音的渠道」base_url = http://127.0.0.1:8792
jingyin-silent-gpt-image-adapter（8792 端口，配置文件 provider_families.json）
   ↓  按 channelId 选渠道
真实上游（laoye / api.lk888.ai / yunshuaiapi.com / origingateway.com / vakv …）
```

**关键方向**：`provider_families.json` 里每个渠道的 `baseUrl` 必须是**下游真实上游**（外部 API 地址）。
**绝不能填 `api.jingyin.online`** —— 那是 adapter 的**上层**，填了就形成 `adapter → New API → adapter` 回环，表现为 **504 超时**。

> 本次 LK 渠道就是这个错误，排查了好几轮才定位。

## 3. 参数限制是怎么生效的（两层）

### 第 1 层：服务端 adapter（`provider_families.json` 的 `capabilities`）
请求进来后 `tt25_channel_supports_request()` 逐项比对：

| 校验项 | 字段 | 不通过时报错 |
|---|---|---|
| 能力状态 | `capabilityStatus == "tested"` | 400 `tt25_capability_unavailable` |
| 版本 | `supportedVersions` | 同上 |
| 质量 | `supportedQualities` | 同上 |
| 背景 | `supportedBackgroundModes` | 同上 |
| 尺寸档位 | `supportedResolutions` | 同上 |
| 比例 | `supportedAspectRatios` | 同上 |
| 自定义像素尺寸 | `supportsCustomSize` | 同上 |
| **定价条目匹配** | `pricing.entries[].dimensions` | **503 `tt25_price_unavailable`** |

### 第 2 层：前端（下拉置灰）
前端 `sizesForChannel()` / `qualitiesForChannel()` 取「模型能力 ∩ 渠道声明」，
不允许的档位**保留但置灰 disabled**（不是隐藏），选了渠道后自动收敛到合法值。

## 4. 计价

- adapter 侧（我方给客户的价）：`pricing.<model>.entries[].customerPrice`
  - 例：LY满血版 上游 0.12 / 售 0.14；LK-1K 上游 0.12 / 售 0.12
- **上层 New API 另有按模型的全局价**：`ModelPrice`（SQLite `options` 表），例如 `tt-image-2.5 = 0.1`
  - 这是**按模型**收的，不区分渠道。若客户实际扣费与渠道售价不一致，先查这一层。
- 改 adapter 的 `customerPrice` 后**实时生效**（adapter 每次请求读盘）。

## 5. 新增渠道的标准流程

### 步骤

1. **确认上游三要素**：`baseUrl`（真实外部 API）、上游模型名、可用 KEY。
   - 拿 KEY 去 `GET https://<上游>/v1/models` 验证，返回 200 且能看到目标模型才算数。
2. **154 adapter**：在 `provider_families.json` 的 `channels` 下新增一条，至少包含：
   ```json
   {
     "displayName": "渠道名",
     "status": "ACTIVE",
     "baseUrl": "https://真实上游",
     "apiKeyEnv": "LK888_SILENT_XXX_API_KEY",
     "protocol": "openai-images",
     "publicId": "silent-tt25-line-XX",       // 必须未被占用
     "allowedRouteModes": ["manual"],
     "supportedModels": ["tt-image-2.5"],
     "upstreamModels": { "tt-image-2.5": {"flare":"...","sunburst":"..."} },
     "capabilities": { ... 见下方红线 ... },
     "pricing": { "tt-image-2.5": { "status":"ACTIVE", "entries":[{ "dimensions":{...全 "*"...}, "upstreamCost":x, "customerPrice":y }] } }
   }
   ```
3. **写 KEY**：`/etc/jingyin-silent-adapter/relay.env` 追加 `LK888_SILENT_XXX_API_KEY=...`
   → **必须 `systemctl restart jingyin-silent-gpt-image-adapter.service`**（env 只在启动时读）
4. **前端同步（两处同源，必须一起改）**：
   - `server/channel-config.js` 的 `ROUTING_CHANNELS`
   - `src/shared/routing.js` 的 `MODEL_CHANNEL_ALLOWLIST`
   - 若要进「优质渠道」置顶组：加到两处的 `OFFICIAL_CHANNELS`（顺序 = 显示顺序）
5. **重建 dist**：用项目自带 Node 跑 `vite build`，浏览器硬刷新
6. **验证**：见第 7 节

### 检查清单（打勾再上线）

- [ ] `baseUrl` 是外部真实上游，不是自家 `api.jingyin.online`
- [ ] `capabilities.capabilityStatus = "tested"`
- [ ] `supportedResolutions` / `Qualities` / `BackgroundModes` / `Versions` 都填全
- [ ] `pricing.entries[].dimensions` 用 `*`（除非确实要按维度差别定价）
- [ ] `publicId` 未被其它渠道占用
- [ ] KEY 只存在于 `relay.env`，前端/源码零 KEY
- [ ] 前端两处配置已同步、已 build

## 6. 红线与易错点（血泪教训）

1. **🚫 baseUrl 绝不能填自家网关** → 回环 504。（本次 LK 踩坑）
2. **🚫 capabilities 没填全 = 渠道不可用**。历史上多次出现：
   - 缺 `auto` 背景 → 选"背景(默认)"就 400
   - 缺 `xhigh/max` 质量、缺 `transparent` → 选这些就 400（本次补齐）
   - 缺 `auto` 尺寸档 → 不指定尺寸时 400（本次也踩过）
3. **🚫 定价维度写死具体值**（如 `background:"opaque"`）→ 换成 `auto` 就 503 `tt25_price_unavailable`。用 `*` 通配。
4. **🚫 只看"用户上次的参数"去排查**。必须**穷举**所有参数组合（版本×质量×背景×尺寸）才能一次看清所有缺口。
5. **适配器改配置**：除 KEY 外都**实时生效，不用重启**；改 KEY 必须重启。
6. **前端配置两处同源**（`server/channel-config.js` + `src/shared/routing.js`），只改一处会导致服务端与前端不一致。
7. **KEY 绝不进源码/前端**，只存 `relay.env`。
8. **日志位置**：`/opt/jingyin-silent-gpt-image-adapter/adapter.log`（journalctl 查不到）。
   - 看 `upstream_status`：为 `null` = 请求**没打到上游**（本地校验就拒了）；有值 = 已转发到上游。

## 7. 验证方法

### 7.1 静态验证（不花钱，推荐先做）
在 154 上直接调 adapter 的真值函数：
```python
import sys, json, itertools
sys.path.insert(0, "/opt/jingyin-silent-gpt-image-adapter")
import server as S
cfg = json.load(open("/opt/jingyin-silent-gpt-image-adapter/provider_families.json"))
ch = cfg["channels"]["<渠道id>"]
for v,q,bg,r in itertools.product(["flare","sunburst"],
        ["auto","low","medium","high","xhigh","max"],
        ["opaque","transparent","auto"], ["auto","1K","2K","4K"]):
    f = {"model":"tt-image-2.5","prompt":"x","n":1,"version":v,
         "quality":q,"background":bg,"outputSize":r,"outputAspectRatio":"2:3"}
    if not S.tt25_channel_supports_request(ch, f, 1):
        print("FAIL", v,q,bg,r)
```

### 7.2 真实出图验证
```bash
curl -s -X POST http://127.0.0.1:8792/v1/images/generations \
  -F model=tt-image-2.5 -F channelId=<publicId> -F prompt="a red apple" \
  -F n=1 -F outputSize=1K -F outputAspectRatio=1:1
```
返回 200 + 图片即通过。

### 7.3 判错速查

| 现象 | 含义 | 查什么 |
|---|---|---|
| 400 `tt25_capability_unavailable` | 本地能力校验没过 | capabilities 缺项 |
| 503 `tt25_price_unavailable` | 定价条目没匹配上 | pricing dimensions |
| 401 `Invalid token` | 上游不认这个 KEY | KEY 是否属于该上游（拿 KEY 试 `/v1/models`） |
| 504 超时 | 多为 baseUrl 指回自家网关形成回环 | baseUrl |
| 上游 503 "No available channel for model …" | 上游该模型/版本暂时没资源 | 换版本（如 flare）或联系上游 |
