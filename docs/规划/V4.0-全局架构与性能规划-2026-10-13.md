## 1. 三个目标 → 工程定义

| 你的原话              | 工程定义                                                    | 可验收口径                                                         |
| ----------------- | ------------------------------------------------------- | ------------------------------------------------------------- |
| 操作界面丝滑流畅、不吃配置     | 渲染预算制：任何交互不触发全树重渲染；无高频全局定时器；长列表窗口化；图片解码不占主线程；内存不随任务数线性涨 | 输入/拖动跟手无 >200ms 感知延迟；批量 50 张结果卡滚动不掉帧；连续出图内存回归稳态               |

## 4. 丝滑架构规范（渲染预算）

### 4.1 六条硬规则

**R1 状态就近（colocation）**——计时器、时钟、悬停、展开态只归最小组件。  
反例是 C1：`outfit-workflow.jsx:1006` 的 `clockNow` 挂在 4837 行组件顶部，每 500ms 全树重渲染。正例已存在：`src/shared/ui/elapsed-timer.jsx` 自己管 tick，父组件零重渲染。修复模式：

```jsx
// 反例（删掉）：outfit-workflow.jsx 顶部
const [clockNow, setClockNow] = useState(Date.now());
useEffect(() => { const t = setInterval(() => setClockNow(Date.now()), 500); return () => clearInterval(t); }, []);

// 正例（换成已有组件）：只给需要显示计时的那一张卡
<ElapsedTimer since={task.startedAt} />
```

**R2 重渲染隔离**——列表项必须是独立 `memo` 组件；父组件传稳定引用（`useCallback`）。重点对象：批量结果卡、参考图缩略条、任务行。判定方法：改一个任务的状态，只应重渲染那一张卡。

**R3 长列表虚拟化**——同屏结果 >50 张必须窗口化。先做 outfit-workflow 结果区（`features/result-queue/`），main.jsx 图库随后评估。不引第三方库，用 React 19 手写窗口化或 CSS `content-visibility` 过渡。

**R4 重交互让路**——输入框 / 滑块驱动重计算时用 `useDeferredValue` / `useTransition`（React 19 已就位）。不引 Zustand / Redux 等状态库，现有 `useState` + colocation 足够。

**R5 面板懒加载**——新面板默认 `React.lazy` + `Suspense`，跟随 `LazyOutfitWorkflow` / `LazyImageEditorPanel` 既有模式。

**R6 图片不堵主线程**——缩略图先行；大图只在图片编辑器内全尺寸加载；`createImageBitmap` 异步解码；objectURL 成对创建/回收（审计已确认现状基本成对，保持）。

### 4.2 三大件的处置策略：冻结增量 + 切片迁移

- **冻结**：`src/main.jsx`、`src/outfit-workflow.jsx`、`src/image-editor.jsx` 不再追加新功能代码（导航注册除外，每处 ≤10 行）。新功能一律落 `src/features/<name>/`。
- **迁移**：按 §5-P3 一视图一单切；每单 = 抽视图组件 + 写 README + 回填台账 + P0 验收。
- **降级档位**：若某视图状态耦合过深，允许“只抽纯逻辑（state/hook）不抽 JSX”，先降行数再谈抽 UI；不为了拆而拆。

### 5.2 内存预算（“不吃配置”的底线）

- 已知峰值风险：100mb JSON 上限 + 96MB 上传内存 + base64 副本，单请求峰值 1GB+（B6）。客户机器配置不可控，这是 OOM 隐患。
- 规则（新代码立即生效）：禁止同一份大 base64 存两个变量；批量结果只留 objectURL，不留 ArrayBuffer；上传临时文件评估落盘（P4，不盲目改，保 8K 原图能力）。

## 7. 开发硬规范（写新代码对照）

1. **落位**：新功能 → `src/features/<name>/` 三件套（`<Name>View.jsx` + `<name>-state.js` 纯逻辑 + `README.md`）；禁止往三大件追加代码。
2. **上限**：单文件 ≤600 行、组件 ≤400 行；超线开拆分单，不就地堆。三巨头豁免新增但冻结增长。
3. **API**：只走 `src/api/` 薄封装，页面不散写 `fetch`（`src/api/README.md` 即契约）。
4. **共享**：被 ≥2 个功能使用的能力进 `src/shared/`，不进某个 feature 私有目录；暂时抽不了的登记同步表。
5. **样式**：同类控件一套样式，进 `src/shared/ui/` 或统一 token。
6. **门禁**：每单 `npm run check` + `npm run build`；碰 P0 链路（快捷生成 / 批量换装 / 局部回贴 / SKILL）加九项验收清单。
7. **提交**：一单一 commit，`git commit -F tmp/<msg>.txt`，禁 `git add -A` / `git add src/`。

## 8. 避坑清单（开工前扫一眼）

1. 不要新增全局定时器——计时器永远隔离在最小组件（R1）。
2. 不要往 `main.jsx` / `outfit-workflow.jsx` 加功能——新代码进 `features/`（§4.2）。
3. 列表项先写 `memo` 再写交互，不要等卡了再优化（R2）。
4. 大图不进列表态，缩略图先行（R6）。
5. 不要把用户 KEY 写进任何日志 / 前端存储。
6. 新增接口先改 `src/api/`，再改页面；后端字段变更同步查前端封装。
7. 中文文案驱动的正则反猜（B5）是行为耦合重灾区，新工作流用声明式配置。
8. 文件一动就回填 §3 台账——这是后续省 token 的唯一机制。
9. 批量任务与交互任务分优先级，不要共用一个无差别队列（P2-1）。
10. 每单只读“涉及文件清单”内的文件 + grep 验证，不整文件通读。
