## 1. 行业能力包的定位

### 1.1 不是第九个基础 Skill
裁决 D-PLAN-14-01 明确：行业能力包独立目录，与 8 个基础 Skill 分开。基础 Skill（8 个）是通用策划能力，行业包是该行业的专业知识模块，**按需加载**。

### 1.2 提供规则，不提供模板
行业包提供：消费者决策逻辑、适合展示的内容方向、产品类型与使用对象关系、行业适用/不适用的任务、特殊事实要求与宣传边界。
行业包**不提供**：固定屏序、固定标题、强制模板。屏序由 `storyPlan` 按用户 `count` 与资料决定（裁决 -04：首屏不套模板）。

## 2. 主行业唯一与事实边界

### 2.1 单一主行业决策源
- `industryProfile.industryId` 是**唯一生效主行业**；展示行业 = 规则行业 = 加载包行业同源（修复阶段 A P0-1 双路径）。
- 判定优先级：产品主要功能 > 产品类型 > 明确证据 > 弱语境词不越权。
- 现状根因：`getIndustrySkillByText`（`detail-skills.js:403-412`）关键词计分，apparel 含单字"包/面料/模特"（`:49`），"包装材质"误命中服装。

### 2.2 强特征优先规则（工程可自主）
- 强特征：产品功能与形态词（泵头 + 去渍 + 清洁成分 → cleaning）。
- 弱语境词：使用对象/场景（衣物、棉质衣服、厨房台面、包装）——**不得改变行业**。
- 冲突时：强特征胜；仍不明确 → generic。

### 2.3 未知属性不得默认值化
- 行业包里"该行业常见属性"是**候选**，不是当前产品的事实。
- 只有 `productFacts[]` 中 `status=L1` 的属性才算已确认；L2/L3 进 `unresolvedFacts`，不得因行业包"通常有"就写成确认（直击真机"棉"材质错误）。

## 3. 加载机制

### 3.1 目录结构（建议，实际落地随 S2-C）
```
prompts/server/detail-v2-planning/
  industry-packs/                    # 新增：行业能力包独立目录
    cleaning/                        # 清洁日化（首个接入对象，内容待 ChatGPT）
      manifest.json                  # 机器可读：industryId/version/适用任务白名单
      INDUSTRY.md                    # 人类可读：消费者决策逻辑/边界（ChatGPT 写）
    _template/                       # 空模板，供后续行业复制
      manifest.json
      INDUSTRY.md
```

### 3.2 manifest.json 接口（机制；枚举值待 ChatGPT 填）
| 字段 | 含义 | 谁定 |
|---|---|---|
| `industryId` | 主行业 ID（如 `cleaning`） | 工程定 ID，专业命名待确认 |
| `industryName` | 展示名 | 同上 |
| `version` | 包版本 | 工程 |
| `allowedTaskIds` | 该行业允许的任务 ID 列表 | ChatGPT（专业内容） |
| `excludedTaskIds` | 明确排除的任务 | ChatGPT |
| `factRequirements` | 行业特殊事实要求 | ChatGPT |
| `promotionBoundaries` | 宣传边界 | ChatGPT |

> 本批只建目录骨架与 manifest 字段定义，**不写 cleaning 的专业内容**；ChatGPT 交付后填入。

### 3.3 加载流程（确定性）
1. 读 `industryProfile.industryId`。
2. 查 `industry-packs/<id>/manifest.json` 是否存在且合法。
3. 存在 → `loadedIndustryPackIds=[id]`，包规则进 L3 准入与 L4 编译。
4. 不存在 → generic（§4）。
5. **禁止**：加载多个行业包；在 generic 下加载任何行业包。

### 3.4 与 G-2 词表的关系（裁决 -01 与 V219 裁决⑤）
- `prompts/server/detail-skills.js` 的 10 类词表受 G-2 禁改约束，**不直接改**。
- `cleaning` 走**新增覆盖层**：行业包 manifest + 加载器识别，优先级高于旧词表；旧词表保留兜底。
- 这样避免撞门禁冻结哈希，也不返工已复核的 8 Skill 资产。

## 4. generic 回退机制

### 4.1 触发条件
- 行业不明 / confidence 低；行业包缺失；模型未给 industryProfile。

### 4.2 generic 行为（任务书要求 3/4）
- `fallbackMode=generic_no_pack`，`loadedIndustryPackIds=[]`。
- 只用 L1 事实控制 + L3 **通用任务池**（少量、可靠、无行业假设）。
- **禁止**套用任何其他行业的观察点、禁忌、任务（真机服装残留的根因）。
- 通用视觉任务必须基于真实产品属性准入，不假设"产品细节图"默认可用。

### 4.3 generic 下的安全任务示例（仅机制占位，内容待专业）
- 内容：商品定位（基于 L1 事实）、已确认使用方式、保守规格。
- 视觉：产品整体展示（外观可见即可）、不编造结构细节。
- 首批只建少量（任务书阶段 D："不追求一次性庞大任务库"）。

## 5. 用户偏好与准入边界

### 5.1 selectedSections 的角色
- 用户选择的内容板块 = 规划偏好/优先级，不是固定模板（裁决 -04、任务书 #4）。
- 影响 L3 候选任务的优先级排序，不改变准入判定结果。

### 5.2 不可突破的边界
- 用户偏好**不能**把 `rejected`（行业不匹配/无依据）或 `pending`（缺事实）的任务翻成 `admitted`。
- 用户指定方向但无事实支持 → 该方向降级为保守表达或省略，不编造（裁决 -04：血渍清洗剂不得扩奶渍）。
