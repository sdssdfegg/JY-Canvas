## 0. 给 Owner 看的结论（白话）

你反馈的七个问题，我一个都没有去"改提示词修漂亮"——因为那是把症状盖住，病根还在。我把真实生成记录翻出来逐屏对过代码，结论是：**大部分问题不是模型笨，是我们这套流程本身有几处接错线和反复说废话的地方。**

- **服装规则串进清洗剂**：不是商品识别错了（识别出的就是血渍清洗剂、家居百货），是**两条路各走各的**——页面显示的行业用一个结果，挑行业规则用另一个结果，后者把"衣物/面料"当成了服装信号，于是把服装词塞进了提示词。这是**接线错误，能修**。
- **两屏信息重复、质检一模一样**：一是模块说明里写了"要引起购买兴趣"，但下面的具体指令根本没告诉模型怎么做；二是每屏提示词里都把同一大段总规则整个复制一遍，占了一张提示词的**三分之二**；三是质检那一项被程序**截断了**，专门针对每屏的质检内容根本没进来。这些也都是**我们流程的问题，不是模型的锅**。
- **材质无法确认却要求展示材质/工艺/五金**：选模块的环节没有"这个商品能不能确认材质"这道检查，模型选了就照做。
- **商品和中文标签怕生成错**：现在**只靠文字反复叮嘱**，没有用图像处理手段把商品主体真正锁住。

真正跟"资料不够"有关的只有一条：你测的商品只有一张白底图，没有更多角度和素材，有些细节本来就没法确认——模型在这种情况下保守，是合理的。

下面每一条我都标了具体代码位置和属于哪类问题，**给外部架构顾问设计正式方案用**。哪些是工程上现在就能修、哪些必须等方案定，我在最后一节分清楚了。

### 2.1 问题 1：清洗剂出现服装规则（版型/面料/袖口/领口/纽扣/模特比例）

**实测**：三屏逐字重复 `行业识别：家居百货；重点观察：款式结构、版型轮廓、面料肌理、袖口/领口/纽扣/拉链、穿着场景、模特比例和姿态、搭配关系` 与 `行业禁忌：不要改款式结构；不要改变袖口层次、纽扣颜色和领口形态…`。

| 环节 | 溯源结论（带行号） |
|---|---|
| ①商品分析/分类 | 模型返回 `product.name=血渍清洗剂`、行业展示值取 `product.industryName`（`server/detail-middleware.js:196`：`industry: asText(product.industryName, …)`）。**分类本身没错**——展示为「家居百货」。 |
| ②行业规则路由 | **问题根因：双路径分叉且无一致性校验**。`detail-middleware.js:481` 另有 `industrySkill = aiIndustry(input, productImages, aiPlan)`，与 `:196` 的展示行业各自独立计算。`aiIndustry`（`:102-112`）把模型的 `realSellingPoints` / `materials` 拼成文本喂给关键词打分；`getIndustrySkillByText`（`prompts/server/detail-skills.js:403-413`）按命中数降序取首位。清洗剂语境中的「衣物 / 面料」词使 `apparel` 得分压过 `home`，于是规则词表取到服装段。 |
| 词表内容核验 | 串入词**逐字出自** `apparel`：`prompts/server/detail-skills.js:50`（`analyzeAttributes` 含"版型轮廓/面料肌理/袖口…/模特比例"）、`:54`（`taboos` 含"不要改款式结构/袖口层次/纽扣颜色/领口形态"）。相对地，`home` 段 `:79-88` **不含任何服装词**（其 keywords 本含「清洁」）。⇒ 排除"家居百货词表写错"。 |
| ③Skill 上下文 | 候选行业全量表随 instruction 给模型（`detail-ai.js:52-64`）；`compactSkillPack`（`:52-60`）保留 taboos/qcRules。但**规则词表的最终取值发生在 middleware 而非模型**，故模型无法纠正这次分叉。 |
| ⑥注入 | `buildGlobalLock` 在 `detail-middleware.js:422/427` 取 `industrySkill.analyzeAttributes / taboos` 写入 globalLock，`:610` 每屏复制。 |

**归类**：**代码缺陷（主）** —— 展示行业与规则词表两条路径（`detail-middleware.js:196` vs `:481-483`）无一致性校验；**通用模块库设计不合理（次）** —— 关键词计数路由 `detail-skills.js:403-413` 无强规则、同分因 `Object.values` 顺序偏向 apparel。排除词表错配、输入不足；"模型为何产出衣物语境词"属**待验证**（完整 aiPlan 未落盘）。

## 4. 改进建议（方向性，交外部顾问定型）

> 以下只给方向与约束，**不写最终规则、不定义专业内容**。

### 4.1 是否需要按行业建立专业规则路由 —— 需要，但先修"双路径"
- **必须先做（工程）**：统一"展示行业"与"规则词表行业"为**单一决策源**——`middleware:196` 与 `:481` 取同一个 `industryId`，并对"模型行业名 vs 关键词路由结果"加一致性校验；不一致时以商品事实为准并记录，不再让两条路径分叉。
- **专业方案层（外顾）**：行业识别的判据、关键词/语义路由的优先级、同分裁决规则、以及"清洗剂商品出现衣物语境词时是否仍可判 apparel"的原则，由正式方案定义。可考虑把 `getIndustrySkillByText`（`skills:403-413`）的纯计数升级为"行业强特征词优先 + 弱语境词不越权"。

### 4.2 事实 / 需求 / 营销卖点 / 视觉表达分层 —— 建议分层
- 现状 sellingPoint 是自由字符串（`ai:181-200`），无法承载转化。建议 schema 增结构化字段（商品事实 = 图片可证 / 消费者需求 / 营销表达 / 视觉任务），并把"不可确认事实时如何保守表达"作为通用约束。
- **分层字段的具体定义与策划方法属专业方案**；工程侧只提供 schema 槽位与透传，不填规则。

### 4.3 避免同组模块与信息价值重复 —— 建议加确定性去重层
- 工程可解：在 `:602-624` 编译前加一道**跨屏去重检查**（模块 id 不重复、sellingPoint/画面任务语义不重复），作为门禁可验的确定性规则；`dedupLog`（`ai:213`）当前只有声明没有消费，可接上。
- 模块层"每屏承担什么信息角色"的划分由专业方案定义。

### 4.4 视觉 DNA 统一但逐屏构图不同 —— 现有资产可复用，别重造
- `composition-variants.js`（`CV:5`）+ `variantFor`（`V2:40-55`）已有 9 模块 × 4 变体，默认 v1 不生效（`middleware:566-568`）；`V1_LIGHT_LINE`（`middleware:19`）全屏恒定，`visualSpec` 在 detail-main 不存在（仅 B 域有同名变量）。
- 建议：工程侧把"整组视觉 DNA 一行 + 逐屏构图变体"的拼装做成可开关的确定性层；**六维度比较算法（构图/主体位置/镜头/场景/光影/表达类型）与"变体耗尽重规划"的专业规则交外顾**，不自行定型。

### 4.5 减少全局提示词重复 —— 工程可直接解
- 把 `buildGlobalLock` 拆成"整组一次"与"逐屏必需"两部分：商品锁定/平台/文案/行业禁忌/全局风格等**同值段只在整组层写一次**，`text`（`:602-624`）只保留每屏差异段 + 必要的极简引用。
- 预期收益：按实测可省约 41.8% 重复字符；不改变模型可见的信息量。此项**纯工程、可独立单验证**（用提示词长度与逐槽 diff 做断言）。

### 4.6 质检覆盖三维（真实性 / 单屏任务 / 整组逻辑）—— 先修截断，再谈内容
- **必须先做（工程）**：去掉或改造 `:622` 的 `.slice(0,8)`，让模块 qcRules 与 AI 按屏 qualityChecks 真正进入提示词；`buildQualityChecklist`（`skills:426-433`）增加"按屏任务"入参。
- **专业方案层**：三维质检的具体标准、评分口径、"质检不自动覆盖用户提示词"的产品规则（v1.1 §10.3 已确认决策）由外顾方案定义。可评估复用 B 域 `qc-review.js:133-166` 的叙事质检，但不得直接照搬。

### 4.7 商品主体保真是否需要图像链路配合 —— 建议评估，不预判结论
- 现状只有文字约束（§2.7）。建议外顾评估：主体分割/抠图后作为固定图层合成、遮罩编辑锁定中文标签、多视角素材补充三条路线的成本与收益。
- **工程侧可先做准备**：让 `referenceMeta`（`detail-state.js:459-462`、`images.routes.js:343`）从"只归档"升级为"携带主体/参考角色"的结构化字段——这是纯数据契约改动，不涉及专业内容，但需另发单且与旧链路兼容。

### 5.2 工程框架可直接解决（不依赖专业设计，可另单施工）

|---|---|---|
