# 第一章：产品目标与核心设计原则

## 1.1 我们要解决的根本问题

现有一键详情生成流程的核心问题，不是提示词不够长，也不是图片模型不够聪明。

而是整个生成流程缺少真正的商品营销策划能力。

目前容易出现：

1. AI 识别商品后，直接复述商品包装信息。
2. 不理解商品所属行业与商品使用场景的区别。
3. 不会根据商品特点判断哪些内容值得展示。
4. 详情屏幕之间缺少营销叙事和信息递进。
5. 模块名称不同，但实际画面构图和信息表达相似。
6. 缺少事实、消费者利益、营销表达之间的转换。
7. 缺少针对整套详情的质量控制。
8. 最终提示词过度依赖重复的自然语言约束。

V2 必须改变这一生成逻辑。

## 1.2 核心工作流程

商品输入 → 商品理解 → 行业识别 → 消费者需求分析 → 营销策划 → 整套详情叙事规划 → 逐屏视觉导演 → 结构化策划结果 → 提示词编译 → 用户编辑 → 生图。

这里必须明确：

- Agent 负责理解、分析、判断和策划。
- Skill 负责提供专业知识、判断方法、决策规则和执行标准。
- Schema 负责结构化承载策划结果。
- 编译器负责把策划结果转换成最终生图提示词。
- 图片生成模型负责根据最终提示词生成图片。
- 质检负责发现问题、给出修改建议，不擅自修改用户确认的内容。

不能让一个大段系统提示词同时承担所有这些职责。

## 1.3 五项最高原则

**原则一：商品真实性高于营销创意。**

可以创意表达商品的真实价值，但不能为了营销效果编造功效、参数、认证、材料和使用效果。

**原则二：消费者利益高于商品参数罗列。**

详情页不是商品说明书。商品参数只有在能够帮助消费者理解、判断和购买时，才应该成为内容重点。

**原则三：整组叙事高于单屏独立美观。**

每一屏都要好看，但更重要的是整套详情有逻辑、有递进、有不同的信息价值。

**原则四：视觉创意必须服务于内容。**

不能为了追求视觉差异而随意堆砌场景、道具和装饰。视觉设计必须解释、强化或证明本屏表达的内容。

**原则五：确定性问题不能只依赖模型自觉。**

行业路由、数据校验、字段完整性、提示词优先级、跨屏硬约束等，应该尽可能由工程逻辑负责。

# 第二章：总体 Agent 架构

## 2.1 采用单一总策划 Agent，而不是多 Agent Runtime

V2 采用：

**一个详情总策划 Agent + 多个专业 Skill + 结构化输出 + 确定性编译器。**

不建议为了功能拆分创建多个独立 Agent，也不需要引入复杂的 Agent 协作框架。

原因：

1. 当前项目已有模型调用和 Skill 注入基础设施。
2. 详情策划本身需要统一理解商品、营销方向和整组视觉关系。
3. 多 Agent 之间传递信息容易产生事实丢失、策划冲突和重复调用。
4. 当前产品并不需要用户理解后台有多少个 Agent。
5. 单次策划调用更容易控制成本、上下文和执行可靠性。

这里的总策划 Agent 是具备专业决策流程的模型调用层，不宣称它已经具备独立的长期自主运行时。

## 2.2 总策划 Agent 的职责

总策划 Agent 是整个 V2 的核心大脑。

必须负责：

1. 理解商品图片及用户提供的资料。
2. 判断商品的真实身份和所属行业。
3. 区分商品所属行业与使用场景。
4. 判断商品事实的可信度。
5. 分析消费者可能存在的需求。
6. 从真实商品事实中提炼可表达的消费者利益。
7. 制定整套详情的营销叙事。
8. 根据用户指定屏数安排各屏内容。
9. 为每一屏分配独立的信息任务。
10. 为每一屏制定差异化视觉方案。
11. 检查整组信息重复和视觉同质化。
12. 生成结构化策划结果。
13. 给出需要规避的风险和不确定事项。

总策划 Agent 不应该：

- 自行发明商品功效。
- 将商品使用场景误判成商品所属行业。
- 为了填满屏数强行增加无价值内容。
- 为了凑齐模块而选择不适用的内容。
- 直接把商品包装上的参数当成营销卖点。
- 将每一屏都做成同样的正面商品展示。
- 将最终提示词编译逻辑全部交给模型自由发挥。

## 2.3 Agent 的内部执行阶段

一次规划调用内部按照以下决策顺序执行：

| 阶段 | 任务 | 主要输出 |
|---|---|---|
| A | 商品理解 | 商品身份、结构、可确认事实 |
| B | 行业判断 | 主行业、细分品类、使用场景 |
| C | 可信度判断 | 已知、推断、未知、风险 |
| D | 消费者分析 | 需求、痛点、购买顾虑 |
| E | 营销策划 | 利益点、表达角度、证据依据 |
| F | 整套叙事 | 屏幕分工、信息顺序 |
| G | 逐屏导演 | 画面创意、构图、文案布局 |
| H | 整组校验 | 重复、矛盾、视觉差异、事实风险 |
| I | 输出 | 结构化详情策划数据 |

这些是同一个 Agent 的逻辑阶段，不代表需要分别调用九次模型。

# 第三章：专业 Skill 体系设计

Skill 不应该只是几段角色描述或者提示词。

每一个 Skill 都应该具有：

- 明确的专业职责。
- 适用场景和触发条件。
- 输入数据要求。
- 专业判断方法。
- 执行规则。
- 输出字段。
- 与其他 Skill 的边界。
- 冲突处理原则。
- 测试案例。

建议建立以下八项专业能力。

## Skill 01：商品理解与真实性识别

英文标识：product-understanding

### 职责

理解商品是什么、具有什么结构、有哪些可确认信息，以及哪些信息不能确认。

### 必须具备的能力

1. 识别商品品类和商品形态。
2. 识别瓶体、包装、结构、标签、配件等。
3. 提取图片中清晰可辨认的文字和参数。
4. 识别商品图片中实际存在的结构。
5. 判断不同商品图之间是否属于同一商品。
6. 区分商品事实和视觉猜测。
7. 标记无法确认的材质、功效和参数。

### 事实分级

所有重要商品信息必须归入以下类型：

| 类型 | 含义 | 使用规则 |
|---|---|---|
| observed | 图片直接可见 | 可以作为事实使用 |
| user_provided | 用户明确提供 | 可以作为事实使用 |
| verified | 有可靠资料支持 | 可以作为事实使用 |
| inferred | 基于品类和常识的合理推断 | 只能作为策划参考，不能包装成商品承诺 |
| unknown | 无法确认 | 不得编造 |
| prohibited | 存在冲突或明确禁止使用 | 不得进入最终提示词 |

例如：

商品图片显示一个白色泵头瓶，标签明确写着血渍清洗剂，净含量150ml。

可以确认：

- 商品是血渍清洗剂。
- 商品采用白色泵头瓶。
- 标签上标示150ml。
- 商品主要面向衣物血渍清洁这一品类需求。

不能仅凭这些信息确认：

- 瓶体一定是什么塑料材质。
- 产品一定适用于所有面料。
- 一定能够清除陈旧血渍。
- 一定可以达到某个去渍率。
- 一定不会损伤衣物。

### 输出要求

商品理解结果必须包含事实依据和置信度，不能只输出一段商品介绍。

## Skill 02：行业知识与规则路由

英文标识：industry-routing

### 职责

确定商品所属行业，并为后续策划提供正确的行业专业知识。

这是本次血渍清洗剂问题必须优先解决的能力。

### 核心设计：行业与使用场景必须分离

例如：

血渍清洗剂：

- 商品所属行业：家居清洁 / 日化清洁。
- 商品细分品类：衣物血渍清洗产品。
- 使用场景：衣物清洁。
- 目标对象：衣物上的血渍。
- 服装行业属性：不成立。

衣物清洁剂不能因为出现衣物、面料、领口等词语，就自动进入服装行业。

同样：

- 宠物清洁剂不属于宠物食品。
- 汽车清洁剂不属于汽车制造。
- 儿童衣物洗涤剂不属于童装。
- 家具清洁剂不属于家具制造。

### 行业判断优先级

1. 商品明确名称。
2. 商品实际功能和用途。
3. 商品形态和包装特征。
4. 用户明确提供的商品资料。
5. 强行业特征。
6. 弱语境词和使用场景。

弱语境词不得推翻已经明确的商品身份。

### 路由规则

行业路由必须使用统一的规范化结果：

```text
industryId
industryName
subIndustryId
productCategory
useCases[]
confidence
evidence[]
```

展示行业和专业 Skill 选择必须使用同一个行业决策结果。

不能出现：

- 页面显示家居百货。
- 后台实际调用服装行业 Skill。

如果行业置信度不足：

1. 优先采用商品名称和明确功能所支持的上级行业。
2. 采用通用商品真实性规则。
3. 不加载可能产生错误约束的专业行业规则。
4. 将不确定性保留在策划结果中。

### Skill 边界

行业 Skill 提供专业知识和判断标准。

行业路由的最终一致性必须由工程代码负责，不能仅靠提示词保证。

## Skill 03：消费者需求与营销策划

英文标识：consumer-marketing-strategy

### 职责

把商品事实转换成消费者能够理解的购买理由。

这是 V2 最重要的专业能力之一。

### 核心方法

建立四层关系：

**第一层：商品事实**

商品本身有什么，能够确认什么。

**第二层：消费者需求**

消费者为什么会关注这类商品，购买前有什么问题和顾虑。

**第三层：消费者利益**

商品的真实属性能够给消费者带来什么价值。

**第四层：营销表达**

如何把消费者利益转化为简洁、可信、有吸引力的详情文案。

### 示例

商品：血渍清洗剂。

已确认事实：

- 商品名称为血渍清洗剂。
- 包装标示150ml。
- 使用对象是衣物上的血渍。

可以进行的策划：

| 层次 | 示例 |
|---|---|
| 商品事实 | 针对衣物血渍清洁需求 |
| 消费者需求 | 衣物出现血渍后，不知道应该如何处理 |
| 消费者利益 | 让消费者找到更有针对性的清洁产品 |
| 营销表达 | 衣物血渍，针对性清洁 |

注意：这里没有宣称能够清除所有血渍，也没有虚构去渍效果。

### 营销策划禁止事项

1. 不得把推断写成商品事实。
2. 不得将品类通用需求写成已经验证的商品功效。
3. 不得编造消费者调查结果。
4. 不得制造不存在的认证和检测数据。
5. 不得为了增加说服力编造使用前后对比。
6. 不得将商品参数简单改写成夸张营销文案。
7. 不得为了填充详情页制造没有价值的卖点。

### 文案要求

文案应该：

- 站在消费者角度。
- 直接表达购买价值。
- 简短、易懂。
- 有明确的沟通目的。
- 避免空洞形容词。
- 避免企业自我表扬。
- 不重复商品标题和参数。

## Skill 04：详情叙事与内容规划

英文标识：detail-story-planning

### 职责

负责整套详情内容的策划与屏幕分配。

这是解决详情页同质化的核心 Skill。

### 核心原则

每一屏必须承担一个明确的信息任务。

不能只根据屏数平均分配商品参数，也不能按照固定模块顺序机械轮换。

### 详情内容角色库

以下是可供 Agent 选择的内容角色，不是强制模板：

| 内容角色 | 主要任务 |
|---|---|
| hero | 开篇吸引、商品定位、建立认知 |
| problem | 消费者问题和需求 |
| benefit | 核心消费者利益 |
| mechanism | 产品原理或作用方式，有证据时使用 |
| usage | 使用方法和操作流程 |
| scenario | 使用场景 |
| detail | 商品包装或结构细节 |
| comparison | 有依据的差异比较 |
| evidence | 真实检测、认证或可信证据 |
| trust | 消费者购买顾虑和信任建立 |
| faq | 常见疑问 |
| conversion | 购买理由与最终转化 |

以上角色可以组合、跳过、调整顺序，也可以根据商品建立新的合理内容角色。

### 内容角色适用性

每个内容角色都必须有适用条件。

例如：

**materialDetail**

适用条件：

- 商品材质可以确认。
- 有足够清晰的材质或工艺细节素材。
- 材质细节确实对消费者购买决策有价值。

不适用时，不得强制生成材质展示。

可以替换为：

- 包装结构展示。
- 使用方式说明。
- 商品细节展示。
- 其他具有实际价值的内容。

**comparison**

适用条件：

- 存在可靠的比较依据。
- 比较对象和维度清晰。
- 不制造虚假的竞品差异。

**evidence**

适用条件：

- 存在真实、可核验的检测或证明资料。

没有证据时不能为了详情完整而虚构检测报告。

### 屏数规划

用户指定的 count 是硬约束。

例如用户指定6屏：

Agent 必须在6屏范围内完成策划。

不能自行增加到8屏，也不能因为内容不足就擅自删成4屏。

但如果某些内容没有足够依据，应该换成更适合的内容任务，而不是制造信息。

### 首屏原则

首屏始终承担：

- 开篇吸引。
- 商品定位。
- 建立初步购买兴趣。

但不要求首屏永远使用正面居中商品图。

可以根据商品特点选择：

- 商品英雄视觉。
- 商品与真实使用场景结合。
- 消费者问题切入。
- 核心利益视觉化。
- 商品与使用对象的关系表达。

首屏必须先完成营销任务，再决定视觉形式。

## Skill 05：逐屏视觉导演

英文标识：visual-art-direction

### 职责

把每一屏的营销任务转换成具体、可执行的视觉创意。

它不是简单地给每屏指定一种颜色或一种构图。

### 全局视觉 DNA

整套详情应有统一的视觉识别。

全局 DNA 包含：

1. 整体色彩体系。
2. 视觉风格。
3. 光影基调。
4. 材质与质感表达。
5. 摄影或渲染语言。
6. 字体与文案层级。
7. 商品展示规范。
8. 画面精致程度和视觉密度。

全局 DNA 负责统一，不负责让每屏长得一样。

### 单屏视觉规划

每一屏独立规划：

- 视觉概念。
- 构图。
- 主体位置。
- 镜头视角。
- 景别。
- 场景。
- 光线。
- 道具。
- 背景层次。
- 画面焦点。
- 文案布局。
- 视觉表达方式。

### 六维视觉差异体系

整组页面必须比较：

| 维度 | 检查内容 |
|---|---|
| composition | 构图方式 |
| subjectPosition | 商品主体位置 |
| camera | 镜头和视角 |
| scene | 场景与环境 |
| lighting | 光影表达 |
| expression | 视觉表达类型 |

例如：

同样是清洁剂，不能六屏都是：

白色背景 + 商品正面居中 + 蓝色装饰 + 左右卖点卡片。

可以分别设计为：

- 首屏：商品与使用对象形成视觉关系。
- 第二屏：污渍问题的视觉化表达。
- 第三屏：商品使用方式的步骤展示。
- 第四屏：产品包装结构和细节展示。
- 第五屏：适用场景展示。
- 第六屏：购买前注意事项和转化收尾。

这些只是构图方向示例，实际必须根据商品事实、素材和内容任务决定。

### 视觉差异的硬性要求

不允许仅通过更换背景颜色、标题文字、装饰图案来认定视觉差异。

如果两屏在六维度上高度相似：

1. 判断是否存在内容任务重复。
2. 如果存在，重新规划其中一屏。
3. 如果内容任务不同，重新设计视觉表达。
4. 如果商品素材不足，选择可实现的差异化表达，不编造场景和结构。

不允许为了追求差异而损害商品真实性。

---

## Skill 06：电商文案与信息排版

英文标识：ecommerce-copy-layout

### 职责

将营销策划转化为适合详情图片的文案层级和排版结构。

### 文案层级

每屏原则上包含：

1. 主标题：本屏最核心的表达。
2. 辅助文案：补充解释核心价值。
3. 信息点：参数、步骤、证据或细节。
4. 必要说明：使用限制、注意事项等。

不是每屏都必须有四层。

如果一屏只需要一个主标题和一条辅助信息，就不要为了填满版面增加无意义文案。

### 文案质量标准

- 标题有明确的消费者沟通目的。
- 不重复商品名称和包装参数。
- 不把每屏都写成商品功能列表。
- 不使用没有证据支持的夸大表达。
- 不使用空洞的品牌自夸语言。
- 不让多个信息点争夺主视觉。
- 文案长度适合实际画面排版。

### 排版要求

文案布局必须与构图绑定。

不能先生成一段文案，再机械指定左侧文字、右侧产品。

Agent 应根据视觉焦点、主体位置和信息重要性决定：

- 标题位置。
- 标题宽度。
- 字体层级。
- 辅助文案位置。
- 信息卡片数量。
- 文案与商品的空间关系。
- 留白与视觉密度。

---

## Skill 07：跨屏一致性与差异控制

英文标识：cross-screen-coherence

### 职责

检查整套详情是否形成完整的内容体系。

### 必须检查的内容

1. 商品名称是否一致。
2. 商品结构是否一致。
3. 商品参数是否冲突。
4. 核心卖点是否重复。
5. 消费者利益是否重复。
6. 屏幕任务是否重复。
7. 视觉构图是否高度相似。
8. 文案表达是否重复。
9. 前后屏是否存在逻辑矛盾。
10. 是否存在没有依据的内容。

### 两种去重

**内容去重：**

不同屏幕不能仅仅更换标题，实际表达同一件事。

**视觉去重：**

不同屏幕不能只换背景和装饰，实际使用同一种构图。

### 重要规则

不是所有重复都必须禁止。

例如商品主体在每屏都应保持一致，这是商品真实性要求。

商品名称也可能在多屏出现，这是必要的信息识别。

真正需要消除的是没有意义的信息重复和视觉重复。

因此去重不能简单采用“同一模块不允许出现两次”这种机械规则。

---

## Skill 08：质量评估与风险检查

英文标识：detail-quality-control

### 职责

从单屏、整组、商品真实性三个层面评估策划结果。

### A. 商品真实性

- 商品名称是否准确。
- 包装结构是否一致。
- 商品颜色是否一致。
- 标签和文字是否被随意修改。
- 参数是否有依据。
- 功效是否有依据。
- 是否出现虚构材质。
- 是否出现虚构检测或认证。
- 是否出现虚假的前后效果对比。

### B. 单屏任务

- 本屏任务是否明确。
- 是否完成本屏信息表达。
- 文案是否服务于任务。
- 画面是否能解释内容。
- 视觉焦点是否清晰。
- 是否存在无意义装饰。
- 是否存在商品与道具逻辑冲突。

### C. 整组详情

- 是否有完整的叙事逻辑。
- 首屏是否完成商品定位。
- 各屏是否有独立信息价值。
- 是否存在内容重复。
- 是否存在视觉同质化。
- 是否存在前后矛盾。
- 是否形成合理的购买决策路径。

### D. 风险分级

| 级别 | 处理方式 |
|---|---|
| critical | 商品事实错误、虚假功效、严重违反真实性要求，必须阻止通过 |
| high | 核心屏幕任务缺失、重要内容冲突，需要修改 |
| medium | 视觉相似、文案重复、信息层级不清，建议修改 |
| low | 非关键排版或表现优化建议 |

质检输出必须指出：

- 问题发生在哪一屏。
- 具体问题是什么。
- 为什么有问题。
- 推荐修改方向。
- 修改是否涉及商品事实。
- 是否需要用户确认。

质检建议不能自动覆盖用户已经确认的提示词。

# 第四章：结构化输出 Schema 设计

## 4.1 为什么必须结构化

当前最大问题之一，是把大量策划信息压缩成一个 sellingPoint 字符串和一个 composition 字符串。

这样会丢失：

- 商品事实来源。
- 消费者需求。
- 营销利益。
- 单屏任务。
- 视觉规划。
- 跨屏关系。
- 风险信息。

V2 必须采用结构化输出。

## 4.2 顶层数据结构

建议规划结果采用以下逻辑结构：

```json
{
  "schemaVersion": "1.0",
  "productProfile": {},
  "industryProfile": {},
  "consumerInsights": {},
  "marketingStrategy": {},
  "globalVisualDNA": {},
  "screens": [],
  "groupQuality": {},
  "uncertainties": []
}
```

## 4.3 商品信息

```json
{
  "productProfile": {
    "name": "血渍清洗剂",
    "category": "衣物血渍清洁产品",
    "industryId": "home_cleaning",
    "facts": [
      {
        "key": "netContent",
        "value": "150ml",
        "source": "image_observed",
        "confidence": "high"
      }
    ],
    "unknowns": [
      "瓶体具体材质",
      "具体去渍率"
    ],
    "authenticityLocks": [
      "保持瓶身外观",
      "保持泵头结构",
      "保持标签布局"
    ]
  }
}
```

这里的商品信息只是示例，不代表该商品已经确认具有其他未提供的属性。

## 4.4 行业信息

```json
{
  "industryProfile": {
    "industryId": "home_cleaning",
    "industryName": "家居清洁",
    "subIndustryId": "laundry_stain_removal",
    "productCategory": "衣物血渍清洁产品",
    "useCases": [
      "衣物血渍清洁"
    ],
    "confidence": "high",
    "evidence": [
      "商品名称",
      "标签文字",
      "商品用途"
    ]
  }
}
```

重点：

industryId 和 useCases 必须分离。

衣物是使用对象，不是服装行业判定依据。

## 4.5 营销策划信息

```json
{
  "marketingStrategy": {
    "corePositioning": "",
    "targetNeeds": [],
    "consumerConcerns": [],
    "verifiedBenefits": [],
    "creativeAngles": [],
    "claimsToAvoid": []
  }
}
```

每一项营销利益都应该能追溯到事实依据。

## 4.6 单屏数据结构

```json
{
  "screenId": "screen-01",
  "screenRole": "hero",
  "communicationGoal": "",
  "consumerQuestion": "",
  "productFacts": [],
  "consumerBenefit": "",
  "marketingMessage": {
    "headline": "",
    "subheadline": "",
    "supportingPoints": []
  },
  "visualConcept": "",
  "composition": {
    "layout": "",
    "subjectPosition": "",
    "camera": "",
    "scene": "",
    "lighting": "",
    "expressionType": ""
  },
  "copyLayout": {},
  "authenticityConstraints": [],
  "relationToOtherScreens": {
    "previousScreen": "",
    "nextScreen": "",
    "avoidRepeating": []
  },
  "qualityChecks": []
}
```

以上是逻辑字段示例，正式实施时由总控根据现有项目的 Schema、数据结构和兼容机制进行映射，不得直接照搬示例字段而破坏旧版接口。

## 4.7 Schema 设计要求

1. 必须有 schemaVersion。
2. 必须有字段默认值与空值处理规则。
3. 必须限制数组长度和文本长度。
4. 必须校验屏数与用户 count 一致。
5. 必须校验 screenId 唯一。
6. 必须校验商品事实引用。
7. 必须校验行业标识。
8. 必须校验单屏必需字段。
9. 必须保留 unknown 和 uncertainty。
10. 必须保留向旧版提示词结构转换的兼容层。

不允许把模型输出的任意 JSON 直接当作可靠业务数据。

# 第六章：提示词编译器设计

## 6.1 Agent 不直接负责最终提示词拼装

Agent 输出结构化策划结果。

编译器负责将其转换成图片模型能够执行的最终提示词。

这样可以避免：

- 每屏重复大段全局规则。
- 模块说明与实际画面任务脱节。
- 质检规则被截断。
- 不同屏幕的商品约束不一致。
- 模型随意遗漏关键字段。

## 6.2 三层规则结构

**第一层：全组共享数据**

只存储一次：

- 商品身份。
- 商品事实档案。
- 商品真实性约束。
- 行业信息。
- 全局视觉 DNA。
- 平台要求。
- 文案基本规则。
- 整组统一禁忌。

**第二层：单屏策划数据**

每屏独立：

- 本屏任务。
- 本屏利益表达。
- 本屏画面概念。
- 本屏构图。
- 本屏镜头。
- 本屏场景。
- 本屏光影。
- 本屏文案。
- 本屏专属质检项。

**第三层：最终图片提示词**

由编译器把共享规则和单屏规则组合成可直接生图的文本。

重要工程说明：

虽然全组共享数据只存储一次，但每张图片的生成请求通常是独立的。

因此不能简单地把全局规则只写在第一屏提示词里，再期待第二屏图片模型自动记住。

正确方式是：

- 全组共享规则在数据层只存储一次。
- 编译时为每屏提取必要的精简约束。
- 每屏最终提示词都携带足以独立执行的商品保真规则和必要的全局视觉约束。
- 不重复塞入无关的大段说明。

这样才能同时解决提示词冗长与独立生图上下文丢失的问题。

## 6.3 最终提示词结构

建议统一为：

1. 商品主体与真实性锁定。
2. 本屏核心任务。
3. 核心营销表达。
4. 画面创意与构图。
5. 商品与场景关系。
6. 镜头、光影与色彩。
7. 文案内容与排版。
8. 全局一致性约束。
9. 本屏专属限制。
10. 负面约束。

具体文本不应机械套用固定17槽位。

应该由结构化策划数据决定哪些段落需要出现。

## 6.4 中文标签与商品保真

必须明确：

文字约束不等于图像保真。

提示词可以要求图片模型保持商品包装，但不能保证模型百分之百准确复现中文标签、商品细节和结构。

因此编译器需要支持两种模式：

**模式 A：完整 AI 生图**

适合场景、背景、道具和视觉创意较为自由的页面。

**模式 B：商品主体保真优先**

在工程条件允许时，将真实商品主体作为独立图层保留，通过背景生成、合成或局部编辑完成详情图。

是否使用抠图、蒙版、固定图层合成，应由工程可行性评估决定。

不得为了实现主体保真而擅自破坏当前图片生成链路。

# 第七章：整套与单屏沟通上下文

## 7.1 整套沟通

用户提出：

- 整套换一个营销方向。
- 整套视觉更高级。
- 整套减少文案。
- 整套调整色调。
- 重新规划详情顺序。

Agent 应获取：

- 商品事实档案。
- 当前营销策略。
- 整组视觉 DNA。
- 全部屏幕策划结果。
- 用户本次修改要求。
- 已确认的用户约束。

重新规划后，必须检查所有屏幕的连贯性。

不得只修改一屏后造成其他屏幕逻辑冲突。

## 7.2 单屏沟通

用户提出：

- 第二屏重新设计。
- 第三屏换一种构图。
- 第一屏标题重写。
- 某一屏增加使用步骤。

Agent 应获取：

- 商品事实档案。
- 整组营销主线。
- 全局视觉 DNA。
- 目标屏幕完整策划。
- 其他屏幕的简要摘要。
- 用户本次修改要求。

只修改目标屏幕，除非用户明确要求联动修改。

修改后检查：

- 是否改变商品事实。
- 是否与整组叙事冲突。
- 是否与其他屏幕重复。
- 是否破坏全局视觉一致性。

## 7.3 用户确认状态

必须区分：

- AI 初始策划。
- 用户编辑中。
- 用户已确认。
- 用户要求重新策划。
- 已生成图片。

Agent 不得在用户只要求修改某屏时，自动重写整套已经确认的策划。

具体状态存储沿用项目已有任务和版本设施，不另建一套互不兼容的状态系统。

# 第八章：可选质检体系

## 8.1 质检是独立能力

质检按钮与生成提示词按钮分离。

用户可以：

- 生成策划。
- 修改提示词。
- 直接生图。
- 主动点击整套质检。
- 主动点击单屏质检。

不得把质检设计成生成图片前的强制步骤。

## 8.2 质检分层

| 质检类型 | 检查内容 |
|---|---|
| 本地规则检查 | 屏数、字段、商品事实引用、重复字段、基础冲突 |
| 单屏 AI 质检 | 本屏任务、文案、画面逻辑、商品真实性风险 |
| 整组 AI 质检 | 叙事递进、信息重复、视觉同质化、整体购买逻辑 |

## 8.3 质检结果

输出：

- 问题等级。
- 问题位置。
- 问题描述。
- 问题原因。
- 修改建议。
- 修改影响范围。

不允许质检自动修改用户已经确认的提示词。

## 8.4 费用策略

模型质检可能产生额外模型调用费用。

本版设计不默认强制调用模型质检。

具体收费与调用方式留待产品决策，工程上应预留：

- 本地检查。
- 模型质检。
- 两者组合。

# 第九章：模型调用与工程兼容要求

## 9.1 复用现有体系

必须复用：

- 现有模型渠道配置。
- 现有 API Key。
- 现有模型路由。
- 现有 `postChatCompletion`。
- 现有图片生成路由。
- 现有任务、资产、存储设施。
- 已有降级机制。

不得新建第二套 Provider、Key、模型网关或图片生成系统。

## 9.2 模型调用职责

推理模型负责：

- 商品分析。
- 营销策划。
- 详情叙事。
- 逐屏视觉规划。
- 结构化输出。
- 用户沟通。

图片模型负责：

- 根据最终提示词生成图片。

二者职责不能混淆。

## 9.3 模型适配

不同推理模型可能存在：

- 图片理解能力差异。
- JSON 输出能力差异。
- 上下文长度差异。
- 指令遵循差异。
- 多屏规划能力差异。

必须测试不同模型的结构化输出可靠性。

不能因为某一个模型测试成功，就认为所有模型都适配。

## 9.4 降级原则

模型输出异常时：

1. 不得编造缺失的商品事实。
2. 不得将无效 JSON 直接交给编译器。
3. 不得自动退化成没有经过验证的旧模板并宣称策划成功。
4. 应记录错误原因。
5. 保留用户输入和草稿。
6. 给用户明确的失败或重试反馈。

# 第十章：测试与验收标准

## 10.1 建立固定测试商品集

至少包含：

1. 日化清洁剂。
2. 衣物护理产品。
3. 服装商品。
4. 家居用品。
5. 美妆个护产品。
6. 结构复杂的商品。

每类至少包含：

- 单张白底图。
- 有包装信息的商品图。
- 多角度商品图。
- 有使用场景的素材。

不能只用血渍清洗剂一个案例判断体系是否合格。

## 10.2 核心测试案例

### 案例 A：行业路由

商品是衣物血渍清洗剂。

预期：

- 行业属于清洁日化方向。
- 使用场景可以是衣物。
- 不加载服装版型、纽扣、袖口等专业规则。

### 案例 B：资料不足

商品只有一张白底图。

预期：

- 可以完成策划。
- 不虚构材质。
- 不虚构功效。
- 不强制选择材质展示模块。
- 能根据现有事实规划有效内容。

### 案例 C：屏数约束

用户指定6屏。

预期：

- 输出6屏。
- 首屏完成商品定位。
- 每屏有不同的信息任务。
- 不机械轮换模块。

### 案例 D：内容板块为空

用户没有选择任何内容板块。

预期：

- AI 自主规划整套内容。
- 不要求用户补充额外偏好。
- count 仍然是硬约束。

### 案例 E：视觉差异

同一商品生成6屏。

预期：

- 整体视觉 DNA 统一。
- 构图、主体位置、镜头、场景、光影、表达类型有实质变化。
- 不以更换背景色冒充视觉差异。

### 案例 F：营销表达

商品只有包装参数，没有额外功效证明。

预期：

- 从已知事实出发。
- 能分析消费者需求。
- 不把推断写成商品功效。
- 不输出空洞的参数罗列。

## 10.3 六个评价维度

| 维度 | 评价内容 |
|---|---|
| 商品理解 | 商品识别、结构、事实准确性 |
| 营销策划 | 消费者需求与利益转化 |
| 叙事逻辑 | 整组内容递进与信息价值 |
| 视觉创意 | 构图、场景、表达差异 |
| 提示词质量 | 指令明确、结构合理、可执行 |
| 真实性 | 商品、功效、参数和文案可信度 |

每项采用1—5分人工评价，同时记录严重错误。

商品事实错误、虚假功效、行业错误等严重问题不能被其他维度的高分抵消。

## 10.4 验收必须分层

- 代码测试：代码结构、字段、规则、编译器。
- 接口测试：模型调用、请求参数、返回结构。
- 真实模型测试：实际模型输出的策划质量。
- 图片生成测试：实际生图的构图和商品保真。
- 用户操作测试：完整工作流是否顺畅。

不能把代码测试通过等同于真实模型质量合格。

# 第十一章：实施边界与阶段安排

本方案定义专业能力目标，不意味着要求总控一次性全部开发完成。

## 阶段 A：专业资产与数据契约

目标：

- 建立 Agent 职责与执行流程。
- 建立八项专业 Skill。
- 建立结构化输出 Schema。
- 建立商品事实与行业分类规范。
- 建立固定测试集。

交付：

- Agent 主定义。
- 八项 Skill 文件。
- Schema。
- 测试用例。
- 专业规则冲突优先级。

## 阶段 B：接入现有规划链路

目标：

- 复用当前 Skill 注入基础设施。
- 让 Agent 输出结构化策划结果。
- 验证专业 Skill 实际进入模型请求体。
- 验证输出 Schema。
- 保持旧版详情功能兼容。

交付：

- 真实模型规划结果。
- 请求与响应取证。
- 结构化数据验证报告。
- 兼容性测试报告。

## 阶段 C：提示词编译与跨屏控制

目标：

- 建立全局与单屏分层。
- 解决全局规则重复。
- 建立跨屏信息检查。
- 建立视觉差异检查。
- 解决按屏质检内容被截断的问题。

交付：

- 编译器测试。
- 多屏提示词对比。
- 重复率对比。
- 跨屏校验报告。

## 阶段 D：整套沟通、单屏沟通与质检

目标：

- 建立整套修改机制。
- 建立单屏修改机制。
- 保留用户确认内容。
- 建立独立质检功能。
- 保持版本和任务兼容。

## 阶段 E：商品主体保真增强

目标：

评估并选择合适的图像处理方案：

- 商品主体抠图。
- 固定图层合成。
- 遮罩编辑。
- 局部重绘。
- 多角度商品素材。

这一阶段不应阻塞 Agent / Skill 专业能力体系的建设。

# 第十二章：总控 AI 执行权限与禁止事项

## 12.1 总控可以自主决定

- 文件组织方式。
- Skill 注入技术实现。
- Schema 兼容方式。
- 现有代码复用方式。
- 工程任务拆分。
- 测试执行方式。
- 工程内部实现细节。

但必须保证不偏离本方案的专业能力定义。

## 12.2 总控不能擅自改变

1. 不能把单一总策划 Agent 改成普通模板提示词。
2. 不能将八项专业能力删减为几段角色描述。
3. 不能把行业与使用场景混为一谈。
4. 不能取消商品事实分级。
5. 不能取消营销利益转化。
6. 不能取消整组叙事规划。
7. 不能取消逐屏视觉差异控制。
8. 不能把质检重新做成强制流程。
9. 不能擅自新增用户必填设置。
10. 不能为了接入 Skill 重建第二套模型调用体系。
11. 不能修改 G-2 禁改词表。
12. 不能用临时提示词的偶然好结果代替体系验收。

如果总控认为某项设计与现有代码存在冲突，应提交：

- 实际代码证据。
- 冲突原因。
- 可选实现方案。
- 各方案的利弊。
- 对产品能力的影响。

可以提出更优技术方案，但不能无依据地降低专业能力要求。

# 第十三章：最终验收目标

一键详情 V2 最终应该达到以下效果：

用户只需要上传商品图片，必要时补充一些商品资料，选择屏数和自己想要的内容偏好。

点击生成后：

1. AI 能真正理解商品，而不是只识别包装。
2. 能正确判断商品所属行业。
3. 能知道哪些事实可以表达，哪些不能编造。
4. 能理解消费者为什么需要这个商品。
5. 能将商品事实转化成消费者利益。
6. 能规划完整的详情营销叙事。
7. 能让每一屏承担不同的信息任务。
8. 能为每一屏设计有差异的视觉方案。
9. 能保持商品主体和整组视觉一致。
10. 能生成清晰、完整、可执行的生图提示词。
11. 用户可以自由修改整套或单屏内容。
12. 用户可以跳过质检直接生图。
13. 用户可以主动质检并自行决定是否采纳建议。

最终让用户感受到的是：

**我只需要提供商品，AI 就能像一个真正懂电商运营、商品营销和视觉设计的专业团队一样，帮我把整套详情策划出来。**

而不是：

我上传一张商品图，AI 帮我把商品参数换个说法，再套进几张差不多的详情模板。

# 设计结论

本方案采用：

**单一详情总策划 Agent + 八项专业 Skill + 结构化策划 Schema + 确定性提示词编译器 + 可选质量评估。**

它既保留当前 JY-Canvas 已有的模型调用、Skill 注入、图片生成和项目管理设施，也把真正需要专业化的能力独立定义出来。

这是一套可以持续扩展的专业策划体系，而不是针对血渍清洗剂这一个测试商品临时修补出来的提示词。

后续新增行业、商品类型、营销方法和视觉能力时，可以扩展专业 Skill 和知识资产，而不必推翻整个 Agent 架构。

**V1.0 的核心验收标准不是文件数量，而是：同一商品输入下，系统能否稳定地产出事实可信、营销有价值、叙事完整、逐屏有差异、能够实际生图的详情策划结果。**
