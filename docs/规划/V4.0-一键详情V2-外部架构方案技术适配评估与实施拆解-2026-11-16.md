## 5. 冲突与风险清单（按严重度）

### 5.1 🔴 最高：九阶段专业资产全量注入 vs 单次调用上限
- 方案 §2.3 定义 A–I 九个逻辑阶段，§5.3 要求"Agent + 真实性 + 行业 + 营销 + 叙事视觉规则始终存在"。
- 现状 `compactSkillPack`（`detail-ai.js:28-91`）已注入 10 类行业候选 + modules + 全量 quality；再叠 8 个 Skill 全文会放大单次 prompt 与输出 JSON，可能撞 `DETAIL_ANALYSIS_TIMEOUT_MS=120000`（`:16`）与 4 类降级重试（`:274-298`）。
- **建议**：先把 C-1（单/两段式）裁掉；用真实数据实测 token 上限（v1.1 C-11 待验证项）；按方案 §5.3「压缩重复、分层加载」执行，**不删关键专业能力**。若实测单次不可行，按方案 §5.3 的授权"拆分专业规则层级"而非降能力。

### 5.2 🟠 Schema 落点与数据边界四红线
- 新 Schema 顶层字段若挂 `group` 会被 `sanitizeDetailGroupsForStorage`（`detail-group.js:336-359`，V217 白名单）剥离；入 `detailSettings` 会经 `saveDetailPreset`（`:251`）与 `detail-state.js:225` 落 localStorage；**严禁进 `seed/manifest.json`**（四红线：前端无 KEY 记录 / 包内无生图记录 / 提示词模板随包 / 页面状态以用户为准）。
- **建议**：沿用 V216 已验证的「planning 作响应独立顶层、不挂 group」+ 前端 `detailPlanningContext` 会话态（不落盘），新字段走条件注入，三通道一律不进。

### 5.3 🟠 测试集清单归一（非新增）
- v1.1 §13.1 六类：`日化 / 服装 / 美妆 / 食品 / 家居 / 数码或结构复杂`；方案 §10.1 六类：`日化清洁剂 / 衣物护理 / 服装 / 家居 / 美妆个护 / 结构复杂`。两份高度重叠但措辞不同。
- **建议**：以 v1.1 §13.1 为准合并为一份测试集清单，方案 §10.2 六个案例（行业路由/资料不足/屏数/空板块/视觉差异/营销表达）作为固定用例；**不得把 21:01 已结案的"功能验收"重新打开**——方案 §10.1 是"专业质量测试"的具体化，口径写清楚。

### 5.4 🟡 目录落点与 8 Skill 资产组织
- 方案 §5.2 建议新建 `detail-v2/{agent,skills,schemas,tests}/`。新建**代码**目录不违反"不新建平行文档"（该纪律约束 docs/）。但项目已有 `prompts/server/detail-v2-planning/`、`prompts/server/detail-skills-v2/` 三文件 + `server/detail-skills-v2.js` 活壳。
