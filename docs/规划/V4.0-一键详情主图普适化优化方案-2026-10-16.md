## 1. 背景与痛点诊断

### 1.1 现状链路（已核实）

```
前端 DetailView（按钮/上传/参数）
  → createDetailPromptPlan()
  → server/detail-ai.js  createDetailAiPlan()
      · compactSkillPack(input) 组装 v1 规则包（行业/平台/模块/质检）
      · 调 AI（temperature=0.2，默认模型 gpt-5.4-mini）→ 返回 JSON 方案
  → server/detail-middleware.js  buildDetailPromptGroup()
      · AI 方案 + 本地规则合并 → 每屏最终生图提示词（十二段式 text）
  → 前端分段提示词确认卡片 → 批量出图
```

每次「生成分段提示词」产出一个**分组**（= 一套完整详情/主图方案）。用户连续出 10 套 = 10 个分组。

### 1.2 "10 套严重相似"的四个根因（均在供给侧，不在模型）

| # | 根因 | 实证 |
|---|---|---|
| 1 | **构图模板单一收敛** | `SCREEN_MODULES` 每个模块的 `composition` 只有一句固定模板，AI 逐屏扩写时全部收敛到同一构图解 |
| 2 | **光线/构图行整体写死** | `detail-middleware.js:521`：`【构图与光线】主体清晰、边缘干净、柔和四面光、低反差、无生硬黑影` —— 每一屏、每一套都逐字相同 |
| 3 | **风格只有"统一"约束，没有取值** | `BASE_SKILL.globalStyleConsistency` 要求"统一色彩体系/光线方向"，但不给本组具体选哪套；AI 只能默认最通用的"干净背景+柔光" |
| 4 | **视觉锚点全行业堆叠、无选择逻辑** | `compactSkillPack` 把 10 个行业候选全量塞进 prompt（`industryCandidates`），只给一个 `seedIndustry` 提示，模型没有"本组选定哪套视觉方向"的决策点 |

补充隐患：**行业靠关键词自动判别**（`getIndustrySkillByText` 计分），跨类目词易误判（如"儿童洗衣液"同时命中母婴"儿童"与家居"清洁"），前端无手动覆盖入口。

### 1.3 设计目标

1. **普适**：任何类目可用；行业只是"倾向"，风格是独立"轴"，二者解耦。
2. **多样**：套与套之间有明确、可复现的分化（风格包 × 构图变体 × 驱动力），组内保持统一。
3. **专业**：对齐 2025 主流电商视觉方法论 + AI 生图工程实践（见 §2）。
4. **兼容**：JSON 契约向后兼容，新增字段全部可选；旧前端无感。
5. **可回退**：v1 逻辑零改动保留，运行时开关一键切回。

### 2.2 来自 2025 主流实践（检索实证）

- **首图 3 秒法则**：用户均停留仅 2.7 秒，首图必须同时回答"这是什么/解决什么/为何选你"；产品占比 ≥60%；利益点标签左上角、社会证明右下角；短句 ≤5 个。
- **F 型视觉动线**：前三屏按"痛点场景+解决方案 → 产品全景+参数对比 → 认证/买家秀+促销"布局，结构化详情页转化率比图文混排高 10-20%。
- **60-30-10 配色法则**：主色 60%/辅助 30%/强调 10%。
- **白底+场景双版本**：公域搜索场景（淘宝/京东/亚马逊）首图需白底安全款；场景图用于详情承接。
- **视频主图/竖屏承接**：抖音等渠道 CTR 增益明显，详情首屏需能承接短视频流量的近景冲击构图。
- **视觉三角法**：产品、文字、标签三者构成稳定视觉三角，3 秒抓住眼球。
- **数据可视化**：销量/评价/成分用图表表达，降低阅读成本。
- **避坑**：文字堆砌、图片堆砌无动线、忽视移动端、照搬大牌丢掉自身调性。

### 2.3 AI 生图工程实践（本项目已验证的教训）

- **中文乱码是生图第一杀手** → negativePrompt 保留并加强"错字/乱码/伪英文"。
- **参考图角色分离**：商品图锁身份、参考图只吸收氛围/构图/配色（v1 已有，保留）。
- **一屏参考图有上限**：防主体漂移与风格割裂（v1 已有，保留）。
- **文案安全区**：文字置于画面下部/留白区，避开主体与易变形边缘。
- **主体占比量化**：60-80% 可执行区间。

## 3. 总体架构：五层决策模型

```
L1 输入层   商品事实（图+文） × 用户选择（平台/页面类型/屏数/风格/驱动）
L2 决策层   D1 转化驱动力判断 → D2 行业画像 → D3 平台规范 → D4 风格包选定
L3 模板层   主图任务库(KV1-5) × 详情模块库(M1-9) × 构图变体库 × 触感光影 × 文案规则
L4 输出层   每屏：画面任务+图内文案+设计说明+生图提示词（保持现契约）
L5 质检层   五维自审 + 品类合规 + 负面约束 + 真实性锁
```

与 v1 的关系：**L1/L4/L5 的骨架全部继承 v1**，L2/L3 是新增与增强。v1 的四大资产（真实性锁、图序角色规则、11 平台矩阵、9 模块库）逐字保留。

### 4.2 切换机制

| 层 | 机制 | 默认 |

### 4.3 回退与验证

- 回退 = 把开关改回 v1（或删掉 v2 分支调用），**v1 代码零 diff**。

## 5. 核心设计

### 5.1 风格包体系（Style Pack）——解决"套间相似"的主杠杆

每套风格包是一组完整的视觉取值（不是名词清单，是决策值）：

| ID | 名称 | 色温/色调 | 布光方案 | 构图族 | 背景策略 | 情绪/字体 | 适配驱动 | 适配平台 | 禁忌 |
|---|---|---|---|---|---|---|---|---|---|
| S1 | 白底极简 | 中性白 | 均匀柔光、近无影 | 居中/微偏置 | 纯白/浅灰纯色 | 干净理性、无衬线 | 理性/视觉 | 淘宝/京东/亚马逊公域首图 | 禁文字、道具、装饰 |
| S2 | 生活场景 | 暖中性 | 自然窗光 | 环境融合中景 | 真实生活空间 | 亲切、常规字 | 痛点/情感 | 全平台详情 | 场景抢主体 |
| S3 | 质感微距 | 中性偏冷 | 侧逆光+柔光补 | 微距、浅景深 | 纯色/材质台面 | 高级、细体 | 视觉 | 天猫/小红书 | 过曝糊细节 |
| S4 | 痛点对比 | 中性 | 平光、双场景光比一致 | 左右/前后对比 | 双色块分屏 | 直接、粗体 | 痛点 | 拼多多/抖音 | 虚假对比 |
| S5 | 促销信息 | 暖色高饱和 | 明亮平光 | 主体+信息块 | 品牌色底 | 热闹、粗黑 | 痛点/理性 | 拼多多 | 廉价感过度 |
| S6 | 氛围情绪 | 暖调浓郁 | 戏剧光/光束 | 场景+情绪特写 | 氛围环境 | 情绪、手写感 | 情感 | 小红书/抖音 | 产品被淹 |
| S7 | 科技理性 | 冷调 | 硬光、条形高光 | 结构分解/信息图 | 深色/渐变灰 | 理性、等宽 | 理性 | 京东/亚马逊 | 浮夸装饰 |
| S8 | 自然原生 | 暖自然 | 自然光+柔反 | 有机摆放/俯拍 | 天然材质台面 | 质朴、衬线 | 情感/视觉 | 小红书/食品/母婴 | 脏乱背景 |

**分配算法（组间分化 + 组内一致）**：

```
stylePackForGroup(groupIndex, driver, platform, userChoice):
  if userChoice ≠ auto: return pack(userChoice)
  preferred = driver.preferredPacks          # 每驱动 2-3 个优选包
  allowed   = platform.allowedPacks          # 平台禁用的包剔除（如白底规范）
  pool = preferred ∩ allowed，空则 preferred ∪ allowed
  return pool[(groupIndex - 1) % pool.length]  # 连续两组必不同（pool≥3）
```

- **组内一致**：同组所有屏共享同一风格包（继承 v1 的 `globalStyleConsistency` 意图）。
- **组间分化**：轮转 + 驱动匹配，保证第 k 套与第 k-1 套不同；用户也可手动指定。
- **主图特例**：`pageType=main` 且平台要求白底时，KV1 强制 S1（公域安全款），KV2-KV5 用组风格包——白底与风格化分离，互不牺牲。
- 与现有选项关系：`richness/fontStyle/copywriting/modelMode/reverseScreens` 是**内容轴**，风格包是**视觉轴**，互补不冲突；风格包内部已含字体气质，`fontStyle` 作为覆盖项优先。

### 5.2 转化驱动力四型（L2 决策层，v2 新增）

| 驱动力 | 判断信号 | 视觉战略 | 主图首图策略 | 详情侧重 |
|---|---|---|---|---|
| 视觉驱动 | 饰品/美妆/家居摆件/外观差异化强 | 质感、光影、氛围优先 | 产品美学霸屏 | 材质/场景/细节 |
| 痛点驱动 | 清洁/收纳/母婴/健康护理 | 问题先行、对比、证据 | 痛点画面+产品介入 | 对比/证据/FAQ |
| 理性驱动 | 数码/家电/3C/参数敏感 | 参数可视化、机制解释 | 产品+核心参数 | 参数/结构/兼容 |
| 情感价值 | 香氛/礼盒/宠物/节日商品 | 情绪、仪式感、使用后状态 | 氛围+使用后状态 | 场景/情绪/礼赠 |

输出位置：JSON `strategy.conversionDriver` + `driverReason`（供前端展示与自检）。同行业不同产品自动分化——这是行业维度之外的关键第二轴。

### 5.3 构图变体库（Composition Variants）——解决"屏间同构"

每个模块给 3-4 个变体（替换 v1 的单模板），每变体必带五要素：**构图描述 / 视觉第一落点 / 视线动线 / 文案安全区 / 禁忌**。

| 模块 | 变体 A | 变体 B | 变体 C | 变体 D |
|---|---|---|---|---|
| hero 首屏 | 居中霸屏（占比 60-80%） | 黄金分割偏置+角标标签 | 对角线动态 | 满版出血+底部文案安全区 |
| painReverse 痛点反转 | 左右对比 | 前后时间轴 | 上下分屏（问题→解决） | 数据条对比 |
| coreSellingPoint 核心卖点 | 主体+右上信息块 | 爆炸分解式 | 图标+短句矩阵 | 场景化证明 |
| materialDetail 材质细节 | 微距特写 | 剖视/结构解构 | 多细节排列 | 光影扫掠（侧光勾纹理） |
| useScenario 使用场景 | 环境全景 | 中景互动 | 使用瞬间特写（手部/动作） | 镜像反射（用户视角代入） |
| specInfo 参数说明 | 结构化表格 | 引线标注 | 尺度参照（与常见物对比） | 图标矩阵 |
| trustProof 信任背书 | 证书/报告卡式 | 数据可视化 | 服务流程条 | 品牌背书墙 |
| conversionClose 收尾转化 | 产品回归+CTA | 组合陈列+价格锚 | 保障图标排 | 结束语+品牌收尾 |
| fitStructure 版型结构 | 整体展示 | 局部放大 | 多角度排布 | 线条解构 |

选择规则：`variant = variantFor(moduleId, screenIndex, stylePack, driver)`——由模块+屏序+风格包构图族+驱动共同决定，**同组内不连续重复同一变体**；AI 也可在 JSON 中显式指定 `compositionVariantId`（人审保留最终权）。

**主图任务库 KV1-KV5**（`pageType=main` 时映射 5 屏）：

| KV | 任务 | 构图要点 | 文案铁律 |
|---|---|---|---|
| KV1 | 视觉截流 | 主体 60-80%、缩略图可读、白底或场景 | ≤5 行、单行 ≤6 字 |
| KV2 | 痛点/问题 | 用户语言提问，不堆功能 | 问句优先 |
| KV3 | 差异对比 | 前后/新旧/参数对比，画面自证 | 数字优先于形容词 |
| KV4 | 场景代入 | 真实使用、镜像效应、环境不淹主体 | 场景词具体 |
| KV5 | 行动引导 | 规格/价格/组合/人群/CTA | 数字+行动词 |

### 5.4 触感→光影映射库（普适版）

| 触感关键词 | 布光方案 | 背景倾向 | 色调 |
|---|---|---|---|
| 泡沫/绵密/奶油 | 柔和顶光+边缘微过曝 | 浅色洁净 | 高明度低饱和 |
| 液体/透亮/晶莹 | 侧逆光+高光点 | 深色反衬或渐变 | 清透 |
| 粉末/颗粒/砂 | 侧光勾边+微阴影 | 哑光台面 | 自然 |
| 织物/柔软/亲肤 | 漫射光、低反差 | 暖浅色 | 暖柔 |
| 金属/科技/精密 | 硬光、条形高光 | 深灰/黑 | 冷调 |
| 木质/天然/有机 | 侧光纹理+暖阴影 | 原木/植物 | 暖自然 |
| 皮质/绒面/厚重 | 顶光+侧光结合 | 深色 | 低明度暖 |
| 玻璃/陶瓷/脆 | 柔光+透射 | 渐变 | 干净 |

用法：AI 从商品图/产品特征推断触感词（如"泡沫丰富""液体透亮""面料柔软"），映射到布光+背景+色调，写入每屏 `【触感与光影】` 段——**直接替换 §1.2 中写死的"柔和四面光"行**。行业默认触感词表内置于 `industries.js`（增强版），AI 可覆盖。

### 5.5 文案规则与利益翻译

- **F-A-B-E 利益翻译**：卖点先过 Feature→Advantage→Benefit→Evidence 再成文；禁止说明书语言残留。
- **行数铁律**：主图单屏 ≤5 行、单行 ≤6 字；详情模块 ≤6 行（对齐 Cola + 移动端可读性实证）。
- **一屏一卖点**（继承 v1）；数字优先于形容词；社会证明仅基于用户提供资料。
- **首屏 3 秒三问**：这是什么/解决什么/为何选你——写入 hero 模块变体约束。
- **F 型动线**：详情前三屏默认"痛点/钩子 → 核心获益 → 信任证据"，与平台 rhythm 合并排序。

### 5.6 合规内建（三层 + 品类自动匹配）

| 层 | 适用 | 核心内容 |
|---|---|---|
| L0 通用 | 所有产品 | 绝对化违禁词表+替换映射（唯一/最/第一/100%…→多数/约/之一）；数据宣称必须附检测报告编号；竞品对比三不原则（不贬低/不二元对立/引用公开数据）；平台审查重点（淘宝敏感词/京东参数一致/拼多多价格绝对化/抖音口播同审/亚马逊 claims） |
| L1 保健食品 | 蓝帽子 | 只可宣传批准功能原文；功效边界表；法定免责声明 |
| L2 运动器材/体态管理 | 非医疗器械 | 医疗化术语替换表（痛感/医学术语/治疗动词/效果承诺）；效果弱化词强制 |
| L3 普通食品 | 非保健非药品 | 四条底线；安全表达白名单（产地/工艺/口感/场景）；兜底声明 |
| L4 家清日化（增强层） | 清洁/洗涤/护理 | 除菌率/去污力等数据必须附检测报告；禁暗示治疗皮肤病/过敏；"除菌"≠"消毒"表述边界 |

匹配规则：`industryId + 关键词 → 合规层`，generic 默认 L0；命中层的违禁词表与免责声明模板按需注入（不全量堆，省 token）。免责声明位置写入收尾屏设计说明。

### 5.7 五维自审（进 JSON，作为提示不阻断）

| 维度 | 判定依据 |
|---|---|
| 合规性 | 法律基线逐条核查+平台附加约束 |
| 利益翻译度 | Feature 是否翻译成用户可感知 Benefit |
| 视觉第一落点 | 主体占比/卖点唯一性/文案行数/视线动线 |
| 触感媒介表达 | 材质光影匹配度/主图与详情分工 |
| 叙事连贯性 | 组内屏间去重/详情沿成交路线推进 |

输出：`screens[].selfReview = {dimension: {score, note}}`；任一 <80 的维度，`intervention` 标注"建议重写：XX 维度"——**提示用户，不阻断已有确认流程**。

## 8. A/B 验收方案（v1 vs v2）

用同一批商品（建议覆盖 4-6 个不同类目，各跑主图+详情）分别出 5 套，按维度打分：

| 维度 | 评判方式 |
|---|---|
| 套间多样性 | 风格包/构图族/光线方案/背景策略的去重计数（v2 目标：5 套两两不同） |
| 屏间专业度 | 对照 §2.2 主流清单逐项核（3 秒三问/F 动线/60-30-10/白底首图） |
| 合规 | 违禁词表机扫 + 免责声明存在性 |
| 商品一致性 | 结构锁遵守（颜色/材质/logo/比例不漂移） |
| 文案可读性 | 行数/单行字数/乱码率 |
| 成本 | v1/v2 prompt 长度与出图可用率对比 |

验收通过后再决定 v2 转正（默认版本切换）、继续迭代或回退。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| v2 prompt 变长、token 成本上升 | 风格包/变体/合规层全部**按需注入**（只注入选中项），不全量堆叠 |
| 行业关键词误判 | 加权计分+负向词表；P5 前端手动选择覆盖 |
| 商品真实性回归 | 真实性锁逐字保留；质检清单增强；白底首图独立逻辑 |
| v2 输出不稳定 | 五维自审提示+用户确认门（前端卡片）保留最终决策权 |
| 开关遗漏导致行为意外 | 默认 v1；`JINGYIN_DETAIL_SKILL_VERSION` 显式开启 |
| 风格包与平台规范冲突 | 平台 `allowedPacks` 剔除（如公域首图禁场景包） |
