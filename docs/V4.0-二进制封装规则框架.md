## 四、封装流程（发布工程 SOP + 数据边界五步）

发布工程既有 SOP 不变（`build.config.json` 版本真相源 → `node build.mjs --version vX.Y.Z` → 四项验证 → 登记表）。本框架在其**前**插 2 步、**后**插 3 步：

### 1. 快照导出 / 同步（构建前，用户操作）

> V123 起**正路改为「一键同步」**：源码版设置页点「同步到封装配置」→ 直接把开发者最新状态写回仓库 `seed/manifest.json`（git 跟踪，历史即备份，满足红线③"永不清"）；封装自动读取、缺失硬失败。

- **（正路·V123）一键同步**：源码版设置页「数据与存储」→「同步到封装配置」→ POST `/api/seed-sync`（仅 internal 模式路由，public 打包经 esbuild 死代码消除）→ 服务端强制复核（entry id 合法 + 无凭据 + 逐 entry sanitize）后原子写 `seed/manifest.json`；新鲜度提示实时比对浏览器现算 `seedId` 与仓库 `seedId`，不一致即提醒「封装前请先同步」。
- **（旧档·V121，保留兼容）导出下载**：点「导出封装种子」下载 `jingyin-seed-<日期>.json`，再交给构建器；导出即过 **B/C 类剔除**（字段白名单：prompt 库仅 `id/title/category/content/custom`；pages 仅 `id/name/deleteLocked/settings/uploadLabels/activeUploadGroup`；凭据与图像/任务字段一律不写）。
- 两条路径产出的都是同一形态 `{version, seedId, entries}`，构建期校验复用 `release-seed-schema.js` 同一份白名单/剥凭据实现。
- 备选：用户不愿点按钮时，由统筹用浏览器 DevTools 控制台片段导出（同白名单）。

### 2. 种子入包（V123：默认读仓库真相源，缺失硬失败）

- **（默认·V123）仓库真相源**：`secure-win-release.mjs` 未设 `JINGYIN_SEED_FILE` 时，默认读取仓库根 `seed/manifest.json`（开发者一键同步生成），存在即走既有校验注入；**不存在则醒目警告 + 非零退出**（红线③不满足），仅内部试验构建可设 `JINGYIN_SEED_ALLOW_MISSING=1` 放行（工厂包）。
- **（兼容·V121）显式指定**：`build.mjs` 支持 `--seed <文件>`，经 env `JINGYIN_SEED_FILE` 传给 `secure-win-release.mjs`；解析优先级 **`--seed` ＞ 仓库 `seed/manifest.json` ＞ 发布工程/seed/ 最新 `jingyin-seed-*.json`**。
- 种子经校验后在 vite build 之后、`generate-static-assets.mjs` 之前复制进 `dist/seed/manifest.json`（走既有 `EMBEDDED_STATIC_ASSETS` 内嵌管线自动进 SEA，无需新路由）；
- 种子**不单独进包**（它随 exe 内嵌），其完整性由 exe 校验和覆盖（发布工程原则 5）；登记表记录**种子文件 SHA256**，溯源「哪份用户状态进了哪版 exe」。

### 3. 构建（既有链路，不改）

`secure-win-release.mjs`（public 三件套 env + 清 dist + vite build + SEA + 图标/版本信息）→ 发布工程 `renderDocs/enhanceVersionJson/shipTools/writeManifest/makePatch`。

### 4. 包体扫描（新增门禁，缺一不可）

| 扫描项 | 判据 | 范围 |
|---|---|---|
| KEY 样串 | `sk-`、`Bearer\s+[A-Za-z0-9]`、`apiKey`/`token` 后跟非空串值 → **0 命中** | dist、seed、包内全部文件 |
| 生图记录 | `generation.jsonl`、`logs/tasks`、`task-history`、`page-draft` 字样；连续 base64 块 >100KB → **0 命中** | 包内全部文件 |
| 种子字段白名单 | prompt 库仅 5 字段；pages 无 `*Images`/`tasks`/`originalLibrary`；无 `apiKey`/`baseUrl`/`channelId` 键 | seed 文件 |
| 目录纯净 | 包内无 `logs/`、`data/`、`.env`、`.secure-build/` | 包根 |

### 5. 冒烟 + 登记（沙盒）

- 沙盒 `DATA_ROOT`（**隔离目录，禁用默认路径防残留**）起 exe，等 `uptimeSec` 个位数（发布工程原则：HTTP 200 + uptimeSec 双判据）；
- 首跑断言（tabbit 探针，与 verify 探针同基建；**必须带 `indexedDB.deleteDatabase('jingyin-outfit-workflow-local-v1')` 清草稿**，V120 探针坑口径）：
  1. 提示词助手可见用户模板：条数 = 快照条数、标题一一对应；
  2. 批量生成页提示词库同样可见（双键验收）；
  3. 页面 chip 集 = 用户当前集合（含改名页；已删单例不回归）；
  4. 全量 localStorage 扫描无 key 样串；无任务历史（`task-history` 键不存在）；
  5. 客户自建/删模板后重启：不丢失、不被 reset 清（V118 红线回归）；
- 登记表追加一行，**新增「种子 SHA256」列**（含种子文件名与哈希）。

## 七、留档（裁决与理由，事后可复核推翻）

1. **裁决：种子用「dist/seed/ + SEA 内嵌 + 首跑仅空库导入」，不用「打包进前端 bundle 代码」**。理由：① 用户数据以数据文件形态存在，包体扫描口径干净（扫 seed 文件即可，不必从 js 里抠）；② 种子可独立小更新（不改前端 js 时补丁包只含种子）；③ 走既有 `static-assets.generated.js` 管线，零新路由零新失败点。
2. **裁决：导出走「设置页按钮」而非纯控制台片段**。理由：用户浏览器不在自动化可达范围，且「导出」应是用户明确的同意动作（同意边界）；控制台片段仅作备选留档。
3. **裁决：种子必须同时带两套提示词键**（main 前缀键 + outfit 硬编码键）。理由：红③要求「客户打开可以看到我的模板」——用户可能在任一视图建模板；只带一套会造成客户侧两个视图模板不一致，正是红线要防的「同类内容两个来源」。键合一属未决产品决策，本框架不越权裁决，只要求种子口径覆盖现状。
4. **教训沿用**：兜底/导出类能力所触碰的每一类用户资产，先查有没有「自动清理」路径会误伤（V118 教训）；本框架的 seed 导入因此设计为「仅空库 + 一次性标记」，与 public reset 的「保留提示词键」口径叠加成双保险。
