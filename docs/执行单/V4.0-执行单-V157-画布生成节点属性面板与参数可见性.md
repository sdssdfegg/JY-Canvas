# V4.0 执行单 V157 — 画布生成节点参数编辑改为「属性面板」（解决溢出裁剪 + 渠道/模型选择不可见）

> 前置依赖：V143（画布引擎）、V144（节点生态）已合入；V152（模型下拉）、V153（推理默认模型）、V154（Agent 推理模型下拉）、V155（实际生效参数显示）、V156（渠道选择链路）均已提交且门禁全绿。
> 方向裁定：V156 已把「渠道选择」的**数据链路**打通（form 带 channelId + 下拉组件已渲染），但**用户实测仍看不到**。本单定位为渲染层与交互范式问题，不推翻 V152/V156 的功能实现。

## 根因（已实测确认，非猜测）

1. `.aiCanvasNodeBody` 带 **`overflow: hidden`**（`src/features/ai-canvas/ai-canvas.css:190`）。
2. generation 节点尺寸**固定** `w=280, h=224`（`ai-canvas-store.js:29-31`），扣掉节点头（`.aiCanvasNodeHead`）后内容区约 **190px**。
3. NodeBody 内容累计高度已超 220px：模型下拉 + **渠道下拉（V156 新增）** + **实际参数行（V155 新增）** + 提示词 textarea（min-height 42px）+ 尺寸/比例行 + 执行按钮。
4. ⇒ **底部内容被 `overflow:hidden` 裁掉**，用户看到的是"没有模型/渠道选择"。

**结论：功能在 DOM 里、数据链路也通了，只是渲染不可见。** 因此本单不得再"继续往节点里堆控件"——堆得越多裁得越狠。

## 目标

1. 生成节点的 **模型 / 渠道 / 尺寸 / 比例** 全部**可见且可编辑**。
2. 采用画布类应用标准范式——**Inspector（属性面板）**：选中节点后在面板里编辑全部参数；节点卡片内只保留**只读摘要**。这样参数再多也不会溢出。
3. 复用现有视觉与既有渠道/模型目录，**不新增第二套数据源**。

验收标准：
1. 选中生成节点时，属性面板可编辑：模型、渠道、提示词、尺寸、比例；每项改动即时写回节点。
2. 渠道选项**按当前模型过滤**（模型换成香蕉2，渠道列表随之变），数据来自 `channelsForModel()`，与快捷/批量/详情同一份目录。
3. 节点卡片内以只读摘要显示当前生效值（模型 / 渠道 / 尺寸 / 比例 / 单价），不堆叠可编辑控件。
4. 属性面板内控件**全部可见**（无裁剪、无需滚动才能发现）。
5. **浏览器探针实测通过**（见下"验收方式"，本单强制要求，不得只做静态断言）。
6. 出图仍带正确的 `channelId` + `dispatchMode`（V156 链路保持有效）。

## 设计要点

- **Inspector 范式**（与 n8n / ComfyUI / Figma 一致）：节点只做「画布上的图形 + 摘要」，参数编辑统一在面板。这是解决"固定高度节点塞不下"的根本办法，而不是继续调高度或开滚动。
- **分类纪律**（用户明确要求"代码有分类、不混乱"）：
  - 数据/解析 → `ai-canvas-params.js`（纯逻辑，零 import，可无头断言）
  - 节点注册表/类型 → `ai-canvas-nodes.js`
  - 只读展示组件 → `ai-canvas-panels.jsx`
  - 可编辑面板 → **`ai-canvas-inspector.jsx`（新，职责单一）**
  - 视图编排/状态 → `ai-canvas-view.jsx`
  - **禁止**把可编辑控件再塞回 `NodeBody`。
- **单一数据源**：模型列表 `config.routing.models`；渠道列表 `channelsForModel(模型, 目录)`；推理模型 `CANVAS_REASONING_MODELS`。三者都已有，Inspector **只消费不重新定义**。
- **视觉复用**：控件沿用 `.aiCanvasGenSelect` / `.aiCanvasGenPrompt` 等既有类，与尺寸/比例同一套观感；新样式一律 `.aiCanvasInspector*` 前缀（与 `.aiCanvas*` 家族一致，参考 V152/V154 的 CSS 作用域纪律）。
- **隔离**：不动 outfit / 详情 / 快捷生成任何页面；不动 channel-config、routing.js 的目录语义。

## 复现 / 验收方式（强制浏览器探针）

> 教训：本单的前置问题正是"静态门禁全绿、但用户实际看不到"。因此**必须**用浏览器探针验证可见性，不得仅凭 `run-all --fast` 绿灯就判定完成。

1. **无头（`ai-canvas-inspector-check.mjs`，进 `run-all` 的 ORDER 与 `--fast`）**：
   - 断言生成节点摘要字段完整（模型/渠道/尺寸/比例/单价）
   - 断言 `channelsForModel()` 对 tt-image-2 / banana-2 返回非空且随模型变化
   - 断言 Inspector 改动写回 store（`updateNodeData` 语义不变）
2. **浏览器（`ai-canvas-inspector-browser-check.mjs`，复用项目 tabbit 探针能力）**：
   - `npm run dev` → 进入「AI 无限画布」→ 新建生成节点 → **选中**它
   - 探针断言（真实 DOM 几何，不是"元素存在"）：
     - 属性面板内 模型/渠道/尺寸/比例 四个控件 **均可见**（`offsetParent !== null` 且 `getBoundingClientRect()` 宽高 > 0）
     - 每个控件**未被祖先裁剪**（其矩形落在 Inspector 可见区内）
     - 切换模型后，渠道下拉**选项数量/内容发生变化**
     - 选中渠道后执行生成，请求体带该 `channelId`
   - 探针须能**复现旧缺陷**：先在"节点内堆叠"实现下断言失败（控件被裁），改造后断言通过——否则探针是恒绿假绿。

## 风险与回滚

- **风险**：Inspector 是新增交互面，可能影响节点选中/取消选中的既有状态流。
- **缓解**：`NodeBody` 只读摘要保持原有字段读取方式；store 的 `selectedNodeId` / `updateNodeData` 语义**完全不变**，Inspector 只在其之上渲染。
- **回滚**：本单改动集中在画布 feature 内（`src/features/ai-canvas/**` + 2 个 verify 脚本 + css），回退对应提交即可，不影响任何业务页面与服务端。

## 不做的事（明确边界）

- 不新增/修改服务端端点；不改 new-api 渠道配置与计费。
- 不动快捷生成 / 批量生成 / 详情 / 参考改图任一页面。
- 不重写画布引擎（拓扑、工作流、版本管理、存储守卫一律不动）。
- 不重新定义模型/渠道数据源（沿用现有三处）。
- 不顺手重构画布其它模块（体量债另开拆分单）。
