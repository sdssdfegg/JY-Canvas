### 1.2 🔴 统筹范围裁定（推翻 V187 派单时的 T3-b 描述）

V187 归档件 §9 与 README/NEXT 把 T3-b 写成「`ChannelPicker` 与 **10+ 处原生 `<select>`** 的单一形态收口，评估 `.ui-select` / `Select` 组件落地」。**按本轮发布日取证，该描述属发布时的推断，现予重裁定**：

2. **V188 不改渠道入口的交互形态**。形态 ④ 有 `styles.css:1861` 与 `OutfitComposer.jsx:448` 两处历史注释背书，是刻意保留的「批量页与参数同级下拉」；把它换成圆钮要动 `updateSetting("channelId")` 业务逻辑、`.rightTools` flex 布局、`option` 官方绿着色与 `.channelSelect` 金色语义，属**改交互**而非改视觉，风险外溢且不在「只统一视觉」的 T3 范畴。**该归一列为须 Owner 明确点头的独立决策，不预建、不占槽位**（与 T1-b2 同级）。
3. **因此 V188 只做「样式契约层」**：把选择器的视觉外壳上收到 `ui.css` 的 `.ui-select*` 契约类（单一**样式**真相源），并让**批量换装 `.rightTools` 的 12 个选择器**接入它、删净该作用域的重复外壳声明 —— 这是本单**唯一、可控、可独立回滚的可见变化**（边框/底色/圆角/焦点环归顺全局基样式）。
4. **T3-b 拆两刀**：V188 = 契约类落地 + 单作用域试点；**T3-b2** = 其余 53 处普通 select 的全量接入与 CSS 覆盖收编（是否发单由 V188 目视后统筹裁定；若 V188 试点已满足规划稿「渠道选择器单一形态」的样式判据，可直接进 T3-c，不强行凑刀）。
