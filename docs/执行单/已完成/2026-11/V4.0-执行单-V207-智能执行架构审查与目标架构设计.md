## 1. 任务背景与产品目标（任务书 §一/§二 原文口径）

V200–V206 已建立 Agent/Skill 基础架构、详情创作工作流、任务持久化、单屏编辑与版本管理。但**不能仅凭已存在的 Agent 文件、Skill 文件、角色定义或接口，就认定系统已具备成熟智能执行能力**。本次独立审查，不以维护现有架构为目的，也不预设推翻。

长期产品目标（8 条，目标架构须能合理支撑，不要求本阶段实现）：
1. 电商服装换装：单图 / 批量 / 局部 / 连续换装、参考图约束
2. 电商详情创作：商品分析、用户需求分析、策划、分屏、视觉设计、生成、修改、版本管理
3. 无限画布：AI 理解画布内容、选择图片与对象、结合画布上下文执行任务
4. 连续图片创作：理解历史版本 / 当前图 / 修改意图，保持多轮编辑上下文
5. 多图协作：理解同项目不同图片的关联，保持商品主体、视觉风格、内容逻辑一致
6. 专业视觉能力：按行业 / 商品 / 平台 / 营销目的调用专业知识
7. 长任务执行：复杂任务拆解、持续执行、失败恢复、任务追踪、结果验收
8. 用户可控：模型、渠道、参数、创作方向、最终执行内容保留必要用户控制权

### 9.3 E 等级分布
- **E1（代码与调用链实证）**：全部关键判断（Agent/Skill/Context/Tool/Orchestration/Quality/Model Adapter/四条链路/四个已知缺陷）。
- **E2（自动化或模拟执行）**：本单未新增 verify 脚本（属后续 P1–P8 实施阶段）；现状门禁均为静态断言（E2 性质但仅扫描）。
- **E3（真实模型/服务运行）**：**0**——本仓无真机运行日志纳入审查，交 Owner 实机覆盖。
- **E4（真实用户操作）**：**0**——同上。
- 严禁把 E1 写成 E3：所有「真实运行成功」类判断均标注「尚未验证」。

### 9.4 三选一结论
**对现有架构进行较大改造。** 保留确定性执行内核（任务状态机/幂等/重试/并发闸门/启动恢复），改造 Agent/Skill/Tool/Context/Model Adapter 上层；其中 Model Adapter 图像侧仅替换内部实现（抽出 `generateImage` 适配器），外部契约完全复用，故归「改造」而非「替换核心结构」。

### 9.5 重大风险（≤3，带 E 等级）
1. **P1 无标准化 Tool 体系（E1）**：当前出图/编辑/资产/任务/版本均为散落业务模块，无法支撑「Agent 经工具执行」「换装声明化」等长期目标。
2. **P3 多轮编辑历史不回灌模型（E1）**：`version-routes.js` 仅传 `frozenPrompt`，editThreads/版本链不进提示词 → 连续编辑无多轮上下文（history-loss）。
3. **P6 参考图在 `buildTaskRecord` 被丢弃（E1）**：出图请求实际不带参考图，影响参考图约束类场景（如服装换装/电商详情参考图）。

### 9.6 下一项最值得执行的任务
**P1 · Tool 抽象底座**。理由：它是后续所有改造（Context 闭环需 Tool 调版本/任务、Agent 受控决策需 Tool 调用契约、链路 C 工具执行最后一跳、换装声明化）的**共同前置**；且为纯增量包装（旧函数保留为 Tool 内部实现），风险最低、回滚最简单，能立即把「无 Tool 体系」这一最高优先级缺口补上，并为 P3/P5/P7/P8 解锁依赖。
