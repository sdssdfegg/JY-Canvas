## 2. 目标与交付标准

1. **真实写入入口**：在换装成功出口写一条版本记录（`task_id` = `tryonTaskId`、`status = succeeded`、`parent_version_id = null`、`result_asset_ref` = 固化后资产引用、`user_instruction` / `model_and_versions` / `execution_params` / `created_at` 等按 contract-v1）。失败出口是否写 `failed` 记录，由执行方取证后**二选一并写进契约与交付回填**，避免出现「只有成功才有历史」的隐性缺口。
2. **资产固化结论**：给出结果图脱离 TTL 缓存的可执行方案（例如 `app-paths.js` 新增独立版本资产目录 + `storage-usage.js:23-29` 白名单钉桩），并附**运行前后真实 `data/` 内容 sha256 逐字一致**断言；未给结论不得宣称「保留原图」。
3. **只读 API**：新增 `GET` 薄封装（参照 `server/routes/garment-profile.routes.js`），**不提供 DELETE / 覆盖 / 写接口**；前端一律经 `src/api/**`，禁止裸 `fetch`。
4. **最小前端展示**：在现有结果队列内联区展示「当前编辑对象 + 版本列表（版本序号 / 状态 / 创建时间）」，纯只读；不改 dock 布局、不改既有中文文案、不新增 `<Modal>`、不新增持久化键。
5. **门禁配套**：新增 verify 脚本必须同时登记 `scripts/verify/run-all.mjs` 的 `ORDER`（`:39-235`）与 `FAST_ORDER`（`:246-343`），否则 `run-all-check.mjs:130-132` 判红；前端新增文件按 §4 正当刷新基线并留前后值。
6. **可回滚**：纯新增调用点 + 新文件，任何既有响应体字段 / 参数语义不改；出问题可只回退本单提交，不影响 V170 数据层与生成链路。
