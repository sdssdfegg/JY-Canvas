### 1.2 统筹裁定（专业判断，写进单留档，可事后推翻）

1. **第三刀只做 `#f2bc74` 单值族（4 处 → 1 个令牌）**，不做「所有暖色」。理由：① 4 处同值、同一组件语义（视频计费角标），替换后逐字恒等、理论零视觉变化，可独立验收与回滚；② 其余 3 个暖色值各 1 处且伴生 `rgba()`，硬凑成 4 个令牌会把「半收敛」放大成 4 处新的语义债；③ V181 / V182 已确立「按单值色族切片」节奏，本单延续。
2. **新增 `--warm-ink: #f2bc74` 四主题各显式一行**（parity 22→23 键）。四主题同值是**刻意设计**：现状四主题本来就都是硬编码 `#f2bc74`，同值令牌 ⇒ 计算值逐字恒等，不做主题差异化的新配色（那是 T1-b2 主段的事）。
3. **2 处 `color-mix(in srgb, var(--warm-ink) N%, var(--panel-strong/border))` 是双 `var()` 混色**，与 V182 已真机通过的第二参数 `var(--border)` 同款、比 V181 的 `transparent` 略复杂 ⇒ 保留 **4 主题 A/B + Owner 目视**闸门，不因「理论零变化」而免测。
4. **Owner 同周期自主变更（新增 YS 满血版渠道 + HK 反代专属前缀）不进本单、不代提交、不代归档为执行单**。理由：统筹只规划 / 复核 / 出单，不碰 Owner 工作树代码；这些改动无对应执行单、无施工提交哈希，硬写成「已归档执行单」会伪造交付记录。处置 = 在 V182 归档件新增 **§8.2** 如实留痕（已完成、真机通过、**未提交**），并在 README 末尾状态段 / `NEXT.md` 顶部 / 本单抬头登记 6 项禁碰清单。若 Owner 要正式纳入执行单体系，另派补单（不与本单并行）。
5. **当前 `run-all --fast 55/56` 的已知红灯不许由 V183 消化**：`size-ratchet` 唯一回归来自 Owner 的 `src/shared/routing.js +3`。执行方不得 `--update --reason` 刷 `size-ratchet-baseline.json`（那等于替 Owner 给未提交改动背书、并把基线改动夹带进 V183 提交），也不得改 `routing.js`。由 Owner 提交其自主改动时自行带 `--update --reason` 处理。
6. **序列**：V183 → 第四刀深色底族 `#061515` 等 → 收尾单 → T2 → T3 → T4 → T5-b → T6 / T7，严格串行。T1-b2 主段继续挂起。
