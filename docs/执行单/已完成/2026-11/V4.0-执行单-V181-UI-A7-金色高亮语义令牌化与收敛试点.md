### 1.2 统筹裁定（专业判断，写进单留档，可事后推翻）

1. **T1-b3 主段必须按色族切片，不许一单吞 162 处**。理由：① `#fbbf24` 与现有 `--warn` / `--success` 值不同，直接替换会改变可见配色，混在 100+ 处替换里出问题无法定位、无法独立回滚；② `color-mix()` 里大量 `#ffffff` / `#000000` 是混色基色，替换成 `var()` 会改变计算值且浏览器对 `color-mix` 内 `var()` 的解析有差异；③ 纯白底是 Owner 明确要求，不能令牌化。按「每单独立验收与回滚」，先做语义最内聚、风险最低的一刀。
2. **第一刀选 `#fbbf24` 金色族（39 处）**，因为它跨 4 文件重复度最高、注释里语义最明确、且**四主题同值替换 ⇒ 理论零视觉变化**，可用静态断言 + 门禁验收；同时 `outfit-intent.css` 收敛后正好归零，把 V180 刚修好的死锁放进真实仓库跑一遍（V180 自测只在 mkdtemp 里跑过）。
3. **新增 `--gold: #fbbf24`，四套主题块各一行、同值**，刻意跨主题固定（该色是「当前渠道 / 选中态」标识，不随主题变）。同值却写四遍是 V178 parity 护栏的刚性要求，须在 `tokens.css` 注释里写明理由，避免后人误删。
4. **注释里的 3 处历史 hex 保留**，不得替换、不得删除。它们是决策留痕（尤其 `styles.css:1523` 解释为何改用绿色），且门禁本就把它们计入基线；本单不追求「所有文件归零」，只有 `outfit-intent.css` 自然归零。
5. **本单不设「严禁把任何文件 hex 收敛到 0」的旧禁令** —— 该禁令是 V180 修死锁**之前**的临时口径，V180 收口后已作废（V180 归档件 §9 与规划稿 §8 均已写明「可以合法把某文件收敛到 0」）。本轮同步作废 `NEXT.md` 顶部、V180 §8.1、README 末尾状态段、规划稿 §8 末行的旧禁令，避免口径互斥。
6. **最终闸门设 4 主题 A/B + Owner 目视**：虽然同值替换理论零视觉变化，但 `color-mix(in srgb, var(--gold) 65%, transparent)` 是本仓首次在混色函数里用 CSS 变量，全仓无自动化配色护栏（探针只量高度 / 视口），必须用目视兜底。
7. **严格串行边界**：本单在跑期间不预建 T1-b3 后续色族单、T1-b2 主段、T2 等任何单据；`进行中/` 只保持这一张。
