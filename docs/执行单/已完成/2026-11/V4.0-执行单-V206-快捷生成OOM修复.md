## 1. 缺陷与根因（统筹已实证，不必重查）

Owner 2026-11-11 17:55 实机反馈：切换到「快捷生成」时浏览器显示「内存不足，无法打开此网页 / Out of Memory」。

| 证据 | 实测值 |
|---|---|
| `loadHistoryResults()`（`storage-store.js:164`）读取分支 | 从服务端 `/api/history` 拉全量 **93 条**，无条数上限（`slice(0,120)` 只在 `saveHistoryResults` 的 fallback 分支） |
| 切 quickgen 后 DOM `<img>` | **245 个**，切前切后同值（默认视图即快捷生成）；`imgsWithRealSrc=245` ⇒ 离屏 1x1 占位未生效 |
| `loading="lazy"` | 244 个，**被主动预加载绕过** |
| `data/history-images/` | 172 文件 / **534 MB**，单张最大 9.5 MB，最大 5334×7997，平均 399 万像素 |
| 解码内存 | 单张 4 字节位图约 **15 MB**，93 张理论峰值 **≈1.4 GB**（未计参考图托盘） |
| JS 堆 | 探针读得 30 MB —— 解码位图不计入 JS heap，勿据此误判「不是内存问题」 |

根因链：`loadHistoryResults()` 全量回载 → `main-canvas-board.jsx:163` 全量 `map` 无虚拟化 → 每个 `CachedImage` 的 `[src]` effect 无条件 `preloadDisplayImageUrl()`（`new Image()` + `decode()`）→ 93 张高分辨率原图近同时解码 → 标签页 OOM。

**不是本轮 V205 / 阶段 5 引入**：最近 15 个 commit 未触碰 quickgen / 画廊 / `CachedImage`（最后相关为 V183–V196 统一视觉），属历史数据累积到临界点。统筹独立探针在干净环境未崩，但机制缺陷确凿。
