## 1. 需求与裁定

### 1.1 🔴 先对齐口径：这个「剪裁」到底裁的是什么

**UI 上的准确文案是「裁剪」不是「剪裁」**，位于精修页设置区「正反」同一行（`src/features/outfit/panels/RetouchIntentPanel.jsx:85`），state 名 `splitHalves`，持久化键 `jingyin-white-refine-split-halves-v1`（`src/shared/image-split.js:12`）。

**它从来不裁页面上的结果预览图**。现有实现（V78 起刻意设计）：生成成功 + 自动保存成功之后，用本地 canvas 把结果图**竖切中线**，额外另存 `xxx-左.png` / `xxx-右.png` 两张到**保存目录根目录**；`task.result` / `displayImage` 保持整张不变，页面结果卡与预览永远显示整张。依据：`src/features/outfit/handlers/outfit-batch-execution.js:576-609,610-615`、`src/features/outfit/handlers/outfit-save-handlers.js:67-91`、`src/shared/image-split.js:89-129`、`docs/执行单/已完成/2026-10/V4.0-执行单-V78-UI规范-精修正反裁剪比例三联联动.md:28,74,119`。

⇒ **用户说「开启了没有剪裁」必须先分清三种可能，否则一定修错对象**：

| 可能 | 判定方法 | 性质 |
|---|---|---|
| **P1 可见性**：两张 PNG 其实已落盘，但页面预览整张、又无明显提示 ⇒ 用户以为没裁 | 查保存目录根有无 `*-左.png` / `*-右.png` | 实现语义与预期不符，**非代码失效** |
| **P2 门控 / 条件不满足**：两张确实没生成 | `frontback` 未开、`task.workflowMode !== "white-refine"`、静默失败 | **真失效** |
| **P3 用户期望就是「页面结果图被裁成两张」** | 需 Owner 一句话裁决 | 产品口径变更，触及 P0 结果展示 |
