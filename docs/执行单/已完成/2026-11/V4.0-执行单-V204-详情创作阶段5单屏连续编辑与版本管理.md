## 1. 目标与交付（总任务书 §十一）

图片生成完成后，用户需要对**每一屏独立编辑**。必须支持：

1. 单屏重新生成。
2. 修改单屏文案和画面要求。
3. 单屏**连续对话式修改**（多轮，每轮基于上一版结果继续改）。
4. 根据上一版结果继续修改（不是每次从头生成）。
5. 保存每次生成的**历史版本**。
6. 查看不同版本（图 + 当时的提示词 + 修改说明）。
7. 切换历史版本。
8. 保留用户选定的**当前版本**。
9. 修改某一屏时**不影响其他屏幕**。

🔴 **最重要的一条隔离约束**：用户只修改第 5 屏，就**只重新生成第 5 屏**；不得因此重新执行整套详情页策划（V202 B1/B2/B3 不重跑），也不得自动重生成其他屏幕。

**可选路径（须明确边界）**：若用户**主动明确提出**要调整整套视觉方向，可以提示「可能影响哪些屏」，由用户确认后再批量调整；此路径默认关闭、必须展示受影响屏清单 + 用户显式确认，且不得与单屏编辑共用同一条自动流程。

## 2. 数据结构（版本管理核心）

- **`screenVersions[]`**：每屏一条版本链，字段至少含 `versionId` / `screenIndex` / `imagePath` / `prompt`（该版实际发送、已冻结的提示词）/ `sourceTaskId`（关联 V203 任务）/ `parentVersionId` / `editNote`（本轮用户指令）/ `editThreadRef`（关联本轮对话轮次）/ `generationContext`（**该版生成上下文最小快照**：`referenceRoles[]` + `model` / `channelId` / `imageSize` / `aspectRatio`）/ `createdAt` / `isCurrent`。
  > 🔧 **架构复核补充（Owner 2026-11-11 第 3 点）**：`generationContext` 保证每个版本可独立追溯当时的参考图与关键生成参数，不依赖 `sourceTaskId` 指向的任务记录是否还在；字段只做快照、不复制任务状态逻辑，**不是第二套任务体系**。若实现时确认任务记录永不被清理，可改为只存 `sourceTaskId` + 从任务记录取值，但必须在 §9 说明取舍并保证追溯到全部五项。
- **`currentVersionId`**：每屏一个，用户选定；切换版本只改这个指针，**不删历史版本、不覆盖图片文件**。
- **`editThread[]`**：连续对话轮次，每轮字段：
  | 字段 | 含义 | 本期是否使用 |
  |---|---|---|
  | `userInstruction` | 用户本轮原始修改意图，**永久只读**，任何 AI 不得覆盖 | ✅ 必填 |
  | `agentSuggestion` | 可选，后续 Agent / SKILL 产出的**建议**（`{ kind, patch, diff, reason }`）；`kind ∈ copy / visual / composition / prompt`，对应文案优化 / 画面调整 / 构图调整 / Prompt 修改建议 | ⏳ 本期恒为 `null`，仅留结构化位 |
  | `adoption` | 用户对该建议的处置：`pending / adopted / rejected / manual`（`manual` = 用户自己改、无 AI 建议） | ✅ 本期恒为 `manual` 或 `adopted`（用户直接改） |
  | `appliedPatch` | **实际采纳并生效**的修改内容（结构化补丁），与 `agentSuggestion` 严格分离 | ✅ |
  | `diff` | 上一版 → 本版的具体差异，可看可核对 | ✅ |
  | `resultVersionId` / `createdAt` | 本轮产出的版本与时间戳 | ✅ |

  🔴 **用户原始意图、AI 建议、实际采纳三者必须可区分**（Owner 第 2 点）：不得用 `agentSuggestion` 直接覆盖 `userInstruction`，也不得把「建议」当成「已采纳」落库；采纳动作必须由用户显式触发后才写 `appliedPatch` 与 `adoption=adopted`。同模式 B 的 `rawIntent` / `assistPatch` / `diff` 口径。
- **落盘**：`data/detail-studio/versions/`（版本元数据 + 版本图片独立目录），**不进** `data/results`（7 天 TTL）、不进 `seed/manifest.json`、不进安装包默认种子。
- **项目存储**：`server/features/detail-studio/store/project-store.js` 受控合并新增 `versions` 字段；`schemaVersion` 迁移要兼容 v2 旧项目、`migrateProject()` 在 `get` 与 `list` 两个读取路径生效，且**读操作不得产生写盘副作用**；`mode` / `id` / `createdAt` / `schemaVersion` 一律不可变（三种模式硬隔离）。

🔴 **与 V203 任务层的接口（本单最易踩的坑）**：单屏重生成复用 `generation` 的任务机制，但 **`idempotencyKey` 必须绑定 `versionId`（或等价的版本序号）**。V203 现用 `sha256(projectId | screenIndex | frozenPrompt)`：若单屏编辑后新提示词不同尚可，但「重新生成同一提示词」或重试会命中旧账本直接复用已有任务，导致**新版本拿不到图 / 历史版本被覆盖**。必须扩成 `sha256(projectId | screenIndex | versionId | frozenPrompt)`（或同等的版本维度），并给负向对照断言：同一屏连续生成两次应产生**两个独立任务、两个独立版本、两张独立图片**。
