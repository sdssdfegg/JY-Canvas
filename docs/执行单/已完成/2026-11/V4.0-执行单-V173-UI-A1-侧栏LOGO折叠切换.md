## 2. 目标与交付标准

### 2.1 交互

1. **LOGO 可点**：`.brand` 里的 LOGO 成为可聚焦、可键盘触发（Enter/Space）的开关，带 `aria-expanded` 与 `aria-label` 随状态切换，`focus-visible` 有可见轮廓。
2. **展开态 = 现状布局逐字不变**（形状/底色按 §2.3 微调）：166px、LOGO + 品牌文字（标题 / 标语 / 联系方式行）、图标+文字导航、设置入口。
3. **收起态**（仅折叠时生效）：宽度 56px；LOGO 变正圆；品牌文字容器隐藏；每项只留图标并居中；`.subNavItem` 的左缩进归零；当前项为 `var(--accent)` **实心块 + `var(--accent-on)` 图标/文字**；底部设置保留图标。
4. **文字不能简单 `display:none` 了事**：折叠态须保留可访问名称（推荐 clip 视觉隐藏技法，`<span>` 仍在 DOM 与可访问树），并有 hover 提示或等价可辨识手段；纯图标导航不可变成"认不出的图标"。
5. **主区不受伤**：`minmax(0,1fr)` 自动变宽；结果卡不重排变形、底部 dock 与生成按钮恒可见、页面不重挂载、滚动归属不变。
6. **≤760px 禁用折叠**：现有断点已把侧栏改为横向导航（§7），窄屏下必须强制展开态、折叠开关不生效。
7. **动效**：仅 `width` / `opacity` 过渡、160ms，遵守 `prefers-reduced-motion`；不新增遮罩 / 渲染层 / 动画帧（产品原则第 7 条）。
8. **可回滚**：纯 `class` + CSS + 1 个会话内 state，零数据写入、零持久化键、零 API 变更；`git revert` 本单提交即回到发布日状态。

### 2.3 🔴 LOGO 形状与底色（Owner 2026-11-06 15:27 / 15:28 追加口径，逐字执行）

> Owner 原话：「展开的时候 LOGO 是方形的，隐藏后变成圆形，LOGO 图案底色就纯白色」「方块不要直角，要带一点点弧度」。

| 状态 | 形状 | 圆角 | 底色 |
|---|---|---|---|
| **展开（166px）** | 方形 | **带一点点弧度，不要直角** —— 用现有 `.avatar` 的 `border-radius: 8px`（30×30px），**此值已符合口径，不要改成 0，也不要加大到接近圆** | **纯白** |
| **收起（56px）** | 正圆 | `border-radius: 50%` | **纯白**（与展开态一致，不换色） |

- **底色口径**：LOGO 图案**底色纯白**，不是半透明白、不是渐变、不是青绿环、不是浅灰。现状 `.avatar` 是 `rgba(255, 255, 255, 0.72)`（**半透明**，见 §7），须提到**不透明纯白**。
- 🔴 **禁止写 hex**：`hardcoded-color` 门禁对「新建含 hex 的 CSS」判红 ⇒ 纯白**不得**写 `#fff` / `#ffffff`，用 `rgb(255 255 255)` 或把现有 `rgba(255, 255, 255, 0.72)` 的 alpha 改为 `1`；更优做法是在 `tokens.css` 复用/新增一个语义令牌（但会扩大 §3.1 封闭集合，须回报统筹）。
- **形状过渡**：`border-radius: 8px → 50%` 允许随折叠一起做 160ms 过渡（只动 `border-radius` / `width` / `opacity`，不引入新动画层）；`prefers-reduced-motion` 下直接切换。
- **素材边界**：`/app-avatar.webp` 是 LOGO 图案本身，本单**不替换、不改动素材**；若该 webp 自带非白底导致「纯白底」无法实现，执行方须**先回报统筹**再决定是否另立素材单，禁止自行改图。
- 统筹侧 HTML 演示与主方案 §5.3.1 已按此口径同步（展开圆角方块 / 收起正圆 / 两态纯白底）。
