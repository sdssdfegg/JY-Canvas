## 2. 目标与交付标准

**目标**：在 `server/ai-tryon/` 新增服装档案存储层，实现契约 `garment-profile.md` §1 字段集的本地持久化，满足「档案修改生成新版本、既有任务永远引用创建时快照、旧版本只增不改不删」。

**交付标准（可验收）**：
1. 能创建 / 查询 / 改版服装档案；每次改版写 `profile-v<n>.json`，`version` 整数递增，**旧版本文件内容逐字不变**。
2. `index.json` 记录每个档案的最新版本与摘要，单写入器串行化 + 临时文件 rename 原子替换；索引缺失/损坏可重建。
3. 标准参考图可落 `assets/<asset_id>.<ext>`，扩展名按 mimeType 判定、重名不覆盖（`flag:"wx"` 或等价唯一命名）。
4. `approved_baseline_asset_id` 只能由显式调用设置，**禁止用生成结果静默覆盖**。
5. 零依赖叶子：新模块只 import Node 内置 + `server/core/app-paths.js`。
6. 刷新/重启后已持久化档案仍可读（文件即真相源，不依赖内存）。
7. 验收脚本在临时沙盒跑完全部断言，**真实 `data/ai-tryon/garments/` 未被创建或改动**。

**明确非目标**：不产生任何用户可见 UI 变化、不改任何现有接口返回、不改生成结果、不改提示词、不新增网络端点。

### 4.3 并发与原子性

- **单写入器**：照 `task-store.js:42-59` 的 `withChain(map,key,fn)` Promise 链（每档案一链 + 索引一链，`settled.finally` 清理防 Map 膨胀，单个失败不阻断后续写）。

## 6. 验收脚本规格（`scripts/verify/garment-profile-check.mjs`）

照 `tryon-execution-check.mjs:1-55,138-145` 结构：

1. **在任何服务端模块 import 之前**：`const sandboxRoot = mkdtempSync(path.join(tmpdir(), "garment-profile-check-")); process.env.JINGYIN_RELEASE_ROOT = sandboxRoot;`（`app-paths.js` 在 import 期固化 `rootDir`，设晚了会写到真实 `data/`）。

3. 必须覆盖的断言：
   - 创建 → 查询（默认最新 / 指定 version）字段完整、`version=1`、`status=draft`、时间戳存在；
   - 改版 → `version=2`、旧 `profile-v1.json` **逐字不变**（内容哈希比对）；
   - 并发：同一档案连续 N 次改版后版本号严格递增无丢失、索引与磁盘一致；
   - 索引缺失/损坏 → 可重建且摘要正确；主文件损坏 → `.bak` 回退；
   - 资产落盘：mimeType→扩展名正确、重名不覆盖、路径穿越输入被拒；
   - `setApprovedBaseline` 显式生效；**模拟「用生成结果覆盖基准」路径应被拒绝或不存在**（红线 1）；
   - 静态钉桩：仿 `tryon-recovery-check.mjs:173-183`，校验新模块 import 白名单只含 Node 内置 + `app-paths.js`（红线 3）；
   - 静态钉桩：新目录不出现在 `STORAGE_TARGETS` / 清理白名单（红线 2）；
   - 静态钉桩：`server/index.js` / `server/app.js` / `server/routes/**` 未 import 新模块（§3.2 边界）。
4. 失败时 `process.exit(1)` 并打印可读清单；不得吞异常。
