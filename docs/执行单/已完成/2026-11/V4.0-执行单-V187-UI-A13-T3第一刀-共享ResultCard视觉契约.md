### 1.2 统筹裁定（专业判断，写进单留档，可事后推翻）

1. **T3 拆成三刀，本单只做第一刀**。规划 T3 把「ResultCard + 选择器 + 生成按钮」并成一块，但发布日取证显示：① 两套卡片是**业务语义不同的 React.memo 组件**（§1.1 #3），强行合成一个 `ResultCard` 会动 24+ props 与换装专属状态逻辑，风险远超收益；② 生成按钮已统一走 `<Button lg primary>`（§1.1 #9），只剩 2 条 CSS 覆盖待评估；③ 选择器牵涉 10+ 处原生 `<select>` 与 `ChannelPicker` 共存，需独立决策。⇒ **V187 = 结果卡片「视觉外壳」统一（可见、可控、可独立回滚）**；T3-b 选择器、T3-c 生成按钮后续按序，不预建不占槽位。
2. **只统一「视觉外壳」，不合并业务组件**：把 11 项重复外壳声明上收到 `src/shared/ui/ui.css` 的 `.ui-result-card*` 契约类，两套 feature 组件**仅在 `<article>` 上叠加该类名**；JSX 结构、props、事件、状态逻辑、子组件调用参数**逐字不动**。这样既有可见变化，又保住 V5.0-001/002/006 的 P0 验收成果。
3. **底色归顺主应用真相源**：换装侧 `var(--panel-strong-bg)` → `var(--panel)`（V69「合并以主应用令牌为准，换装归顺」）。🔴 **这是本单唯一肉眼可辨的预期视觉变化**，四主题下换装结果卡底色会变；别名 `--panel-strong-bg` 本身保留（其余 9 处引用不动），只改卡片这一处引用。
4. **零新增文件、零新增 / 删除 hex、零基线刷新**：新增文件会撞 `frontend-duplication` 硬断言（§1.1 #7），新增带回退值的 `var()` 会撞颜色棘轮（§1.1 #8），两者都会在当前 56/57 阻塞态下额外制造「刷基线」需求。⇒ 本单封闭集合**只改既有文件**，公共规则只用 `var(--token)` 无回退值，**216 / 8 文件 / `fileCount=154` / `baseKeys=23` 全部逐字不变**，`scripts/verify/**` 零改动。
5. **层叠特异性是最大技术风险**：`.outfitWorkflowEmbedded .assetCard`（0,2,0）高于 `.ui-result-card`（0,1,0）。执行方须先实测量测确认共享类生效；若被覆盖，**优先把换装侧重复声明删到只剩差异项**（而非提权共享类或新增 `!important`），并在 §8 记录实测选择器与计算值。🔴 严禁靠 `:where()` 改其它既有规则、严禁新增 `!important`。
6. **最终闸门 = 4 主题 A/B + Owner 目视 + 门禁 + 统筹只读复核**：本单有真实可见变化，比 V185/V186 严格；必须含「切到别的主题再切回来」、卡片底色 / 圆角 / 边框 / hover 量测。Owner 若不接受底色变化，按 §3.3 独立回滚（只撤 1 处引用）。
7. **不做的事**：不新增 / 删除任何文件、不合并两个业务组件、不动 `Select` / `Tag` / 生成按钮 / `ChannelPicker`、不动 V69 别名块（134 处）、不动令牌值与主题数量、不收敛任何 hex、不动 `server/**` / 用户态 / 模型渠道 / 打包二进制、不刷任何基线、不跳钩子、不代提交 Owner 代码。
8. **门禁阻塞如实继承**：本单同样可能因 `pre-commit` 被 `routing.js` 回归拦下而**无法提交**；执行方仍须完成全部交付、自检、`git mv` 归档与台账回填，并在 §8 如实写「未提交（阻塞）」，**不得跳过交付或自行刷基线**。统筹不跳钩子、不代提交 Owner 代码。
9. **序列**：V187（本单）→ **T3-b → T3-c → T4（Workspace Frame）→ T5-b（折叠持久化）→ T6 / T7**；T1-b2 主段继续挂起，Owner 点头后作为插队单插入。
