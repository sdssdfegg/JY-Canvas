## 5. 实现要求

### 5.1 自建 Skill 真实注入且可断言（条件注入）

- `skillModuleV2` 必须在 **V2 启用时**真实进入 `textPayload.skillPack`（`detail-ai.js:146`），从而经 `:199` `JSON.stringify(textPayload, null, 2)` 进入 `body.messages[1].content[0].text`。只 import、只放在目录里、只加载成功 **不算完成**。
- **V2 未启用（前端未传 V2 开关 / 空选）时，模型请求体与 S0 基线逐字节一致**：字段「不存在」而非空数组，沿用 V214 的条件展开策略；`text` 数组 `.filter(Boolean)` 保持。
- Skill 内容必须包含：商品事实保护（不得虚构材质 / 参数 / 认证 / 疗效 / 销量 / 品牌背书）、首屏 `hero` 默认、板块是偏好不是固定模板、不机械凑屏。
- 必须能给出**请求体片段断言**（哪个变量 / 哪一行），并可做注入 vs 不注入的 A/B 对照；不得只验 JSON 结构合法或模块可 import（v1.1 §8.6）。

### 5.2 空板块 AI 自主规划（S0 §2.1 四处改动，全在 `detail-middleware.js`）

| # | 落点 | 要求 |
|---|---|---|
| 1 | `:485-487` `screenTitles` | 去掉 `fallbackWithSections` 三级回退；AI 有屏时标题由 `aiPlan` 的 `screenRoles/title` 驱动；首屏强制 `hero` 角色但**不写死标题文字** |
| 2 | `:127-131` `normalizeAiScreens` | 缺屏不再补 `{}`，改补「由 AI 规划派生的最小占位」；**保留 `count` 屏，不引入新屏数** |
| 3 | `:311-332` `buildScreenTitles` | 函数**保留但降级**为「仅旧路径 / 未启用 V2 时」使用；V2 启用后不再作为标题来源。不删函数（保证老前端逐字节一致） |

- `getScreenModule`（`prompts/server/detail-skills.js:415-424`）在 **G-2 禁改词表内**，不得从源头改，只能在 `moduleSkill` 优先级绕开。
- **只改屏序 / 内容任务 / 标题来源；`:546-568` 的 17 槽位文本格式保留不动**（这是「展示=生图」与旧版兼容的基础）。

### 5.3 `planning` 平级返回与数据边界

- `detail.routes.js:111` 响应改为 `{ ok: true, group, planning }`（或等价写法），**`planning` 不得挂进 `group`**。
- 理由（S0 §2.4 / §5.3）：`group` 会被前端 `detail-state.js:210-212` → `detail-group.js:313-323` 全量写入 `DETAIL_GROUPS_KEY`；挂进去会污染预设 / 分组 / 历史数据，并可能随发布种子扩散。
- S1-b **不改前端**，`sanitizeDetailGroupsForStorage` / `normalizeDetailSettings` 白名单护栏属 **S1-c**，本单不实现、不得顺手做。
- 禁止 import B 域 `server/features/detail-studio/planning/director-visual.js:117` 的同名 `planningContext` 变量。

### 5.4 门禁锚点维护约定（🔴 必读，否则会被门禁挡住）
