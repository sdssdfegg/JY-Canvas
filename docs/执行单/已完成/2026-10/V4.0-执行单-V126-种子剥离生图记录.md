# V4.0-执行单-V126-种子剥离生图记录（红线②收紧）

> 派发日期：2026-10-22 ｜ 派发依据：用户 2026-10-22 诉求（原话纪要）：
> "需要合并归档，最好是不要留生图记录，不然客户感觉这个软件也太业余了把"
> 本单目标：封装种子（`seed/manifest.json`）**零生图记录**——上传图/生成图文件名、图片槽位、文件记录一律不随包；出口、服务端写入、构建校验、静态门禁四处同口径锁死；清理仓库现有 manifest。

---

## 0. 现状取证（2026-10-22 实测）

- V123 一键同步机制已生效（`secure-win-release.mjs:121-126` 默认读仓库 `seed/manifest.json`），但该文件处于**未跟踪状态**（同日已由统筹提交保护，commit `cfb45b9`）。
- 深扫实测（node 脚本逐 entry 遍历）：**`detail-groups` entry（81KB）含 115 处图片文件名**，初判路径三处：
  - `params.productImageNames` / `params.referenceImageNames`（文件名字符串数组）；
  - `prompts[].imageSlots[].name`（槽位名，如 `3 (1).jpg`）；
  - `productFiles` / `referenceFiles`（组级，当前为 `[]`，但字段在，旧数据可能非空）。
- **深挖后发现更严重层**（本单范围据此扩大）：
  - `prompts[].results[*]` 持**真生成结果**：`image.value`/`image.localUrl`（`/api/history-image/...`）、`image.archiveFile`（`<uuid>_1.png`）、`references[*].name/archiveFile/localUrl`；
  - `analysis.imageFacts[*]` 持上传图事实（文件名 + mime + 尺寸）；
  - `prompts[].text` **正文嵌入图片文件名**（键级剥不净，不能对用户正文做字符串手术——误杀风险）。
- `outfit-pages`（白名单 6 字段）干净：0 命中；`outfit-settings`/`resize-settings` 为纯配置；`detail-presets` 为 `{id,name,createdAt,settings}` 纯配置预设（保留随包）；无 blob:/data:image URL 于非 detail-groups 区。
- `rounds` 为纯文本（skill 规则 stage/title/content）。
- 根因：`detail-groups` 走**原样导出**（`release-seed.js:136-149`），只过了全出口 `stripCredentials`（红线①），没有红线②关口；且该 entry 本质是**生图工作区状态**，不是模板/页面状态。

## 1. 改动要求

### 1.1 schema 新增「生图记录键」深剥 + 扫描（单一真相源）

`src/shared/release-seed-schema.js`（纯模块，Node/浏览器/构建三侧共用，严禁另写一份）：

- 新增导出 `IMAGE_RECORD_KEYS`（结构性键名，任何深度出现即剥/即拒）：
  - outfit 域：`modelImages`/`clothingImages`/`referenceImages`/`originalLibrary`/`fixedClothingId`/`tasks`（与 `OUTFIT_PAGE_FORBIDDEN_FIELDS` 同源）；
  - 详情域：`productFiles`/`referenceFiles`/`productImageNames`/`referenceImageNames`/`imageSlots`；
  - 通用：`taskHistory`。
- 新增 `stripImageRecords(value)`：递归剥键（与 `stripCredentials` 同形态）；新增 `containsImageRecords(value)`：递归扫描（供构建期/服务端拒收判定）。
- 不按文件名字符串做判定（用户提示词正文出现 "image.png" 会误杀）——**只认结构键**。

### 1.2 浏览器出口最终关口（`src/shared/release-seed.js`）

- `buildReleaseSeed()` 最终清洗由 `stripCredentials(v)` 改为 `stripImageRecords(stripCredentials(v))`（红线①②双关口，注释同步更新）。
- 下载导出（`downloadReleaseSeed`）与同步（`syncReleaseSeed`）同路径受益。

### 1.3 服务端写入复核（`server/routes/seed.routes.js`）

- POST `/api/seed-sync` 新增红线②拒收：`containsImageRecords(manifest) === true` → 400（与红线①拒收并列）。
- `sanitizeManifestEntries`：默认分支 `stripImageRecords(value)`；`outfit-settings` 分支 `stripImageRecords(stripCredentials(value))`（双关）。
- 规范 sanitize 管线（服务端/校验/清理脚本三处同口径）：
  `outfit-pages`→sanitizeOutfitPage 映射；presets→sanitizePromptPreset 映射；`outfit-settings`→stripImageRecords∘stripCredentials；其余→stripImageRecords。

### 1.4 构建期硬失败（`scripts/secure-win-release.mjs`）

- 逐 entry 校验区新增：`containsImageRecords(value)` → throw（种子含生图记录字段，违反红线②，禁止随包）。

### 1.5 静态门禁（`scripts/verify/release-seed-sync-check.mjs`）

- (d) 段新增断言：仓库 manifest `containsImageRecords === false`。
- (d) 的 sanitize 逐字一致管线同步加 `stripImageRecords`（与新出口/服务端同口径），清理后的文件必须过「逐字一致 + seedId 重算一致」。

### 1.6 detail-groups 移出种子范围 + 清理仓库现有 manifest

- **决策（统筹裁决，凭据见 §0 深挖层）**：`detail-groups` entry 从种子范围**整体移除**——
  它是生图工作区状态（生成结果 URL/archiveFile、上传图事实、正文嵌文件名），键级剥不净；
  随包即向客户分发开发者的生成历史（红线② + 用户原话「客户感觉业余」）。
  - `SEED_ENTRY_IDS` 移除 `detail-groups`（构建/服务端/校验三处拒收，附友好报错说明 V126）；
  - `buildReleaseSeed()` 不再收集该 entry；`SEED_TARGET_KEYS` 同步移除（导入侧未知 id 自然跳过）；
  - 客户详情页从空白自建项目；`detail-presets`（纯配置）仍随包。
- 其余 entry 按 1.3 规范管线清理仓库 `seed/manifest.json`：剥图片记录键，保留页面结构/提示词/配置；
  `seedId` 按 `fnv1a32Hex(JSON.stringify(sanitized))` 重算；`syncedAt` 取当前时间；
  落盘形态与服务端写入完全同构（`{version:1, seedId, syncedAt, entries:[{id,value}]}`，`JSON.stringify(..., null, 2)`）。
- 该文件已在 git（`cfb45b9`），本次为内容修订提交。
