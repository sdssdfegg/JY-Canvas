## 2. 阶段 A —— 下沉计时

文件：`src/outfit-workflow.jsx`，三处改动，**别的一行不动**：

1. **删** `:479`：`const [clockNow, setClockNow] = useState(Date.now());`
2. **删** `:1003-1008` 整个 effect：

```js
  useEffect(() => {
    if (!running && !hasPendingTasks) return undefined;
    setClockNow(Date.now());
    const timer = window.setInterval(() => setClockNow(Date.now()), 500);
    return () => window.clearInterval(timer);
  }, [running, hasPendingTasks]);
```

3. **改消费点** `:3713`：`const durationMs = taskDurationMs(task, clockNow);` 这一行删掉；在该任务卡片的 JSX 里原先渲染 `durationMs` 的位置，改用组件（import 路径相对本文件是 `./shared/ui/elapsed-timer.jsx`）：

```jsx
<ElapsedTimer startedAt={task.startedAt} />
```

- 先读 `src/shared/ui/elapsed-timer.jsx` 确认 props：只收 `startedAt`，内部自管 500ms tick，`startedAt` 为空时退化为当前时间——与 `taskDurationMs(task, now)` 对运行中任务的语义一致。
- **已完成任务**（`task.status === "success"` / `"failed"`）原本 `taskDurationMs` 返回固定值，不随 clockNow 变——替换前先确认 `taskDurationMs` 对已完成任务确实不依赖 `now`（读它的函数体）。若已完成任务也走 `task.startedAt` 计时，视觉上会变成“永远在走”，**这与本单无关（既有行为）**，不要自行改 `taskDurationMs`，在汇报里如实说明即可。
- import：文件顶部 import 区加 `import { ElapsedTimer } from "./shared/ui/elapsed-timer.jsx";`（按现有 import 排序风格插入）。
- 若删除后 `running` / `hasPendingTasks` 出现 unused 警告——不会，它们还有大量别处引用；万一 eslint 报 unused，**停手回报**，不要顺手删别的代码。

4. **顺手修正单号漂移**：`src/shared/ui/elapsed-timer.jsx` 头注释里的 "V46.1" 表述改为指向本单（如“outfit-workflow 侧的 clockNow 由 V49 收口”），只改注释、不改逻辑。
