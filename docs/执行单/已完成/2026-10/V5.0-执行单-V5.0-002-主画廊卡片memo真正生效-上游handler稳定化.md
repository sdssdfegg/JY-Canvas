## 0. 现状取证（2026-10-23 统筹实测 + 源码走读）

- **V5.0-001 只完成 1.1（抽卡片为 `React.memo` 组件）**：`quick-gallery-card.jsx` 已 `React.memo`，但 §3.1 实测确认 memo 被绕过——上游 15 个 handler（`openPreview`/`openContextMenu`/`handleQuickResultReplaceDragOver`/`handleQuickResultReplaceDrop`/`toggleSelected`/`downloadItem`/`rerunResult`/`deleteResult`/`beginResultImageDrag`/`clearQuickResultDragState`/`markResultImageBroken`/`openReferencePreview`/`openReferenceContextMenu`/`beginReferenceImageDrag`/`copyText`）来自 `main.jsx` 在 `App()` 体内每次 render 调一次的三个**普通工厂**（`createResultActions`/`createResultDownload`/`createQuickResultReplace`）与 `useMainHandlers`，每次都重建闭包 → 每次 `App` 重渲染传给 `QuickGalleryCard` 的 handler 引用都变 → memo 恒不 bail。
- **整包集合也破 memo**：`selectedIds`/`downloadFeedbackIds`/`quickResultReplaceTargetId` 三个集合/标量被**整包**传给每张卡。即便 handler 稳定，单张选中/下载/拖拽高亮也会改其中某个引用 → 46 张卡全重渲染（正是 R2 要消灭的「全树重渲染」）。
- **`quickGalleryItems` 已 memo**：`useQuickGenState` 内 `useMemo([visibleResults, runningQuickTasks])`，常态（非 results/quickTasks 变更）下元素引用稳定 → 是 memo 可生效的前提，已具备。
- **`setQuickResultReplaceTargetId` 是 React state setter**：引用天然稳定，无需处理。

## 1. 改动要求

### 1.1 上游 handler 稳定化（核心，晚期绑定委托）

- **不碰主链路**：不在 `main.jsx` / 三个工厂里加 `useMemo`/`useCallback`（避免改 state 闭包依赖、引入陈旧闭包风险）。
- **在展示件 `MainCanvasBoard` 内做晚期绑定委托**（沿用本仓既有 `handlerLateRef` 同款手法，零陈旧闭包风险）：
  - `const cardHandlersRef = useRef(null);` 每渲染把 15 个最新 handler 灌入 `cardHandlersRef.current`。
  - `const cardHandlers = useMemo(() => ({ ...15 个 (...a)=>cardHandlersRef.current.x(...a) 委托... }), []);` 委托函数仅在首渲染创建一次 → 引用永久稳定；调用时经 ref 转发到最新实现，永远拿到最新闭包（无陈旧值、无依赖管理）。
  - 透传给 `QuickGalleryCard` 的是 `cardHandlers.*`（稳定引用），而非原始 props。

### 1.2 整包集合改每卡派生布尔

- `map` 内对每张「结果卡」计算：`isSelected = selectedIds.has(item.id)`、`isDownloaded = downloadFeedbackIds.has(item.id)`、`isReplaceTarget = quickResultReplaceTargetId === item.id`，作为**布尔基元**透传。
- 单张选中/下载/拖拽高亮时，仅该卡对应布尔翻转 → 其余卡布尔值不变（基元相等）→ memo bail，不再全树重渲染。
- **`brokenResultImages` 保留整包透传**：仅当某图真正加载失败（`markResultImageBroken`）才变更引用，属罕见事件，常态不破 memo；卡片内据此算 `brokenReason`（逻辑零改动）。

### 1.3 QuickGalleryCard props 收敛

- 删除整包 props：`selectedIds` / `downloadFeedbackIds` / `quickResultReplaceTargetId`。
- 新增基元 props：`isSelected` / `isDownloaded` / `isReplaceTarget`。
- 内部：`selected = isSelected`；`downloadFeedbackIds.has(item.id)` → `isDownloaded`（2 处）；`quickResultReplaceTargetId === item.id` → `isReplaceTarget`（className + 1 处）；`setQuickResultReplaceTargetId` 保留（稳定 setter，卡片内 `onDragLeave` 仍用）。

## 5. 风险

- 委托 ref 刷新时机错（渲染期前未灌入）→ 首次调用拿到空：委托在组件体顶部 `cardHandlersRef.current = {...}` 先于 `useMemo` 与 `return` 执行，事件回调均在渲染后触发，安全。
- 漏传/错传某个 handler → 交互失效：实现后 tabbit 探针逐按钮点击验证（P0 兜底）。
- 与 HMR/打包 TDZ 既往坑区分：本单不移动顶层状态声明、不碰启动链路模块，不引入 TDZ 风险。
