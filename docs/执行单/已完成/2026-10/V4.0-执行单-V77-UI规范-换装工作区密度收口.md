## 3. 改动要求

### 3.1 三区面积比例（需求 3，总纲 §5.6 增补条款落地）

- `outfit-workflow.css` `.assetGrid`：`repeat(3, minmax(0,1fr))` → **容量加权比例**：图1 `2fr`、图2 `1fr`、图3 `1fr`（参考图实测约 50/25/25；若派发日参考图重测值不同，以参考图为准并在回报注明）；
- 列数：图1 `--upload-columns` 由 2 → **4**（`OutfitComposer.jsx` 图1 UploadZone 传 `columns` prop 或直接改 `columnCount` 判据——`outfit-panels.jsx:660` 改为按 `maxCount` 分档：≥8 → 4 列、2-7 → 2 列，回报附新旧值）；图2/图3 保持 2 列；
- 三区高度**不锁死**（内容撑起，图1 高图2/图3 矮属预期）；`align-items: start`。

### 3.2 上传钮去除 + 右上角仅清除钮（需求 1）

- `outfit-panels.jsx:845-856`：删除 `<Button>上传</Button>`（846-849）；`uploadHeaderActions` 仅留清除钮（850-855，`items.length > 0` 条件不变）；
- 上传入口保留：空态 `emptyUpload`（925-930，点击/拖入）不动；有图后**新增图片靠拖入 + 单张替换**（`handleReplaceDrop`/`replaceImage` 已有能力，不新增入口）；
- `Upload` 图标 import 若仅此一处使用则删除（回报注明）；input[type=file] 与 `inputRef.click()` 触发链不动（空态仍走它）。

### 3.3 删除"统一处理 + 新上传默认"（需求 2）

- `outfit-panels.jsx:934-953`：删除 `bulkModeControl` label 块（936-947）与 `small` 文案块（949-951）；`footerControls`（948）保留；
- footer 仅剩 `footerControls` 时容器条件改为 `footerControls &&`；**`bulkMode`/`onBulkModeChange` props 与 `applyGroupPreprocess` handler 按 Park 纪律保留不删**（停止传参即可：三处 `bulkMode={...}`/`onBulkModeChange={...}` 从 `OutfitComposer.jsx:141-142/173-174/241-242` 移除，原位置注释 `/* V77（用户要求·停用）：统一处理/新上传默认停用；数据流与 handler 保留，恢复时传回 bulkMode/onBulkModeChange */`）；
- `showBulkControl` 判据若存在则随之恒 false 或删除判据（回报注明处理方式）。

### 3.4 缩略图与操作钮大小（需求 4）

- `.thumbCard`（`outfit-workflow.css` compact 段 `:3663` 起）与 `.thumbActions button`（`:3670` 起）：尺寸/图标按参考图实测（预期 thumbActions 钮 ~20-22px、图标 12-13px；thumbCard 高度以"图1 放 4-10 张不超参考图高度"为上限）；
- 目标可检查：**单区 4 张图时不产生第二行浪费**（图1 4 列 × 1 行放 4 张；回报附实测：1/2/4/10 张各状态的高度与行数）。

### 3.5 删除换装设置不重要文案（需求 5）

- 删除范围：提示词自动主体预填文案中的纯说明性长句（"让服装跟随换装组合、水袖、袖子和领口形状…"类）与 `composerFieldHint` 中与参考图不符的冗余说明；**保留**：所有选项标签（上下装/内衣/鞋/连体、跟随图2穿法/保持下图穿法、"另存为提示词"主操作）、`本次需求/额外补充` 标签、字数统计；
- 派发日与用户确认待删文案清单（参考图红区为标准），回报附删除前后文案对照；**只删文案不改逻辑**。

### 3.6 参数条重构：开关隐藏 + 左对齐 + 生成钮独立右侧（需求 6）

- 常规文本开关（`smartInterventionSwitch` 块）与 AI 质检开关（`qualityCheckSwitch` 块）**停止渲染**（Park：JSX 注释标明停用、state/handler 保留，恢复=去掉注释）；
- `.rightTools`（`:2962`）：`justify-content: flex-end` → `flex-start`（与上方 tab 行左缘对齐）；
- 生成钮（`:503`）：从 rightTools 控件流中**独立右侧**——两种实现二选一（回报注明）：a) 生成钮移出 `.rightTools` 作为 `.composerFooter` 的独立行内右端元素；b) rightTools 内生成钮 `margin-left:auto`。要求：生成钮与最后一个参数控件间距 = `--space-4`（16px），窄窗口不重叠；
- "然后画面"（用户原文未完）：按参考图执行——结果区宽度不压缩、参数条单行优先。

### 3.7 tab 切换跳动修复（需求 7）

- 排查方向（执行者实测归因后修）：① 各工作流 rightTools 控件数不同（换装 9 / 随机背景 10 / 精修 8 …）在窄宽度下换行行数不同；② `.outfitIntentBar--placeholder` 占位态与实态高度不一致；③ `.composerFooter` 单列 grid 下行高叠加；
- 修法（治本）：冻结区总高度**与工作流无关**——控件统一不换行策略（参数条 `flex-wrap: nowrap` + 窄窗口横向滚动 or 控件收纳，二选一回报注明）+ `outfitIntentBar` 占位/实态恒高 + 切换前后 `document.querySelector('.composerStickyControls').offsetHeight` 量测差 = 0；
- 验收量测：窗口宽度 1280/1600/1920 × 每两板块互切，offsetHeight 差全为 0，附量测表。

### 3.8 底部距离与结果区空间（需求 8）

- 以参考图为基准：appShell 底部至参数条底边的距离、冻结区内部 padding/margin（`.composerStickyControls:2621` 的 `margin: 2px -2px -2px; padding: 8px 2px 2px`）微调至参考观感；**禁止**留 >8px 的无意义底部空间；
