## 1. 改动要求

### 1.1 新增 `src/shared/release-seed.js`（种子导入 + 导出，纯 public 模式生效）

**种子文件格式**（单文件 `/seed/manifest.json`，随 SEA 内嵌）：

```json
{
  "version": 1,
  "seedId": "<fnv1a-hex，由 entries 内容算出，更新种子即变>",
  "entries": [
    { "id": "main-prompt-presets",   "sourceKey": "jingyin-internal-prompt-library-v2-20260802", "value": [...] },
    { "id": "main-prompt-categories","sourceKey": "jingyin-internal-prompt-categories-v2-20260802", "value": [...] },
    { "id": "outfit-prompt-presets", "sourceKey": "jingyin-outfit-workflow-prompt-library-v2-20260802", "value": [...] },
    { "id": "outfit-prompt-categories", "...": "..." },
    { "id": "outfit-pages",          "sourceKey": "jingyin-outfit-workflow-pages-v1", "value": [...] },
    { "id": "outfit-deleted-modes",  "sourceKey": "jingyin-outfit-workflow-deleted-modes-v1", "value": [...] },
    { "id": "outfit-settings",       "sourceKey": "jingyin-outfit-workflow-settings-v1", "value": {...} },
    { "id": "resize-settings",       "sourceKey": "jingyin-outfit-workflow-resize-settings-v4", "value": {...} },
    { "id": "resize-batch-crop",     "sourceKey": "jingyin-outfit-workflow-resize-batch-crop-v1", "value": {...} },
    { "id": "detail-presets",        "sourceKey": "jingyin-internal-detail-presets-v1", "value": [...] },
    { "id": "detail-groups",         "sourceKey": "jingyin-internal-detail-groups-v1", "value": [...] },
    { "id": "white-refine-split-halves", "sourceKey": "jingyin-white-refine-split-halves-v1", "value": {...} }
  ]
}
```

- `id` → 运行期目标键的映射表写死在本模块（用各键常量，**不写死字符串**）：main 侧用 `app-defaults.js` 的 `PROMPT_PRESETS_KEY/PROMPT_CATEGORIES_KEY/DETAIL_*`，outfit 侧用 `outfit-top.js` 的 `OUTFIT_PAGES_KEY/OUTFIT_DELETED_WORKFLOW_MODES_KEY/STORAGE_KEY/PROMPT_*`，另 `outfit-panels.jsx` 的 `RESIZE_SETTINGS_KEY/RESIZE_BATCH_CROP_KEY`、`image-split.js` 的 `SPLIT_HALVES_STORAGE_KEY`。`sourceKey` 仅作溯源记录，**不参与导入**（public 前缀不同，靠 id 解析）。
- **`importReleaseSeed()`**（导入侧，客户首跑）：
  1. 非 `PUBLIC_RELEASE_MODE` → 直接 resolve（internal 模式零影响）；
  2. 读一次性标记 `{STORAGE_PREFIX}-seed-imported-{seedId}`：若已有值且与即将导入的 seedId 相同 → 不再 fetch（每份种子只导一次；**换种子（更新包）seedId 变 → 重新评估**）；
  3. `fetch("/seed/manifest.json")`（AbortController 3s 超时；404/网络失败/JSON 坏 → catch 后 resolve，**不阻断启动**）；
  4. 逐 entry：目标键 `readJsonStorage(key, null)` 为**空/null/空数组**才 `writeJsonStorage(key, value)`；非空（回头客已有数据）→ **跳过不覆盖**（红线③防旧种子盖客户数据）；
  5. 全部处理完写标记 `{STORAGE_PREFIX}-seed-imported-{seedId}` = seedId。
- **`buildReleaseSeed()`**（导出侧，用户源码版用）：按上表 id 逐个读当前存储——提示词两类键用共享加载器口径（`loadPromptLibraryPresets/loadPromptLibraryCategories` 传各自 key，保证「用户看到什么导什么」）；其余 `readJsonStorage` 原样读；`outfit-pages` 过**字段白名单**（见 1.2）；`outfit-settings` 与任何 settings 状对象过**剥凭据**（删 `apiKey`/`baseUrl`/`channelId` 三个键，递归到嵌套对象）；空值 entry **不写入**（种子只含有内容的项）；seedId = entries JSON 的 FNV-1a 32bit hex。
- **`downloadReleaseSeed()`**：Blob + `URL.createObjectURL` + `<a download="jingyin-seed-yyyyMMdd.json">`，点击后 revokeObjectURL。

## 4. 留档（统筹写入）

- **产品口径最终版（封装数据边界）**：客户打开看到的 = 用户的提示词模板（两套键都带）+ 用户当前页面集合（含删除留痕）+ 纯配置；**看不到**密钥与任何生图信息记录；客户自己的修改永不被种子/reset 覆盖。

- **教训**：给用户资产设计「随包/迁移」能力前，先审计该资产在浏览器里的**全部持久化点**——本单取证发现 outfit 全局设置键持久化含 apiKey 的全量 settings（`outfit-workflow.jsx:807-812`），种子若整体照搬即违反红线①；白名单+剥凭据因此做成硬编码双侧同口径。

- **修法**：7 个 outfit 侧存储键常量迁入零依赖叶子模块 `outfit-storage-keys.js`（单一真相源，git grep -l 全量核对、旧路径零残留）；outfit-top/outfit-panels 改从叶子取键；outfit-page-actions/outfit-workflow import 改向；门禁增补 [4c] 断言（release-seed.js 的 outfit 依赖仅限叶子）锁死边界。
- **教训（写入记忆）**：`vite build` EXIT=0 与 Node 单测**抓不到打包产物的运行期 TDZ**；public 模式（启动即挂载 outfit）与 internal 模式（延迟加载）的模块初始化次序不同，**发版前必须做 public 模式首启动冒烟**；启动链路模块严禁 import 特性模块群。
