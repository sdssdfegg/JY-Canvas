## 1. 背景与真因

用户反馈：2.5 上换任何渠道，扣费都塌成 `默认(最低价)` 0.1，实际价格不生效。

真因链：

1. new-api 计费表达式（`options.billing_setting.billing_expr`，`tiered_expr` 模式）只能从 **JSON 请求体**读 `channelId`；
2. 前端带图请求走的是 **multipart/form-data**，计费侧根本看不到 `channelId`，于是全部落入兜底 tier；
3. 全局 `routeModes` 只有 `manual` 是 ACTIVE，`price_first` 长期 DISABLED，所以没有合法 `channelId` 就直接报错，不会自动挑渠道。

因此修法只有一条：**带图请求也走 JSON**，而不是改排序或加自动兜底（用户明确禁止改排序/自动填补渠道）。

## 4. 实测（2026-10-31，JSON 通道）

| 渠道 | 模型 | 结果 | 实扣 |
|---|---|---|---|
| LK-1K（line-11） | tt-image-2.5 | 200 出图 24.5s | **$0.12** ✅ |
| XT-default（line-03） | tt-image-2.5 | 200 出图 23.4s | **$0.10** ✅ |
| LY满血版（line-10） | tt-image-2.5 | 上游 503 | 未扣费 ❌ |
| laoye（line-12，新增） | tt-image-2.5 | 上游 503 | 未扣费 ❌ |

laoye 的诊断结论（重要）：

- manual 路由已正确命中：`candidateChannels: ["silent-tt25-laoye-2"]`、`upstream_model: gpt-image-2.5-flare`；
- 上游 `https://api.luckfill.com` 返回 503，原文 `No available channel for model gpt-image-2.5-flare under group image2.5全参 (distributor)`；
- **三个密钥（MANXUE / TT25 / SUPERRES）直连上游全部 503**，而 `LK-1K`(`api.lk888.ai`)、`XT-default`(`api.lk888.ai`) 正常 200
  → 结论：**我们的链路与配置没问题，是 luckfill 侧「image2.5全参」分组/额度当前不可用**，需上游侧开通或充值后才能出图。

修复过程中发现的第二个坑（已修）：

- 新增渠道最初 `upstreamCost` 填 0.12，与 `markup` 0.02 相加得 0.14 ≠ `customerPrice` 0.08，
  导致 `tt25_has_any_active_price()` 返回 False → manual 解析不到 → 报 `price_first_route_disabled`（503）。
  把 `upstreamCost` 调整为 0.06 后即可通过校验（0.06 + 0.02 = 0.08）。
  **以后新增/改价渠道必须满足：`upstreamCost + markup == customerPrice`**，否则该渠道在 manual 模式下选不中。
