## 2. 迁移方案（V135 建议方案的落地细化）

**整块单 hook、逐字迁移、调用点保序**：

1. 新建 `src/features/outfit/handlers/outfit-effects.js`，只 export 一个 `useOutfitEffects(ctx)`；
   28 个 effect **按原声明顺序逐字迁移**（含注释与依赖数组；唯一例外见 §5.3 的 5 处 lint 注释）；
   纯函数/常量（`getAppConfig`/`persistTaskHistory`/`ensureWorkflowPages`/`STORAGE_KEY` 等 20 项）在新文件**直接 import**，不进 ctx；
   模块级 `outfitWorkflowDocumentBooted` 连同其 112–117 行注释**随迁**至新文件（语义不变：文档级一次性标记），原件 118 行删除。
2. **调用点置于 957 行之后**（三个 ref 声明之后、原 E24 位置之前）：组件内 effect 全部入 hook，
   其余 hook 调用点不变 ⇒ 28 个 effect 的相对顺序、与下游 hook effect 的相对顺序**逐条不变**。
3. `refreshSaveDirectory` 走**晚期绑定 ref**（沿用本仓 `handlerLateRef`/V5.0-002 同款模式）：
   组件内新增 `const refreshSaveDirectoryRef = useRef(null)`（调用点前），
   `useSaveDirectory` 解构后追加一行 `refreshSaveDirectoryRef.current = refreshSaveDirectory;`；
   E11 体内 `void refreshSaveDirectory();` → `void refreshSaveDirectoryRef.current?.();`（effect 后于整棵 render 执行，ref 必已刷新；语义等价）。
4. ctx 采用既有「deps 注入薄壳」模式（同 `outfit-selection.js`/`use-outfit-pages.js`），**每次 render 重建**，行为零变化。

## 5. 风险与对策

### 5.1 TDZ（V136/V121-R2 同族：lint/build 都不报，运行时白屏）
- 调用点（958）之前必须完成初始化的值：§1 已逐个核实（function 声明提升的 4 个 + 其余均早于 654）；
- `refreshSaveDirectoryRef` 声明紧邻调用点之前；`useSaveDirectory` 后一行赋值——**赋值行位置即事实，探针须覆盖冷启动**。

### 5.2 effect 顺序漂移
- 整块单 hook + 调用点置于原区域末尾 + 区间外无 effect ⇒ 顺序不变属结构性保证，非"逐条 review 保证"；
- 验收仍附 §4 对照表（原行号→新行号一一对应，行数合计 = 384 行 effects+注释逐个对账）。

### 5.3 lint 注释处理（`reportUnusedDisableDirectives: "warn"` 是硬门禁）

- 起草时预判：迁入 hook 后 ctx 值不再是规则可追踪的响应式源 ⇒ 原 5 处 disable 失去对象、摘除即可。
  **施工实测推翻该预判**：规则对 ctx 解组值**照样报缺依赖**（24/28 个 effect 触发，含 setter/ref——
  规则在组件内认识 `useState` setter / `useRef` 的稳定性，经 ctx 注入后不再认识），
  且对 E7/E8/E15/E28 的 `modelImages` / `loadOutfitPage` 等**要求补入会改变重跑时机**的值。
- **实际处置（两手都避开）**：依赖数组保持**逐字不动**（迁移契约第一位），effects 区域用一段
  **带说明的 scoped 禁用块**（`/* eslint-disable react-hooks/exhaustive-deps */` … `enable`），
  块头注释写清三条：规则为何在此失效、依赖数组正确性由什么保证、新增 effect 写在禁用区外。
  原 5 处 per-effect disable 不携带（会被块覆盖 ⇒ unused directive 警告）。
- 副作用（如实记录）：与既有 6 个 handler hook 同性质——本文件内 exhaustive-deps 失效，
  靠「薄壳 + 每次 render 重建注入」约定 + 逐字 diff 验收保证新鲜度。

### 5.4 漏注入（V132 踩过：漏注入 preview，lint 抓到）
- ctx 62 项按 §3 清单逐个注入；效应体引用的每个标识符在注入后跑 ESLint `no-undef` 全覆盖（漏注入 = 未定义 = error，可机检）。

### 5.5 行数账（V135 教训：净行数大概率为正，如实记）
- 实测：组件 2008 → **1635（−373）**（移除 392 行 effects/注释 + 7 行标志区，新增 ctx 对象 34 行 + ref/赋值/注释 12 行）；
- 新文件 **513 行**（392 effects + 文件头/import/ctx 解组/禁用块说明约 121 行）；**净增约 +140 行**。
  收益是「组件只剩 state/派生/渲染/编排」，不是代码变少——与 V132–V134 三刀同性质的账。
