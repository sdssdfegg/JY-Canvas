# 执行单：V11-RF-018（新增「相对导入路径存在性」静态门禁）

**执行人**：具备命令执行能力的 AI 代理。本单是**测试基建**，零业务改动。
**配套契约**：`REFACTOR_TICKETS.md`（**§0.9 第 10 条「路径保真」**、§5 的 RF-116/117 行）。

> **🔒 单一写入纪律**：**不要修改** `REFACTOR_TICKETS.md` 或任何总表 / 执行单 / 报告类 `.md`。成果以**汇报**交回，由文档作者统一落表。

**为什么做本单（血案直接解药）**：`V11-RF-116` 把 `app-bootstrap.js` 搬进 `server/core/` 后，相对导入写成 `./static-assets.generated.js`（该生成物其实在 `server/` 根目录）⇒ **`ERR_MODULE_NOT_FOUND`，整个软件起不来**；
而 `run-all` 从 36/36 掉到 21/36，**15 个失败全是「测试实例未起来」**。这类错**逃得过现有全部门禁**：

| 现有门禁 | 为什么抓不到 |
| --- | --- |
| `node --check` | 只查语法，不解析 import |
| ESLint（直跑） | **未开 import 解析规则** |
| `server-duplication-check` / `state-singleton-check` / `routing-check` | 只看符号与文本 |
| 沙盒"全绿" | 不起服务 ⇒ 盲区正好盖住这类错 |

**本单要把"相对导入写错"变成一条一跑就红、且**零副作用**的静态断言。**

**账目**：新增 1 个脚本 ⇒ `run-all --list` 由 **36 → 37**（预期变化，以改前 `--list` 为准）。

## 1. 步骤

### 步骤 1-1 · 先做"考古"：确认当前基线是干净的
- **人工操作要点**：先手工扫一遍 `server/**` 里的相对导入，确认**每一处都能解析到真实文件**（117 已修，预期干净）。
- **校验要点**：**预期 0 处坏路径**。
- **不通过怎么办**：若真扫出坏路径 → **先别 `--update`/放过**，把它当**新发现**汇报（可能还有第二处 116 同类漏网）。

### 步骤 1-2 · 新建 `scripts/verify/import-path-check.mjs`
- **实现要点（逐条落实）**：
  1. **源码范围复用** `scripts/verify/lib/server-sources.mjs` 的 `listServerSourceFiles()`（自动覆盖未来的 `server/routes/**`、`server/shared/**`；天然排除 `skill-baselines/**` 与生成物）。
  2. **只扫相对说明符**：`from "./x.js"` / `from "../x.js"` / `import "./x.js"` / `import("../x.js")`；**跳过**裸包名（`express`、`node:fs` 等）。
  3. **解析判定**：把说明符拼到**该文件所在目录**，用 `existsSync` 判断目标是否存在。
     ⚠️ 注意两种写法都要覆盖：① 带扩展名的（`./x.js`）；② 目录形式（`./dir/`，解析到 `dir/index.js`）。
  4. **不做 URL 解码花活**：直接 `path.resolve(path.dirname(file), specifier)` + `existsSync`，必要时再试 `specifier + ".js"` / `+ "/index.js"`。
  5. **违规输出必须点名**：`文件:行号` + `说明符` + **解析后的绝对路径**（三样都要有，否则定位要二次翻查）。
  6. **无基线、无棘轮**：坏路径**任何时刻都是错** ⇒ 直接 `ok = 违规数 === 0`，`exit 1`。不需要 `--update`（本门禁无"存量"概念）。
  7. JSON 输出：`ok` / `scannedFiles` / `scannedSpecifiers` / `violations[]`。
- **校验要点**：脚本自身 lint 干净（新文件 = 棘轮新 key）；**不得 import 任何业务模块**（尤其**不要** `import` 被测文件本身 —— 那会执行副作用）。

### 步骤 1-3 · 🔴 边界声明（**必须写进脚本头注释**，防误用）
- **只覆盖 import 说明符**，**不覆盖**运行期拼出来的路径（如 `path.resolve(runtimeDir, "..")` —— 那是 RF-011 `app-paths.js` 那类错，需要**值级复核**，本门禁抓不到）。
- **不扫 `src/**`**：前端由 Vite 解析（允许省略扩展名、`.jsx`/`.css` 混用），朴素存在性判断会**大量误报**。若将来要覆盖前端，另开工单。
- 头注释里写明这条血案的来龙去脉（116 → 117），让后人知道它为什么存在。

### 步骤 1-4 · 登记 `ORDER`
- **人工操作要点**：把 `"import-path-check"` 加进 `scripts/verify/run-all.mjs` 的 `ORDER`，放在**纯源码检查那一批**（`state-singleton-check` / `server-duplication-check` / `app-paths-check` 附近）。
- **校验要点**：`--list` 由 **36 → 37**；`run-all-check` 的「顺序表覆盖所有磁盘脚本」不报漏登记。

### 步骤 1-5 · 🔴 负向验证（**必须做**，这是本单存在的意义）
- **人工操作要点**：
  1. 临时把 `server/core/app-bootstrap.js:25` 改回 **`./static-assets.generated.js`**（复现 116 的原错）；
  2. 跑本门禁 → **必须变红**，且输出里**同时给出**：`server/core/app-bootstrap.js:25`、说明符 `./static-assets.generated.js`、解析后的 `…\server\core\static-assets.generated.js`；
  3. **逐字节还原**成 `../static-assets.generated.js`，再跑一次确认恢复绿。
- **补充负向**：再临时造一处不存在的目标（如把某处改成 `./__nope.js`）→ 同样必须红。两处都还原。
- **校验要点**：变红时**信息三项齐全**；只报"有坏路径"不点名 = 判别力不足，要重写。
- **不通过怎么办**：不变红 → 检查是不是正则漏了 `from "..."` 之外的形式，或 `existsSync` 拼错基准目录。

### 步骤 1-6 · 正向验证 + 全套
- **校验要点**：本脚本 `ok:true`、`violations` 为空；**全套 37 项、失败 0**；`lint-ratchet-check` 的 `regressions` 为空数组；`server-duplication-check` 仍绿。

### 步骤 1-7 · 提交 + 汇报
