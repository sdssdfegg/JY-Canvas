# V5.0-003 · 软件显示版本 v4.0 → v5.0 同步

> 统筹：静音AI画板 ｜ 日期：2026-10-23 ｜ 来源：用户裁定「里面能看到 v4.0 的都要跟着同步改成 v5.0，不然 5.0 软件显示 4.0 内容尴尬」
> 关联：V5.0-001 / V5.0-002（性能线，已归档）

## 0. 背景与结论前置

用户担心：出 v5.0 包后，软件里仍显示 v4.0 的内容。

排查结论（先说清楚，避免误改）：
- **运行界面（浏览器标签）不显示任何产品版本号**——`index.html` 标题恒为「静音AI绘画」，src 内无关于/版本面板、无 version.json 读取。
- 软件**包层面**展示的版本只来自一处真相源：发布工程 `build.config.json` 的 `productVersion`，经 `build.mjs` 写入包内 **文件夹名 / 使用说明.txt / version.json(appVersion) / exe 版本资源**。
- 用户贴的 `Node 版本 / version : v24.9.0 (source: project-local)` 来自 `scripts/start-jingyin-board.ps1:492`，是**启动器探测到的 Node 运行时版本**（项目自带 `runtime/node/node.exe` = v24.9.0），**不是产品版本，严禁改成 v5.0**（改了既误导、又会让软件因 Node 不匹配起不来）。
- `package.json` / `server/routes/system.routes.js:234` 的 `11.0.0` 是**内部 npm 包版本**，与产品 v4/v5 线无关，不动。
- src 代码注释里的 `(V4.0)` 是「代码引入时的版本纪元标记」，非用户可见，不动（保留便于考古 grep）。
- 文档文件名 `V4.0-*.md`、源码目录名 `静音AI画板v4.0源码` 是开发归档/文件系统路径，不随产品号改（改目录名会破坏 `sourceDir` 配置与大量引用）。

## 1. 范围（要改的）

| 文件 | 改动 |
|---|---|
| `发布工程/build.config.json` | `productVersion`: `"4.0.13"` → `"5.0.0"`；`minUpdatableVersion`: `"v4.0.0"` → `"v5.0.0"`（v5.0 新大版本，v4.x 不增量更新到 v5.0） |
| `scripts/secure-win-release.mjs`（源码） | 兜底默认 `releaseName` `"静音AI画板（v3.7）"` → `"静音AI画板（v5.0）"`；`productVersion` `"3.7.0"` → `"5.0.0"`（注：`build.mjs` 会注入 env 覆盖这两项，实际不生效，但属陈旧年代默认，对齐防 standalone 误用） |
| `发布工程/build.mjs` | 头部注释 `静音AI画板 v4.0 · 发布构建器` → `v5.0`；示例 `node build.mjs --version v4.0.1` → `v5.0.0`；兜底默认 `|| "v4.0.0"` → `"v5.0.0"` |

## 2. 不改的（明确划线）

- `start-jingyin-board.ps1` 的 `Node 版本 / version: v24.9.0` —— Node 运行时，留。
- `package.json` version `11.0.0` / `system.routes.js:234` `version: "11.0.0"` —— 内部包版本，留。
- src 内 `(V4.0)` 历史注释、文档 `V4.0-*.md`、`sourceDir` 路径 —— 留。
- `secure-win-release.mjs` 内 `v3.7.0` 注释段落（2026-09-29 规范化说明）保留史实。

## 3. 验收

- `scripts/check-syntax.mjs` 全绿（仅配置/脚本字符串改动，src 不受影响）。
- 比对：改动后 `build.config.json` 不再含 `4.0`/`v4` 产品号；`build.mjs` 默认与示例为 v5.0。
- 出包验证（里程碑，按用户此前裁定暂未做）：`build.mjs --version v5.0.0` 后，包内 `version.json.appVersion` / 使用说明.txt `版本：` / 文件夹名 应均为 `5.0.0`，不再出现 `4.0.x`。

## 4. 风险与边界

- 配置改动零运行时风险（不进 dist/src）；仅影响下一次出包的产品号。
- 若用户出 v5.0 时仍手传 `--version`，以手传为准；本单是把「不传时的默认」从 v4 纪元抬到 v5 纪元，消除遗漏风险。
