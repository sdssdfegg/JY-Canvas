## 1. 步骤

### 步骤 1-1 · 先做一次"考古"，确认基线应该是干净的
- **人工操作要点**：先手工搜一遍服务端源码，看看**当前是否真的没有跨文件同名函数**。至少覆盖本批搬出来的模块：
  `image-concurrency.js` / `generation-trace.js` / `billing-attempts.js` / `directory-picker.js` / `history-display.js` / `image-diagnostics.js` / `outfit-upload-groups.js` / `local-image-stream.js` / `outfit-archive.js` / `image-channel-candidates.js`。
- **校验要点**：**预期是"没有重复"**（110 刚清完）。
- **不通过怎么办**：若真搜出重复 → **先别急着 `--update` 记账**，把它当成一条**新发现**汇报（可能是 111–116 之前就存在的漂移），由文档作者决定是"先修"还是"先记账"。

### 步骤 1-2 · 新建 `scripts/verify/server-duplication-check.mjs`
- **人工操作要点**（实现要点，逐条落实）：
  1. **源码范围必须复用** `scripts/verify/lib/server-sources.mjs` 的 `listServerSourceFiles()`（自动覆盖未来的 `server/routes/**`、`server/shared/**`）；
     ⚠️ 该收集器**天然排除** `server/skill-baselines/**`、`server/features/**`、生成物 —— 正好符合需要（`skill-baselines` 里有大量历史同名副本，**必须排除**）。
  2. **只认"顶层"函数声明**：匹配**行首（列 0）**的 `function NAME(` 与 `async function NAME(`；
     **不要**扫缩进的内层函数/箭头函数（`const foo = () => {}` 不做也行，但内层同名属正常局部作用域，全扫会大量误报）。
  3. 统计 **同名 & 跨文件**（同一文件内重名不算，但要顺手报出来作为异常）。
  4. 输出 JSON：`ok` / `duplicateCount` / `duplicates[]`（名字 + `文件:行号` 列表）/ `regressions[]` / `improved[]`；
     违规时**必须点名两处文件与行号**，并 `exit 1`。
  5. **棘轮模式**（与 `shared-ui-duplication-check` / `lint-ratchet-check` 一致）：存量记账、**新增即失败**；`--update` 刷新基线。
- **校验要点**：脚本自身 lint 干净（新文件 = 棘轮新 key，**任何一个 warning 都算新增问题**）；不得 import 任何业务模块。

### 步骤 1-3 · 基线文件 `scripts/verify/server-duplication-baseline.json`
- **人工操作要点**：跑一次 `--update` 生成基线；文件头写一句说明（"记录当前已存在的跨文件同名函数，只用来拦新增；消除后跑 --update 划掉"）。
- **校验要点**：**基线内容应为空（或只有明确可知的存量）**；若出现你没预期的名字 → 回 1-1 当新发现处理。

### 步骤 1-4 · 登记 `ORDER`
- **人工操作要点**：把 `"server-duplication-check"` 加进 `scripts/verify/run-all.mjs` 的 `ORDER`，放在纯源码检查那一批。
- **校验要点**：`--list` 由 **35 → 36**；`run-all-check` 的「顺序表覆盖所有磁盘脚本（新增脚本不会被漏跑）」不报漏登记。

### 步骤 1-5 · 负向验证（**必须做**，否则这条门禁等于没写）
- **人工操作要点**：
  1. 临时把 `server/core/local-image-stream.js` 里的 **`parseByteRange`** 整段复制到另一个服务端文件（例如临时新建 `server/core/__tmp_dup.js`，或复制进 `server/core/format-utils.js` 末尾）；
  2. 跑本门禁 → **必须变红，并同时点名两处文件与行号**；
  3. 删除临时内容，**逐字节还原**，再跑一次确认恢复绿。
- **校验要点**：变红时必须**点名两处**（只报"有重复"不点名 = 判别力不足，要重写）。
- **不通过怎么办**：不变红 → 检查是不是把 `__tmp_dup.js` 之类放到了"收集器不覆盖"的目录（收集器只走 `index.js + core/routes/shared`）。

### 步骤 1-6 · 正向验证 + 全套
- **校验要点**：本脚本 `ok:true`；**全套 36 项、失败 0**；`lint-ratchet-check` 的 `regressions` 为空数组。

### 步骤 1-7 · 提交 + 汇报
- **人工操作要点**：一单一 commit（新脚本 + 基线 json + `run-all.mjs` ORDER 一行）；commit message 写明「测试基建：新增服务端同名函数重复门禁（棘轮，存量记账/新增即失败）；ORDER 35→36」。
- **校验要点**：**汇报**交回（含基线内容、负向验证的红/绿输出片段），**不要**改 `REFACTOR_TICKETS.md`。
