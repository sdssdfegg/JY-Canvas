## 1. 真正的债：换装 CSS 里硬编码的主题色不跟随换装子主题

`src/features/outfit/outfit-top.js` 的 `themeToVars`（L684-760）为换装定义了 **4 套独立子主题**，并在 `outfit-workflow.jsx` L588-604 以**同名 CSS 变量**注入到换装根节点：

| palette 键 | → CSS 变量 | dark | jade | graphite | mist |
| --- | --- | --- | --- | --- | --- |
| `accent` | `--accent` | `#1fcfc3` | `#ec6f9e` | `#c98652` | `#0d7a76` |

> ⚠️ 起草日表格里 graphite/mist 写成 `#d8a25a`/`#7fb8b0`（沿用了记忆中的旧值、未现算），执行方勘误后**实际为 `#c98652`/`#0d7a76`**，已由上表更正。详见 §7 勘误 2 与 §9.3。
| `accentText` | `--accent-text` | `#061515` | `#ffffff` | — | — |
| `accentBorder` | `--accent-border` | `#1fcfc3` | `#ec6f9e` | — | — |

而 `outfit-workflow.css` 把这些值**写死在 CSS 里**，于是**换装切到 jade（粉）/graphite（金）时，这些元素仍是 dark 的青/旧红**——视觉不一致：

| `#061515` | **7** | `color:`(L126/599/835/1570/…) 青底上的文字 | `var(--accent-text)` |
| `#ffb3b3` | **3** | `color:`(L159/927/1084) 危险态文字 | `var(--danger)` |

**共 22 处**（`grep -n` 逐条核对，执行日必须重 grep 重测）。

### 1.1 为什么这是债而不是"刻意固定色"

同一个换装模块里，其它元素已经在用 `var(--accent)` 等（跟随子主题切换），唯独这 22 处写死 → 切主题时它们不跟着变，是**同一界面内的不一致**，不是设计决策。

### 1.2 保留（V106 已裁决，本单不动）

- `#ffffff` ×35、`#000000`、`#141622`、`#cfd4d8` —— 中性/黑白色。
- `#49c85b` ×7 —— 成功/绿色语义。
- `#fbbf24` ×2（及 outfit-intent/retouch-intent 里的金色）—— 渠道高亮语义色（与 `--accent` 刻意区分）。
- `#00000052`、`#fff6fa`/`#fff6df`/`#fff6da` 等 —— 阴影/浅底。
- 若执行日发现其中某个值**在 `themeToVars` 的 palette 里存在**（即属子主题色），则**应替换**并在回执列明。

## 2. 改动要求

### 2.1 替换规则

- 只改 `src/outfit-workflow.css`（真实路径在 `src/` 根，与 `outfit-workflow.jsx` 同处；`src/features/outfit/` 下并无此文件。其余三个 intent CSS 经实测为语义色，**不动**）。
- `#1fcfc3`：`background:` → `var(--accent)`；`border-color:` / `border:` → `var(--accent-border)`。
- `#061515`：`color:` → `var(--accent-text)`。
- `#ffb3b3`：`color:` → `var(--danger)`。
- **不得**改成 `var(--accent-on)`（那是全局 tokens 的命名，换装注入的是 `--accent-text`）。
- 行内改写为主，**尽量保持物理行数不变**（size-ratchet 只降不升）。

### 2.2 硬性约束

- 替换后**主应用（非换装作用域）不受影响**：这些 `var()` 在换装根节点被子主题覆盖，在主应用取 `tokens.css` 的值。
- 每改一处先确认其上下文用途（background / border / color），**用途不同的不要套同一个变量**。
- 若某处的视觉语义存疑（例如不确定是强调色还是状态色）→ **停下回报**，不得猜。
