### 9.5 探针基建坑留档（非产品缺陷，防后续误判）

首轮两次探针报「页面 chip 未找到: 服装改色，现有 7 个默认单例」，曾疑加载回归。诊断探针（`tmp/v120-diag.mjs`）定位：**根因是探针与持久层的竞态，不是代码问题**——

1. outfit 页状态在 `OutfitWorkflow` 挂载时 `useState(readOutfitPages)` 懒初始化（`outfit-workflow.jsx:308`），但随后草稿 hydration effect 会用 `loadOutfitDraftState` 的草稿 `setOutfitPages` **覆盖**它（`outfit-workflow.jsx:723-728`）；
2. 草稿存 **IndexedDB**（`jingyin-outfit-workflow-local-v1` / store `state` / key `page-draft`，`outfit-task.js:25`），**不在 localStorage**——探针的 `localStorage.clear()` 碰不到它；
3. tabbit 浏览器配置跨探针运行持久，早期运行留下的 7 单例草稿于是覆盖了每次新注入的页；V119 探针当时能过，只因那个配置里的草稿恰好不含冲突页。

修复（已写入探针）：init script 增补 `indexedDB.deleteDatabase('jingyin-outfit-workflow-local-v1')` + `gotoNav` 改点击重试（首轮点击曾丢在 hydration 前）。**教训**：验证 outfit 页相关改动时，注入必须同时清 IndexedDB 草稿，否则读到的是上一次运行的草稿快照。用户态纪律遵守：探针只写自建临时页/键，未触碰用户真实浏览器状态。
