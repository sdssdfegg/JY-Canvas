## 一、背景与实测现状（已查证，非推测）

V40 治理了根目录 md，但其范围是"只移 md"。执行过程中发现 `scripts/dev/` 下有 **26 个未跟踪（untracked）的游离脚本/数据**，属各次重构与热修的一次性施工产物：

- `rf079-*` / `rf080-*` / `rf081-*` / `rf082-*` 系列（重构分析、抽取、修补脚本 + `rf081-result.json` 38KB 分析结果）
- `v32-*` / `v33-*` 系列（旧版本修补）
- `hotfix01-apply` / `hotfix04-apply`（热修落盘脚本）
- `bug01-bounce-probe` / `server-027-scope` / `blade4-check-template` / `block-clone-lines` / `cycle-scan` / `domain-fn-list` / `guard-scan` 等零散探针
- 其中 `rf081-build-doc.mjs` 已跟踪（tracked），其余 25 个未跟踪

### 关键查证结论
1. **无任何运行时代码依赖**：全仓（src/server/scripts/package.json）grep 这些文件名，除 `rf081-build-doc.mjs`（已跟踪，内部 `require` 了 `rf081-const.mjs` 与 `rf081-grep.mjs`）外，其余仅出现在**注释 / 基线说明 note** 中，无任何 `require/import` 链路。
2. **基线 manifest 钉死了当前路径**：`create-baseline.mjs` 的 `INCLUDE_DIRS` 含 `"scripts"`，V40 刚重建的 `baselines/V11-baseline-20261007-085946/manifest.json` 已把 `scripts/dev/` 下全部 26 个文件按路径记录。**移动任何一个都必须跟着重建基线**，否则 `verify-baseline` 判路径不符。
3. **非活跃工具**：`lint-ratchet-mirror.mjs` 是 EBUSY 绕法的人工手动工具（用户真机环境手跑），不被任何 npm 脚本按路径调用（已验证 `lint-ratchet-check.mjs` 内无字面引用），仅因在 `scripts/dev/` 被基线快照记录。
4. **发布包不受影响**：`secure-win-release.mjs` 显式组装（exe/version.json/bat/说明），不整拷 `scripts/` ⇒ 这些文件不会发给客户。

## 二、方案定夺：纳入跟踪 + 迁至基线外归档（不删除）

**三条原则**
- **零删除**：一律先 `git add` 保命，再 `git mv`（改名式移动，不触发沙盒 safe-delete 守卫），绝不 `rm`。一次性施工脚本是重构/热修的审计轨迹，丢失后无法回溯"当初怎么改的"。
- **迁出基线快照**：新建顶层 `archive/`（**不在** `INCLUDE_DIRS` 内）⇒ 归档脚本既不被基线快照（减噪），也不进发布包（安全）。
- **保留人工工具在根**：`lint-ratchet-mirror.mjs` 是用户手跑的活跃绕法工具，留 `scripts/dev/` 根更顺手，且基线 manifest 已钉其路径 ⇒ 不移动它即可保持基线零改动。

### 具体步骤（建议 1 个 commit，或拆为 2 个：先保命 add，再 mv）
1. `git add scripts/dev/<26个文件>` —— 把 25 个未跟踪 + 顺带确认 `rf081-build-doc.mjs` 已跟踪（它本就在库，无需 add）。**保命，零丢失风险。**
2. 新建 `archive/scripts-dev/` 目录。
3. `git mv` 以下 **25 个未跟踪文件** + **`rf081-build-doc.mjs`（已跟踪，连同其依赖簇一起搬）** 进入 `archive/scripts-dev/`：
   - rf079/rf080/rf081/rf082 整簇（含 `rf081-result.json`、`rf082-analysis.txt`）
   - v32/v33 系列、hotfix01/04、bug01、server-027、blade4、block-clone-lines、cycle-scan、domain-fn-list、guard-scan
   - **连同** `rf081-build-doc.mjs`（它 require 了 `rf081-const.mjs`/`rf081-grep.mjs`，必须同簇移动否则其 require 断链）
4. **保留** `scripts/dev/lint-ratchet-mirror.mjs` 在根，`git add` 它（转为已跟踪，路径不变 ⇒ 基线对该文件零变更）。
5. 运行 `node scripts/baseline/create-baseline.mjs` 重建基线（预期变更：25 个文件从 `scripts/dev/` 变为 `archive/scripts-dev/`，`lint-ratchet-mirror.mjs` 不变；属正常迁移，非回归）。

## 五、风险提示
- **必须 `git add` 先于 `git mv`**：26 个未跟踪文件若直接 `mv` 再 add，中途失败会丢未跟踪内容；先 add 进库即不可丢。
- **禁止批量 `rm`**：沙盒 safe-delete 守卫对 >50 文件批量删会卡死；本单 26 个远小于阈值，但仍一律用 `git mv`，不留删除动作。
- **禁止漏搬 `rf081-build-doc.mjs`**：它已跟踪且 require 同簇两文件，若只搬 const/grep 不搬它，其 require 断链（虽一次性的，仍应避免留下坏引用）。
- **基线必须重建**：否则 V40 刚建的基线会因路径变更判失败，被误读为回归。
