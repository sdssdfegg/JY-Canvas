## 4. 你要回答的七个问题

**Q1 · 全量与真伪甄别**
用 `node scripts/dev/measure-top.mjs src/main.jsx` 列出**全量**真顶层定义（不少于 59 个），并给出：
- 每个定义的：名字 / 行区间 / 行数 / 是否真顶层
- 🔴 **自由标识符抽测**：对每个候选，扫描它函数体内引用但**不在自身作用域内定义**的标识符，判定它是否隐式依赖 `App` 组件内的东西（state / 闭包变量）。
  **禁止只看 `indent=0` 就判"顶层"** —— RF-079 的 `buildTasks` 就是这么翻的车（`App` 区间是 **1677-6622**，落在此区间内的 column-0 定义都是伪顶层）。
- 分成三档：**A 档 完全纯净**（零外部依赖，可直接普通模块导出）／**B 档 需随迁依赖**（依赖其他待搬顶层函数或常量，一起搬即可）／**C 档 不可搬**（依赖组件 state 或已裁决）。

**Q2 · 循环依赖（头号风险）**
现状环数量 = **0**（`node scripts/dev/cycle-scan.mjs` 实测，108 文件）。
本单若新建落点文件，main 必然要 import 它；若落点文件又需要反向 import main ⇒ **环 0→1**。
你必须给出：
- 落点文件是否会产生反向 import？产生几个名字？
- 若会产生，三选一：**① 相关依赖一起随迁（参照 RF-080 做法）／ ② 下沉到 `src/shared/` ／ ③ 判不可搬**。
- 🔴 **判据：环数量必须保持 0。** 做不到 ⇒ 结论改为"不做"。

**Q3 · 落点方案**
`src/features/` 现有子目录：`auth` `canvas` `detail` `local-edit` `outfit` `result-queue` `savedir` `upload` `video`。
- 按子域分组建议落点（如 history 三件套 / reference 文案族 / channel 压缩族 / crop 快捷族 / canvas 状态族），
  说明每组是**追加既有文件**（`fileCount` 不变，**不划账**）还是**新建**（`fileCount` 60→N，**需统筹划账**）。
- `QuickCropViewportModal` / `DetailUploadZone` 两个独立组件单独给落点建议。
- 各落点文件预估行数。

**Q4 · 收益测算 A / B**
- **A** = 巨石减少行数 = 搬出的定义行数 + 删掉的孤儿 import − 原位回填的 import 行数。
  🔴 **回填 import 是"加回巨石"，是减项不是加项**（RF-080 设计单在这里算错过 28 行，别重蹈）。
- **B** = 仓库总行数净变化（本单是**单侧拆分单**，B 为**正**属正常，不叫失败；参考 RF-079 A=−988/B=+81、RF-080 A=−2083/B≈+83）。
- 给出 main 6631 → 预估多少行；并给出**两巨石合计占比**（现 13817 / ≈54.3%）。

**Q5 · 随迁项清单**
- 需要跟着函数一起走的**模块级常量**逐个列出。
- 需要跟着走的 import（哪些是孤儿需要删，哪些要复制到落点文件）。
- 🔴 按原行号**升序**搬（`const` 不提升，乱序会 TDZ）。

**Q6 · 风险与易翻车点**
