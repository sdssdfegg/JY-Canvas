## 0. 背景与结论（统筹审计发现，非执行方回报）

用户询问"优化是否全部完成"，统筹做状态审计。UI 规范化 program（V69-V108）指标全部复算归零 ✔，但追查台账记录的遗留观察项「快捷生成未上传图点『生成』抛 `undefined.map` TypeError」时，**发现该观察项的定性错误**——它不是"特定场景才抛的既有小缺陷"，而是**主功能在任何情况下都会崩的 P0 回归**。

### 根因链（统筹已逐环取证，commit 级证据）

1. `src/features/quickgen/quickgen-state.js` L61：`const [files, setFiles] = useState([])` —— 上传图状态，默认空数组，**永不为 undefined**；L154 随 hook 返回。
2. `src/main.jsx` L308-340：`const quickApi = useQuickGenState(); const { setFiles, ... }` —— **解构了 `setFiles`，但没有解构 `files`**。
3. `src/main.jsx` L774-804：`} = useCanvasGenerationHandlers({ config, settings, models, saveDirectory, ... })` —— 调用参数**没有传 `files`**。
4. `src/features/canvas/canvas-generation-handlers.js` L99：hook 内 `const { ..., files, ... } = ctx` → **`files === undefined`**。
5. 同文件两处直接使用：
   - **L259**（`generate()` 函数体第一段）：`const runItems = files.map(normalizeQuickReferenceItem)...`
   - **L164**（`optimizePrompt()`）：`const quickFiles = quickReferenceUploadFiles(files.map(...))`
6. UI 触发点：`src/features/main-app/panels/main-canvas-board.jsx` L422：`<Button size="lg" tone="primary" onClick={() => generate()}>` —— 主「生成」按钮直达 `generate()`。

**后果：点「生成」必抛 `TypeError: Cannot read properties of undefined (reading 'map')`；点「优化提示词」同样必抛。主功能已坏。**

### 引入 commit（定责取证）

- `git log -S "    files, setFiles," -- src/main.jsx` → **`04f5269` P6-5(commit 1/2): main.jsx 其余全部 handler(37) 抽取至 main-handlers.js（2026-10-16 00:25）**
- 该 commit 的 diff 同时删了两处（`git show 04f5269 -- src/main.jsx`）：
  - 解构区：`-    files, setFiles,` → `+    setFiles,`
  - `useCanvasGenerationHandlers({...})` 调用参数（diff L352-353，紧跟 `activeCanvas,` 之后）：`-    files,`
- 删参数时 `generate`/`optimizePrompt` 已在该 hook 内使用 `files`（P6-4 `7c87c43` 搬入，创建时调用参数是带 `files` 的，见 `git show 7c87c43:src/main.jsx` L1030），但**没有任何编译期/门禁手段能发现"hook 参数少传一个键"**，故带病合入。
- **V94（`3e20227`，10-18）实测复现过该错误**，但做了 base 对照实验后判"既有缺陷、非 V94 引入"记录在案即放行——**相对 V94 而言"非本单引入"是对的，但"既有缺陷"的定性错了**：它是 P6-5 引入的功能回归，只是被发现得晚。教训记入 §9。
