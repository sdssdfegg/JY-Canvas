## 1. 背景：V135 第⑤项复扫结论（2026-10-24 实测）

V135 单当年对「页面切换域」裁决**不拆**，死结论证为：

> 三个函数被 `useOutfitPages` ctx 立即求值消费 ⇒ hook 必须早于 useOutfitPages；
> 但 `resetOutfitPageTransients` 需要 `clearSelection`（selection hook 晚于）⇒ 要 getter；
> 让 selection hook 提前也解不开：它依赖 `addEvent`，而 `addEvent` 又来自 `useOutfitPages` ⇒ **环**。

**复扫实测（当前 HEAD，V5.0-006/007/008 之后）：环的前提已不成立。**

| V135 当年事实 | 当前实测 | 结论 |
|---|---|---|
| `addEvent` 来自 `useOutfitPages`（~1161） | `addEvent` 来自 `useOutfitSettingsIntent`（704 行解构） | **环已断**（V66 拆 settings-intent 时的副产品，V135 未回扫） |
| `resetOutfitPageTransients` 需 `clearSelection`（selection hook 晚于 hook 位） | 仍晚于，但项目已有 **ref 晚绑定惯例**：`refreshSaveDirectoryRef`（638 行，V5.0-008 E11）、`startBatchRef`（668 行，P6-3）——渲染后调用的函数用 getter/ref 晚期取值是既有模式，非新创坏味道 | getter 方案符合项目惯例 |
| `useOutfitPages` ctx 立即求值消费三函数 | 实测 `use-outfit-pages.js` 仅在**事件 handler 函数体内**调用（87/92/111/117/145/251/276 行），渲染期不调用 | 新 hook 调用点置于 `useOutfitPages` 前即安全 |

**第④项（下载域）复扫 = 维持不拆**：`setDownloadFeedbackIds` 仍被 `useOutfitSaveHandlers`（993 行）ctx 立即求值消费，而 `downloadTask` 要从该 hook 才返回 ⇒ 反向依赖死结仍在；且域仅 13 行逻辑（`downloadSelected`/`downloadAll` 各 ~5 行），收益为负。**本单不碰下载域。**

## 2. 目标域与方案

域 = 组件内三个连续函数（现 749–807，共 59 行函数体 + 头尾空行）：

- `buildCurrentOutfitPageSnapshot`（749）—— 生成当前页快照（切页/新建/删页前保存用）
- `resetOutfitPageTransients`（770）—— 清空瞬态（选择/预览/裁剪/下载反馈/提示词编辑器）
- `loadOutfitPage`（783）—— 载入目标页（设置/图组/任务/标签全量切换 + 瞬态重置）

**方案：逐字搬迁 + ref 晚绑定 + 引用方直改**（同 V5.0-008/009 先例，不留 re-export 壳）：

1. 新建 `src/features/outfit/handlers/outfit-page-switch.js`，export `useOutfitPageSwitch(ctx)`，三函数按原顺序逐字搬入；
2. 调用点置于 `useOutfitEffects`(641) **之前**（⚠️ 复扫后修正：初版方案置于 `useOutfitPages` 前，漏算了 effect 簇 ctx 在渲染期消费 `loadOutfitPage`/`buildCurrentOutfitPageSnapshot`——原 hoisted function 声明改 hook 解构后居其后即 TDZ，V136 同族事故，由 modal-shell-check 浏览器探针抓出：base 38/38 vs 改动 32/38）。本 hook 是**纯函数工厂（内部无任何 React hook）**⇒ 上移零 hook 顺序影响；ctx 依赖的全部 state/setter 均在 275–363 声明，亦早于调用点。`useOutfitPages`(826) 只在其事件 handler 内触发时读取三函数引用，无时序约束；
3. `clearSelection` 用 `clearSelectionRef` 晚绑定（刷新点置于 `useOutfitSelectionHandlers` 解构后），规避「下游反向取上游」——与 `refreshSaveDirectoryRef`/`startBatchRef` 同模式；
4. 10 个引用方中仅 `src/outfit-workflow.jsx` 消费这三函数（其余经 useOutfitPages/useOutfitEffects ctx 间接获得）⇒ 只改本文件 import/解构 + ref 样板。

## 3A. 实测记录（2026-10-24）

**⚠️ 调试期抓出并修复的两个缺陷（均已回归验证）**：

1. **TDZ 事故（V136 同族，首跑 modal-shell-check 32/38 抓出）**：初版把 hook 调用块放在 `useOutfitPages` 前，漏算 `useOutfitEffects`(641) 的 ctx 在**渲染期**消费 `loadOutfitPage`/`buildCurrentOutfitPageSnapshot`——原 hoisted function 声明居后无碍，改 hook 解构后 641 行引用即 `ReferenceError`，outfit 嵌入壳挂载失败（`.uploadZone` 15s 轮询超时）。base 对照 38/38 vs 改动 32/38 定位。**修复 = 调用块上移至 `useOutfitEffects` 之前**；本 hook 是纯函数工厂（内部无 React hook）⇒ 上移零 hook 顺序影响，ctx 依赖的 state/setter 全部在 275–363 声明亦早于调用点。
2. **`getClearSelection` 取函数未调用（首跑探针 24/26 抓出）**：ctx 注入 `() => clearSelectionRef.current`，hook 内 `getClearSelection();` 只取了引用没执行——切乙页时 `selectedOnB=0` 只是「乙页卡 id 不在选中集合」的巧合，切回甲页 `selectedOnA=1` 暴露。**修复 = 组件侧 `() => clearSelectionRef.current?.()`（调用语义）+ 探针断言论证**。
