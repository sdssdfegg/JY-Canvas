## 0. 为什么现在做、以及统筹的裁决

V94 交付时执行者申报：「`POST /api/canvas-assets` 前端已零调用，但 `canvasAssetDir` 仍被 `asset-urls.js` / `storage-usage.js` 引用，不得只删端点留半截」。统筹当时裁定"单列清理"，本单执行。

**统筹裁决（全链路删，不留半截）**，依据：

1. 无限画布从未上线（`SHOW_INFINITE_CANVAS=false`），前端上传入口 `uploadCanvasAssets` 已在 V94 删除 → 该端点**不可能被调用**。
2. **`data/` 目录实证无 `canvas-assets`**（当前只有 `asset-library` / `history-images` / `reference-assets` 等）→ 该目录**从未被写入过**，因此 `GET /api/canvas-asset/:filename` 那条"用于兼容历史链接"的注释**前提不成立**，一并删。
3. `storage-usage.js` 的「画布资源」统计项因此恒为 0，留着是误导。

**预期用户可见变化（本单接受）**：设置页「磁盘/缓存用量」列表少一行「画布资源」；清理按钮不再包含该目录。这是功能不存在的正确结果。
