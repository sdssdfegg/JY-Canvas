## 0. 问题

根目录 md 已从"几份说明"膨胀到 **89 份 / 1.9MB**，峰值 **20 份/天**。三种文件混在一个扁平目录里：

| 类别 | 数量 | 现状位置 |
|---|---|---|
| `V4.0-执行单-V*` | **48** | 根（含已交付的 V11~V38） |
| `V*-*-执行汇报-YYYY-MM-DD.md` 等复盘 | ~22 | 根 |

| `V4.0-修复单-BUG01` | 1 | 根 |

**根因不是"文件多"，而是三件事：**
1. **扁平** —— 待派 / 执行中 / 已完成 / 存档全混在根目录，看不出哪些是活的；
2. **无索引** —— 查一张单要在 89 个文件里肉眼扫，也没有"V号 → 状态 / commit"的对照表；
3. **命名两套制式** —— `V4.0-执行单-V31-….md` 与 `V31-…-执行汇报-2026-10-05.md` 并存，很难机器处理。

## 1. 前置调研结论（执行前请复核，别凭印象）

### 1.1 发布包不受影响 ✅（已确认，勿多虑）
`scripts/secure-win-release.mjs:479-545`：release 目录是**显式组装**的
（`exe` / `version.json` / `更新日志.md` / `使用说明.txt` / `启动（推荐）.bat` / `导出诊断日志.bat` / `tools/*`），**不整拷贝根目录**。
⇒ 内部 md 不会发给客户。本单是**内部效率/可追溯**治理，不是泄漏治理。

### 1.2 坑 1：基线会扫描根目录所有 md
`scripts/baseline/create-baseline.mjs:104` 在 `INCLUDE_ROOT_FILES` 之外，又对根目录做了一次 `entry.name.endsWith(".md")` 全扫。

**但 `docs` 已在 `INCLUDE_DIRS`（`create-baseline.mjs:36`）** ⇒ 文件迁进 `docs/` 后**仍然被快照**，不丢回滚能力。

⇒ 对策：迁移完成后**重建一次基线**（`node scripts/baseline/create-baseline.mjs`），这类"文件位置变化"属**预期变更，不算回归**。

### 1.3 坑 2：有 38 份 md 根本没进 git ⚠️
```
git status --short -- "*.md" | grep '^??' | wc -l   →   38
```
主要是 `*执行汇报-YYYY-MM-DD.md` 那批。

⇒ **迁移第一步必须先把它们 `git add`**，否则一旦移动就有丢失风险。

### 1.4 沙盒守卫
禁止批量 `rm`（`safe-delete` 守卫：单轮删除 >50 文件会卡死）。
⇒ **一律用 `git mv` 逐个移动**，严禁 `rm -rf` / 脚本批量删。

## 4. 执行步骤（三段式，各自一个 commit）

### P1 — 保命 + 迁移（纯移动，不改内容）
1. `git add` 那 38 份未跟踪 md（**先保命**），单独 commit。
2. `git mv` 逐个迁移（严禁批量删）：
   - `V4.0-执行单-V11~V38` → `docs/执行单/已完成/2026-10/`
   - `V4.0-执行单-V39-*.md` → `docs/执行单/进行中/`
   - `*执行汇报*` / `*隐患复查*` / `*自检汇报*` → `docs/复盘/`
   - `V4.0-设计-*` → `docs/设计/`
   - `V4.0-修复单-BUG01-*` → `docs/执行单/已完成/2026-10/`（或单独 `修复单/`，二选一并写明）
   - `REFACTOR_*` → `docs/存档-台账/`
3. commit：`docs: 执行单与各类 md 按生命周期归入 docs/，根目录只留常设 5 份`

### P2 — 总表 + 纪律
4. 新建 `docs/执行单/README.md` 总表，回填 V11~V39（含 V37.1 这种子版本）。
5. 在 `AGENTS.md` 追加一节《文档存放纪律》：
   1. 新单一律建在 `docs/执行单/进行中/`；命名 `V4.0-执行单-Vxx-主题.md`
   2. **交付当天**：移入 `docs/执行单/已完成/<YYYY-MM>/` + **更新总表** + 回填 commit
   3. 根目录禁止新增 md（例外：`AGENTS.md` / `README.md` 维护）
   4. 汇报类一律进 `docs/复盘/`，不得再在根生成 `-执行汇报-YYYY-MM-DD.md`
   5. 所有 md 必须 git 跟踪
6. commit。

### P3 — 基线 + 校验
7. 重建基线：`node scripts/baseline/create-baseline.mjs`
8. 跑一轮全量校验，确认：六道门禁 + cycle-scan 全绿、`vite build` 通过、`git status` 无未跟踪 md。
9. commit。
