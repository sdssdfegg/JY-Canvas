## 3. 阶段 A —— 断开联动

在 `server/routes/images.routes.js` 的 `/api/images` handler 内（`:116` 起），按以下语义加监听（具体措辞按 A0 读到的 abort API 形态调整，**保持本文件既有代码风格**）：

```js
  // V52：交互单图——客户端断开（关页面/取消）后没有理由继续打上游。
  // 批量链路（/api/generate-outfit）要跑完出结果，故意不加此监听。
  let clientGone = false;
  const onClientClose = () => {
    // 响应已正常结束时的 close 是正常尾流，不能误伤
    if (res.writableEnded) return;
    clientGone = true;
    attemptAbort?.abort?.(); // 排队阶段 attemptAbort 还是 undefined，可选调用
  };
  req.on("close", onClientClose);
```

并把 attempt 循环（`:222` 起）里的 `const abort = createAbortSignal(...)` 结果赋给 handler 作用域的 `attemptAbort`（每次 attempt 重建时同步更新），使监听器总能 abort 掉**当前** attempt。响应正常返回后 `req.off("close", onClientClose)` 清理（或依赖 `res.writableEnded` 守卫，二选一，说明理由）。

**边界语义（写进注释）**：
- 排队中被断开 → 放弃等待，不 acquire、不打上游；
- 上游 attempt 中被断开 → abort 当前 attempt，不再重试后续候选渠道；
- 响应已 flush 后断开 → 无害（图已拿到，后端该缓存缓存该保存保存，不受影响）；
- **`/api/generate-outfit` 一律不加**——批量任务的结果还要用。
