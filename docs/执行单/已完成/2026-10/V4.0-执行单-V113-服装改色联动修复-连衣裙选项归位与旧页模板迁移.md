## 0. 背景与现场（先读）

V110–V112 交付后，用户在自己的浏览器里继续按"服装改色"页实操，暴露出四个**静态门禁探不到**的问题（均属"状态 / 数据口径"类，只有真机或注入状态才能复现）：

1. **旧自定义页"联动失效"**：V111 的模板迁移只发生在**新建** custom 页时（`makeOutfitPage` 内分支）。用户已存在的自定义页（V111 之前创建、或由旧页改名而来）从 localStorage 加载时**不经过 `makeOutfitPage`**，正文若是空串或旧 recolor 默认模板，点「更换部位」chip 时 `replaceRecolorPartWords` 因"正文里没有任何部位词"而原样返回 → 表现为"点了没反应"。
2. **「连衣裙」选项来源错位**：V111/V112 的部位行直接复用换装的 `OUTFIT_PART_OPTIONS`（`src/shared/outfit-intent.js`，带 `promptLabel`、用于换装提示词编译）。改色侧真正驱动联动的是 `RECOLOR_PART_WORDS` 词表——**选项表与词表分属两个来源**，将来任一侧增删都会立刻错位（例如词表加了部位、选项表没加 → 该部位不可选）。
3. **「上装层级」选了不进提示词**：V112 明确定位为"仅记录、不改写提示词"。用户实际使用时期望层级选择也体现在通用改色提示词里（否则"内搭+外套"选了跟没选一样）。
4. **删掉的「批量改色」页以另一种方式回来**：V110 已加删除留痕，但 `ensureWorkflowPages` 里 **recolor 单例补建块仍在**；且 V110 把 recolor 名字判成 `custom` 后，给自定义页改任何含「改色」的名字都会走 `forgetDeletedWorkflowMode("recolor")` → 留痕被清 → 下一轮启动把「批量改色」补建回来。

## 1. 改动要求（回溯：执行方已按此实施）

### 1.1 部位行选项归位到单一来源（`src/features/outfit/outfit-top.js` + `OutfitComposer.jsx`）

- `outfit-top.js` 新增 `RECOLOR_PART_OPTIONS`（上装/下装/**连衣裙**/鞋子），注释写明"**UI 选项必须与 `RECOLOR_PART_WORDS` 词表一一对应**"，与词表同文件就近维护。
- `OutfitComposer.jsx` 部位行由 `OUTFIT_PART_OPTIONS` 改为 `RECOLOR_PART_OPTIONS`（import 同步调整；`UPPER_LAYER_OPTIONS` 仍取自 `shared/outfit-intent.js`）。
- 效果：改色页可选项 = 改色联动词表，**新增部位只需改一处**；换装侧 `OutfitIntentPanel` 不受影响。

### 1.2 旧自定义页加载期模板迁移（`src/features/outfit/outfit-page-actions.js`）

- `ensureWorkflowPages` 末尾（返回 `dedupeSingletonWorkflowPages(output)` 之前）加一段加载期映射：
  - 仅对 `inferOutfitWorkflowMode(...) === "custom"` 的页生效；
  - 命中条件与 `makeOutfitPage` 口径一致：正文 `prompt` 为空串、或等于 `RECOLOR_DEFAULT_PROMPT`、或等于 `RECOLOR_COLOR_LEGACY_DEFAULT_PROMPT`；
  - 命中则写入 `GARMENT_RECOLOR_DEFAULT_PROMPT` 并清空 `productNote`（旧模板自带"补充信息"语义，留着会重复）；
  - **用户手写提示词一律不动**（未命中即原样返回）。

### 1.3 彻底停用「批量改色」单例补建（同文件）

- 删除 `ensureWorkflowPages` 中的整段 recolor 补建块（`hasRecolorPage` 判定 + 插入位计算），改留说明注释：recolor 能力自 V110 起并入 custom 页、名字现判为 `custom`，该单例**退役**；**用户删除即永久消失**。
- `makeRecolorPage` → `_makeRecolorPage`（模块内私有 + `_` 前缀），保留实现以备手动建页（延续 V110"退役代码保留不删"策略），同时消除 dead-export / unused 债务。

### 1.4 改名留痕口径收窄（`src/features/outfit/use-outfit-pages.js`）

`renameOutfitPage` 原逻辑：只要改名后名字属于某 singleton 家族就 `forget`（清留痕）。收窄为：

```js
const trackedPrevMode = deletionTrackingMode(page.name, page.id === activeOutfitPageId ? uploadLabels : page.uploadLabels);
const trackedNextMode = deletionTrackingMode(name, nextUploadLabels);
if (trackedNextMode && trackedNextMode !== trackedPrevMode) forgetDeletedWorkflowMode(trackedNextMode);
```

→ **跨家族改名**（自定义页 → 「随机背景」）才解除目标家族留痕（用户主动重建）；**家族内改名**（服装改色 → 服装改色2）不再误清其它页的留痕。

### 1.5 上装层级联动提示词（`outfit-top.js` + `outfit-workflow.jsx`）

- 新增 `RECOLOR_UPPER_LAYER_WORDS`：`single: []`（无专属词，正文标记就是当前部位词）、`inner: [内搭/里搭/里层]`、`outer: [外套/外搭/外层]`、`inner-outer: [内搭和外套/内搭外套/内搭加外套/内外叠穿]`。
  - ⚠️ 注释写明**不得与 `RECOLOR_PART_WORDS` 重叠**（上衣/上装已被部位词占用）；**"内搭"是"内搭和外套"的子串，替换必须长词优先**，否则切出残句。
- 新增 `replaceRecolorUpperLayerWords(prompt, fromLayer, toLayer, partWord = "上衣")`：把正文里实际出现过的层级词（`from=single` 时即上装部位词）整体换成新层级的词；**正文没有任何层级词/部位词时不改动**（保护手写内容，与部位联动同口径）。
- `selectRecolorUpperLayer` 由"只记状态"改为"记状态 + 改写提示词"，`partWord` 取当前部位的提示词词（如选中下装时不误用"上衣"）。

### 1.6 明确不做（范围封口）

- 不动换装页 `OutfitIntentPanel` 的三行（更换部位/上装层级/穿法）与其提示词编译；
- 不动服务端（recolor 路由按页名识别的分支保持原样，两条路线提示词拼装都走 `buildUserPromptOnly`）；
- **零新增 CSS**（继续复用 `.outfitIntentRow` 系列既有类名）；
- 不清理其它遗留的 recolor 老代码（本轮只做退役与降级标记，整体清理留给后续专项单）。

## 4. 留档（统筹写入，执行方知悉）

- **裁决链延续**：V110 定"recolor 能力并入 custom 页 + 退役代码保留" → V111/V112 建改色 UI 与联动 → **本单收口四条现场缺陷**：选项表归位（可选项与词表同源）、旧页加载期迁移（补上"只在新建设时迁移"的窟窿）、单例补建彻底停用（删块 + 工厂降级私有）、改名留痕口径收窄（家族内改名不误清）。四项互为因果：第 4 项是第 3 项的根因修复之一。
- **"连衣裙不可选"表述更正（重要，防后续幻觉）**：commit message 称"修复连衣裙不可选"。统筹实测：main 上 `OUTFIT_PART_OPTIONS`（`src/shared/outfit-intent.js` L26-31）**本来就含 `{ value: "dress", label: "连衣裙" }`**，UI 上一直有且可选。**本单的真实价值是"来源归位"**——把改色部位行从换装的编译选项表切到改色自己的 `RECOLOR_PART_OPTIONS`，使"可选项"与"联动词表"同文件一一对应，杜绝将来单侧增删导致错位。后续引用本单时**不要照抄"连衣裙不可选"**，以本节为准。
- **两套词表必须分开维护**：UI 标签（`RECOLOR_PART_OPTIONS` / `UPPER_LAYER_OPTIONS`）与提示词词（`RECOLOR_PART_WORDS` / `RECOLOR_UPPER_LAYER_WORDS`）不是一套东西；层级词刻意避开"上衣/上装"以免与部位词互相污染。
- **迁移口径单一来源**：新建页走 `makeOutfitPage` 分支、老页走 `ensureWorkflowPages` 加载期映射，两处命中条件必须一致（空串 / `RECOLOR_DEFAULT_PROMPT` / `RECOLOR_COLOR_LEGACY_DEFAULT_PROMPT`）。改模板时**两处一起改**，否则老页永远停在旧模板。
- **用户态纪律不变**：本单不触碰用户浏览器已保存页面；用户改名与删页属于用户有意状态，agent 不代管、不"还原默认"。
