## 1. 需求（用户原话转译，2026-10-16 截图反馈）

1. "中间空着一行特别奇怪"——tab 行与参数行之间有大块异常空白；
2. "最下面也空了很大一块位置，要是没有东西可以靠底下去"——结果区内容不足时底部大面积留白，要求内容贴底；
3. "每一页的这些按钮高度不要出现任何偏移"——同排按钮高度必须零偏差（量测 spread=0），切页面不跳；
4. "图1~图3 的模块参考图3 的分区做成一整条，包括里面上传的图片和按钮大小"——三个上传区合并为一整条横排，样式/图片/按钮大小以图3（compact）为基准；
5. "图2 的服装事实整个都隐藏暂时不需要，包括里面的分析当前图2 和查看修改都隐藏掉"——ImageFactsPanel 停止渲染（数据不动）；
6. "变成一排后和下方的整个冻结固定的地方一起固定住"——上传横条并入底部冻结区，与参数条一起常驻；
7. "把换装设置和提示词优化美观一点减少高度，给上面的结果图多腾出点空间"——设置区/提示词区压缩密度，结果区获得最大空间。

## 3. 改动要求

### 3.1 上传三区合一横条（需求 4/6）

- `OutfitWorkbench.jsx`：`.assetGrid` 内三区改为**并列横排一整条**：图1/图2/图3 三个 `UploadZone` 同级平铺，去掉 `.assetSide` 包裹层与图1 的 `primary` 差异（三区共用 compact 基准）；`grid-template-columns: repeat(3, minmax(0, 1fr)); gap: var(--space-3)`；
- **样式单一变体**：`outfit-workflow.css` 中 `.uploadZone.primary` 专属规则（thumbGrid 10 列、height:100% 等）与 compact 差异合并——三区统一：缩略图网格列数、`.thumbCard` 尺寸、`.thumbActions` 操作钮大小全部取图3 现值（起草日实测 `--upload-columns` 与 thumbCard 量测值附回报；以"三区像素级一致"为验收）；
- 保留全部 props/行为：上传/删除/勾选/拖序/替换/裁剪/局部编辑/上限/清空/预览**一个不能少**（原样透传，只改包裹结构）；
- 各工作流对图2/图3 的条件渲染逻辑（`isOutpaintWorkflow`/`isRandomBackgroundWorkflow`/`isWhiteRefineWorkflow` 等）原样保留。

### 3.2 服装事实隐藏（需求 5）

- `OutfitWorkbench.jsx` 图2 `UploadZone` 的 `sideControls={...ImageFactsPanel...}` 摘除，改为 `null`，并在原位置留注释：`/* V76（用户要求·暂时隐藏）：图2服装事实面板停止渲染；数据/handler/组件文件保留，恢复时传回 sideControls */`；
- **不得删** `ImageFactsPanel.jsx`、`analyzeImageFacts`/`updateOutfitFact`/`factsDetailOpen` 等 state 与 handler、`outfitRecognizedFacts` 数据流（V71 已迁的该文件 `<Button>` 保持）；
- `.uploadZone.hasSideControls` / `.uploadZoneSideControls` 相关 CSS 规则本单不删（V77 按"无引用后清理"处理，回报注明已无引用）。

### 3.3 冻结区重组（需求 2/6）

- 上传横条并入冻结区：`.assetGrid` 从 `.outfitScrollArea` 移入 `.composerPanel` 顶部（或 composerStickyControls 之上，二选一以"冻结区=上传横条+意图条+页面 tab 行+参数行一条视觉整体"为准，回报附最终 DOM 顺序）；
- `.outfitScrollArea` 只包 `ResultQueue`：结果区为唯一滚动内容，**结果图获得最大可用空间**（需求 7 的落脚点）；
- 内容不足策略：结果区结果卡片网格 `align-content: start`（贴顶不拉伸）；冻结区贴底；**不允许**用 `justify-content:space-between` 之类把结果卡片拉散（需求 2：消除底部大留白的方式是"冻结贴底+内容贴顶"，不是拉伸内容）；
- 原图库（`.originalLibraryPanel`）位置不变（仍在滚动区内、上传横条之下→冻结区之上的位置关系按最终 DOM 顺序保持"结果区→原图库→冻结区"）。

### 3.4 高度阶轨与零偏移（需求 1/3）

- **行高预算固化**：控件行统一 `--control-h-md`(36) + `gap var(--space-2)`(8)；删除 `.composerHeader/.leftTools/.rightTools` 的 `min-height:72px` 两行预留，改为 `min-height: var(--control-h-md)`；随机背景页多出的 select 若导致换行，回报实测（预期不换行：V70 后 select 高度归 36 阶且参数条 flex-wrap 已有；如仍换行，报"视觉重点"select 实测宽度由统筹裁决，**禁止**回退 72px 预留）；
- **同排高度对齐**：`.outfitPageTab`、`.zoomControl > button`、`.thumbActions button`、`.imageFactToggle` 的 height 全部对齐 28/36 阶中对应的一档（与相邻 `<Button size="sm">` 并排的取 28/与 `md` 并排的取 36；起草日以同排邻居为准，回报附逐钮量测表）；
- 验收量测：换装页同排按钮高度 spread=0（浏览器量测，四主题各一遍关键排）。

### 3.5 设置/提示词压缩（需求 7）
