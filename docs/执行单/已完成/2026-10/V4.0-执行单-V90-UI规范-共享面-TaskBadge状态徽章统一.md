## 3. 改动要求

### 3.1 新建共享组件 `src/shared/ui/TaskBadge.jsx`

```jsx
export function TaskBadge({ status = "idle", className = "", ...rest }) {
  return <span className={`taskBadge task-${status}${className ? ` ${className}` : ""}`} {...rest} />;
}
```

- **status 枚举**：`idle` / `running` / `success` / `failed` / `detached`（与全局 CSS 现有 `.task-*` 对齐）。
- **不开 `size` / `tone` prop**（同 `UploadClearButton` 立下的规矩：统一视觉防分叉）；`className` 与 `...rest` 透传（V73 教训：缺 `...rest` 是已修过的偏差，不得重犯）。
- 文案由调用方以 `children` 传入，组件内**不做任何状态→文案映射**（文案来源各版块不同，映射收进组件会变成新的分叉点）。

### 3.1.1 组件登记表随行

`src/shared/ui/README.md` 是共享组件登记表（现有 Button/Modal/Panel/ModuleHeader/Field/Toolbar/UploadClearButton/ChannelPicker 等条目）。本单须**新增 `TaskBadge.jsx` 一行**，写明：用途（任务状态徽章）、API（`status` 枚举 + `className`/`...rest`）、为何不开 size/tone、建立日期与来源单号（V90，2026-10-18）。

### 3.2 7 处接入

- 逐处替换为 `<TaskBadge status={…}>{…}</TaskBadge>`；**嵌套三元原样搬进 `status` 表达式**（L167/L175 建议先提成局部变量 `const status = …;` 再传，可读性更好，但**不得改变判定逻辑**）。
- 替换后：全仓 `git grep -n "className={\`taskBadge"` = **0 命中**（验收 §4.2）。
- 补 import；`main-top-bar.jsx` / `outfit-panels.jsx` / `OutfitWorkbench.jsx` 均已 import Button（相对路径 `../../shared/ui/Button`，**注意：本仓 import 惯例不带 `.jsx` 后缀**，照抄现有写法）。

### 3.3 CSS 收口（本单的重点，逐条验收）

1. **`src/styles.css`**：`.taskBadge` 基色（L232-242）与 `.task-running/.task-failed/.task-detached`（L258-268）**保持不动**，作为唯一来源（**绝对不动清单**）。
2. **`src/outfit-workflow.css` L282-289 与 L2417-2421**：两条 `.outfitWorkflowEmbedded .taskBadge` 互相覆盖，收敛为**至多 1 条**——
   - **默认裁决**：换装归顺主应用（总纲 §12），即**两条全删**，换装区徽章走全局 `.taskBadge`（颜色由 `var(--muted)` + `color-mix(--panel-strong 88%)` 决定）。
   - 若执行日实测发现换装区**必须**保留差异（例如外壳背景导致对比度不足），则只保留 1 条最小语境覆盖（只写必要的 `color`/`background`，不重复 height/padding/radius），并在回执里附实测值 + 对比说明，**不得保留两条**。
3. **`.outfitWorkflowEmbedded .taskBadge` L246-251**（min-height/padding/font-size/white-space）：padding `0 10px` 与全局 `0 12px` 冲突 → 同上收敛（默认随第 2 条一并删；若保留则只留 padding 一项并说明）。
