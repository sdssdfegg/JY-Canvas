## 0. 问题清单

| # | 现象 | 定性 | 处理 |
|---|---|---|---|
| N1 | multer ≤2.3.0 高危（当前声明 `^2.0.2`，lock 实际解析到 **2.2.0**，在漏洞范围内） | 上传解析面（`/api/images`、`/api/generate-outfit` 的 multipart）存在已知漏洞 | 升 `^2.4.0`（统筹 2026-10-13 已核实 2.4.0 为最新正式版） |

## 2. 阶段 A0 —— 版本核对（**先查再写，npm registry 是真相源**）

> 统筹已于 2026-10-13 核实：multer 最新 **2.4.0**（现装 2.2.0，在漏洞范围内）、proxy-addr 最新 **2.0.8**（现装 2.0.7）。执行时仍须复核一遍，防止期间又有新版本：

```bash
npm view multer version          # 期望 ≥2.4.0；若出现 2.5.x 等更新正式版，写更新的，不要死守 2.4.0
npm view proxy-addr version      # 期望 ≥2.0.8
npm ls multer proxy-addr         # 当前安装版本
```

把三条命令输出贴进汇报。**若 registry 输出与统筹核实的版本矛盾**（如 multer 被弃用/改名）：停手回报，不要自行猜版本。

## 3. 阶段 A1 —— 改 package.json

只改两处，其它依赖一行不动（以下版本号为统筹 2026-10-13 核实的基线，若阶段 A0 复核发现更新正式版，以复核为准并在汇报中说明）：

1. `dependencies.multer`：`"^2.0.2"` → `"^2.4.0"`
2. 新增 `overrides` 字段（放在 `dependencies` 后面，与现有字段风格一致）：
