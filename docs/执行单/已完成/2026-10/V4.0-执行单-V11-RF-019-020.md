## 1. V11-RF-019 · 前端跨文件同名函数棘轮门禁

**目标产物**
- 新脚本：`scripts/verify/frontend-duplication-check.mjs`
- 新基线：`scripts/verify/frontend-duplication-baseline.json`（由 `tmp/RF-019-基线-候选.json` 转正）
- 共享提取逻辑：`scripts/verify/lib/frontend-sources.mjs`（**见 1-2 的"唯一一份"要求**）
- `scripts/verify/run-all.mjs` 的 `ORDER` 登记一行

### 步骤 1-1 · 复核基线口径（只读，30 秒）
- **人工操作要点**：打开 `tmp/RF-019-基线-候选.json`，确认三件事：
  ① 条数 = **104**；② `scanScope.fileCount` = **36**；③ `scanScope.files[]` 里**含 `src/shared/` 下的文件**。
- **校验要点**：三项全对。**若条数不是 104**，先别开工 —— 说明口径还在漂，把差异点汇报出来。
- **背景**：初版评估报告给的 98 是**漏扫 `src/shared/`** 得出的；用 98 上线第一天就会漏 6 个（例：第 4 份 `canvasToBlob` 在 `src/shared/local-edit-geometry.js:248`）。

### 步骤 1-2 · 🔴 提取逻辑只能有一份
- **人工操作要点**：把 `tmp/drift-audit.mjs` 里那套"抽顶层函数名 + 跨文件同名"的正则与遍历**原样搬到** `scripts/verify/lib/frontend-sources.mjs`，然后**让 `drift-audit.mjs` 与门禁都 `import` 这一份**。
- **校验要点**：全仓**只有一处**定义该正则；
  ⚠️ `tmp/` 是草稿区，**不要把共享逻辑留在 `tmp/`**（门禁不得依赖 `tmp/`）。
- **不通过怎么办**：若两边口径必须不同（例如门禁要排除某类文件）⇒ **停下来汇报**，不要在门禁里另写一份正则（那正是"两套逻辑各自漂移"的起点）。
- **附带要求**：门禁运行时**首行打印扫描范围**（root / extensions / excludes / 文件数），便于一眼看出漂移。

### 步骤 1-3 · 门禁本体
- **实现要点**：
  1. 扫描 `src/**` 的 `.js` / `.jsx`；**排除**：`node_modules`、`dist`、`tmp`、`.codex-artifacts`、`server/skill-baselines/**`（冻结快照）、任何生成物。
  2. 抽取**行首顶层函数声明**（`function NAME(` / `async function NAME(`），与 `server-duplication-check` 同款判据（不扫缩进内层函数）。
  3. **跨文件同名 = 违规**（同文件内重名单独报为异常，不拦）。
  4. **棘轮**：存量 104 条记账、**新增即失败**；`--update` 刷新基线。
  5. 违规输出**必须点名**：函数名 + 所有 `文件:行号`。
  6. 🔴 **口径自检（本单的关键设计）**：基线文件里记着 `scanScope`（root/extensions/excludes/fileCount/files[]）。
     运行时**当前口径与基线口径不一致 ⇒ 直接判红**，报"**扫描范围漂移**：文件数 X → Y"，并提示"复核新文件后跑 `--update`"。
     **理由**：`98 → 104` 那次事故就是口径漂移**静默**改变了结论；本门禁必须让这种事**当场可见**。
     为控制噪声：**只比对 `fileCount` 与 `excludes`**，`files[]` 只作留档与人工排查用（新增前端文件属正常事，不必每次都炸）。
- **校验要点**：脚本自身 lint 干净（新文件 = 棘轮新 key）；**不 import 任何业务模块**（只 `fs` 读文本）。
- 🔴 **头注释必须写明边界**（否则名字会被误读）：
  - 本门禁覆盖 **camelCase 顶层函数**；
  - **PascalCase React 组件**由既有 `shared-ui-duplication-check` 覆盖（两者**允许重叠**，重叠不代表冲突）；
  - **不做任何自动修复**（"把 4 份 `canvasToBlob` 收成 1 份"属前端专项阶段 B，是另一批单）。

### 步骤 1-4 · 登记 `ORDER` + 基线转正
- **人工操作要点**：`ORDER` 里 `"frontend-duplication-check"` 放在**前端检查那一批**（`shared-ui-duplication-check` / `ui-duplication-check` 附近，**紧邻**前者以便人工对照）。
  基线从 `tmp/RF-019-基线-候选.json` 转正为 `scripts/verify/frontend-duplication-baseline.json`（内容可原样搬，`generatedAt` 更新）。
- **校验要点**：`--list` **37 → 38**；`run-all-check` 的"顺序表覆盖所有磁盘脚本"不报漏登记。

### 步骤 1-5 · 🔴 负向验证（**两条，都要做**）
- **负向 A（新增重复必须红）**：临时把 `src/image-editor.jsx` 里的 `canvasToBlob` 复制一份到 `src/shared/local-edit-geometry.js` **改名不改逻辑的冗余副本**？不行 —— 直接**再造一处同名**：把某文件的 `canvasToBlob` 整段复制进另一个前端文件 → 门禁必须变红并点名**两处及以上** `文件:行号` → 逐字节还原。
