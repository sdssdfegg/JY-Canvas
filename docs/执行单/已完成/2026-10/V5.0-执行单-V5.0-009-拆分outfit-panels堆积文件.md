**探针调试实录（两条硬教训，已写入门禁/记忆）**：

1. **IDB 注入必须形状自感知**：探针 profile 的 `jingyin-outfit-workflow-local-v1` store 曾被旧探针
   建成 out-of-line（无 keyPath）形状，而 app 自己建的是 `keyPath:"key"`（outfit-task.js:918）。
   `put({key,value,updatedAt})` 在 out-of-line store 上**同步抛 DataError**（pageerror 可见），
   且若 Promise 无护栏会直接挂死到 CLI 180s 硬杀、零诊断。正解：先探 keyPath，形状错则
   deleteDatabase 重建（delete 被挡则降级 out-of-line 兼容写），所有连接必须 close。
2. **双层导航模型**（本单最大认知修正）：`.navItem` 是**主壳**导航（AppSidebar，快捷生成=主画板
   quickgen、提示词助手=PromptAssistantView 模态不切视图、批量改尺寸=顶层 BatchResizePanel）；
   本单拆分的六类面板全在 **outfit 嵌入壳的内侧边栏**（WorkbenchSidebar，`.outfitWorkflowEmbedded
   .sidebar nav button`）各视图里。且 dev 默认视图=quickgen ⇒ outfit 壳不在 boot 时挂载；
   E8 草稿 hydration 是异步的，chip 断言必须轮询等它完成（P6 cards=2 才是终态证据）。
3. dev 冷编译整图 ~16s（实测 goto1=15961ms）而 CLI 单次 evaluate 硬上限 180s ⇒ 探针必须
   两阶段（warm-up goto 先把 vite 模块图编译热，server 常驻内存），真实段总耗时 ~12s。
