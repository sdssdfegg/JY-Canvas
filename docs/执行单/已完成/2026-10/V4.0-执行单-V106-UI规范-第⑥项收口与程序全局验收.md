## §2 实测调查（证据）

### §2.1 `ui.css` 33 hex —— 全部 `var()` 回退，非硬 hex
`git grep` 逐行核对：`ui.css` 全部 33 处 hex 均位于 `var(--token, #hex)` 的**回退位**（如 `var(--accent, #13d2c3)` / `var(--muted, #a1a6ba)` / `var(--panel-strong, #1e1f2e)` / `color-mix(in srgb, var(--danger, #f05252) 24%, transparent)`）。
- 这些回退**仅在 token 未定义时生效**，而 `tokens.css :root` 已定义全部 token → 运行时永不渲染回退值。
- `hardcoded-color-check`（V74）对 `var(--x, #fallback)` 语法**豁免**（或已计入基线），不判红。
- **裁决：合规，零改动。**

### §2.2 `styles.css` 61 hex —— 语义/品牌色，无 1:1 令牌等价
抽样（L160–L3786）分类：
- **金色渠道高亮**：`#fbbf24`（L1241/1246/1247/1296/1307/1308/1638/1647/1651/1652）、`#f2bc74`（L1145/1146/1147）—— 渠道选择器的"当前渠道"语义色，**刻意区别于 `--accent`（青）**，替换为 `--accent` 会改变语义。
- **强调文字对比色**：`#061515`（L957/3150/3203/3254/3274）—— 青色强调底上的文字色（旧 `#1fcfc3` 强调的 `accentText`），与现 token `--accent-text` 同义但作用域不同。
- **近黑背景**：`#050708`/`#030404`/`#050505`/`#050507`/`#11131d`/`#141622` —— 深色模式专用底，与 `--app-bg` 取值不同（更纯黑），非简单替换。
- **color-mix 混合端点**：`#111111`/`#000000`/`#ffffff` 在 `color-mix(in srgb, var(--accent) 82%, #111111 18%)` 内 —— 是**明暗混合终点**，非独立色，无令牌等价。
- **纯白 `#ffffff`**：多处 `color`/`background`（L454/510/528/600/637/678/701/726/861/887/903/1537/1884/3222/3678） —— 白底/白字，白常无专用令牌（或 `--surface` 语义不符）。
- **状态/警示色**：`#ff8a00`（橙警示 L160）、`#49c85b`（绿 L2536）、`#ff6363`/`#ffb4b4`/`#ff8080`（红 L2694/3481）、`#ffd9a0`（L2915）、`#ff8f8f`（L487）—— 状态语义色。
- **裁决：均为有意语义/品牌色，无干净 1:1 令牌映射；批量替换会引发色偏（金→青、暗→token 值不同），高视觉风险。V74 设计即"存量只报 improved、只拦新增"，本仓存量已 baseline 记账 → 保持为可接受基线，不强行清扫。**

### §2.3 `outfit-top.js` `themeToVars` —— 刻意的独立子主题（非遗留 bug）
- `themeToVars(theme)`（L684–760）定义 **4 主题 × 17 色**的调色板（dark/jade/graphite/mist），由 `outfit-workflow.jsx:587` `useMemo` 计算后于 L588–604 **以同名 CSS 变量作用到换装根节点**（`--accent`/`--text`/`--border`/`--danger`/`--app-bg`…，与全局 token **同名**但**局部覆盖**）。
- 换装模块另有**自己的主题选择器**：`THEME_OPTIONS`（L502–507，暗夜/柔粉/米杏/浅雾，各带色卡）+ `defaultSettings.theme`（L645）+ `normalizeTheme`（L681）。即换装的"主题"是**独立于主应用 `data-theme` 的模块级设置**。
- 所谓"不随主应用 data-theme 联动"是**设计使然**（换装用户可单独选 暗夜/柔粉/米杏/浅雾，且四主题强调色 pink/gold/teal 与主页不同，是换装模块的刻意视觉身份）。`THEME_OPTIONS` 的 `colors` 色卡（L503–506）是给选择器预览用的硬编码样本。
- `outfit-image-pipeline.js` 的 `ctx.fillStyle = "#ffffff"` ×3 是 **canvas 绘制底色**（非 UI 令牌，属运行时绘图语义），与令牌体系无关，留。

## §3 裁决（统筹自行裁决，留档备查）

1. **换装旧令牌（themeToVars）**：**保留**为刻意的局部 token 覆盖（ratchet 豁免例外，写入总纲 §9 注释与 MEMORY）。理由：① 它是带独立用户选择器的功能，删之等于删功能 + 抹掉换装视觉身份（粉/金/青 → 主页强调色），属产品设计决策而非清理；② 换装**复用 token 契约（同名变量）**，只是局部作用域覆盖——符合"令牌层单一来源（tokens.css 定义）+ 局部覆盖"的合法模式；③ V69 已把 `:root` 收为单一来源，本项不冲突。
   - ⚠️ **可推翻项**：若日后产品决策要"换装跟随主页主题"，应改为删除 `themeToVars` + 换装根节点去掉同名变量覆盖 + 移除 `THEME_OPTIONS`/`theme` 选择器（届时是一张破坏性单子，须先与产品确认）。
2. **hex 存量收口**：**不做盲扫**。`ui.css` 33 = 合规回退值；`styles.css` 61 = 有意语义/品牌色无 1:1 令牌；V74 棘轮已**只拦新增**、存量 baseline 记账，无新回归风险。保持为可接受基线。
3. 第⑥项据此**收口为"设计裁决 + 文档化例外"**，无源码改动。
