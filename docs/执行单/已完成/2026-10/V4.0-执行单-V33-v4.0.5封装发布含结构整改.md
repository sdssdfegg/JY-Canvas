## 0. 本次要解决的问题（客户视角，统筹已实测取证）

v4.0.4 的发布包里有两处会让客户误判的地方：

| # | 现象 | 实测取证 | 裁决 |
|---|---|---|---|
| 1 | 根目录出现**两个同名**的「导出诊断日志」（一个 `.bat`、一个 `.cmd`） | 源码 `scripts/secure-win-release.mjs:432-433` 把**同一段** batch 内容写了两遍，文件名完全相同（Explorer 默认隐藏扩展名 ⇒ 显示成两个一模一样的名字） | **保留两份**（`.bat` 被安全软件拦截时 `.cmd` 是唯一退路），但把 `.cmd` **改名为「导出诊断日志（备用）.cmd」** |
| 2 | 根目录「静音AI画板.ico」与「静音AI画板.exe」**同名**，客户可能把 ico 当启动器双击 | 发布工程 `build.mjs:58` 用 `${productName}.ico` 命名；实测该 ico 只是桌面快捷方式的图标源（101 KB） | **移入 `tools\` 并改名为 `tools\静音AI画板-图标.ico`** |
| 3 | 根目录 `export-diagnostics.ps1` 是英文技术脚本，客户不该看见 | 只被诊断 bat 调用 | **一并移入 `tools\`** |

### 🔴 连带必须做的修复（不做会让整改结果更乱）

发布工程 `build.mjs` 的 `makePatch()` **已经算出** `removed`（本版被删除/改名的旧文件）并写进 `patch-manifest.json`，
但 `tools/apply-update.ps1` **从未读取它**（实测 `grep 'removed\|Remove\|删除'` 零命中）。
⇒ 只改名不补链路，v4.0.4 用户升级后会**原地残留**旧文件：根目录同时存在 `导出诊断日志.cmd`（旧）与
`导出诊断日志（备用）.cmd`（新）—— 比现在更乱。

**本单必须让更新器具备"按 removed 清单清理废弃文件"的能力，并在升级演练里验出该行为。**

### B3. `tools/apply-update.ps1`：新增 removed 清理能力

**改动 1** —— 在 `param(...)` 块之后、`$ErrorActionPreference = 'Stop'` 之后新增安全解析函数：

```powershell
# 只接受「包内相对路径」：拒绝绝对路径与 .. 穿越。
# 清单是本工程自产的，但不能假设它永远可信（清单一旦被替换，删除面就失控）。
function Resolve-PackagePath([string]$rel) {
    if ([string]::IsNullOrWhiteSpace($rel)) { return $null }
    if ([System.IO.Path]::IsPathRooted($rel)) { return $null }
    $norm = $rel.Replace('/', '\').TrimStart('\')
    if (($norm -split '\\') -contains '..') { return $null }
    return (Join-Path $PackageDir $norm)
}
```

**改动 4** —— 步骤 3「备份旧文件」（L149-163）末尾（`Write-Host "  ✓ 已备份 $backedUp 个文件"` 之后）新增：

```powershell
# 被废弃的文件同样进备份：回滚时才有东西可还原。
$backedUpRemoved = 0
foreach ($rel in $removed) {
    $target = Resolve-PackagePath $rel
    if (-not $target -or -not (Test-Path $target)) { continue }
    $dest = Join-Path $backupDir ($rel.Replace('/', '\'))
    $d = Split-Path -Parent $dest
    if ($d -and -not (Test-Path $d)) { New-Item -ItemType Directory -Path $d -Force | Out-Null }
    Copy-Item -Path $target -Destination $dest -Force
    $backedUpRemoved++
}
if ($backedUpRemoved -gt 0) { Write-Host "  ✓ 其中 $backedUpRemoved 个是本次要废弃的旧文件（已一并备份）" }
```

**改动 5** —— 步骤 4 之后（L190 的 `}` 之后、`Write-Host ''` 之前）新增：

```powershell
# ── 步骤 5：清理本版已废弃的文件（改名/移除的旧文件）───────────
# 单独 try/catch：删不掉一个废弃文件不该把整个更新判失败。
$deleted = 0
if ($removed.Count -gt 0) {
    Write-Host "[清理] 移除 $($removed.Count) 个已废弃文件…"
    foreach ($rel in $removed) {
        $target = Resolve-PackagePath $rel
        if (-not $target -or -not (Test-Path $target)) { continue }
        try { Remove-Item -Path $target -Force; $deleted++ }
        catch { Write-Host "  ⚠ 无法删除 $rel（$($_.Exception.Message)）" -ForegroundColor Yellow }
    }
    Write-Host "  ✓ 已清理 $deleted 个"
}
```
