## 5. 必须回答的 6 个问题

### Q1 自由标识符清单（最重要）

逐个组件列出它引用的**模块级**名字（常量 / 函数 / 类型），不含 React、不含 props、不含组件内局部变量。
⇒ 这是判定"能否单向搬"的唯一依据。

### Q2 循环依赖定性（🔴 本单最大风险）

若组件依赖 `outfit-workflow.jsx` 本体的 helper，抽出去后会形成：

```
outfit-workflow.jsx → outfit-panels.jsx → outfit-workflow.jsx   （环）
```

必须明确回答：环是否成立？若成立，三选一并论证：

- (a) 相关 helper 一并随迁到新文件（推荐，保持单向）
- (b) helper 下沉到 `src/shared/`
- (c) 判不可搬，本组件剔除出清单

### Q3 `PromptPresetGrid` 的硬约束

源码里已有注释约束：**必须定义在模块顶层**。
挪进组件体内会因每次 render 重建类型，导致**失焦 / 拖拽态重置** bug（RF-078-b 血案）。
⇒ 搬到新文件后**仍须是该文件的模块顶层**，不得变成别的组件的内部定义。本单要确认这一点。

### Q4 落点与 `fileCount` 代价

- **方案甲**：5 个组件合进一个 `src/features/outfit/outfit-panels.jsx` ⇒ **+1 个文件**（59→60）
- **方案乙**：拆 5 个独立文件 ⇒ **+5 个文件**（59→64）

⇒ `fileCount` 是记账项，需统筹批。给出推荐方案并论证性价比。

### Q5 形态

组件是模块顶层定义、不依赖组件 state ⇒ 走**普通模块导出**（`export function Xxx`），
**不需要** B3 工厂（`createXxx(deps)`）。但搬出后必须 `export`、原位必须补 `import`。

### Q6 复现 `buildTasks` 教训（🔴 必做，不许只看缩进）

RF-079 已纠正：**column-0 的文本缩进 ≠ 词法作用域**。
`buildTasks`(73) / `modelForIndex`(5) 写在 column 0，实为**组件内部**函数（column-0 的 `}` 全文件只有两处）。

⇒ 本单**必须做自由标识符 / 闭包抽测**来确认这 5 个组件是真模块顶层。
任何只靠 `indent=` 得出的"顶层"结论都无效。
