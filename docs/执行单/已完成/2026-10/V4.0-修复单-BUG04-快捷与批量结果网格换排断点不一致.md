# V4.0-修复单-BUG04：快捷生成与批量生成结果网格换排断点不一致

> 类型：修复单（V138 后续） · 提交 `a34f26a` · 归档日期：2026-10-28
> 关联：`V4.0-执行单-V138-标注式AI编辑.md`（卡片尺寸统一的三~五轮即本单前身）

## 0. 一句话结论

快捷生成画廊与批量生成结果网格的**卡片尺寸早已统一**（真相源 `GALLERY_CARD_MIN_BASE=176`），但缩窗到某些宽度时仍「一边先换排、另一边差一点距离才换」。根因是**两侧布局引擎不同 + 输入的"可用宽"不同**（差约 20px），改由 **JS 用同一函数算列数**后两侧口径结构性一致。

## 1. 现象

- 同一张结果图在快捷生成与批量生成里显示大小一致（V138 三~五轮已统一）。
- 但把窗口缩到某个宽度时：**一侧先掉一列（换排），另一侧还保持原列数**，要再缩一点才换。
- 属"差一点距离"的小偏差，非整档错位。

## 2. 根因

| | 快捷 `.galleryStrip`（`styles.css:328`） | 批量 `.taskGrid`（`outfit-workflow.css:679`） |
|---|---|---|
| 布局引擎 | `flex-wrap` | `grid auto-fit` |
| gap | 12px | 12px |
| 卡片宽 | `--asset-card-min` | `--asset-card-min` |
| 自身横向 padding | 8px（**仅右**） | 8px（左右各） |
| 滚动条预留 | `scrollbar-gutter:stable` + **9px** 自定义滚动条 | 外层 `.outfitScrollArea` + **~15px** 默认滚动条 |

**列数公式其实完全相同**：`N = floor((可用宽 + gap) / (卡宽 + gap))`；gap 与卡宽都已由 `src/shared/gallery-layout.js` 统一。**差异 100% 来自"可用宽"不同**——两边 padding 链与滚动条预留差约 20px，正好压在换排阈值附近。

> 🔴 教训：**"共用常量"不等于"共用行为"**。卡片宽和 gap 统一了，但可用宽没统一 ⇒ 阈值照样错档。要真正一致，必须让两侧**输入同一个计算**。

## 3. 修复（方案 B·根治）

1. **`src/shared/gallery-layout.js`**（零依赖叶子）
   - 新增 `GALLERY_GAP_PX = 12`（两侧间距唯一真相源）
   - 新增 `computeGalleryColumns(availableWidth, cardMin, gap)`：纯函数，`max(1, floor((width+gap)/(card+gap)))`；宽度未知返回 0（调用方保持 CSS 兜底）。
2. **新增 `src/shared/use-gallery-columns.js`**
   - `ResizeObserver` 观测容器，量**内容宽** = `clientWidth − paddingLeft − paddingRight`（两边口径一致，天然排除滚动条与边框）
   - 用同一函数算列数，写入 `--gallery-columns`。
3. **两个面板接线**：`main-canvas-board.jsx`（`quickGalleryRef`）与 `ResultQueue.jsx`（`taskGridRef`）各自调用该 hook。
4. **CSS 两侧统一读同一变量**
   ```css
   grid-template-columns: repeat(var(--gallery-columns, auto-fit), var(--asset-card-min, 176px));
   ```
   - 未注入时退回 `auto-fit`，与改造前行为一致 ⇒ **不会闪成单列**。
   - 快捷侧新增 `.galleryStrip.galleryStripColumns` 改 grid（双类选择器优先于 `.galleryStrip` 的 `display:flex`）；**视频 `.videoGalleryStrip` 不带本类，仍是 flex，不受影响**。
