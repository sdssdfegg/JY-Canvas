### 4.1 新增组件（模块顶层）

🔴 **必须定义在模块顶层**，`OutfitWorkflow` **之外**。
**绝不能**定义在 `OutfitWorkflow` 函数体内部 —— 那会每次 render 重建组件类型 ⇒ React 卸载重挂子树 ⇒
输入框失焦、拖拽态重置等真实 bug。

- 用 `function Xxx(props) {}` 声明（**不要用箭头函数赋给 const** —— `function` 声明会提升，位置不受限，避免 TDZ）。
- 建议落位：`5727 export default function OutfitWorkflow` **之前**（紧邻主组件，易读）。

### 4.2 props 清单（统筹实测扫出的自由标识符，约 19 个）

### 4.3 改巨石 —— 三条铁律

1. 🔴 **禁止用 Edit 类工具整文件改写** `outfit-workflow.jsx`（CRLF→LF 会导致万行级 diff）。
   ⇒ 用 **node 脚本按锚点打补丁**。
2. 🔴 **逐行保留行尾**：`split("\n")`（**不能** `split(/\r?\n/)`），`t` 剥尾 `\r` 记 `cr`，
   写回时 `t + (cr ? "\r" : "")` 再 `join("\n")`。
3. 🔴 **自检 `CRCR=0`**，且**纯 LF 行数 delta = 0**（该文件本就存在一批 mixed 行尾，不许因为你的改动变化）。

锚点判据用 `startsWith`；插入判断写在 `drop.has(i) continue` **之前**；**插入段本身也要进 drop 集合**（RF-071 教训）。

## 5. 对照组（必须落 `scripts/dev/`，不得用 `tmp/`）

新建 **`scripts/dev/rf078b-control.mjs`**，必须包含：

1. **等价性主证**：抽出的组件在两处调用点传入**完全相同**的 props 值（逐项断言 props 表达式文本两侧一致）。
2. **单一来源反证**：临时改组件内一处文案（如搜索框 `placeholder`），**两个调用点的渲染输出都必须改变**；
   改回后恢复。⇒ 证明两处真的共用同一份，而不是各写一份。
3. **零分叉反证**：组件体内**不存在**任何 `mode` / `isDock` / `isModal` / 三元区分两侧的分支（grep 必须为 0）。

4. **props 完整性**：以 `no-undef` 为准，组件体内无未声明标识符。
5. **负向对照**：故意在组件内删掉一个必传 prop 的解构 ⇒ 必须报错/断言 FAIL（证明 harness 灵敏，不是恒真断言）。

对照组输出格式沿用既有：`ALL PASS` / 逐条 `PASS|FAIL name`。
