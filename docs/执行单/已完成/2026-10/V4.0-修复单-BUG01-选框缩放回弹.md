## 1. 现象

局部回帖选框，用鼠标**慢慢**拖动角柄放大/缩小时，框会忽然「弹一下」——
突然变大一点或变小一点。快速沿单一方向拖不明显。

## 3. 根因（统筹实测，含可复现数值）

### 3.1 出问题的代码

`src/shared/local-edit-geometry.js`：
- `resizeRectFromCornerLocked`（**L185-208**，病点在 **L198-200**）
- `resizeRectFromCenterLocked`（**L211-232**，病点在 **L222-224**，Alt 缩放同源）

```js
// L197-201（Center 版在 L221-225 逐字相同）
const widthFromHeight = (desiredHeight * ratioWidth) / ratioHeight;
const driven = Math.abs(deltaX) >= Math.abs(deltaY)
  ? Math.max(1, desiredWidth)      // 宽驱动
  : Math.max(1, widthFromHeight);  // 高驱动
```

### 3.2 为什么这里会跳

调用侧语义（`crop-drag.js:62-74`）：

- `drag.rect` 在 `beginCropDrag` **一次性冻结**（拖拽起点选框）；
- `deltaX / deltaY` 是**从起点累计的总位移**。

⇒ 不是取整累积误差，而是 **`driven` 是一个分段函数，在 `|deltaX| == |deltaY|` 处存在跳变**：
两个分支对**同一个鼠标位置**算出**不同的尺寸**，而由谁算取决于累计位移哪个更大。

### 3.3 实测复现（用真实模块跑出来的数字）

场景：图 1200×1800，比例 `2:3`，起始选框 400×600，拖 `se` 角柄向内收。

| 帧 | deltaX / deltaY | 走哪个分支 | 结果 |
|---|---|---|---|
| A | −50 / −49 | \|dx\| ≥ \|dy\| → **宽驱动** | **350 × 525** |
| B | −50 / −51 | \|dx\| < \|dy\| → **高驱动** | **366 × 549** |

> **鼠标只多动了 2px，选框宽度跳了 16px** ← 这就是肉眼看到的"弹一下"。

连续轨迹扫描（200 帧，每帧鼠标仅动 ~1-2px，叠加 ±1px 抖动模拟手抖）：

| 指标 | 实测 |
|---|---|
| **最大单帧宽度跳变** | **41px** ❌ |
| 比例失真帧数 | **0** ✅（⇒ 比例约束本身没问题，**病根纯粹是连续性**） |

### 3.4 为什么"慢慢拖"才明显

快速沿单轴拖 ⇒ 一个 delta 始终占优，永远不交叉。
慢慢拖 / 斜着拖 ⇒ 两个累计位移量级接近，**反复穿越 `|dx| ≥ |dy|` 边界**，于是反复跳变。

## 4. 修复方案（三选一，统筹已实测评估）

### ❌ 方案甲：`Math.max(宽驱动, 高驱动)` —— **不可采用**

连续函数取 max 确实消掉跳变，但有致命反例（**已实测**）：

> 纯水平向内拖（dy = 0，dx = −60）：宽驱动给 340，高驱动给 400（dy=0 ⇒ 高不变），
> `max` 取 400 ⇒ **框完全不缩小**。

单向拖拽彻底失效，故否决。

### ✅ 方案乙：沿「比例对角线」投影（**备选**，已验证达标）

把 `(moveX, moveY)` 投影到比例方向向量 `(rw, rh)` 上，得到单一连续公式：

```js
const moveX = deltaX * directionX;
const moveY = deltaY * directionY;
const deltaWidth = ((moveX * ratioWidth + moveY * ratioHeight) * ratioWidth)
                 / (ratioWidth * ratioWidth + ratioHeight * ratioHeight);
const driven = Math.max(1, sourceRect.width + deltaWidth);
```

实测（同一条 200 帧轨迹）：**最大跳变 41px → 1px**，比例失真 0，越界 0 ✅

⚠️ **代价**：纯单向拖拽灵敏度下降 —— `2:3` 竖框纯水平拖 +100px 只到 **431**（31%）。
沿比例对角拖 `(+100,+150)` 精确跟上（500）✅。
⇒ 若判定手感变迟钝，改走方案丙。

### 🎯 方案丙：一次拖拽内锁定驱动轴（**推荐**）

保留现有"主导轴"手感（100% 响应），只在一次拖拽里**不许中途翻转**：

1. `crop-drag.js` 的 `moveCropDrag`：累计位移超过死区（建议 3px）时**首次**定轴并写进 `dragRef.current`：

   ```js
   if (drag.drivingAxis === undefined && Math.hypot(deltaX, deltaY) >= 3) {
     drag.drivingAxis = Math.abs(deltaX) >= Math.abs(deltaY) ? "x" : "y";
   }
   ```
2. 把 `drivingAxis` 透传给 `resizeCropRectFromCorner / FromCenter`（`crop-rect-resize.js`）。
3. `local-edit-geometry.js` 两个 Locked 函数把 switch 换成：

   ```js
   const driven = drivingAxis === "y" ? widthFromHeight : Math.max(1, desiredWidth);
   ```

   参数**默认 undefined ⇒ 行为回落旧逻辑**，向后兼容，不影响其他调用方。

优点：尊重用户已有手感（只修 bug 不改行为），原理上彻底消除中途翻转。
代价：需改 3 个文件 + drag 状态加一个字段。

## 5. 验收判据（硬性，必须量化交付）

交付前必须提供**实测数字**，不是"我觉得好了"。

把下面这段跑一遍（它就是本次用来复现的探针，改完应转绿）：

```js
import { resizeRectFromCornerLocked, resizeRectFromCenterLocked } from "../src/shared/local-edit-geometry.js";
const sourceRect = { x: 200, y: 300, width: 400, height: 600 };
let prev = null, maxJump = 0, ratioBad = 0, outOfBounds = 0;
for (let i = 0; i < 200; i++) {
  const t = i / 199, base = -120 * t, jitter = i % 2 === 0 ? 1 : -1;
  const r = resizeRectFromCornerLocked(sourceRect, "se", base + jitter, base - jitter, "2:3", 1200, 1800);
  if (Math.abs(r.width / r.height - 2 / 3) > 0.02) ratioBad++;
  if (r.x < 0 || r.y < 0 || r.x + r.width > 1200 + 0.5 || r.y + r.height > 1800 + 0.5) outOfBounds++;
  if (prev !== null) maxJump = Math.max(maxJump, Math.abs(r.width - prev));
  prev = r.width;
}
```

| 指标 | 修复前（现状） | 修复后必须达到 |
|---|---|---|
| **最大单帧宽度跳变** | **41px** | **≤ 6px** |
| 比例失真帧数 | 0 | **0**（不得退化） |
| 越界帧数 | 0 | **0**（不得退化） |

同时 `resizeRectFromCenterLocked`（Alt 中心缩放）必须**同源修复**并跑同一组断言。
