## 6. 回收站 `.lock` 防线（硬性·2026-10-16 修订）

**根因（已取证，勿再误判）**：`.lock` **不在工作区产生**。它是 "safe-delete / 软删除" 类工具在批量删除时，于 `%TEMP%\codebuddy-safe-delete-bulk\<hash>\` 下自建的作业锁目录；作业完成后该工具又把整个 temp 作业目录丢进回收站，于是 `.lock` 以 `$R*.lock` 形式堆进 `C:\$Recycle.Bin\<SID>`。实测 C 盘回收站 `...-1001` 顶层 15531 项中 `.lock` = **15494**；抽样 400 个 `$I*.lock` 索引，**400/400 来自 `codebuddy-safe-delete-bulk`**；删除时间集中在执行窗口（10-16 05 点单小时 6054 个）——**谁用 safe-delete，谁造垃圾**。
旧口径「扫工作区 `.lock` 并报 0」恒为 0、形同虚设，**自本修订起废止**。

三条硬纪律：

1. **禁用软删除**：本单全程**禁止**使用 safe-delete / 移入回收站 / 任何"先暂存再删"的批量删除封装。删除一律用 PowerShell 原生 `Remove-Item -Recurse -Force` 或 node `fs.rmSync(p,{recursive:true,force:true})`。
2. **收尾清场**（两处都清，两处都报数）：`%TEMP%\codebuddy-safe-delete*` 残留目录 → 0；回收站 `.lock` 计数 → 0。
3. **回报改口径**：回报必须附**回收站 `.lock` 计数**（C 盘 `S-1-5-21-...-1001`），且**不得高于执行前基线**。

复制即用（PowerShell 原生，勿经任何封装）：

```powershell
$bin = 'C:\$Recycle.Bin\S-1-5-21-511319357-3548521711-479395384-1001'
# 核对（执行前 / 执行后各跑一次）
(Get-ChildItem $bin -Force | Where-Object { $_.Name -like '*.lock' }).Count
# 清理：只删 .lock，非 .lock 项一律保留
Get-ChildItem $bin -Force -Filter '*.lock' | Remove-Item -Recurse -Force
Get-ChildItem $env:TEMP -Directory -Force -Filter 'codebuddy-safe-delete*' | Remove-Item -Recurse -Force
```
