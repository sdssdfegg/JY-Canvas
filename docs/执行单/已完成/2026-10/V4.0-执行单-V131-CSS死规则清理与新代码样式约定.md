## 0. 现状取证与诊断修正（2026-10-22 实测，重要）

原担忧「两个全局 CSS 文件是一团乱麻/串味根因」——实测后**诊断需要修正**：

1. **`outfit-workflow.css`（4531 行）已被天然作用域化**：728 条规则全部以 `.outfitWorkflowEmbedded` 前缀开头（单个容器作用域），不会污染其他视图——它是「大」，但不是「串味源」；
2. **`styles.css`（4041 行）的类名是跨 feature 共享词汇表**，不是各 feature 私有：如 `.detailFormSection`/`.detailField` 同时被 detail 与 reference-remix 使用，`.detailUploadBox`/`.detailThumb` 在 shared 组件里，`.referenceThumb` 被 main-app + 探针使用——**按前缀机械拆分会直接拆墙**；
3. **CSS Modules（类名编译期重命名）不可取**：探针依赖全局类名（`navItem`/`composerStatus`/`detailUploadBox`/`detailPresetRow` 等），机械转换会让门禁探针全灭；
4. **仓库已有正道先例**：`outfit-intent.css`/`retouch-intent.css`/`white-refine-split.css` 就是「feature 目录内建分区 CSS、全局类名、按 feature 导入」的模式（outfit-intent.css 头注原话：「不塞进已经很大的 outfit-workflow.css，避免和其它分区样式互相影响」）。

**结论：CSS「模块化」的正确形态 = ① 清死规则（本轮）② 新代码一律走 feature 分区 CSS 先例（本轮立约定）③ 存量拆分留待后续按簇逐片验证（不本轮做）**。
