## 3. 改动要求

**推荐路径（最小侵入）：`userChoice === "off"` 时让 `stylePackForGroup` 返回 `{ pack: null, groupIndex, reason: "用户关闭视觉风格" }`，并让下游把「pack 为 null 的 decision」等价当作「无风格包」处理。**

1. `prompts/server/detail-skills-v2/index.js`：
   - `stylePackForGroup`（`:18-35`）加 off 分支：`userChoice === "off"` → 直接返回 `{ pack: null, groupIndex, reason }`（**不进入轮换、不进平台禁配回落**）。
   - `buildSkillPackV2`（`:54-91`）与 `buildStylePackRound`（`:93-99`）补 pack 判空（off 时返回不含 stylePack 字段或返回 null——选一种并在回报写明，保证 `detail-ai.js:107` 不抛）。
2. `server/detail-middleware.js`：
   - `:451-453` 后加一行归一：`styleDecision = styleDecision && styleDecision.pack ? styleDecision : null`（把 off 等价为"无风格包"），**下游 `:495 / :524 / :579 / :609 / :612-620` 的既有判真分支即可全部复用，无需逐处改**；
   - **`:495` 首屏强制 S1 逻辑随 styleDecision 为 null 自然关闭**（这正是"off 含首屏 S1 一起关"的裁决语义），不要在首屏单独写死 S1。
3. `server/detail-ai.js`：`:89-96` 处 off 时令 `v2Context = null`（复用 `:70` 早返回路径），或给 `:106-110` 判空——二选一，回报写明。
4. 前端：
   - `detail-state.js:99-109` 选项列表头部加 `{ value: "off", label: "关闭视觉风格" }`（放在 auto 之前或之后自定，回报附截图说明）；
   - `detail-group.js:289` 归一化放行 `"off"`（正则改为 `off` 或 `^S[1-8]$` 二选一分支）；
   - v1 下下拉仍 disabled（`:253` 行为不变）。
5. **v1 逐字节不变（硬验收）**：v1 路径 `styleDecision` 恒为 null，本单任何改动不得触碰 v1 输出；沿用 v2-1 的验证手法（stash 旧码 vs 新码 JSON 比对 IDENTICAL）。
