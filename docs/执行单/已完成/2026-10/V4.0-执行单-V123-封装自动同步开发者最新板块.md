# V4.0-执行单-V123-封装自动同步开发者最新板块

> 派发日期：2026-10-21 ｜ 派发依据：用户 2026-10-21 诉求（原话纪要）：
> "我的源码功能都是通过让 AI 执行修改优化的，但是每次封装的时候 AI 却只能封装成它固定的页面板块，没有按照我更新的最新板块内容来。既然源码都是 AI 做的，那就不应该说不能更新我最新的内容、需要我做种子的方式更新。"
> 本单目标：把"手工种子搬运"改为**「应用内一键同步 → 仓库封装配置 → 封装自动读取 + 缺失硬失败」**，让 AI 封装会话天然带上开发者最新板块/模板/设置。

---

## 0. 现状取证（2026-10-21 实测，行号以此为准）

### 0.1 用户"最新板块"的真相在浏览器，不在源码仓

- 页面集持久化于浏览器 localStorage `jingyin-outfit-workflow-pages-v1`（`OUTFIT_PAGES_KEY`，读取 `src/features/outfit/outfit-page-actions.js:632 readOutfitPages`，启动经 `:518 ensureWorkflowPages` 补建缺失单例）；实时草稿在 IndexedDB `jingyin-outfit-workflow-local-v1`。
- 用户在浏览器里新建/改名/删除页面（如把 "+"页改名「服装改色」、删掉随机背景/批量改色页）**只写浏览器**，源码仓无对应文件。
- 封装（`vite build` / SEA）只读源码仓 → 包里永远是 `ensureWorkflowPages` 的**出厂默认单例**。这就是"AI 只能封装成固定板块"的根因：不是 AI 不肯，是封装流程够不着浏览器。

### 0.2 V121 种子桥存在，但全靠人走

现行链路（V121 已归档，机制本身正确）：

1. 设置页「导出封装种子」（`src/features/settings/SettingsView.jsx:167-176`，`!PUBLIC_RELEASE_MODE` 门禁）→ `downloadReleaseSeed()`（`src/shared/release-seed.js:221`）浏览器下载 `jingyin-seed-<日期>.json`；
2. 用户**手动**把 JSON 放进 `D:/源码开发/静音AI画板v4.0-发布工程/seed/`；
3. `发布工程/build.mjs:141-168` 按 `--seed <路径>` > `seed/` 目录最新 mtime 选取；
4. `scripts/secure-win-release.mjs:119-176`（`JINGYIN_SEED_FILE`）校验后注入 `dist/seed/manifest.json` → 内嵌进 SEA；
5. 客户首跑 `importReleaseSeed()`（`release-seed.js:170`）只填空键。

**断点**：第 2 步纯人工。AI 封装会话看不到用户浏览器、也不知道该用哪个种子文件；忘了/没交接 → 静默出工厂包。

### 0.3 实测证据（本次派单前刚查）

- `D:/源码开发/静音AI画板v4.0-发布工程/seed/` **目录为空**（无任何 `jingyin-seed-*.json`）；
- 源码仓 `dist/seed/` 不存在；
- 即：当前封装链路处于"要么手工补种子、要么出不含开发者状态的包"的状态，与用户诉求直接冲突。

## 1. 改动要求

### 1.1 仓库新增封装配置单一真相源 `seed/manifest.json`

- 路径：源码仓根 `seed/manifest.json`，**git 跟踪**（先查 `.gitignore` 无 `seed/` 忽略；有则放行）。
- 形态 = `buildReleaseSeed()` 产物（`{version:1, seedId, entries}`；entry id 全集见 `src/shared/release-seed-schema.js:43 SEED_ENTRY_IDS`，共 12 个 id）。
- 定位：**开发者最新状态的快照**。AI 封装会话读仓库即可见、可 diff；进 git 即满足红线③"永不清"（历史即备份）。
- 内容边界沿用 schema 白名单：pages 仅 6 字段（C 类图片/任务字段禁入）、提示词仅 5 字段、任何深度 `apiKey/baseUrl/channelId` 剥除。

### 1.2 设置页「同步到封装配置」按钮（仅 internal 模式）

- `src/shared/release-seed.js` 新增 `syncReleaseSeed()`：
  - 调 `buildReleaseSeed()`；entries 为空 → 返回明确失败（调用方提示"当前没有可同步的提示词模板或页面状态"，与 `downloadReleaseSeed` 的 null 口径一致）；
  - 非空 → POST `/api/seed-sync`（body = manifest）→ 返回 `{ syncedAt, seedId, entriesCount }`。
- 网络出口纪律（P7-1 / V121-R1 同款口径）：在 `src/api/` 新增薄封装（建议 `src/api/seed.js`：`syncSeedManifest` / `fetchSeedSyncStatus`），`release-seed.js` **不出现裸 fetch**；同步更新 `src/api/README.md`。
- 设置页 UI（紧挨现有「导出封装种子」，同在 `!PUBLIC_RELEASE_MODE` 块内）：
  - 按钮「同步到封装配置」+ 状态行：`封装配置同步于 <时间> · <N> 项`；
  - **新鲜度提示**：页面内现算 `buildReleaseSeed().seedId` vs GET `/api/seed-sync` 返回的文件 seedId；不一致 → 黄色提示"浏览器有未同步改动，封装前请先同步"；
  - 同步成功/失败都必须可见反馈（沿用 `seedExportMsg` 模式，不许静默失败）。
- 保留原「导出封装种子」下载按钮（手动备份/旧流程兼容，不删）。

### 1.3 服务端写入路由（仅 internal 模式注册）

- 新文件 `server/routes/seed.routes.js`，在 `server/app.js` 路由装配区注册；**注册条件：非 public 发布模式**（与 `server/index.js:13-19` 的 `.release-mode` 探测同源判定），public 构建不含此路由——客户版无此出口。
  - `POST /api/seed-sync`：接收 manifest → Node 侧强制复核 → 原子写 `seed/manifest.json` → 返回结果。
  - `GET /api/seed-sync`：返回 `{ exists, syncedAt, seedId, entriesCount }` 供新鲜度提示。
- 写入前复核（`release-seed-schema.js` **同一份实现**，严禁另写一份）：
  1. entry id 必须全在 `SEED_ENTRY_IDS`，否则 4xx 拒收；
  2. `containsCredentialFields(manifest) === false`（红线①，发现即拒写）；
  3. 逐 entry 过 `sanitizeOutfitPage` / `sanitizePromptPreset` / `stripCredentials` 后再落盘（第二道防线：浏览器侧被篡改/旧格式也不怕）；
  4. 原子写（临时文件 + rename，口径对齐 `server/core/history-store.js:289`）。
- 路径推导用 `server/core/app-paths.js` 既有能力取仓库根，**不写死绝对路径**（docs-path-check 纪律）。

### 1.4 封装链路自动读取（消除记忆负担）

- `scripts/secure-win-release.mjs`（`:110-176` 种子注入段）：
  - 未设 `JINGYIN_SEED_FILE` 时，**默认读取 `<repo>/seed/manifest.json`**：存在 → 走既有校验注入；
  - 不存在 → 打印醒目警告（"未找到 seed/manifest.json：本次封装将使用出厂默认板块/空模板，红线③不满足"）并**以非零退出码结束**；显式设 `JINGYIN_SEED_ALLOW_MISSING=1` 才允许放行（内部试验构建用）。
  - `JINGYIN_SEED_FILE` 显式指定仍最高优先（兼容）。
- `发布工程/build.mjs`（独立目录，随本单一并改）：
  - 种子解析优先级改为：`--seed <路径>` > **源码仓 `seed/manifest.json`** > `发布工程/seed/` 最新 `jingyin-seed-*.json`（旧手动档保留兼容）；
  - 三者皆无且未传 `--skip-seed` → 构建失败，提示"请到源码版设置页点「同步到封装配置」"；
  - `--skip-seed` 语义不变（显式打工厂包，警告照旧）。
- 目标行为：AI 封装会话在源码仓跑 `npm run release:win`（或经发布工程 build）即自动带上 `seed/manifest.json`，**零口头交接、零环境变量**。

### 1.5 文档同步（漂移门禁纪律：改代码必须同步配套物）

- `docs/V4.0-二进制封装规则框架.md`：SOP 更新为"设置页一键同步 → `seed/manifest.json` → 封装自动读取 + 缺失硬失败"；**四红线与 A–D 键映射不变**；刷新文末"最后复核日"。
- `发布工程/封装规范.md`：种子解析新优先级 + 同步按钮说明。
- `AGENTS.md` 开发流程追加一条：封装前确认 `seed/manifest.json` 已同步（新鲜度口径）。
- `docs/README.md`：框架文档已在册，仅当其正文结构大改时刷新指针行。

### 1.6 门禁（新增并注册进 `run-all --fast`）

- 新脚本 `scripts/verify/release-seed-sync-check.mjs`，静态断言：
  - a) `src/api/` 存在 seed 薄封装，且 `src/shared/release-seed.js` 无裸 `fetch(`（api-layering 口径延伸）；
  - b) `server/routes/seed.routes.js`（或并入处）存在非 public 模式守卫（grep 断言）；
  - c) `scripts/secure-win-release.mjs` 含 `seed/manifest.json` 默认读取分支；
  - d) **若仓库存在 `seed/manifest.json`**：Node 侧过 schema 校验（entry id 合法 + 无凭据字段 + sanitize 后与落盘逐字一致）——防手编坏文件入 git。
- size-ratchet：新增文件按纪律复跑 `--update`；`regressions=[]` 且 `improved=[]` 不许 `--update`。

### 1.7 二期（同单第二阶段；**开工前必须先交影响评估，统筹确认后才许动工**）

- 仓库真相源化：`ensureWorkflowPages`（`outfit-page-actions.js:518`）在浏览器无页面状态时（internal 首跑/新装机/清缓存），以 `seed/manifest.json` 的 `outfit-pages` 为默认页集，取代代码内默认单例表。
  - ⚠️ 启动链路只准**静态 import JSON 叶子**，不得因此引入任何特性模块依赖（V121-R2 TDZ 红线，`release-seed-check.mjs` [4b]/[4c] 已断言，勿踩）。
- 设置页增加「采用封装配置（仓库最新）」：显式二次确认后把仓库 seed 写入浏览器状态（用户主动行为；红线④"以用户当前状态为准"指**不强改**，用户点按钮=用户当前意愿，可做但必须确认弹窗 + 明确文案）。
- 人类/AI 可读源 `seed/pages.json`（可选档）：manifest 改由生成器从 pages.json 产出，便于 AI 直接改板块定义。评估必要性后再做，避免过度工程。
- 二期影响评估必答清单：与删除留痕 `jingyin-outfit-workflow-deleted-modes-v1` 的交互；与种子导入"只填空键"的优先级关系；internal 首跑与 public 首跑行为差异；存量用户升级路径。

### 1.8 明确不做

- 不改种子导入"只填空键、不覆盖回头客"语义（红线③）。
- 不删手动「导出封装种子」下载通道。
- 不碰用户浏览器任何既有状态——一期同步是"读浏览器 → 写仓库文件"**单向**，对存量用户零影响。
- 不做浏览器→仓库实时镜像（每改一个板块就自动写文件）：噪音大且把工作中间态写进 git；一键同步 + 新鲜度提示已覆盖诉求。
- 不追求"AI 直接读用户日常浏览器"（技术不可行：封装进程与用户浏览器隔离，强连入侵性大且违反最小触碰原则）。

### 2.2 运行时（统筹或执行方实跑，留痕 `tmp/`）

1. 源码版设置页点「同步到封装配置」→ 仓库 `seed/manifest.json` 生成；文件 seedId 与页面现算一致；新鲜度由"未同步"变"已同步"。
2. 在批量页改一个页面名（不点同步）→ 新鲜度提示重新变"有未同步改动"。
3. `npm run release:win` 不带任何 env → 日志显示自动读取 `seed/manifest.json` 并注入 N 个 entry。
4. 移走 `seed/manifest.json` 后 release → 非零退出 + 醒目警告；设 `JINGYIN_SEED_ALLOW_MISSING=1` → 放行。
5. public 构建**首启动冒烟**（V121-R2 口径必做）：客户首跑种子导入仍只填空键、不覆盖。
6. 发布工程 `build.mjs` 三档优先级各跑一次（--seed / 仓库 manifest / 旧 seed 目录），日志留痕。
