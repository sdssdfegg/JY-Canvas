# JY-CANVAS P1 架构修复 · 可独立验收任务拆分

> 日期：2026-11-20　依据：外部产品架构顾问对《JY-CANVAS-ARCH-001》复核裁决。
> 性质：**任务拆分（施工规划）**，本阶段不实施、不改代码。每项可独立验收，交顾问确认后再逐项开工。
> 基线：HEAD `1db91b0`（审计归档完成）。

## 拆分原则（对齐裁决 1-9）
1. **暂停增加行业包**：P1 六项均不新增行业配置、不以行业数量为进度。
2. **字段必须有运行时消费证据**：不要求原文进提示词，但须证明对识别/规划/编译/审查产生实际影响。
3. **Skill 五态分别记录**：active / 执行成功 / 输出产生 / 下游消费 / generation_instruction 注入，不把 active Skill 全文塞进提示词。
4. **平台策略不动**（裁决6）。
5. **P1 全绿才进 P2**；P2（五档筛选/成分筛选/三组对比）另立单、先交设计与测试标准。
6. 不重建八 Skill、不推翻一键详情结构、不改稳定对外接口。

## 后续架构约束（顾问 P1-1 验收意见，2026-11-20，不回头扩大 P1-1，后续任务落实）
> 来源：外部产品架构顾问对 P1-1《行业体系统一》的验收通过意见。三条为长期约束，P1-2 及以后各单必须遵守。

1. **多行业同分不得任意启用专属策略**：resolveIndustryDecision 在多包同分时（confidence=medium）不得仅凭排序启用某行业专属专业策略；低置信度无法确定行业时应使用 generic，或仅允许明确安全的公共规则。（当前同分行为：记录 tiedPacks + confidence=medium；后续需明确"medium 不启用专属策略"的落地环节，在 P1-2/P1-4 落实。）
2. **cleaning 覆盖层保留但须归档来源与职责**：cleaning 强特征覆盖层（detectIndustryOverride）为 P1-1 为保回归而保留的既有机制，其来源是正式 cleaning 包的 positiveSignals/negativeSignals + 服装强特征否决；归档时必须说明这一来源与职责边界，不得让它演变为与行业包并行的第二套行业主判断体系。
3. **analysis 与 v2Control 共享同一份行业决策**：避免重新计算造成输出不一致——两者都应消费 P1-1 产出并挂在 industrySkill 上的同一份 resolution（当前实现：buildProductAnalysis 与 buildV2ControlReport 均读 industrySkill.resolution；后续各单不得再各自调 resolveIndustryDecision 重算）。

## 依赖关系总览
```
P1-1 行业体系统一（基础，无依赖）
  ├── P1-2 字段运行时消费（依赖 P1-1）
  │     └── P1-3 子类目识别与降级（依赖 P1-1/P1-2）
  ├── P1-4 Skill输出消费链路（相对独立，可与P1-1并行但建议串行以共享证据）
  ├── P1-5 重复注入治理（独立，但需 P1-2 后确认不再重复引入）
  └── P1-6 污染拦截（依赖 P1-2 字段消费路径）
```
**建议执行顺序**：P1-1 → P1-2 → P1-3；P1-4、P1-5 可在 P1-2 后并行（改动面不重叠时）；P1-6 最后（消费路径稳定后）。
**串行规则**：除明确标注可并行的 P1-4/P1-5 外，其余严格串行（沿用项目 R1 互斥纪律）。

## P1-1 · 行业体系统一（两套并行 → 单一消费链）
- **目标**：消除"进提示词的 INDUSTRY_SKILLS 旧词表"与"只进审计的 industryPacks 配置"两套并行；确立 industryPacks 为行业知识单一真相源，旧词表仅作兼容降级。
- **代码范围**：
  - `server/detail-v2-control/index.js:111-151` loadIndustryPack（接入 pack 字段消费出口）
  - `server/detail-v2-control/index.js:159-184` detectIndustryOverride（去除 cleaning 硬编码，改为遍历所有包正/负信号）
  - `server/detail-middleware.js:366-421` aiIndustry / inferIndustry（统一走包体系）
  - `prompts/server/detail-skills.js:403-413` getIndustrySkillByText（保留为 fallback，不改冻结 G-2 词表本体——该文件被 assets 门禁冻结哈希锁）
- **依赖**：无（基础项）。
- **兼容性**：保留 cleaning 识别与提示词逐字节一致；旧词表作为 fallback 不删除；对外接口（payload/prompts/v2Control）不变。
- **运行时证据**：同一批 8 类商品，识别结果由包体系产生；cleaning 提示词与基线逐字节 diff=0；删一包其它包识别不受影响。
- **验收标准**：8 类均能识别且来源标记为 industryPack；无第二套并行判定；cleaning 无回归。

## P1-2 · 行业包字段真实消费（消費层链路）
- **目标**：让每个 pack 字段明确对应执行环节并产生实际影响（不要求原文进提示词）。
- **代码范围**：
  - `server/detail-middleware.js:743-754` buildGlobalLock、`:756-789` buildRounds（接入 pack 字段）
  - `server/detail-v2-control/config/professional-content-v1.json:25-64` 字段契约（明确每个字段消费环节）
  - `server/detail-v2-control/skill-activation.js:12-41` checkSellingPointBoundary（noGeneralization 提取词从硬编码改配置驱动）
  - 字段消费映射：positiveSignals→识别(P1-1)；negativeSignals→识别否决；weakContextWordsMustNotOverride→污染排除(P1-6)；noGeneralization→编译边界校验；professionalValues.outputRequirements→行业观察点/禁忌进提示词；coverage→规划内容方向提示；recognitionExamples→识别测试夹具。
- **依赖**：P1-1。
- **兼容性**：新增字段消费为追加，不覆盖已确认事实/全局安全规则/核心优先级（裁决6/任务书二.3）；cleaning 行为不变。
- **运行时证据**：逐字段提供"字段→执行环节→运行输出"对照；8 包 professionalValues.outputRequirements 出现在各自行业提示词或规划请求；7 个非 cleaning 包 noGeneralization 提取词从 `[]` 变为非空（实测修复）。
- **验收标准**：每个字段有 consumer 断言（进识别/规划/编译/审查之一）；无字段"只进审计"。

## P1-3 · 子类目识别与降级
- **目标**：大类目→子类目分层识别；识别不确定/包缺失时显式降级 generic 并记原因。
- **代码范围**：
  - `professional-content-v1.json` 增 `extends`/`basePack`/`subCategories` 字段（结构扩展，非新增行业数量）
  - `server/detail-v2-control/index.js:111-151` loadIndustryPack（加继承合并、无循环检测）
  - `server/detail-ai.js:238-239` industryProfile.confidence/uncertaintyNote（从仅 outputSchema 提示改为运行时消费）
  - `server/detail-middleware.js:795-835` buildV2ControlReport（降级原因入审计）
- **依赖**：P1-1、P1-2。
- **兼容性**：flat 包结构仍可用（无 extends 即平铺）；降级不阻塞策划（沿用 checkPlanningIntegrity 现有判据）。
- **运行时证据**：构造带子类的包，验证继承字段正确展开；低置信度输入→generic + 降级原因；删除包→其它包正常。
- **验收标准**：继承展开正确、无循环；置信度降级有因；未知行业不阻塞。

## P1-5 · 重复注入治理
- **目标**：消除 buildGlobalLock 与 buildRounds 对同三份规则（productAuthenticityLock/globalStyleConsistency/taboos）的重复注入。
- **代码范围**：
  - `server/detail-middleware.js:743-754`（buildGlobalLock）、`:756-789`（buildRounds）——二选一保留注入点，另一处移除或改引用。
- **依赖**：与 P1-1/P1-2 相对独立；P1-2 后确认不重新引入重复。
- **兼容性**：输出文本会变化（去重后更短）——需产品确认"去重后文本可接受"再合入；不改变规则内容，只改注入次数。

- **验收标准**：重复计数断言；控制链/同步门禁/planning 全绿；无规则遗漏。
