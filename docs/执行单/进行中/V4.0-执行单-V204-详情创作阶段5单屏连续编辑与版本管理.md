## 1. 目标与交付（总任务书 §十一）

图片生成完成后，用户需要对**每一屏独立编辑**。必须支持：

1. 单屏重新生成。
2. 修改单屏文案和画面要求。
3. 单屏**连续对话式修改**（多轮，每轮基于上一版结果继续改）。
4. 根据上一版结果继续修改（不是每次从头生成）。
5. 保存每次生成的**历史版本**。
6. 查看不同版本（图 + 当时的提示词 + 修改说明）。
7. 切换历史版本。
8. 保留用户选定的**当前版本**。
9. 修改某一屏时**不影响其他屏幕**。

🔴 **最重要的一条隔离约束**：用户只修改第 5 屏，就**只重新生成第 5 屏**；不得因此重新执行整套详情页策划（V202 B1/B2/B3 不重跑），也不得自动重生成其他屏幕。

**可选路径（须明确边界）**：若用户**主动明确提出**要调整整套视觉方向，可以提示「可能影响哪些屏」，由用户确认后再批量调整；此路径默认关闭、必须展示受影响屏清单 + 用户显式确认，且不得与单屏编辑共用同一条自动流程。

## 2. 数据结构（版本管理核心）

- **`screenVersions[]`**：每屏一条版本链，字段至少含 `versionId` / `screenIndex` / `imagePath` / `prompt`（该版实际发送、已冻结的提示词）/ `sourceTaskId`（关联 V203 任务）/ `parentVersionId` / `editNote`（本轮用户指令）/ `createdAt` / `isCurrent`。
- **`currentVersionId`**：每屏一个，用户选定；切换版本只改这个指针，**不删历史版本、不覆盖图片文件**。
- **`editThread[]`**：连续对话轮次，每轮 `{ userInstruction, appliedPatch, diff, resultVersionId, createdAt }`；用户原话保留，AI 建议作为独立补丁，逐条采纳（同模式 B 的 `rawIntent` / `assistPatch` / `diff` 口径）。
- **落盘**：`data/detail-studio/versions/`（版本元数据 + 版本图片独立目录），**不进** `data/results`（7 天 TTL）、不进 `seed/manifest.json`、不进安装包默认种子。
- **项目存储**：`server/features/detail-studio/store/project-store.js` 受控合并新增 `versions` 字段；`schemaVersion` 迁移要兼容 v2 旧项目、`migrateProject()` 在 `get` 与 `list` 两个读取路径生效，且**读操作不得产生写盘副作用**；`mode` / `id` / `createdAt` / `schemaVersion` 一律不可变（三种模式硬隔离）。

🔴 **与 V203 任务层的接口（本单最易踩的坑）**：单屏重生成复用 `generation` 的任务机制，但 **`idempotencyKey` 必须绑定 `versionId`（或等价的版本序号）**。V203 现用 `sha256(projectId | screenIndex | frozenPrompt)`：若单屏编辑后新提示词不同尚可，但「重新生成同一提示词」或重试会命中旧账本直接复用已有任务，导致**新版本拿不到图 / 历史版本被覆盖**。必须扩成 `sha256(projectId | screenIndex | versionId | frozenPrompt)`（或同等的版本维度），并给负向对照断言：同一屏连续生成两次应产生**两个独立任务、两个独立版本、两张独立图片**。

## 3. 单屏隔离与提示词冻结（红线）

- 单屏编辑只触发该屏的一次生成任务；**不得**触发 B1 分析 / B2 导演 / B3 编译 / B4 质检重跑；前后屏上下文**只读**带入，不改写。
- 用户看到的提示词 == 实际发送提示词（V202 B3 的 `frozen-prompt-parity-check.mjs` 继续生效）。单屏编辑产生的是**新版本 + 新冻结提示词**，**不覆盖原 `frozenPrompt` 原件**；历史版本始终可回溯到当时的那一版提示词。
- **模式 C 四边界不因版本管理改变**：`rawPrompt` 永久只读、`tidyVersion` 可选默认关、`diff` 可核对、`frozenPrompt` 仅用户确认后写；C 路径仍不经过任何 planner / skill / quality / `postChatCompletion`（`mode-c-purity-check.mjs` 继续绿）。
- 整页视觉方向批量调整是**独立可选路径**：先展示受影响屏清单 → 用户确认 → 才批量派发；默认关闭，不得偷偷并入单屏编辑流程。

## 7. 阶段验收（来源：总任务书 §十一 + §十六 阶段 5）

1. 单屏可重新生成，且只生成该屏（负向对照：改第 5 屏 → 其他屏任务数不变、B1/B2/B3 未重跑、其他 `frozenPrompts` 字节不变）。
2. 可修改单屏文案与画面要求，产生新版本，**不覆盖**原 `frozenPrompt` 原件。
3. 支持连续对话式修改：第 N 轮基于第 N−1 版结果继续，`editThread[]` 完整留痕，用户原话保留。
4. 每次生成保存独立历史版本（图 + 当时提示词 + 修改说明 + `sourceTaskId`），版本链可追溯 `parentVersionId`。
5. 可查看、对比不同版本。
6. 可切换历史版本；切换只改 `currentVersionId`，不删历史、不覆盖图片。
7. 用户选定的当前版本持久化，重新打开项目后仍生效。
8. `idempotencyKey` 绑定版本维度：同屏连续两次生成产生两任务 / 两版本 / 两图，不命中旧账本、不重复扣费也不丢版本。
9. 整套视觉方向批量调整为独立可选路径：默认关闭、先列受影响屏、须用户显式确认。
10. 模式 C 四边界与 C 路径 0 调用隔离不回退；`frozen-prompt-parity-check` / `mode-c-purity-check` 保持绿。
11. 版本元数据与图片落 `data/detail-studio/versions/`，不进 `data/results` / `seed` / 安装包默认种子；schema 迁移兼容 v2 旧项目、读操作无写盘副作用。
