### 1.1 关键说明

- **用 `--accent` 还是 `--accent-border`**：这 6 处都是**半透明辉光/描边**，语义上更接近"强调色的淡化版"，统一用 **`var(--accent)`**（`--accent-border` 是不透明的强调边框，淡化后语义不符）。若执行日发现某处明显是"边框"语义（如 #1 的 `border-color`）而倾向 `--accent-border` → **停下回报**，由统筹裁定，不得自行切换。
- **#4 是 SVG `rect` 的 `fill`**（局部编辑蒙层）：`fill` 接受 `<color>`，`color-mix` 合法；仓库已在用 color-mix。但 SVG 渲染需**探针实测确认**（见 §2.2）。若实测发现 color-mix 在该 rect 上不生效 → **停下回报**。
- **in-line 改写，物理行数净 0**。

### 1.2 不在本单范围

- 其余 `rgba(...)` 中性色（黑/白/灰阴影）不动。
- `styles.css`、`ui.css` 的 hex（V106 已裁决为合规基线）不动。
- 不做任何其它视觉/规范化改动。

## 2. 验收

### 2.1 静态

- `grep -c "rgba(31, 207, 195" src/outfit-workflow.css` → **0**。
- `grep -c "color-mix(in srgb, var(--accent)" src/outfit-workflow.css` → **6**。
- `hardcoded-color-check` 通过（只记 improved，不 `--update`）。
- 物理行数净 0。

### 2.2 探针（统筹补做；执行者自测更佳）

- **dark 主题下视觉零变化**：`color-mix(in srgb, var(--accent) N%, transparent)` 在 dark 下解析应 **等于** 原 `rgba(31,207,195,N)`（canvas `getImageData` 归一化比对）。
- **覆盖换装根节点 `--accent` 为测试色** → 这 6 处元素应**跟着变色**（同 V107 的 `followsVariable` 验证法，这是比逐主题采样更强的证据）。
- **#4 SVG rect** 需单独确认渲染生效（取 `.thumbLocalEditOverlay rect` 的 computed `fill`）。

### 2.3 门禁（路由纪律①：非里程碑）

- `--fast` **32/32**
- `npx vite build` EXIT=0
- `npx eslint .` → 0 errors（仅 1 基线 warning `outfit.routes.js:407`）

### 2.4 基线
