## 3. 改动要求

### 3.1 图片编辑器 `ImageEditorSlot`（`src/image-editor.jsx` L49-86）

- 把 `{file && <button type="button" onClick={onClear} title="清空"><Trash2 size={13} /></button>}` 换成 `{file && <UploadClearButton onClick={onClear} />}`，**保持 `file` 非空才渲染**（空态不渲染，V82 规格）。
- 补 import：`import { UploadClearButton } from "../shared/ui/UploadClearButton";`（**不带 `.jsx` 后缀**，仓内惯例；路径深度按 `src/image-editor.jsx` 实际相对位置核实）。
- `Trash2` import 若因此变成未使用 → **真删**（不得用 `eslint-disable`；仓库规矩：停用代码用 `_` 前缀）。
- 位置：header 已是 `space-between`，`<strong>{title}</strong>` 在左、清除钮在右，**天然就是右上角**，无需改布局。

### 3.2 批量改尺寸 `BatchResizePanel`（`src/features/outfit/outfit-panels.jsx`）

- **定位方式**：file input L1648/L1658 所属函数；`.batchResizePanel` 容器；`.batchResizeFooter` 内的 danger 清空钮；清空 handler 名 `clearItems`（L1640 附近实测，执行日核实）。
- **右上角补 `UploadClearButton`**：容器若已有 `<header>`，在其内加 actions 容器（参照 UploadZone 的 `.uploadHeaderActions` 写法）并把 `<UploadClearButton onClick={clearItems} />` 放进去；**若无 header**，新建最小 header（左标题 `<strong>`/`<h3>`、右 actions），视觉与 DetailUploadZone / UploadZone 的 header 保持一致。同样**空态不渲染**（`items.length > 0` 才渲染）。
- **footer danger 钮的裁决（默认裁决，反对需明示）**：footer 里那个 `<Button size="sm" tone="danger">Trash2 清空图片</Button>` **删除**，`<span>` 状态文案保留 —— 理由：V82 已确立「清除」单一入口在右上角，footer 再留一个红色图标钮是**双入口 + 视觉分叉**（且红色正是用户否掉的方案）。若执行日实测发现该钮有独立用途（如 debounce/working 态不可删），**停下回报等统筹裁决**，不得自行改判据。
- 注意：`tone="danger"` 是 V82 **明确否掉**的方案（用户原话"颜色不用做成红色那么突出"）——本单落到任何上传模块上的清除钮一律走 `UploadClearButton`（default 中性），**不得**用 danger。

### 3.4 基线（预授权）

- **`size-ratchet-check`**：本单替换/新增会让 `image-editor.jsx`、`outfit-panels.jsx` 行数微增（补 import +1 行属不可避）→ **条件式预授权 `--update` 一次**（仅当出现 +1 且无其它规避手段时），reason 写「V92 上传清除钮补齐，import 接线物理必然」；若行数持平或下降则**不刷新**（conditions=false 不动基线）。
- **`hardcoded-color-check`**：删除 danger 色 CSS 规则（若含 hex）会 improved → **只记前后数，不 `--update`**。
- **`legacy-button-ratchet-check`**：本单不碰按钮类旧类，基线**不得动**。
- **`shared-ui-duplication-check` / `frontend-duplication-check`**：本单**不新建**共享组件（复用现有 `UploadClearButton`）→ **不得 `--update`**（若误判请停下回报）。
