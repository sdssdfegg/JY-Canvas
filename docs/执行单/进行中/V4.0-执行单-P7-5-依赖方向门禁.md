## 1. 现状基线（2026-10-16 审计；派发日必须重测）
- 跨 feature 依赖 **约 24 组**（`src/features/<A>/**` → `src/features/<B>/**`，A≠B）。
- **派发日必须自己解析一遍真实依赖图**，产出真实方向清单作基线初始内容；与 24 不符以实测为准。
- **共享层规则**：`src/shared/**` 允许被任意 feature 依赖，**不算横向违规**（不要把它记进白名单噪音）。

## 2. 做法
1. 新建 `scripts/verify/dependency-direction-check.mjs`（约 120 行）：
   - 解析 `src/features/<A>/**/*.{js,jsx}` 中所有 `from "..."` / `import("...")`，解析相对路径到绝对模块，判断是否落在 `src/features/<B>/`（B≠A）。
   - 产出方向对 `A → B`（去重），与 `baselines/dependency-direction.json` 白名单比对（`{generatedAt, reason, allowed:[{from,to,reason}]}`）。
   - 判红：出现**不在白名单内**的新方向 → 红（提示须显式登记并写 reason）。
   - `stale`：白名单里记的方向已不存在 → 红，逼 `--update`。
2. `--update`（带 `--reason`）；`--json`。注册进 `run-all.mjs` + `--fast`（纯静态解析，应 <1s）。
3. 与既有 `cycle-scan` 互补，不要重复实现环检测。

## 3. 纪律（R1–R6）

## 4. 负向对照（双向）
- 绿：现有方向全在白名单 → `ok=true`。
- 红①：临时在一个 feature 文件里加一行指向**另一个 feature** 的 import（未登记方向）→ 转红；还原 → 复绿。
- 红②：删掉白名单里某方向的实际引用但不 `--update` → `stale` 红；`--update` → 绿。
- 附加：指向 `src/shared/**` 的新 import **不应**判红（验证一次）。
- 红证输出贴回报。
