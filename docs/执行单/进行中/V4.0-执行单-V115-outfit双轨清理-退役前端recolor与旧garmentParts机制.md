## 0. 背景与实测取证（2026-10-19 实测，行号以此为准）

服装改色现在有**两套并行机制**，旧的一套自 V110 起已彻底不可达：

| | 新机制（保留） | 旧机制（本单退役） |
| --- | --- | --- |
| 页面归属 | `custom` 页（用户改名的「服装改色」） | `recolor` workflow 页（「批量改色」单例，V113 起不再补建） |
| 部位选择 | `recolorPart`（`RECOLOR_PART_OPTIONS` / `RECOLOR_PART_WORDS`） | `settings.garmentParts`（`GARMENT_PART_OPTIONS` / `normalizeGarmentParts`） |
| 层级/结构 | `recolorUpperLayer`（`UPPER_LAYER_OPTIONS` / `RECOLOR_UPPER_LAYER_WORDS`） | `settings.garmentComposition`（`GARMENT_COMPOSITION_OPTIONS` / `normalizeGarmentComposition`） |
| UI 落点 | `OutfitComposer.jsx` 的 `.recolorPartRow` / `.recolorUpperLayerRow` | `OutfitComposer.jsx` 的 `.garmentTransferControls`（图2 footerControls，188-228 行） |
| 与提示词关系 | 切换即改写正文 | 只出现在 task 载荷里，**服务端从不读** |

**不可达证明（实测）**：前端唯一的入口是 `src/outfit-workflow.jsx:431` 的 `const isRecolorWorkflow = workflowMode === "recolor";`，而 `workflowMode` 来自 `inferOutfitWorkflowMode()`——V110 起含「改色」字样的页名一律返回 `"custom"`，V113 又删掉了 recolor 单例补建块，所以 **`isRecolorWorkflow` 恒为 `false`**，其下游全部是死分支。

**服务端谨慎确认（实测，勿删）**：

- `server/routes/outfit.routes.js:202-205` 的 `recolorWorkflow` 由**页面名/标题**判定（不是前端传的 mode），**仍在生效**（用于关闭智能介入 `319`、定制"至少需要 1 张图1原图和 1 张图2颜色参考图"报错 `247`）。用户当前「服装改色」页**正在走这条判定** → **一个字都不许动**。
- `server/core/image-error-policy.js:123` `if (key === "recolor") return "批量改色";` 同样是活分支，保留。
- 服务端**从未**读取 `payload.garmentParts` / `payload.garmentComposition`（实测 `git grep` 在 `server/` 与 `prompts/server/` 零命中，仅历史基线 `server/skill-baselines/V3-…/` 与文档叙述里有）→ 删掉这两个载荷字段**不改变任何请求语义**。

## 4. 留档（统筹写入，执行方知悉）

- **为什么现在清理**：同一件事两套实现并存，是后续 AI 执行时最典型的幻觉源——模型检索到 `garmentTransferControls` / `GARMENT_PART_OPTIONS` 就会以为改色还有"图2 改色范围"这条老路，从而改错文件、甚至复活已退役的 UI。以 newest 为准的原则落到代码上就是：**旧的生活迹象要连根拔，只留下"退役记录"这一个痕迹**。
- **新旧边界一句话**：**UI 上的选择能不能进提示词**是新机制（`recolorPart`/`recolorUpperLayer` + `replaceRecolorPartWords`/`replaceRecolorUpperLayerWords`）的唯一职责；旧机制（多部位多选 `garmentParts` + `garmentComposition` 结构描述）自 2026-09-26 起在服务端就从未被消费，V110 后连 UI 入口都没了。
- **服务端故意保留 recolor 判定**：它对用户体验有实际作用（关闭智能介入、专属报错文案），且由**页面名**触发、不依赖前端传 mode——这是"前端已无 recolor、服务端仍有 recolor"看似矛盾但正确的现状，**不要为了对齐而删服务端**。
- **旧 absolute `makeRecolorPage` 工厂保留**：将来若要"手动新建旧式改色页"还是要用，且它是 V110 退役裁决的完整证据。
