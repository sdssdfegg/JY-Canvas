# V4.0-执行单-启动器日志 UTF-8 乱码修复

> 类型：缺陷修复单（启动器 / 运维）
> 状态：**已落地（2026-10-30）；未合 main、未 push**
> 分支：`fix/launcher-log-utf8`（与渠道调整、V144 工作同仓库不同分支）
> 上游诉求（用户 2026-10-30）：Windows 启动器控制台「启动日志」下方中文乱码（如 `鎴◇饼鎴…Jingyin AI Canvas http://127.0.0.1:8787`）。

---

## 1. 根因
- 启动器 `scripts/start-jingyin-board.ps1`（PowerShell 5.1）在拉起 Node 服务端后，用 `Get-Content -Tail 30 -Wait` 实时跟随服务端日志 `launcher-server.log`。
- Node 服务端以 **UTF-8** 写日志；而 PowerShell 5.1 的 `Get-Content` 默认按**系统 ANSI/GBK** 解码，UTF-8 字节被当成 GBK → 中文乱码。
- 同时控制台 `[Console]::OutputEncoding` 默认也不是 UTF-8，进一步放大乱码。

## 2. 修复方案（已实施）
文件：`scripts/start-jingyin-board.ps1`

1. 脚本开头（`$ErrorActionPreference = "Stop"` 之后）强制控制台输出编码为 UTF-8：
   ```powershell
   try { [Console]::OutputEncoding = [System.Text.Encoding]::UTF8 } catch { }
   ```
2. 三处 `Get-Content` 调用统一加 `-Encoding UTF8`：
   - 跟随服务端日志：`Get-Content -LiteralPath $ServerLog -Tail 30 -Wait -Encoding UTF8`
   - 两处失败尾部读取：`Get-Content ... -Encoding UTF8`

仅改解码方式，**不涉及任何业务逻辑、服务端代码或出图链路**。

## 3. 文件清单
| 文件 | 改动性质 |
|---|---|
| `scripts/start-jingyin-board.ps1` | PowerShell 控制台/读取编码改为 UTF-8（3 处 `Get-Content` + 1 处 `OutputEncoding`） |

## 4. 验收
- PowerShell 语法自检通过（`powershell -Command "$null=...; & { param() }"` 解析无错）。
- 重启启动器后「启动日志」下方中文正常显示，不再出现 `鎴◇饼鎴…` 类 GBK 乱码。
