## 3. 验收

- **P0 九项验收清单**（架构规划 §19，至少覆盖）：快捷生成无参考图 / 带参考图 / 局部回贴；批量换装；批量局部回贴；批量运行中追加任务；保存；下载；刷新后历史/页面不异常——**逐项实测或 tabbit 探针**通过。

- 门禁全绿；diff 摘要 + 回滚说明随交付。

## 3.1 验收实测（2026-10-23）

- **门禁**：ESLint 0、syntax 280/280（新增 1 文件）、size-ratchet 无回归（`main-canvas-board.jsx` 438→336 净减 102 行；outfit 也减，整体体量下降）、`vite build` EXIT=0。
- **运行时探针**（`tmp/v5-memo-probe.mjs`：独立 8911 端口 + 独立 Vite 缓存；**实测读到线上/本地真实历史 46 张结果卡**——`loadHistoryResults` 优先取 API，探针的 IndexedDB 注入被覆盖，等于用真实数据验收）：
  - `initialCount=46`（真实历史渲染）、`hasBoundaryInitial=false`（无 ErrorBoundary）
  - `downloadApplied=true`（下载按钮点击后加 `downloaded` 态，CSS 生效）
  - `promptBtnExists=true`（有 prompt 的卡渲染提示词复制按钮）
  - `ctxMenu=true`（右键卡片 → 主右键菜单 `.imageContextMenu` 渲染）
  - `afterDeleteCount=45`（点击删除 → 画廊 -1，`deleteResult` 本地生效）
  - `errAfterDownload`/`errAfterDelete`/`errAfterRerun` 全 `false`（下载/删除/重刷全部交互路径零崩溃）
  - **结论**：抽取后 `QuickGalleryCard` 渲染 + 全部交互（选中/下载/提示词复制/右键/删除/重刷）与抽取前**行为等价，无回归**。
- ⚠️ **memo 收益边界（重要，如实记此）**：本单仅完成 1.1（抽卡片为 `React.memo` 组件）。实测发现上游 handler（`openPreview`/`downloadItem`/`rerunResult`/`deleteResult` 等）来自 `src/features/result-queue/quick-result-replace.js` 的**普通工厂**——该文件头注释（第 6–11 行）明示「调用方在组件体内每次 render 调一次，得到一组捕获最新 state 的普通函数，等价于组件内 function 声明（都是每次 render 重建闭包）」。因此 `MainCanvasBoard` 每次 `App` 重渲染传给 `QuickGalleryCard` 的 handler 引用都变化 → memo 在现状下被绕过、**暂未实测跳过重渲染**。
  - 要让 R2「列表项 memo」真正生效，下一步 **V5.0-002** 二选一：① 把 `MainCanvasBoard` 自身用 `React.memo` 包裹（画廊数据 props 不变时跳过整段 map）；② 稳定上游 handler（工厂返回的函数用 `useMemo`/`useCallback` 缓存，最新 state 改走 ref 转发）——后者触及主链路，属更大改动，需单列评估。
  - 本单纯搬运零风险、结构改善已落地，收益边界如实记此；不擅自扩大范围（遵守 executor 不越权纪律，1.2 原设想「MainCanvasBoard 内 useCallback」经核实不成立——该组件是纯透传展示件，handler 全部来自 props，无可 useCallback 之物）。

- 与 HMR/打包 TDZ 既往坑区分：本单不移动顶层状态声明，仅抽渲染子组件，不引入 TDZ 风险；但落地后仍按 V136 教训带非空数据探针 + public 首启动冒烟。
