## 3. 改动要求

### 3.1 新建 `scripts/verify/legacy-button-ratchet-check.mjs`（LF 行尾）

判据与 V74 `hardcoded-color-check` 同款「存量记账、只拦新增」机制；输出字段对齐：`ok / regressions / improved / stale / failureCount`（+ 两个 section 的明细）。

- **jsx 用量 section**：扫 `src/**/*.jsx`，按 11 个旧类名（`smallButton` / `iconButton` / `toolbarButton` / `generateButton` / `dangerButton` / `primaryButton` / `secondaryButton` / `tabButton` / `modeTab` / `promptTab` / `newPromptButton`）以词边界正则 `\b类名\b` 统计全文件出现次数（含注释——保守口径，宁可多记）；按类名分桶。
- **css 定义 section**：扫 `src/**/*.css`，按 (文件, 类名) 统计**定义次数**——行首可选空白 + `.类名` + 词边界（覆盖 `.类名,` / `.类名 {` / `.类名.active` / `.类名:状态` 等行首形态；行中被引用如 `.foo .smallButton` 不算定义）。
- **基线 `scripts/verify/legacy-button-baseline.json`**：`{ note, generatedAt, jsxUsage: {类名: 次数}, cssDefinitions: {"文件::类名": 次数} }`；note 写明"存量记账、只拦新增；旧类迁移由 V82+ 接入单推进，定义块删除归收口单"。
- **判定（两个 section 同机制，逐 key 比对）**：
  - 当前 > 基线 → **判红**（复活/新增）；
  - 当前 < 基线 → `improved` 只报告不拦（存量下降是好事）；
  - 基线 > 0 且当前 = 0（或该 key 在扫描中消失，如某文件的某类定义全删）→ **stale 判红**逼 `--update`（归零要刷基线）；
  - 基线 = 0 且当前 = 0 → 无动作（**已归零的类不判 stale**，否则永久判红）；
  - 新 .css 文件出现定义位点 → 同 new-file 判红。
- `--update` 重写基线（本单唯一预授权刷新，仅一次，commit message 带 reason）。
- **注册 `run-all.mjs`**：ORDER 注册于 `docs-path-check` 之后、`frontend-duplication-check` 之前；FAST_ORDER 注册于 `docs-path-check` 之后、`reference-gate-check` 之前（V74 同款位置）；`run-all-check` 的顺序表覆盖断言同步更新（V74 先例）。
- **负向自测 5 条**（临时文件构造，跑完 `/usr/bin/rm -rf` 清掉，过程附回报）：T1 临时 .jsx 让某类用量超基线 → 判红；T2 达标 → 通过；T3 `--update` 后重跑 → 绿；T4 临时 .css 新增一个旧类行首定义 → 判红；T5 删掉临时构造文件 → stale 判红。
