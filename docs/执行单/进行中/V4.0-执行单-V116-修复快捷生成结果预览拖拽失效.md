# V4.0-执行单-V116-修复快捷生成结果预览拖拽失效（共享 hook 漏传 previewPan）

> 派发日：2026-10-19 · 统筹：静音AI画板v4.0 · 优先级：🔴 **P0（用户每日使用路径）+ 本批最快交付**
> 性质：**回归修复单**（一行级根因，单文件）
> 背景：用户实测"快捷生成里的结果图点击预览后按住鼠标左键拖拽失效了，批量生成里面的就是正常的"，并追问"这 2 个不应该是一套逻辑吗"。**是的，本来就是同一套** —— 问题出在调用方漏传一个入参。

---

## 0. 根因（已定位到具体提交与行号，执行方无需再排查）

两侧**共用同一套单一来源**：

- 共享 hook：`src/shared/hooks/usePreviewDrag.js`（`beginPreviewDrag` / `movePreviewDrag` / `endPreviewDrag`）
- 共享纯函数：`src/shared/result-image.js:299` `previewDragStart(event, pan)`、`:320` `previewPanFromDrag(drag, event)`
- 弹窗结构同构：main.jsx `:1327` `previewImageFrame` ↔ outfit `ResultPreviewModal.jsx:41` `previewImageFrame outfitPreviewImageFrame`，两者图片都是 `draggable` + `transform: translate(${previewPan.x}px, …) scale(${previewZoom})`

**差异只有一处**（实测）：

| 调用方 | 是否传 `previewPan` |
| --- | --- |
| `src/outfit-workflow.jsx:390` | ✅ `previewPan,` |
| `src/main.jsx:470-477` | ❌ **漏传** |

```js
// src/main.jsx:470 现状
} = usePreviewDrag({
  previewDragRef,
  setPreviewPan,     // ← 只有 setter，没有 previewPan 本身
  closePreview,
  setGalleryZoom,
  resetDragged: setDraggedPromptCategory,
  resetDropTarget: setPromptCategoryDropTarget
});
```

`previewDragStart(event, undefined)` 仍会返回 `{ active: true, startPan: undefined }`，于是 `movePreviewDrag` 里 `drag.startPan.x` → **抛 `TypeError`（或算出 NaN 平移量）**，表现为"按住左键拖不动/预览被单击关闭"。批量侧传了 `previewPan` 所以正常。

**引入点（已追到提交）**：`32b5d72`（2026-10-13，收口共享 hook）**当时是传的**；`04f5269`（P6-5，2026-10-16，37 个 handler 抽到 `main-handlers.js`）的 diff 里出现 `-    previewPan,` → **搬运时丢参**。与 V109（丢 `files`）同类的"搬运丢参"血案，第二次发生。

**受影响面**：自 2026-10-16 起，快捷生成 / 主画板的结果图放大预览平移**一直失效**（滚轮缩放不受影响，只有拖拽平移坏）。

## 1. 改动要求

### 1.1 补传入参（`src/main.jsx`）

在 `usePreviewDrag({ ... })` 里补上 `previewPan,`（放在 `previewDragRef` 之后、`setPreviewPan` 之前，与 `outfit-workflow.jsx:389-391` 顺序一致）。`previewPan` 已在 `src/main.jsx:330` 由 `useMainSettingsState`/顶层 state 产出（同文件已存在，勿新建）。

### 1.2 给共享 hook 加兜底（防再次漏传）

`src/shared/hooks/usePreviewDrag.js`：

```js
function beginPreviewDrag(event) {
  // ⚠️ previewPan 必须由调用方传入（outfit-workflow.jsx 传了，main.jsx 曾漏传导致拖拽失效 V116）。
  // 这里给缺省值只为"漏传时不炸"，不代表允许漏传 —— 缺省会丢掉已有平移量，行为仍不正确。
  const drag = previewDragStart(event, previewPan || { x: 0, y: 0 });
  if (drag) previewDragRef.current = drag;
}
```

同时在 hook 头注释补一句"调用方必须传 `previewPan`；V116 前 main.jsx 漏传致快捷生成预览拖拽失效"。

### 1.3 明确不做

- 不动 `previewDragStart` / `previewPanFromDrag` 的语义（共享纯函数多处复用）。
- 不动 outfit 侧任何一行（它是正确的对照组）。
- 不顺手重构 `main.jsx` 的其它 handler。

## 4. 留档（统筹写入）

- **这正是"源码规整"的价值兑现方式**：两侧早就共用 `usePreviewDrag` + `shared/result-image.js` 这一套，真正出错的只有"调用方少传一个入参"。所以修复是**补一个参数 + 给单一来源加兜底**，而不是再写一套拖拽。
- **搬运丢参第二次（V109 丢 `files`、本次丢 `previewPan`）** → 立规矩：任何"把闭包/handler 搬进 hook 或新文件"的改动，交付前必须把**被搬函数的全部入参**与调用方实参逐一比对（建议 `git show <commit> | grep -n "^- "` 看删掉的行里有没有参数名）。
- hook 兜底只是"不炸"，**仍要求调用方传 `previewPan`**（否则丢掉已有平移量）——这一点写进 hook 注释，避免后人误以为可以不传。
