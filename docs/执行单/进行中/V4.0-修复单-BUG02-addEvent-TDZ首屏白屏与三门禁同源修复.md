## 4. 改动 B —— 新增轻量渲染期 TDZ 门禁（进 `--fast`）

新增 `scripts/verify/main-render-tdz-check.mjs`，使用仓库已有 `espree`，扫描 `src/main.jsx` 的 `App()`：

### 4.1 必须识别

- 收集 `App()` 直接函数体里的 `const` / `let` 绑定及声明位置（含对象/数组解构）；
- 对声明前的**渲染期立即求值表达式**做引用扫描；
- 以下必须判红：
  - hook/普通函数调用参数里直接读取后置 `const`；
  - 对象/数组字面量里直接读取后置 `const`；
  - `useMemo` / `useEffect` / `useCallback` 等依赖数组里读取后置 `const`；
  - JSX 属性或条件表达式里读取后置 `const`。

### 4.2 必须避免误报

- 不进入嵌套的普通函数、箭头函数、class 方法体扫描延迟执行的闭包内容；
- 但函数参数之外的依赖数组仍要扫描；
- 非 computed 的对象 key、成员属性名、标签名不算变量引用；
- 允许 function declaration 的提升语义；
- 当前 `useEffect(() => { detailApi... }, [])` 这类“仅在延迟回调体内读取、依赖数组未读取”的代码不得误报。

### 4.3 门禁自证（必须内置负向对照）

扫描器每次运行都用内置小片段自测：

1. `consume(late); const late = 1;` → 必须红；
2. `useEffect(() => consume(late), [late]); const late = 1;` → 必须红（依赖数组渲染期求值）；
3. `useEffect(() => consume(late), []); const late = 1;` → 不得误报（闭包延迟执行）；
4. `function helper() {}; helper();` → 不得误报。

自测失败时门禁自身判红，禁止只对当前 `addEvent` 写死字符串/行号。

### 4.4 注册

- 登记进 `scripts/verify/run-all.mjs` 的全量 `ORDER`；
- 同时登记进 `FAST_ORDER`，因为它纯解析、无子进程、应在几百毫秒内结束；
- 预期门禁规模：全量 **46→47**，`--fast` **28→29**；
- 无存量违规时不建 baseline，门槛就是 0。

执行者不得改 `eslint.config.mjs` 或既有门禁判据来“让它变绿”。
