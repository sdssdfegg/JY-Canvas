# V4.0-执行单-V118-提示词助手改为纯用户库且永不自动清空

> 派发日：2026-10-19 · 统筹：静音AI画板v4.0 · 优先级：🔴 **最高（用户资产不可丢）**
> 性质：**用户需求驱动的改造 + 数据安全加固**
> 用户原话（两条硬要求）：
> ①"提示词助手的地方是不需要显示任何的我画板功能的提示词，那个位置是让我自己添加我自定义的各种提示词才对"；
> ②"我后面主动添加的任何提示词助手的提示词都不允许清空或者更改，**包括我后续做成封装的话也是需要能保留的**，不然我写了一堆模板最后发给客户都没有的情况"。

## 0. 现状取证（2026-10-19 实测，行号以此为准）

### 0.1 内置提示词会被注入/回灌（三处）

| 位置 | 现状 | 后果 |
| --- | --- | --- |
| `src/main.jsx:190-196` `loadPromptPresets()` | `stored` 为空 → `return builtinPrompts;` | 空库时**满屏都是画板内置词** |
| `src/features/outfit/outfit-top.js:839-860` `loadOutfitPromptPresets()` | 先取 `BUILTIN_PROMPT_LIBRARY`，stored 里**没有的 builtin 会被 push 回去**（`:857-859`）→ 用户删了也回来 | 内置项**删不掉** |

### 0.2 封装发布会把用户提示词整库清空（🔴 最严重）

`src/features/storage/storage-store.js:54-81` `runPublicReleaseStorageReset()`：当 `PUBLIC_RELEASE_MODE` 为真且重置标记不是 "done" 时，直接 `removeStorageItem` 一串键，其中**包含**：

```text

"jingyin-outfit-workflow-prompt-library-v1"、"jingyin-outfit-workflow-prompt-categories-v1"、
"jingyin-outfit-workflow-prompt-library-v2-20260802"、"jingyin-outfit-workflow-prompt-categories-v2-20260802"
```

→ **封装（对外发布包）首次启动就会把用户自建提示词库抹掉**，正好命中用户"写了一堆模板最后发给客户都没有"的担忧。

### 0.3 版本键漂移（第二颗雷）

`PROMPT_LIBRARY_VERSION = "v2-20260802"` **两处重复定义**（`src/shared/app-defaults.js:6`、`src/features/outfit/outfit-top.js:24`），键值 `jingyin-...-prompt-library-${VERSION}`。将来任何人改这个版本号 → **所有用户数据"看起来被清空"**（实际是换了 key，老数据还在但读不到）。

### 0.4 复用面（改一处要知全貌）

- 共享 CRUD：`src/shared/prompt-library.js`（`usePromptLibrary` / `normalizePromptPreset` / `normalizePromptCategories`）已被两侧共用 ✅
- **加载只在两侧各写一份**（`loadPromptPresets` vs `loadOutfitPromptPresets`，`loadPromptCategories` vs `loadOutfitPromptCategories`）——V11-RF-040 裁定"同名不同义勿合并"是针对**聚合口径**不同；现在两边都要改成"纯用户库"，**口径正好统一** → 本单把它们**收口为共享单一函数**（回应用户"规整源码就是为了复用"）。
- UI：`src/features/prompt/PromptAssistantView.jsx`（主画板弹窗）、`src/features/outfit/panels/WorkbenchSidebar.jsx:34` + `src/outfit-workflow.jsx:1988`（批量页「词」tab）共用同一份 presets/categories props。

## 1. 改动要求

### 1.1 不再注入任何内置提示词

- `src/main.jsx` `loadPromptPresets()`：`stored` 为空 → 返回 `[]`（**不再 `builtinPrompts`**）。
- `src/features/outfit/outfit-top.js` `loadOutfitPromptPresets()`：
  - 删掉"builtin 回灌"（`:857-859`）；
  - 删掉"用 builtin 覆盖用户值"的分支（`:850-856`，即 `return {...preset, title: builtin.title, content: builtin.content, custom:false}`）；
  - `stored` 为空 → 返回 `[]`。
- 分类：`loadPromptCategories()` / `loadOutfitPromptCategories()` 的兜底改成 `["全部"]` + 由用户 presets 派生（`storedPrompts.map(p => p.category)`），**不再使用内置 `promptCategories` / `PROMPT_CATEGORIES`**。

### 1.2 收口为共享单一函数（本单的"复用"兑现）

在 `src/shared/prompt-library.js` 新增并导出（命名自定，须在文件头注释写明是两侧唯一加载口径）：

- `loadPromptLibraryPresets({ presetsKey })` —— 读 stored，逐条 `normalizePromptPreset`，过滤空内容；**空 → `[]`**；**不注入任何内置**。
- `loadPromptLibraryCategories({ categoriesKey, presetsKey })` —— `["全部"]` + 用户自定义分类存档 + 由用户 presets 派生的分类，`normalizePromptCategories` 去重。

`src/main.jsx` 与 `src/features/outfit/outfit-top.js` 两个加载入口改为调用它（各自传自己的 key）。**改完后两侧行为必须一致**——这正是本单的验收重点。

### 1.3 封装发布重置豁免用户提示词（🔴 核心）

`src/features/storage/storage-store.js`：把下面 6 个键从重置清单里**移除**：

```text
PROMPT_PRESETS_KEY、PROMPT_CATEGORIES_KEY、
"jingyin-outfit-workflow-prompt-library-v1"、"jingyin-outfit-workflow-prompt-categories-v1"、
"jingyin-outfit-workflow-prompt-library-v2-20260802"、"jingyin-outfit-workflow-prompt-categories-v2-20260802"
```

并在该数组上方加注释：

```js
// V118（用户硬要求）：提示词助手的预设/分类属于**用户自建资产**，任何发布重置都不得清除
// —— 用户会把模板写给客户用，丢了就是不可恢复的事故。下面这些键**不在**重置清单内：
// PROMPT_PRESETS_KEY / PROMPT_CATEGORIES_KEY 及其历史版本键。
```

其余键（STORAGE_KEY、ACTIVE_VIEW_KEY、DETAIL_*、pages、history…）**照原样保留重置语义**，不得扩大豁免。

### 1.4 版本键漂移保护

- `PROMPT_LIBRARY_VERSION` 收口为单一来源：`src/features/outfit/outfit-top.js` 改为从 `src/shared/app-defaults.js` 导入（**删除自己的那份定义**），避免两处不一致。
- 新增一次性迁移（放在加载函数里，只在当前键为空时执行）：按 `v2-20260802` → `v1` 顺序查找历史键，命中且数组非空 → 写入当前键并保留历史键（不删），然后正常返回。写 `addEvent` 或 console 均可，**不要**因为迁移失败阻断启动。

### 1.5 内置常量处置

`builtinPrompts`（`src/shared/app-defaults.js:86`）、`PROMPT_BUILTIN_PRESETS` / `PROMPT_PRESET_GROUPS` / `BUILTIN_PROMPT_LIBRARY`（`src/features/outfit/outfit-top.js:522/580/641`）：**先 `git grep` 确认引用面**——若除上述注入点外无其它使用者，**保留常量 + 加一行"V118 起不再注入 UI，仅留档"注释**（退役保留，与 V110 的 `_makeRecolorPage` 同一策略）；若还有别的引用，停下回报。**不得删除常量本身**（防误伤 + 保留回退能力）。

## 2. 验收标准

### 2.1 静态取证

- `git grep -n "builtinPrompts\|BUILTIN_PROMPT_LIBRARY" -- src` → 只剩定义处 + 退役注释（不再出现在任何返回给 UI 的路径上）。
- `git grep -n "PROMPT_PRESETS_KEY\|prompt-library" -- src/features/storage/storage-store.js` → **不含** `removeStorageItem` 清单里的 prompt 键（用 `sed -n '64,82p'` 复核那段数组）。
- `git grep -c "PROMPT_LIBRARY_VERSION" -- src/shared/app-defaults.js src/features/outfit/outfit-top.js` → 定义仅 1 处、另一处为 import。
- node 直接 import 共享加载函数，用 mock localStorage 跑：
  - 空库 → `[]`（不是内置项）；
  - 存 1 条用户 preset → 原样返回（**不被 builtin 覆盖**）；
  - 历史 `v1` 键有数据 + 当前键空 → 迁移后返回该条数据。

### 2.2 门禁

- `run-all --fast` 32/32；`vite build` EXIT=0；`eslint` 0 errors（基线 1 warning 不动）。
- 注意：`dead-export-check` / `frontend-duplication-check` 可能因"两处加载函数合并为一处"报 improved（好事），若报 regressions → 停下回报，不许自行 `--update` 掩盖。

### 2.3 运行时探针（tabbit）

1. **空库干净**：清掉 prompt 相关 localStorage → 进提示词助手 → **列表为空**、分类只有「全部」（不得出现任何画板内置词）。
2. **自建保留**：手动新增 2 条自定义提示词（不同分类）→ 刷新页面 → **两条仍在**、分类仍在。
3. **删了不回来**：删掉某条 → 刷新 → 不再出现（验证不再回灌）。
4. **改了不被改回**：编辑某条的内容 → 刷新 → 保持用户改后的内容。
5. **两侧一致**：主画板提示词助手与批量页「词」tab 看到**同一份**预设与分类（这是"单一来源"的现场证据）。
6. **发布重置豁免（关键）**：`PUBLIC_RELEASE_MODE` 若无法在探针环境开启，则用静态断言（§2.1 第二条）+ 在真实封装包首次启动时人工确认"自定义提示词仍在"作为交付验收；执行方须在回执明确写清"用哪种方式验的"。

## 4. 留档（统筹写入）

- **产品定性变更（2026-10-19）**：提示词助手从"内置示例库 + 用户补充"改为**纯用户自建库**。内置预设仍留在代码里（`builtinPrompts` / `PROMPT_BUILTIN_PRESETS`）但**不再注入 UI**，随时可回退，不属于删除。
- **用户资产红线**（写进 `AGENTS.md` 与后续所有封装说明）：`PROMPT_PRESETS_KEY` / `PROMPT_CATEGORIES_KEY` 及其历史版本键，**任何自动重置/迁移/清理都不得删除**；发布包重置只允许重置"应用状态类"键（视图、设置、任务、历史）。
- **为什么顺手收口加载函数**：两侧加载逻辑本来各写一份（这是它们行为分叉的根因——一边空库给内置、一边还要回灌+覆盖）。收口后"改一次两边一致"，正是源码规整的意义。
- **版本键是隐形地雷**：键名里带 `PROMPT_LIBRARY_VERSION`，改版本号 = 换 key = 用户数据"消失"。收口定义 + 加历史键迁移，把它变成可控操作。
