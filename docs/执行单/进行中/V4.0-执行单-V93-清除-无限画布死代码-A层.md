# V4.0 执行单 V93 — 无限画布死代码清除（A 层：纯死路径 + 专用模块）

> 统筹：静音AI画板v4.0 · 起草 2026-10-18（来源：**用户 2026-10-18 现场反馈**——"我不知道你在哪里看到的无限画布的相关功能，我这个版本还没有做无限画布板块，要是有可以直接删除了无限画布的部分内容，避免总是打架的情况"）。
> 前置：**V92 已合回 main**；从 main 拉分支 `codex/ui-v93-remove-infinite-canvas`；base = **派发日 main HEAD**（hash 由统筹在派发消息中告知）；一单一 commit；`--no-ff` 合回 main；禁 `--no-verify`；严格串行。
> 总纲：`docs/V4.0-前端UI全局规范方案.md`。**所有行号为起草日实测，执行日必须重 grep 重测，以实测为准**。

## 0. 这单要解决的问题（先读，别只照着删）

无限画布（infinite canvas）在本版本**根本不存在**——`src/features/storage/storage-store.js` L18 `export const SHOW_INFINITE_CANVAS = false;` 把它的导航入口关掉了，L27 的 `navItems` 用三目把它过滤掉，**用户从 UI 上永远看不到它**。但它的**代码、状态、CSS、存储 key 全都还躺在仓库里**。

这就是用户说的"总是打架"的具体来源，实测三个层面：

1. **UI 规范推进时被死代码反复消耗**：V83 曾经为死代码做过 CSS 选择器随迁（`.canvasToolGroup .smallButton/.dangerButton` → `.canvasToolGroup .ui-button`），V89 又删了 `.canvasToolGroup .iconButton`、`.infiniteNode header .iconButton`。**我们花了两个单子的力气去维护一个永不渲染的模块的样式**。
2. **体量与门禁被死代码占用**：`src/features/canvas/` 1146 行 + `src/styles.css` 约 260 行死 CSS + `main.jsx` 25 处 `infinite` 命中 / 37 处 canvas 状态使用点，全部计入 size-ratchet、hardcoded-color、dependency-direction 的账。
3. **复核与探针被死分支干扰**：`activeView === "infinite-canvas"` 这类永不成立的分支散落在主壳与顶栏，读代码与写探针时都要额外排除。

**目标：把这些确认无引用的死代码删干净，让 UI 规范推进不再为不存在的模块付账。**

### 2.2 每一步的硬性校验

- **每删一个符号，先 `git grep -n <符号> -- src` 确认零引用再删**；有引用就停下回报。
- 删完一类立刻 `npx vite build` 试编译，别攒到最后一次性排错。
- `main.jsx` 是主壳，删状态容易漏掉 useEffect 依赖数组、useCallback deps、props 透传链 —— **逐个函数过一遍**，不要靠编译器只报未定义变量（deps 数组残留不会报错，但会留下脏代码）。

### 2.3 `INFINITE_CANVAS_KEY` 的处置（默认裁决）

- **删** `src/shared/app-defaults.js` L16 的常量定义与其导出。
- `src/features/storage/storage-store.js`：删 L2 的 import 项；**L75 清理列表里保留该 key 的字符串字面量**（写成 `"jingyin-infinite-canvases-v1"`，即展开常量值）—— 理由：该列表是 public release 的旧数据清理清单，**老用户 localStorage 里可能已存在这份数据**，删掉字面量会让数据变孤儿永远清不掉。
- 若执行日发现该 key 还有别的读写点未覆盖 → 停下回报。

### 2.4 不要顺手做的（记录即可，不得搭车）

- 任何 UI 规范化改动（本单是**纯删除**，不改视觉、不动 `Button` / `UploadClearButton` / `TaskBadge`）。

## 3. 验收

### 3.1 零残留（统筹会逐条复算）

- `git grep -in "infinite" -- src` → 除 `canvas-generation-handlers.js`（V94 范围）与 CSS `animation: … infinite`（**关键字，不是模块**）外，**应无模块级命中**；`SHOW_INFINITE_CANVAS`、`INFINITE_CANVAS_KEY`、`infiniteCanvasState`、`setInfiniteCanvasState`、`createInfiniteCanvas`、`canvasViewport`、`canvasStageRef`、`infiniteCanvasState` 全部 0 命中。
- `src/features/canvas/` 目录下**只剩** `canvas-generation-handlers.js` 一个文件。
- `ls src/features/canvas/` 与 `git grep -ln "canvas-graph\|canvas-actions" -- src` → 后者 0 文件。

### 3.2 功能不回归（探针）

- 左导航仍是 **7 项**（快捷生成 / 批量生成 / 图片编辑 / 批量改尺寸 / 参考生图 / 一键详情·主图 / 提示词助手），**不出现**「无限画布」。
- 快捷生成视图可正常进入、工具栏与上传入口正常（复用 `tmp/v92-upload-clear-survey.mjs` 的导航与注入框架，跑一遍全 app 上传模块清点，应与 V92 归档时结论一致）。
- 结果区右键菜单**不出现**「发送到无限画布」。

### 3.3 门禁（本单路由：重大结构变更 → 全量）

本单删的是主壳 `main.jsx` 约 1600 行 + 一个 feature 目录，属**里程碑级结构变更**，按验证路由纪律跑**全量串行**：

- `node scripts/verify/run-all.mjs --skip-launcher` **52/52**（同一时刻只允许一个套件在跑）
- `npx vite build` EXIT=0
- `npx eslint .` → **0 errors**；warning 允许且仅允许基线那 1 条（`server/routes/outfit.routes.js` 的 `deferOutfitAutoSave`，**别动**）

### 3.4 基线（条件式预授权，超出即停下回报）

删除类单子**必然**触发以下基线变化，**预授权 `--update`**：

- `size-ratchet-baseline.json`：大量文件行数下降、函数级条目随函数消失而失效 → 预授权刷新（**条件：只降不升；若出现任何文件行数上升 → 停下回报**）。
- `dependency-direction-baseline.json`：涉及 `features/canvas` / `main.jsx` 的依赖方向条目可能变陈旧 → 预授权刷新。
- `dead-export-check` / `import-path-check` / `frontend-duplication-baseline.json`：若因删除产生条目变化 → 预授权刷新。
- `hardcoded-color-baseline.json`：删除死 CSS 会让 hex 计数下降 → **只记 improved，不许 `--update`**（纪律）。
- `legacy-button-baseline.json`：**零改动**（本单不碰按钮类；若发现无限画布死代码里还残留旧按钮类 → 停下回报，由统筹决定是否并入其它单）。
