## 0. 背景与用户原话（先读）

用户 2026-10-18 原话（两条，本单各修一条）：

1. "然后我现在把随机背景、批量改色的板块删了，不需要了，新增了1板块，**后面更新就按我现在的来不要又把我之前的板块加进来了**"
2. "然后有个bug，我在1页面双击输入中文名字改色、服装改色、**名字都会变成批量改色**"

统筹已逐环取证，两个 bug 的根因都定位到行（执行方不必重新排查，按 §1 实施即可；如发现行号与派发日不符，先停下回报）：

### Bug A：改名被强制归一化（用户报障②）

双击页面 chip 改名的链路：
`OutfitPageRow.jsx` L50 `onDoubleClick → renameOutfitPage(page.id)`
→ `use-outfit-pages.js` L152-213 `renameOutfitPage`（`window.prompt` 取输入）
→ `outfit-page-actions.js` L18-31 **`normalizeOutfitPageName`**
→ **L27**：`if (/批量改色|改色|换色|服装改色|颜色替换|颜色参考|recolor/i.test(name)) return DEFAULT_RECOLOR_PAGE_NAME;`

即：任何含"改色"的名字被**改写为"批量改色"**。用户输入"服装改色"→得到"批量改色"，输入"改色"→同样。这就是"名字都会变成批量改色"。

### Bug B：删掉的页面每次启动都被加回（用户报障①）

`outfit-workflow.jsx` L318 `useState(readOutfitPages)`
→ `outfit-page-actions.js` L594-610 `readOutfitPages`：只要有存档就跑 **`ensureWorkflowPages`**（L486+）
→ `ensureWorkflowPages` 对缺失的 singleton workflow 页（pose-remix / background-change / random-background / recolor / white-refine / face-swap / design-draft）**无条件补建**。

用户删掉"随机背景""批量改色"两页后，每次重启 App 都被重新建出来。用户诉求"按我现在的来，不要又把我之前的板块加进来了"。

### 连带裁决（为什么必须在本单一起改）：recolor 模式改向 custom

`inferOutfitWorkflowMode`（L169）只是 `workflowModeFromPage`（L92）的包装，后者 **L115-117** 把"改色"类名字判为 `"recolor"`。

用户的新页面是点页面行"+"新建的 **custom 页**（`createOutfitPageFromCurrent` → "临时需求 N"，用户称之为"1板块"）。V111 要把部位改色功能挂在 custom 页上。**若只修 Bug A 不改向**：用户把页面改名成"服装改色"后，`workflowMode` 会被实时判成 `recolor`（L425 每次 render 都从名字推导），挂在 custom 上的功能全部失效，页面退回旧批量改色形态。

**裁决（统筹，留档可推翻）**：`workflowModeFromPage` 的 recolor 分支返回值 `"recolor"` → `"custom"`。即**改色页并入"自定义改色页"**，旧 recolor workflow 退役（用户已删其页面且不希望它回来；其 UI 由图2底部旧"改色范围/改色部位"选择器改为 V111 的新"更换部位"行）。服务端 `server/routes/outfit.routes.js` L202-205 仍按页面名识别 recolor——**不动**：服务端两条路线的提示词拼装完全一致（都走 `buildUserPromptOnly`：用户正文 + 补充词），兼容无碍（详见 §1.4）。

#### 1.3.2 新增三个留痕函数

文件：`src/features/outfit/outfit-page-actions.js`（`readJsonStorage`/`writeJsonStorage` 已在 L12 import ✔；`OUTFIT_PAGES_KEY` 等同名 import 已在 L16，把新键加进该 import 列表）。放在 `ensureWorkflowPages` 定义前：

```js
/** 用户主动删除过的 singleton workflow 模式留痕（V110）：ensureWorkflowPages 不再补建这些页。 */
export function readDeletedWorkflowModes() {
  const stored = readJsonStorage(OUTFIT_DELETED_WORKFLOW_MODES_KEY, []);
  return Array.isArray(stored) ? stored.filter((mode) => typeof mode === "string" && mode) : [];
}
export function rememberDeletedWorkflowMode(mode) {
  const value = String(mode || "");
  if (!value) return;
  const current = readDeletedWorkflowModes();
  if (current.includes(value)) return;
  writeJsonStorage(OUTFIT_DELETED_WORKFLOW_MODES_KEY, [...current, value]);
}
export function forgetDeletedWorkflowMode(mode) {
  const value = String(mode || "");
  if (!value) return;
  const next = readDeletedWorkflowModes().filter((item) => item !== value);
  writeJsonStorage(OUTFIT_DELETED_WORKFLOW_MODES_KEY, next);
}
```

## 4. 留档（统筹写入，执行方知悉）

- **裁决链**：用户新页面是 custom 页（"+"新建，"1板块"）→ 部位改色功能（V111）挂 custom → 改名含"改色"不能被强制归一化（Bug A）且不能被实时判成 recolor（否则功能失效）→ recolor 分支改向 custom → 旧 recolor workflow 退役、代码保留不删、服务端不动。
- **用户六条诉求对案**（本单 + V111 合起来闭合）：①删页不回来（本单 §1.3）②改名保留（本单 §1.1/1.2）③部位行一条（V111 §1.1）④通用改色提示词框（V111 §1.3）⑤类别词联动（V111 §1.2）⑥补充词末尾+去重（V111 验证，现行链路已满足）⑦拖拽排序（V111 §1.5）。
