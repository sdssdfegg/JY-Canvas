## 4. 实现规格

### 4.1 字段定义（对齐战略 §七 7.2 十三项，逐项落地）

| 字段 | 类型/规则 |
|---|---|
| `version_id` | 稳定唯一 ID；创建后不可变 |
| `task_id` | 对应 TryOnTask 标识，可空（沙盒数据可空，真实数据由后续单填） |
| `parent_version_id` | 父版本 ID；根版本为 `null`；**只存指针，本单不实现树遍历/比较/回退** |
| `input_asset_refs[]` | 输入素材引用（`{type, ref, name?, bytes?}`）；只存引用，不落 buffer |
| `result_asset_ref` | 生成结果路径或资源标识；🔴 **注明引用可能因 TTL 清理失效** |
| `user_instruction` | 用户本轮指令（纯文本） |
| `structured_edit_goal` | 本轮结构化编辑目标（对象，可空） |
| `model_and_versions` | 模型名 / 模板版本 / 策略版本（对象，可空） |
| `execution_params` | 关键执行参数（对象）；🔴 **禁止写入 API Key、口令、私钥等敏感信息**，写入前须做键名剥离并留单测断言 |
| `created_at` | ISO 时间戳（服务端生成，拒绝外部覆盖） |
| `status` | 执行状态（如 `pending` / `succeeded` / `failed`）；枚举值不改既有业务枚举 |
| `error` | 错误信息（纯文本，脱敏后可空） |
| `user_accepted` | 用户是否接受结果；🔴 **只能显式设置，禁止静默覆盖/自动置 true**（照抄 `garment-profile-store.js` 的 patch 剥离范式） |

补充：`version` 序号可由索引推导（根为 1、子版本递增），但**不得**用它替代 `version_id`；不写 `prompt` 全文以外的大段对话历史（战略 §七 7.3 多轮上下文规则：结构化状态，不是越拼越长的对话）。

### 4.2 存储与写入纪律

- 落点 `data/ai-tryon/image-versions/index.json` + `data/ai-tryon/image-versions/<version_id>.json`；目录常量由 `app-paths.js` 新增行提供。
- **版本文件只增不改不删**；`tmp` + `rename` 原子写；索引用 Promise 链单写入器串行化；索引损坏时 `.bak` 回退，两者皆坏则重建（对齐 `task-store.rebuildIndex` / `rebuildGarmentIndex`）。
- 🔴 **坑（V167 实测）**：`rebuildImageVersionIndex` **不得**套用 `withChain(indexChains)` 与「`upsertIndex → ensureIndex → rebuild` 外层链同 key」结构，会自我嵌套死锁（顶层 await 永不 settle）；直接写、对齐 `task-store.rebuildIndex`。

- **不提供任何 DELETE / unlink / rmSync / 清理接口**；本模块无删除能力。
