### 1.3 三层真因（按用户感知排序）

1. **看不到图（主因）**：`src/features/detail-studio/generation/GenerationPanel.jsx:168-191` 只渲染 `TaskBadge` 状态文字 + 一行错误，**全文件零 `<img>` / 零结果网格**；`orchestrator.js:49-73` 的 `isImageLocalPath` 只认 `file://` 与绝对路径，`/api/history-image/...` 相对 URL 被判 `null` ⇒ `resultPath` 恒为 `null` ⇒ 结果图既没进工作区独立目录、也没被任何视图引用。**扣费出的图存在，但用户永远看不到**。
2. **感知「一直」**：`GenerationPanel.jsx:58-68` 的 3s 轮询本身正常，但 8 屏各耗时 55–67s，期间界面只有静态「生成中」，无已等待秒数 / 无上游状态 / 无进度；统计行 `成功 0 · 失败 0 · 待确认 0 · 已取消 0 · 共 8（0%）` 连 `running/queued` 都不显示。截图即这一窗口内拍的。
3. **没复用一键详情的生图（Owner 指出的根）**：一键详情是**前端直调** `generateImages(form)`（`src/features/detail/detail-state.js:419-439` → `src/api/images.js:3-5`），form 含 `baseUrl` / `normalizeApiKeyInput(apiKey)` / `routingFields` 产出的 `dispatchMode` / `referenceMeta` / `source=detail-main` / 真实上传文件，返回后 `:440-476` 立即 `setResults` 把图铺进 `DetailView.jsx:471-544` 网格、写 history、失败就地归一化提示。详情创作却在 `local-images-generator.js:21-70` **另造了一套服务端内部自调用的私有 form**（只有 prompt/model/channelId/imageSize/aspectRatio/n/deferAutoSave/source/apiKey/image），**缺 `baseUrl` / `dispatchMode` / `referenceMeta`**，用 `deferAutoSave=1`，结果只写任务 JSON —— 3 屏「请先上传商品图」正是这套字段不对口的直接后果。

> 结论：**渠道、KEY、网关、`/api/images` 全部正常**（8 条 200 实证）。问题在详情创作自建的「服务端内部自调用 + 只显示状态徽章」这一层。V211 只照搬了布局外观，没照搬生图链路 —— 统筹口径偏差，本单纠正。
