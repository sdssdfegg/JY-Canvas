# V4.0 执行单 P7-4 —— 产物体积预算门禁（bundle budget）

> 派单：统筹　|　执行：开发　|　目标：给打包产物设体积预算，防止依赖膨胀/误引入大包静默拖慢首屏。
>
> 背景：2026-10-16 架构审计：当前**最大 chunk 约 261 kB**，无任何体积门禁；包一大，用户「丝滑」体验直接受损且无人察觉。
>
> 执行标准：① 一单一 commit；② 纯净可粘贴；③ 不符**停手回报**；④ 不得改契约文档与 `.workbuddy/memory/**`。

## 0. 前置（派发日复核）
- main 干净；在 main 上拉分支 `codex/p7-4-bundle-budget`。
- **本单依赖构建产物**：需先 `vite build` 产出 `dist/assets/*.js` 才能测。
- 环境坑同前（禁 `--no-verify`、spawnSync EBUSY → 用 spawn）。

## 1. 现状基线（2026-10-16 审计；派发日必须实测）
| 项 | 值 |
| --- | --- |
| 最大 chunk | 约 **261 kB**（审计值；派发日以 `dist/assets` 实测为准） |
| 预算建议 | 最大 chunk **≤ 300 kB**（约基线 +15%），总 `sum` 一并记录 |

**派发日先跑一次 build，读 `dist/assets` 真实值**，再定预算（预算必须 ≥ 当前实际值，否则门禁一上线就红）。

## 2. 做法
1. 新建 `scripts/verify/bundle-budget-check.mjs`（约 100 行）：
   - 读 `dist/assets/` 下 `*.js`（必要时含 `*.css`）的文件大小（字节）。
   - 与 `baselines/bundle-budget.json` 比对：`{generatedAt, reason, maxChunkBytes, totalBytes, budget:{maxChunkBytes, totalBytes}}`。
   - 判红：实测 > 预算 → 红，输出具体超标项与实际/预算值。
   - `dist/` 不存在 → **不判红**，输出"跳过（无构建产物）"，退出 0（避免未构建时误伤）。
2. `--update`（带 `--reason`，用于调预算或刷新基线）；`--json`。
3. **注册位置（重要）**：加入 `scripts/verify/run-all.mjs` 脚本表，但**不要进 `--fast` 子集**——它依赖 build（数秒），只归全量/CI。单里必须注明这一点，避免拖慢每次提交。

## 3. 纪律（R1–R6）
- R1 串行；R2 分支如上；R3 `--no-ff` 合 main；R4 派发日实测；R5 门禁绿、禁 `--no-verify`；R6 **不为了压体积改业务/依赖**（那是另一单），本单只加观测与拦截。

## 4. 负向对照（双向）
- 绿：当前实际 ≤ 预算 → `ok=true`。
- 红：临时把预算调到低于实际值（如 1 kB）→ 转红并打印超标明细；还原 → 复绿。
- 附加：`dist/` 不存在时应输出跳过且退出 0（验证一次）。
- 红证输出贴回报。

## 5. 度量（派发日填）
- 实测最大 chunk ___ kB；预算设为 ___ kB；总 ___ kB。
- `run-all` 全量条目数：___ → ___（本脚本**不在** `--fast`）。

## 6. 回收站 `.lock` 清理纪律（硬性）
- 结束前直接删除工作区/临时目录残留 `*.lock`（`Remove-Item -Recurse -Force` 或 node `fs.rmSync`），严禁进回收站；回报附计数（应为 0）。
