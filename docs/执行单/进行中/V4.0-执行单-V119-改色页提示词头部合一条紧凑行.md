## 1. 改动要求

把现在的 `{isCustomWorkflow && (<div className="outfitIntentRow recolorPartRow">…})` 整块替换为：

```jsx
{/* V119（用户要求）：按参考图把「通用改色提示词 + 用默认模板 + 更换部位 + 上装层级」合成一条紧凑行。

    <span className="recolorPromptHeaderLead">
      <span className="outfitIntentRowTitle">{promptFieldTitle}</span>
      <Button size="sm" tone="ghost" onClick={onResetRecolorPromptTemplate}>
        用默认模板
      </Button>
    </span>
    <span className="outfitIntentRowTitle">更换部位</span>
    <div className="outfitIntentChips">
      {RECOLOR_PART_OPTIONS.map((part) => { /* V117 的 chip 逻辑一字不动 */ })}
    </div>

      {UPPER_LAYER_OPTIONS.map((option) => { /* V117 的 chip 逻辑一字不动 */ })}
```

同时把 `.composerField` 的 label 首行 `<span>`（现 `:349-362`）改为**仅非 custom 渲染**（custom 的标题与按钮已上移，避免重复出现）：

```jsx
{!isCustomWorkflow && (
  <span>
    {promptFieldTitle}
```

- 「本次需求 / 商品补充信息」补充提示词框**不动**（参考图中它的位置与现状一致）。

## 4. 留档（统筹写入）

- **根因复盘**：V117 复用 `.outfitIntentInline` 时只看了"它是横向 flex"，漏了它的 `justify-content: space-between` 是为"两要素两端对齐"设计的——承载**四组**内容时必然把间距拉满。教训：**复用布局类前先读它的对齐语义**，语义不合就新开最小规则，不要硬塞。
- **「用默认模板」的位置**：从 textarea 的 label span 移到头部行，顺带消除了"button 嵌在 label 内"的点击歧义（点按钮会触发 label 的焦点行为）。
- **布局演进链**：V111 独立行（仅部位）→ V112 加层级行 → V117 两行合一（复用 space-between 容器，间距失控）→ **V119 一条紧凑行（左对齐流式，本次）**。后续引用布局时以本单为准。
