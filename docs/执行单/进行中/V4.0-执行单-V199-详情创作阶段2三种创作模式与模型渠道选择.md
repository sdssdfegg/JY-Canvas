## 3. 三种创作模式独立业务路径（本单重点 B）

项目 `mode` 字段已在阶段 1 建立且**创建后不可变**（`server/features/detail-studio/store/project-store.js`），本单按该字段做硬隔离：

| 模式 | 路径 | 阶段 2 交付 |
|---|---|---|
| A `guided` | 专业 AI 策划 | 商品资料引导式录入骨架 + AI 主动追问的交互入口（追问规则与策划产出留阶段 3） |
| B `assisted` | Agent 辅助策划 | 用户想法/方向/参考图录入 + 「保留原意」的原文留痕骨架（补充与优化逻辑留阶段 3） |
| C `direct` | 完整提示词直接生成 | **完整实现四份边界**（见下）；只识别分屏边界、切屏、组织生成任务骨架 |

🔴 **架构级隔离要求**：三种模式必须是三条独立业务路径，不能变成三个按钮后汇入同一套自动改写流程。建议 `intake/` 下按 `mode-a/` `mode-b/` `mode-c/` 分文件或分 handler；**模式 C 的 handler 不得 import 任何 planner / skill / 策划模块**，从代码依赖上杜绝「自动重写用户提示词」。

### 3.1 模式 C 四份边界（Owner 阶段 0 裁决，必须落实）

1. `rawPrompt`：用户原始提示词，**永久只读**，AI 不得覆盖。
2. `tidyVersion`：AI 生成的独立整理版本（**可选功能，默认不启用**）。
3. `diff`：整理前后具体差异，可展示、可修改。
4. `frozenPrompt`：**仅用户确认后**才成为实际生成使用的提示词。

智能整理只做「识别分屏边界」的整理，一次为限，不得补充/删减/替换卖点与画面要求；即使采纳也必须保留 `rawPrompt` 可回溯。生成模块只能读 `frozenPrompt`（架构保证，不依赖开发人员记得）。

## 4. 商品资料与参考图体系

按总任务书 §五，参考图分三类职责并在数据结构中明确标注，避免互相干扰：

- `product`：商品参考图 —— 确认真实外观/包装/颜色/结构/标签，建立**商品身份锚点**。
- `visualStyle`：视觉风格参考图 —— 色彩/字体/构图/光影/调性；不得误当商品资料。
- `contentStructure`：内容结构参考图 —— 叙事逻辑/模块安排/信息层级；不得照抄他人事实与文案。

用户可只提供一种或多种。阶段 2 只做**录入、职责标注、保存与展示**；图片文件复用现有上传/资产端点，落到 `data/detail-studio/` 独立目录（🔴 不进 `data/results` 7 天 TTL、不进 `seed/manifest.json`）。商品事实的分级（已提供事实 / 合理推导 / 待补充 / 禁止虚构）留阶段 3。
