## 二、方案

1. **逐个读取 6 份**，按「是否被排产/裁决 grep 引用 + 是否含未闭合工单」裁定 live / dead。
2. **live 文件（REFACTOR_TICKETS.md / REFACTOR-冷启动.md 及裁定为活的）：禁止改内容**（契约文档纪律，见禁改清单），仅保留原位。
3. **dead 文件（裁定为死的存档快照）：`git mv` 进 `docs/存档-台账/已归档/` 子目录**，腾出空间且保留可追溯（不 `rm`）。
4. 若 `REFACTOR-工单明细.md` / `REFACTOR-新功能开发规范.md` 裁定为死，同样归档。
5. 移动后**重建基线**：`node scripts/baseline/create-baseline.mjs`（预期变更：dead 文件路径由 `docs/存档-台账/` 变为 `docs/存档-台账/已归档/`，或 Manifest 中消失）。

## 五、风险提示

- **不要为了「瘦身」去改写活台账**：那是契约文档，动则违反纪律且可能丢失裁决依据。瘦身杠杆只有「搬走死存档」。
- 若裁定某份「待裁定」文件为活，保留原位即可，不必强删。
- 迁移动后必须重建基线，否则 Manifest 路径不符会误判回归。
