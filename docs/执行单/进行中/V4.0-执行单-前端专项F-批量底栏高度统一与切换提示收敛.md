## 1. 需求（用户原话转译）

1. 切换批量生成里的生图板块时，下方弹出「页面切换：已切换到「XX」」提示，把下方功能按键区顶得上下跳——**这条切换成功提示直接去掉**。
2. 「固定背景」「随机背景」等板块的下方按键区高度明显比换装页短；**要求所有板块（含「+」新建的临时需求页）下方按键区顶部位置一致**，切换时无偏移感。

## 3. 改动要求

1. **去掉切换成功提示**：删 `use-outfit-pages.js:89` 的 `addEvent("页面切换", 已切换到「X」)`（或改为只写 `setEvents` 不写 `inlineMessage`——但本仓 `events` 列表无渲染出口，等效于删）。**`:74` 的「当前正在生成，完成后再切换页面」拦截提示必须保留**（有业务价值）。
2. **toast 不再推挤布局**（防其他 20+ 处 `addEvent` 同病）：`OutfitComposer.jsx:347` 的 `composerStatus` 改为**常驻渲染占位**（无条件渲染 + `min-height` 与出现时同高 + 空时渲染不可见占位），或改为 absolute 脱离文档流（父级 `:2637-2658` 已有 position:relative 可用）。**二选一，推荐常驻占位**（不遮内容）；回报写明所选方案。
3. **按键区高度统一**：
   - `.outfitIntentBar`：非换装页渲染**等高占位**（visibility:hidden 或空壳），保持 grid 行高恒定；
   - `.rightTools`：设固定 `min-height`（按最坏换行场景取值，回报附取值依据）。
4. **只动布局与提示，不得改任何控件逻辑**：select 的条件渲染（含随机背景视觉重点）、开关、生成按钮行为一律不变；仅允许在条件渲染外套等高占位壳。

## 4. 验收（缺一不可）

1. `--fast` 全绿 + `vite build` EXIT=0 + ESLint 0 errors。
2. **浏览器实测高度一致性（核心验收）**：用 tabbit（或等价）打开批量生成，依次切到：换装 → 固定背景 → 随机背景 → 批量扩图 → 精修 → 新建「临时需求 N」，逐页量 `.rightTools`（或 `.composerStickyControls`）的 `getBoundingClientRect().top`，**各页差 ≤ 2px**；回报附每页实测值。
3. 切换板块过程中：无「页面切换」提示出现；生成进行中点击其他板块，拦截提示仍出现且**不再顶起布局**。
4. 生成主链路回归：任选一板块跑一次生成任务成功（确认布局改动没碰坏提交链路）；`outfit-defer-autosave-check`、`outfit-intent-check` 等门禁绿。
5. `git status -- src/` 无意外文件；TDZ 门禁绿。

## 5. 删除与 `.lock` 纪律（硬性）

允许姿势（四选一）：`/usr/bin/rm -rf`（绝对路径）｜node `spawnSync("/usr/bin/rm", ...)`｜前缀 `CODEBUDDY_SAFE_DELETE_ENABLED=0`｜PowerShell `Remove-Item -Recurse -Force`。
**禁止**裸 `rm` / `rmdir` / `unlink` / 裸 `fs.rmSync`。回报附删除姿势与 `.lock` 增量（应为 0）。
