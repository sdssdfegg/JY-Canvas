# V4.0 执行单 V81 — 门禁提效·run-all 全量套件并行化调研与实施（收尾单·候选）

> 统筹：静音AI画板v4.0 · 起草 2026-10-17（承接 V79/V80 执行者建议：全量 run-all 串行起服务太慢，"值得另立一单看看能否并行化"）。**派发前由统筹补入实测耗时数据**。
> 定位：**收尾单（门禁基础设施提效），非 UI 规范单**。不改任何 check 的判定语义，产品代码零改动。
> 状态：**候选单，待统筹/用户裁决派发时序**（建议排在 V79/V80 归档后、V73 前或与 V73-V75 并行讨论后定）。

## 1. 需求（背景）

`npm run check` 的全量口径（`run-all --skip-launcher`，50 条）目前**纯串行**执行（`run-all.mjs` 主循环 `for + await runOne`，注释自述"顺序执行便于定位失败点（且部分脚本要占用端口，不能并发）"）。实测参考：2026-10-17 统筹全量复跑总耗时 **739.9s（约 12.3 分钟）**；V79/V80 执行者跑到 30 分钟仍未结束即中止（浏览器类逐支起服务 + tabbit 冷启动）。

统筹复核的体感代价：每单复核都要付一次全量钱，慢到诱导"只跑 --fast 就归档"的侥幸——V70 的 modal-shell 锈蚀、V76 的 lint 欠账，都是这个侥幸的产物。本单目标：**在不放水、不改语义的前提下压短全量墙钟时间**，让"统筹复核跑全量"成为默认动作而不是奢侈动作。

**核心约束（项目记忆既有坑，不得违反）**：tabbit 共享浏览器 profile 会跨次残留开关态，污染后续 check——并行跑浏览器探针=互相污染，**浏览器类要么保持串行，要么先做 profile 隔离，不许裸并行**。

## 3. 改动要求（调研先行，实施须统筹确认方案后落地）

### 3.1 调研（必做，回报附数据）

- 全量跑一次，导出**逐条墙钟耗时表**（run-all 已有 `ms`，`--json` 可直接取）；
- 按「纯源码/逻辑（无端口无浏览器）× 起服务/浏览器 × 撞车组」三分类清单，标出每条的资源占用（端口 / tabbit profile / `data/` 写 / vite cache dir）；
- 给出并行化收益估算：静态类并发（并发度 N=4 与 N=8 两档）× 浏览器类维持串行的总墙钟；以及浏览器类 profile 隔离后的进一步收益（仅估算，本期不实施）。

### 3.2 实施（二选一，回报注明选择与理由）

- **方案 A（保守，推荐默认）**：run-all 增加 `--jobs N` 参数，默认 `1`（行为与现在逐字节一致，CI/钩子零风险）；`N>1` 时仅对**静态类**建并发池，端口/浏览器类仍串行，且撞车组（8888 等）同组内串行。
- **方案 B（激进）**：连浏览器类也按「独立 profile + 独立端口」隔离后并入池。**本期禁止**——profile 隔离方案未经验证，留待后续单；如调研认为 A 已达标，明确建议不做 B。

### 3.3 硬约束

- **判定语义零变化**：任何 check 的通过/失败标准、输出格式、退出码不变；
- **失败归因不劣化**：并发时每条脚本的 stdout/stderr 仍按脚本分别捕获，失败时仍打印末 14 行详情；结果表仍按原 ORDER 顺序呈现（与现在一致）；
- **默认路径不变**：不带 `--jobs` 时与当前串行行为一致（含输出顺序）；
- 不引入新依赖（node 原生 child_process 够用）；不改 `--fast` 子集构成；
- 不碰任何 check 脚本本体（除 3.1 发现的 8888 撞车若在方案 A 内必须规避，也只许在 run-all 的调度层规避，不许改被调度脚本）。

### 3.4 附带的 flake 加固（run-all-check 套件内偶发失败）

调研中须一并定位 §2 末行 flaky 的根因（负载下 spawnSync 子进程异常），给出修法并实施：优先把 run-all-check 内的 `spawnSync` 改为与 run-one 一致的异步 spawn（消灭 EBUSY/信号类窗口），**不得**用"失败就重试" masks。修完后套件内连续两次全量 run-all-check 均一次通过。

## 4. 验收（缺一不可）

1. 不带参数全量跑：**50/50 通过**，且逐条结果顺序/摘要与串行版一致（对照改造前一次全量 JSON）。
2. `--jobs 4` 全量跑：**50/50 通过**，连续 **3 次**无 flaky（浏览器类串行 lane 不得互相污染——用 retouch-frontback 的开关态初值假设验证）。
2b. 串行全量（不带 `--jobs`）连续 **2 次** 50/50，且两次 run-all-check 均一次通过（flake 加固生效；改造前 2026-10-17 曾套件内偶发 1 次）。
3. 墙钟数据：`--jobs 4` 总耗时应显著低于串行（目标 ≤ 串行的 60%；未达标的回报实测分布，由统筹裁决是否接受）。
4. `--fast` 30/30、`check-syntax`、`vite build` EXIT=0、ESLint 0 errors 不受影响；`--jobs` 参数本身过 ESLint。
5. `git diff --stat` 仅 `scripts/verify/run-all.mjs`（+ 调研数据文件如留在 `tmp/` 不入库则不计）。

## 5. 删除与 `.lock` 纪律（硬性）

本单无删除。临时文件删除姿势：`/usr/bin/rm -rf`（绝对路径）｜node `spawnSync("/usr/bin/rm", ...)`｜`CODEBUDDY_SAFE_DELETE_ENABLED=0` 前缀｜PowerShell `Remove-Item -Recurse -Force`。禁止裸 `rm`/`rmdir`/`unlink`/裸 `fs.rmSync`。回报附 `.lock` 增量。
