## 3. 改动要求

### 3.1 新建 `scripts/verify/hardcoded-color-check.mjs`（LF 行尾）

规格（与既有棘轮同款语义）：

- 扫描范围：`src/**/*.css`（**不含** `.jsx` 内联 style——动态色合法）；
- 判据：按文件统计 hex 颜色出现次数（`#rgb`/`#rrggbb`/`#rrggbbaa`，大小写不敏感；`rgba()/hsla()` 等函数色暂不记账，回报说明理由）；
- 基线 `scripts/verify/hardcoded-color-baseline.json`：记录起草日实测各文件 hex 数（带 `reason` 说明"UI 规范化存量，V76+ 各接入单顺手清零"）；
- 判定：文件 hex 数 **> 基线 → 判红**（新增）；< 基线 → `improved` 只报告；基线文件已无 hex 而代码仍在（stale）→ 判红逼 `--update`；
- `--update`：重写基线（用法与 `shared-ui-duplication-check.mjs --update` 一致）；
- 退出码/输出格式对齐既有 check（ok/failureCount/improved/stale 字段），附 4 条负向自测（临时构造超限文件判红、达标文件通过、`--update` 后转绿、stale 判红）。

### 3.2 注册进 `run-all.mjs`

`ORDER` 与 `FAST_ORDER` 都加 `hardcoded-color-check`（注册后跑一次 `--fast` 实测全绿，回报附耗时）。

### 3.3 基线初始化（本单明文预授权）

首次 `--update` 生成基线（存量记账），commit message 写 reason。**这是本单唯一预授权的基线刷新**；其余 9 套基线不得动。

## 4. 验收（缺一不可）

1. `npm run check` 全绿（`--fast` 29+1=30 项 + `vite build` EXIT=0）+ ESLint 0 errors；`git status -- src/ scripts/` 无意外文件。
2. **负向自测 4/4 通过**（构造超限判红、达标通过、`--update` 转绿、stale 判红），自测脚本或过程附回报。
3. **误拦验证**：`SettingsView.jsx` 主题色板内联 `backgroundColor` 不判红；`styles.css`/`outfit-workflow.css` 存量 hex 只报告不判红。
4. 基线内容附回报（各文件 hex 数清单），`--update` 仅执行一次且 commit message 带 reason。
5. `docs/执行单/README.md` 模板节落地。

## 5. 删除与 `.lock` 纪律（硬性）

预计无删除。如产生临时文件：`/usr/bin/rm -rf`（绝对路径）｜node `spawnSync("/usr/bin/rm", ...)`｜`CODEBUDDY_SAFE_DELETE_ENABLED=0` 前缀｜PowerShell `Remove-Item -Recurse -Force`。禁止裸 `rm`/`rmdir`/`unlink`/裸 `fs.rmSync`。回报附 `.lock` 增量（应为 0）。

## 6. 不得做

- 不得借机清零存量 hex（那是 V76+ 各接入单"所碰文件顺手清"的活；全量清零单独开单）。
- 不得改判据去适配代码（如把 hex Pattern 放宽）——基线才是适应存量的机制。
- 不得扫 `.jsx` 内联 style（动态色合法，误拦就是破坏主题系统）。
- 不得改其余 9 套基线；不得改 `server/`、`src/api/`、`prompts/`、`.workbuddy/memory/**`。
