## 0. 现状取证（2026-10-19 实测）

- `src/features/outfit/panels/OutfitComposer.jsx:299-323`「更换部位」行 = `.outfitIntentRow.recolorPartRow`；`:325-350`「上装层级」行 = **独立第二个** `.outfitIntentRow.recolorUpperLayerRow`，且条件是 `{isCustomWorkflow && recolorPart === "upper" && (...)}` → 选下装/连衣裙/鞋子时整行消失。
- 布局复用面：`src/features/outfit/outfit-intent.css:85-90` `.outfitIntentRow{display:grid;gap:5px;padding-top:8px;border-top:1px solid var(--border)}`（标题在上、chips 在下，天然是"一块"）；`:141-146` `.outfitIntentInline{display:flex;align-items:center;justify-content:space-between;gap:8px}`（**现成的横向一行容器，可直接复用**）；`.outfitIntentChips` 自带 `flex-wrap: wrap`。
- 联动现状：`replaceRecolorPartWords(prompt, _fromPart, toPart)`（`outfit-top.js:237-247`）**只替换正文里实际出现过的部位词**；`RECOLOR_PART_WORDS` = upper[上衣,上装] / lower[下衣,下装] / dress[连衣裙] / shoes[鞋子]。**正文里一个部位词都没有时原样返回**（V112 定的"保护手写内容"口径）。

**"点了不联动"的唯一合理解释（统筹裁决）**：用户当前改色页的提示词正文里**没有任何部位词**（情况有二：① 用户手改过提示词，把"上衣"换成了别的说法；② 页面带的是旧版长模板的**变体**——只有**完全等于** `RECOLOR_DEFAULT_PROMPT` / `RECOLOR_COLOR_LEGACY_DEFAULT_PROMPT` 才会被 V113 迁移，改过一两个字就不迁移）。此时按设计不动正文，但**界面没有任何反馈**，用户看到的就是"点了没反应"。

## 1. 改动要求

### 1.1 两行合一 + 上装层级常显（`OutfitComposer.jsx`）

把现在的两个 `.outfitIntentRow` 合并为**一行**，复用既有类名，**零新增 CSS**：

```jsx
{/* V111/V117（用户要求）：改色页「更换部位」+「上装层级」排成一行（层级常显，不再随部位隐藏）；
    复用 .outfitIntentRow 的行框 + .outfitIntentInline 的横向排布 + .outfitIntentChips 的 chip 组，零新增 CSS。 */}
{isCustomWorkflow && (
  <div className="outfitIntentRow recolorPartRow">
    <div className="outfitIntentInline">
      <span className="outfitIntentRowTitle">更换部位</span>
      <div className="outfitIntentChips">
        {RECOLOR_PART_OPTIONS.map((part) => { /* 现有 chip 逻辑不变 */ })}
      </div>
      <span className="outfitIntentRowTitle recolorUpperLayerRow">上装层级</span>
      <div className="outfitIntentChips">
        {UPPER_LAYER_OPTIONS.map((option) => { /* 现有 chip 逻辑不变 */ })}
      </div>
    </div>
  </div>
)}
```

- **删掉** `recolorPart === "upper"` 条件 → 上装层级**常显**（用户明示）。
- 保留 `.recolorUpperLayerRow` 类名挂在层级标题上（选择器/后续定位用），但它的语义由"整行"变为"组内一组"。
- 若窄屏实测出现挤压/换行破裂，**只允许新增 1 条** `.outfitWorkflowEmbedded .recolorPartRow .outfitIntentInline { flex-wrap: wrap; row-gap: 5px; }`，**不得**新造 chip/行样式；并须在回执里贴探针截图说明。

### 1.2 联动兜底：无部位词时不再"静默"

`src/outfit-workflow.jsx` 的 `selectRecolorPart`（现 `:457-465`）：

- 计算 `nextPrompt` 后判断 `nextPrompt === String(settings.prompt || "")`（即**没发生任何替换**）→ 在 `addEvent("更换部位", ...)` 之外**追加一条可见提示**：
  `addEvent("更换部位", "提示词里没有检测到可替换的服装类别词（上衣/下衣/连衣裙/鞋子），已保留你的手写提示词；需要自动联动可点提示词框右上「用默认模板」")`。
- `selectRecolorUpperLayer`（现 `:466-476`）同口径：`replaceRecolorUpperLayerWords` 未改动正文时提示没有检测到层级词/上装部位词。
- 事件文案保持现有风格（其它事件都是"已切换为「X」"这一类短句）。

### 1.3 「用默认模板」入口（custom 页）

在改色页提示词框标题行（`.composerPromptCol > label.composerField > span`，现装 `promptFieldTitle` 与 `composerFieldHint`）**右侧**加一个小按钮，**仅 `isCustomWorkflow` 时出现**：

- 复用 `src/shared/ui/Button`（`size="sm" tone="ghost"`），文案「用默认模板」→ **零新增 CSS**（与 V70/V72 收口后的按钮体系一致，勿写裸 `<button>`）。
- 点击行为：
  1. 取 `GARMENT_RECOLOR_DEFAULT_PROMPT`；
  2. 按**当前选中部位**跑 `replaceRecolorPartWords(template, recolorPart, recolorPart)`（先换成当前部位的词）；
  3. 若当前部位是 `upper`，再按**当前层级**跑 `replaceRecolorUpperLayerWords(..., "single", recolorUpperLayer, 部位词)`；
  4. `setSettings({ ...current, prompt: nextPrompt })` + `addEvent("通用改色提示词", "已恢复默认模板（当前部位/层级已套用）")`。
- **只改 `prompt`，不动 `productNote`**（V110 口径：custom 页前端不并 productNote）。

### 1.4 明确不做

- 不改 `replaceRecolorPartWords` / `replaceRecolorUpperLayerWords` 的"保护手写"语义（不强行改写用户手写内容——那才是真的破坏用户资产）。
- 不给"无部位词"做模糊匹配（如把"衣服""服装"也当部位词）——误伤风险大于收益。
- 不动换装页 `OutfitIntentPanel`、不动服务端、不动其它 workflow。

## 2. 验收标准

### 2.1 静态 / 取证（执行方回执**必须逐项列出**）

用 node 直接 import 纯函数，把"不联动"分类跑出来（这是判断用户属于哪种情况的关键证据）：

| 输入正文 | 切到「下装」后的期望 |
| --- | --- |
| `GARMENT_RECOLOR_DEFAULT_PROMPT`（4 处"上衣"） | 4 处变"下衣" |
| 手写且含"上衣"（如"把图1的上衣改色"） | "上衣"→"下衣" |
| 手写且含"上装" | "上装"→"下装" |
| 手写**不含任何部位词**（如"把图1模特的服装改成图2颜色"） | **原样返回**（设计如此）+ 触发 §1.2 提示 |
| 空串 | 原样返回 + 触发 §1.2 提示 |

另：`git grep -c "recolorPart === \"upper\"" -- src` → 应为 0（常显化的直接证据）。

### 2.3 运行时探针（统筹/执行方）

1. **合一 + 常显**：进改色页 → 「更换部位」与「上装层级」在**同一行**（同一 `.outfitIntentRow` 内）；切「下装」/「连衣裙」/「鞋子」→ 上装层级**仍在**（不再消失）。
2. **联动回归**：正文 = 模板 → 依次点 下装/连衣裙/鞋子/上装 → 4 处词整体联动、往返闭合。

4. **回归**：换装页、其它页零影响；零 JS 错误。

## 4. 留档（统筹写入）

- **"常显"取代"仅上装可见"**：V112 的设计是"选下装/连衣裙/鞋子时上装层级无意义所以隐藏"，但用户实操后发现**控件忽隐忽现更难受**（且层级选择会停留在旧值造成误解）→ 改为常显，与部位选择解耦。层级只在部位 = 上装时才**写进提示词**（`selectRecolorUpperLayer` 用当前部位的提示词词，`outfit-workflow.jsx:471` 已如此）。
- **"不联动"不是 bug 而是静默**：联动链条本身是通的（V113 探针 4 部位往返全绿），真正的问题是"正文无部位词 → 按设计不动 → 界面零反馈"。修法是**给反馈 + 给一条恢复路径**，而不是粗暴地改写用户手写的提示词（用户明确要求"我写的提示词不允许被清空或更改"，见 V118）。
- 两处模板迁移口径（`makeOutfitPage` 新建 / `ensureWorkflowPages` 加载期）**仍然必须同改**（V113 留档），本单不动它们。
