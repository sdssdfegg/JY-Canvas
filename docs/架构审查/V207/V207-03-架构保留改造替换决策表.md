## 逐项详述

### 1. Agent 组织方式 → 改造
- **现状**：无真 Agent，四步规划为独立端点由前端按钮驱动；ai-canvas 是单轮 JSON 规划；ai-tryon 纯状态机。
- **改造方向**：保留「同一 `postChatCompletion` + 不同 system」的事实基础，升级为「受控决策者」——统一 Tool 调用契约（#6）+ 显式 model-decided/code-decided 边界（见 V207-02 §2.1）。
- **不做什么**：不引入 LangChain 式多智能体框架、不新增大量 Agent 文件。

### 2. Agent 角色划分 → 改造
- **改造方向**：角色继续以 `system` 文案 + `AgentProfile{ system, availableTools, availableSkills }` 表达；新增工作区=注册 Profile，不改核心。

### 3. Skill 体系 → 改造 + 补齐
- **依据**：`industry/*` 已 INJECTED（好，保留）；`platform/`、`reference-image-roles.js`、`case-library.js` 仅门禁扫描（P9）；`reference-image-guide.md` DEAD。
- **补齐**：让 `platform/`、`reference-image-roles.js`、`case-library.js` 经 Skill 运行时被消费（或明确退役）；删除 DEAD 资产；修复 #8 双真相源（`reference-image-roles.js` vs server 内联常量，二选一为真相源）。

### 4. Skill 加载机制 → 新建（运行时注册表）
- **依据**：当前无运行时发现/加载器，纯构建期 import。
- **新建**：`skill-registry`（轻量，非框架），提供 `registerSkill` / `resolveSkill(industryId, platformId, stage)`；现有 `prompts/detail-studio/**` 内容资产原样迁入，业务代码零改动即可注册。

### 5. 项目上下文 → 改造 + 补齐
- **依据**：P3 history-loss（多轮历史不回灌）、P4（`currentPlanRunId` 未赋值）、无长度护栏。
- **补齐**：`ContextBundle` 回灌 `editThreads`+版本链（受窗口裁剪）；`currentPlanRunId` 规划启动时赋值、续跑恢复；加整体 token 长度护栏。

### 6. 工具调用体系 → 新建（Tool 抽象）
- **依据**：P1，全仓无 Tool 体系。
- **新建**：统一 `Tool` 接口（见 V207-02 §3.1），把出图/编辑/资产/任务/版本封装为 Tool；Agent 仅经 Tool 影响世界；换装新能力从「重写 AI 模块+路由」降为「注册 Tool+Skill」（解 P12）。

### 7. 任务编排 → 保留（小补强）
- **依据**：生成层编排成熟（#7 数据）。
- **补强**：补规划层服务端串联（可选，降低前端驱动耦合）；长任务进度可视化与用户介入点标准化。

### 8. 长任务恢复 → 保留（小补强）
- **依据**：`recovery.js` 收敛终态、绝不重发（E1）。
- **补强**：把「未完成规划续跑」接 `currentPlanRunId`（与 #5 联动），复用既有 `needs_confirm` 人工确认。

### 9. 质量控制 → 改造
- **依据**：P7，`qc-review.js:31-36` 未传 `industryStrategy`。
- **改造**：`buildQcUserPrompt` 收齐 `industryStrategy.promoBoundaries`；确定性 `checklist.js` 继续复用。

### 10. 模型接入层 → 改造（图像侧替换实现）
- **依据**：P2/P10/P11，文本与图像两套并行实现，图像侧无适配器。
- **改造（附替换子项）**：**替换** `images.routes.js:223` 内联 baseLoop 为抽出的 `generateImage(req)` 图像适配器，复用 `channel-config.js`/`image-concurrency.js`/`image-error-policy.js`；`postChatCompletion` 包裹为同构文本适配器；两者共享超时/重试/可观测封装。**不新增 Provider/KEY/网关**。
- **双源同步债**：把 `channel-config.js` 与 `src/shared/routing.js:441 CANVAS_REASONING_MODELS` 收敛为单一生成源（编译期或启动期校验），消除人工同步。

## 决策分布

- **保留**：#7 任务编排、#8 长任务恢复。
- **改造**：#1、#2、#3、#5、#9、#10（#10 含图像适配器替换子项）。
- **新建**：#4 Skill 运行时注册表、#6 Tool 抽象。
- **改造+补齐**：#3、#5。

> 没有任何一项建议「替换整层核心结构」；#10 的替换仅限于图像适配器内部实现，外部契约（KEY/渠道/`/api/images`）完全复用——故总体结论为「较大改造」而非「替换智能执行层部分核心结构」。
