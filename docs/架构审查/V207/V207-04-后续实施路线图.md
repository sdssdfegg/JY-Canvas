## P1 · Tool 抽象底座（最高优先级）

- **目标**：引入 `Tool` 接口（`V207-02 §3.1`），把出图/编辑/资产/任务/版本封装为标准化 Tool。
- **前置依赖**：无。
- **范围**：
  - 新增 `server/features/*/tools/` 或 `server/core/tool-registry.js`（轻量，非框架）。
  - 把 `local-images-generator.js`、`version-store.js`、`project-store.js`、`orchestrator.js` 的公开能力包成首批 Tool（`imageGenerate`/`editScreen`/`saveVersion`/`switchVersion`/`manageAsset`/`createTask`/`retryTask`）。
  - 每个 Tool 声明 `permissions`/`idempotent`/`confirmRequired`/`sideEffectScope`。
- **验收标准**：
  - 现有出图/编辑/版本切换经 Tool 调用后**行为字节一致**（新增 `tool-parity-check` 门禁，负向对照：直接调用 vs 经 Tool 调用结果相同）。
  - `idempotencyKey`/`image-concurrency` 全局 5 并发未破坏（复用既有闸门，不新建并发机制）。
  - `run-all --fast` 全绿；`vite build` EXIT=0；public 首启浏览器冒烟 SMOKE_PASS。
- **回滚策略**：Tool 层为**纯增量包装**，原有函数保留为 Tool 内部实现；若回归，删除 Tool 注册并让路由直调原函数（旧路径不变），`git revert` 单一 commit 即可。

- **前置依赖**：P1（可选，注册表独立）。
- **范围**：

  - 把 `prompts/detail-studio/**` 现有内容资产原样迁入注册表（业务代码零改动即可注册）。

  - 删除 `reference-image-guide.md`、未消费的 `copywriting/methodology` 导出（先 grep 确认零消费）。
  - 修复 P8：选 `reference-image-roles.js` 或 server 内联常量二者之一为唯一真相源（建议统一到 `workspace-contract.js` + 注册表引用）。

  - 行业增删仍数据驱动、业务代码不改（保留现有优势）。
  - 既有 `industry-strategy-match-check` 全绿。
- **回滚策略**：注册表为新增模块，旧静态 import 路径保留；若问题，`git revert` 即可回到静态 import。死资产删除前先确认零消费（grep 全仓）。

## P3 · Model Adapter 统一（图像适配器抽取 + 双源收敛）

- **目标**：#10 改造，替换 `images.routes.js:223` 内联 baseLoop 为 `generateImage(req)` 适配器，复用 `channel-config`/`image-concurrency`/`image-error-policy`；把 `postChatCompletion` 包裹为同构文本适配器；收敛 `channel-config.js` ↔ `routing.js:441` 双源。
- **前置依赖**：无（独立于 P1，但建议与 P1 同批评审）。
- **范围**：
  - 抽出 `server/core/model-adapter/{text,image}.js`，两者同构 `complete(req): ModelResponse`。
  - 图像适配器内部复用既有候选循环/换线/变体重试判定（`image-error-policy.js` 的 `shouldTryNextChannel`/`shouldTryNextImageVariant`）。
  - 双源收敛：以 `channel-config.js` 为唯一生成源，`routing.js` 改为引用它（启动期校验一致性），消除人工同步。
- **验收标准**：
  - 出图结果字节一致（新增 `image-adapter-parity-check`，对照旧 baseLoop 行为；负向对照：禁用适配器退化为旧路径）。
  - `resolveApiKey`/`image-concurrency` 全局 5 并发/换线/重试行为不变。
  - 不新增 Provider/KEY/网关；全局模型配置与设置体系不被破坏。
- **回滚策略**：适配器为旧 baseLoop 的等价重组；保留旧 handler 入口可经开关切回旧路径，单 commit 回滚。

## 全局回滚与风险护栏

- **每阶段单一 commit**，遵循项目纪律（精确暂存、`--fast` 全绿、不 `--no-verify`）。
- **不破红线**：不引入第二套 Provider/KEY/网关、不改画布、不重写可用出图链路、不提前做详情页预览导出（V208 范围）。
- **并行规避**：参照 AGENTS.md R1 串行互斥，P1/P2/P3 虽可并行但建议各自独立分支、串行合入，避免 size-ratchet 基线漂移误判。
- **未验证项**：E3/E4 真实运行证据本单为 0，每阶段验收以 E1 代码 + E2 模拟/单测为主；真机出图与 public 首启冒烟交 Owner 实机覆盖。
- **迁移总原则**：所有改造为**等价重组 + 增量包装**，旧路径保留可切回，杜绝「重写即断裂」。
