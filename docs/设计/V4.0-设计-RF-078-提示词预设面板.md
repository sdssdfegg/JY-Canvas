## 表④ 拆分方案与净省预估（参考值；因已裁决不抽）

若统筹推翻 RF-057 裁决、强行抽共享组件：

- **落点必然新建文件**：`src/features/prompt/PromptPresetPanel.jsx` + `PromptEditModal.jsx`（现有两巨石不适合再塞；`prompt-library.js` 是逻辑 hook 不装 JSX）。⇒ `fileCount` 58→59 ⇒ 019 扫描漂移 ⇒ 需统筹划账（**命中执行单停手条件 #2「必须新建文件」要素**）。
- **props 数量**：≥14（state + `usePromptLibrary` 输入）。RF-057 文件头已判定这"等于改视觉"。
- **净省估算**（三面板 + 两弹窗，去掉重复标记，加组件 + 接线）：
  - 删：main 面板+弹窗 ~158 + outfit 面板×2 ~155 + outfit 弹窗 ~48 ≈ **361 行**
  - 加：2 组件 ~175 + 3 面板/2 弹窗接线 ~90 ≈ **265 行**
  - **净省 ≈ +96 行**（正，但小；且 main 富 tab ~54 行仍内联，实际净省更小，约 +40~70）
- **风险**：drag/drop + 模态高危 UI；把 7 处真分叉塞进 props 脆弱；新建文件触发 019 划账。
- **结论**：即便强行抽，净省也远小于 RF-076（≈180）与 RF-077（≈239），收益/风险比低；且**已有裁决禁止**。⇒ **建议不抽**。
