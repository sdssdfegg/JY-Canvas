# V4.0 前端 UI 全局规范方案（前端UI规范化总纲）

> 统筹：静音AI画板v4.0 · 起草 2026-10-16
> 范围：**仅前端表现层**（`src/` 下样式与组件），不含 `server/`、`src/api/`、`prompts/`，不改任何业务逻辑与接口。
> 配套执行单：V69–V75（`docs/执行单/进行中/`，共 7 张基建单），后续按版块逐个开单（V76+），收口单删除全部旧按钮类。

---

## 0. 结论速览

前端 UI 不统一的根因不是"不会写 CSS"，而是**三套并行视觉体系 + 没有组件层 + 没有尺寸族**：

| # | 体系 | 位置 | 状态 |
| --- | --- | --- | --- |
| 1 | 主应用体系 | `src/styles.css`（`:root` 四套主题 + 9 类共用按钮块，L296 起） | 令牌驱动，是规范底座 |
| 2 | 换装体系 | `src/outfit-workflow.css`（自带 17 个硬编码主题变量 L1-23 + 平行按钮块，全文 804 处 `.outfitWorkflowEmbedded` 引用） | 独立王国，不跟随 `data-theme` |
| 3 | 零散体系 | 约 150 处裸 `<button>` + 30+ 个一次性按钮类（`saveKeyButton`/`pinnedFolderButton`/`assetRerunButton`/`legacyAction`…） | 每个版块自己长 |

解法：**四层规范（令牌 → 组件 → 版块模式 → 功能）**，棘轮式迁移（不推倒重来），6 张基建单先行，之后一单一版块，门禁防复发。

## 2. 规范架构：四层（T/C/P/F）

```text
L4 功能模块层  src/features/**、outfit-workflow.jsx、main.jsx  只写业务逻辑与数据流，零自定义视觉
L3 版块模式层  ModuleHeader / Panel / Field / Toolbar 结构 + 栅格 + 尺寸分级
L2 组件层      src/shared/ui/  Button / Modal / Panel / Field / Toolbar …
L1 令牌层      src/styles/tokens.css  唯一样式来源（颜色×4主题 + 尺寸族）
```

依赖规则：**上层只消费下层**。L4 新增视觉 CSS、L2 之外定义组件样式、L1 之外定义 `:root` 变量，一律视为回归。

## 3. L1 设计令牌层规范

### 3.1 颜色语义令牌（沿用现有名，四主题同源）

现有令牌名不动（`--app-bg/--sidebar/--topbar/--panel/--panel-strong/--border/--soft-border/--text/--muted/--faint/--accent/--accent-strong/--danger/--danger-bg/--shadow`），全部收口到 `src/styles/tokens.css` 的 `:root` 与 `:root[data-theme=...]`。

### 3.2 换装别名映射（过渡期资产，V69 建、收口单删）

换装体系现用名 → 主令牌名，先在 `.outfitWorkflowEmbedded` 内做 12 条别名映射，避免一次性改 804 处引用：

```text
--panel-bg→--panel  --panel-strong-bg→--panel-strong  --input-bg→--input(新)
--button-bg→--control-bg(新)  --text-soft→--muted  --accent-text→--accent-on(新)
--accent-border→--accent  --option-bg→--panel-strong  --shell-bg→--app-bg
--sidebar-bg→--sidebar  --topbar-bg→--topbar
```

### 3.3 新增尺寸族（本方案核心增量）

```text
--control-h-sm: 28px   工具栏/紧凑控件
--control-h-md: 36px   版块内标准控件
--control-h-lg: 44px   页面级主操作
--radius-sm: 6px / --radius-md: 8px / --radius-lg: 12px
--space-1: 4px  --space-2: 8px  --space-3: 12px  --space-4: 16px  --space-6: 24px  --space-8: 32px
--text-xs: 12px / --text-sm: 13px / --text-md: 14px / --text-lg: 16px
--control-px: 12px（按钮水平 padding）
```

### 3.4 命名与落位规则

- 新增令牌一律进 `tokens.css`；feature CSS 内禁止新定义 `:root` 变量。
- 语义命名 `--类别-角色-变体`，禁止按页面命名（如 `--outfit-xxx`）。
- 主题只改令牌值，不改任何结构选择器。

## 4. L2 共享组件层规范

### 4.1 组件清单（与 `src/shared/ui/README.md`、`02-重复功能同步登记表.md` 对齐）

| 组件 | 状态 | 责任单 |

| `Button` | **待建** | V70 |

| `SettingsModal` / `UploadZone` / `ResultCard` / `TaskBadge` / `TopToolbar` / `AppSidebar` / `ReferenceThumbTray` | 登记表已列目标归并位置 | V76+ 按版块/共享面开单 |

### 4.2 Button API（V70 落地）

```jsx
<Button size="sm|md|lg" tone="default|primary|danger|ghost" iconOnly loading active
        disabled title="…" onClick={…}>{icon}{children}</Button>
```

- `size`：sm=28（工具栏/卡片内）、md=36（版块内标准）、lg=44（页面级主操作）
- `tone`：default 灰面 / primary 实心 accent / danger 危险 / ghost 透明
- `iconOnly`：正方形（宽=高），必须配 `title` 作无障碍名
- `loading`：`Loader2` 旋转 + 禁交互；`active`：accent 淡底（供 tab 场景）

旧类映射规则（迁移时按**所在版块层级**选尺寸，不按旧类名硬映射）：

```text
smallButton / toolbarButton / legacyAction / quickToolButton → sm + default（或 iconOnly）
iconButton → 按层级 sm/md + iconOnly
primaryButton / generateButton（页面主操作）→ lg + primary；版块内主操作 → md + primary
dangerButton → 对应尺寸 + danger
tabButton / modeTab（带 active）→ sm/md + default + active
```

### 4.3 ui.css 规则

- 组件样式只维护一份：`src/shared/ui/ui.css`，类名 `.ui-` 前缀（`.ui-button` / `.ui-panel` / `.ui-field`…）。
- feature CSS **禁止覆盖 `.ui-*`**；确需差异化走 props 变体，不走 CSS 覆盖。
- 图标统一 `lucide-react`：常规 16px、紧凑 14px。

## 5. L3 版块模式层规范

### 5.1 版块标准结构

```text
ModuleHeader  标题(14px/500) + 副标题(12px/muted) + 右侧操作区（主操作唯一，右置）
内容区        Panel 卡片或栅格，间距 --space-4/--space-6
底部操作条    次级操作左、主操作右；高度与换装底栏同一量级
```

### 5.2 按钮落位分级（治"有的功能不需要那么大"）

| 频率 | 落位 | 规格 |
| --- | --- | --- |
| 高频 | 工具栏常驻 | 28px 图标按钮 |
| 版块内常规 | 版块操作区 | 36px 标准按钮 |
| 页面级主操作 | 版块头部右侧/底部右端 | 44px 实心，**每版块唯一** |
| 低频 | "更多"菜单/设置弹窗 | 36px，不占常驻位 |

### 5.3 栅格与间距

版块间距 16/24；卡片内边距 12/16；控件 gap 8；同类控件同行右对齐到版块内容区右缘；弹窗操作区右对齐。

### 5.4 Field 规范

`label(12px muted) → 控件 → hint(12px faint)` 三段式，label 与控件 gap 6px；设置类栅格沿用换装 `.settingsGrid` 的列结构思路并收敛为 `Field` 组件。

### 5.5 冻结区模式（Dock Pattern，V76 首落）

重操作版块（换装/批量类）采用「单滚动条 + 底部冻结」结构：

```text
顶部区      ModuleHeader / 视图 tab 行（常驻）
滚动区      唯一滚动内容（结果图/卡片网格，align-content:start 贴顶不拉伸）
冻结区      操作条全家：上传分区横条 + 设置/提示词 + 页面 tab 行 + 参数行 + 主操作钮
            贴底常驻、不随内容滚动；border-top 分隔；整体一条视觉带
```

规则：
- 整页只保留一条滚动条（滚动区内）；冻结区任何子块不得出现 `overflow:auto`（横向 dock 如页面 tab 坞除外，且须 `scrollbar-width:thin`）；
- 内容不足时**不允许**拉伸内容卡片填充（`space-between`/`stretch` 禁用），留白策略 = 冻结区贴底 + 内容贴顶；
- 冻结区内行高预算：控件 36 + gap 8；**禁止**为"防换行"预留双倍高度（F 单 72px 预留的旧习，V76 起废止，控件超宽换行按内容问题个案处理）。

### 5.6 分区横条模式（Zone Strip，V76 首落）

同类上传/输入分区（换装图1/图2/图3）合并为一整条横排：

- 等宽栅格 `repeat(N, minmax(0,1fr))`，gap `--space-3`；
- **单一变体原则**：同组分区只允许一种样式变体（基准 = 最紧凑的那个，如换装取图3 compact），禁止"主区宽卡 + 副区竖堆"的混排；
- 缩略图、操作钮、footer 控件三区像素级一致（验收量测宽高差 = 0）；
- 分区条件显隐（某工作流不需要图2/图3）只改显隐，不改存活分区的形态。

### 5.7 密度档与隐藏档（V76 首落）

- **密度档**：版块分"紧凑/标准"两档，控件高度走 28/36/44 阶；提示词类多行输入 `clamp(最小, vh, 最大)` 且最小值不高于 44px；密度调整只改高度/padding/gap，**不改选项与交互**；
- **隐藏档（Park）**：暂时不用的功能"停止渲染但不删除"——摘除 JSX 渲染点、保留数据流/handler/组件文件、原位置注释标明 `V76（用户要求·暂时隐藏）：…恢复时传回 …`；隐藏不等于删除，恢复成本必须为一处传参。

## 6. L4 功能层治理（禁止清单）

1. 禁止在 `features/**`、`main.jsx`、`outfit-workflow.jsx` 新增视觉 CSS 类（布局结构类除外，且必须走 L2/L3）。
2. 禁止新写一次性按钮类（`xxxButton` 模式）。
3. 禁止在组件外新定义 `:root` 变量或硬编码 hex/rgba 颜色（V73 起 lint 拦截）。
4. 新版块验收硬指标：**视觉 CSS 0 行**，只用组件 + 令牌。

## 7. 迁移策略（五原则）

1. **不推倒重来**：旧 9 类按钮块与换装平行块在过渡期保留，逐点替换，任一步可独立回滚。
2. **一单一版块**：每个执行单独立交付、独立验收、独立合并（`--no-ff`）。
3. **基线预授权**：单内明文写清允许 `--update` 的基线文件与理由；未授权即回报等裁决。
4. **别名过渡**：换装 12 条别名映射 V69 建、收口单删；旧按钮类全量接入后由收口单删除。
5. **可视化验收**：每单附四主题浏览器截图 + 关键量测（`.rightTools` top、按钮高度 spread）。

## 10. 验收总标准（缺一不可）

1. 每单：`npm run check` 全绿（或 `--fast` 29 项 + `vite build` EXIT=0）+ ESLint 0 errors。
2. 全站按钮单一来源：`<Button>`；全局按钮类定义数只降不升。
3. 硬编码 hex 250 → 0（V73 后 lint 拦截新增）。
4. 四主题（默认/jade/graphite/mist）下全模块视觉一致，**含换装页**。
5. 新做版块：视觉 CSS 0 行。
6. 批量底栏高度一致性（`composer-stable-height-check`）不回归；如因按钮长高重锚，单内预授权 `--update` 并附实测。
