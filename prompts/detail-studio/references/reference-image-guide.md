# 参考图三角色方法论（product / visualStyle / contentStructure）

> 阶段 3C P1 · 配套 `reference-image-roles.js`（确定性数据 + 守卫）。
> 角色白名单与服务端校验已在阶段 2 落地，**本文件只补方法论，不改白名单逻辑**。

## 为什么要有三个角色

同一张参考图，若不分角色，模型很容易「串用」：把视觉风格的配色覆盖到商品真实包装色，
把版式骨架当成商品外观，把品牌水印复制进生成图。三角色强制把「身份 / 风格 / 结构」三件事拆开。

| 角色 | 一句话 | 它**只**约束什么 | 它**绝不**碰什么 |
|---|---|---|---|
| `product` | 商品身份锚 | 外观形态、包装/瓶型、颜色、标签文字、材质可见特征 | 场景氛围、构图版式、配色、品牌/水印、人物身份、文案事实 |
| `visualStyle` | 视觉 DNA | 场景氛围、构图基调、配色方案、版式风格、光线情绪 | 商品具体外观、品牌 logo/水印、人物身份、商品标签文字、文案事实 |
| `contentStructure` | 内容结构 | 版式骨架、信息层级、标题/正文排布、留白节奏 | 商品外观、视觉风格/配色、品牌 logo、人物身份、文案事实 |

## 怎么用（每角色的使用纪律）

- **product**：生成图的商品主体必须与此一致。只回答「这个商品长什么样」，不回答「放在什么场景」。
- **visualStyle**：定义整套详情的视觉语言，跨屏统一。可参考其配色/光线，但**不能复制品牌、水印、人物身份**进生成图。
- **contentStructure**：定义「字放哪、信息怎么排」。可以借鉴版式骨架，**不能夹带任何文案事实**（事实只来自用户资料）。

## 禁止串用（确定性红线）

1. 不要把 `visualStyle` 的配色覆盖商品本来的包装色（除非用户明确要换色）。
2. 不要把 `contentStructure` 的版式强加为商品外观或视觉风格。
3. 不要把参考图里的**其它商品**混进目标商品（`product` 角色边界）。
4. 三角色都不许带品牌/水印/人物身份进生成图（`visualStyle` 尤其注意）。

## 程序侧

- `isRoleAllowed(role)`：角色白名单校验（与 server 同口径，本文件只读暴露）。
- `roleGuard(role)`：取某角色的「禁止串用」约束清单，供导演/编译器拼提示词时引用。
- `validateReferenceAssets(assets)`：软校验一组参考资产（未知角色告警）。**真正的强制白名单在 server 侧**（禁改）。
