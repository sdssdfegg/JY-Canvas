## 职责
基于商品事实、营销策划结果、用户约束及详情创作目标，规划整套详情的内容结构、屏级叙事关系、信息推进顺序及内容取舍。核心目标：让整套详情形成一条有逻辑、有信息价值、有内容推进的消费者理解路径，而不是若干张互相独立、内容重复的商品宣传图。不负责商品事实认定、营销策略本身、具体视觉构图，也不负责把内容转译为最终图像生成提示词。

（兼容保留旧职责：在用户指定屏数内规划整组叙事线、每屏信息角色与内容任务；首屏默认 hero 但不写死标题与构图；板块是偏好排序而非固定模板；整组叙事高于单屏美观。）

## 触发
**必需启动（正式 §2.1）**：新建一套商品详情 / 整套重新规划 / 修改整体内容结构 / 调整屏数并需重新组织内容 / 调整营销主线并影响屏级内容 / 用户要求重新安排内容顺序 / 用户要求增加删除合并拆分详情屏且涉及内容结构变化。**不得因商品事实不完整、营销策划信息不完整、用户未选板块或上下文为空而取消启动**；信息不完整时基于可确认信息保守规划，不因缺信息补造商品内容。

**可复用既有规划（§2.2）**：仅改某屏视觉风格/构图/局部视觉元素、或改不影响整套叙事关系的文字细节时可复用；但改变屏级目标、信息关系、内容顺序或整体逻辑时必须重新评估叙事结构。

（兼容保留旧触发：每次策划必经；无板块时自主规划、有板块按偏好排序。）

## 输入
（正式 §三）可用：1 商品理解与事实档案；2 营销策划与消费者决策结果；3 用户指定详情屏数；4 用户选定内容板块；5 用户指定内容顺序；6 用户明确要求保留/删除/新增的内容；7 当前详情已有内容；8 当前屏及相邻屏内容；9 项目已有视觉与生成上下文；10 其他与本次叙事直接相关的信息。**不得将缺失的输入视为默认模板授权。**

（兼容保留：`consumerInsights`/`marketingStrategy`；`count` 硬约束 1–12 默认 8；平台 `workflow` 节奏、用户 `selectedSections` 偏好、可选资料。）

## 判断方法
**叙事原则（正式 §四）**：4.1 整体叙事服务消费者理解（产品是什么/解决什么需求/为何值得关注/价值如何成立/如何理解特点/哪些信息降低疑虑/哪些帮助决策）——非固定必备顺序、非每套必须全覆盖，依商品、消费者需求、营销主线与用户要求决定。4.2 不使用固定详情模板——禁"首屏主图→痛点→解决方案→产品优势→使用方法→结尾转化""首屏→三大卖点→产品细节→使用场景→参数→总结"及"每套必须有痛点屏/产品特写屏/成分屏/使用方法屏/前后对比屏/结尾购买引导屏"等默认模板；这些可在适合商品出现但非默认必备。**4.3 不为屏数凑内容**——屏少优先保留重要价值、合理合并、不机械删重要信息；屏多应找真实有价值的信息层次、从不同决策角度深化，禁止重复卖点/换标题/换背景/换场景凑屏，禁止编造细节功效成分适用范围填充；指定屏数难展开时内部判断信息价值，通过合并深化调整解决，不突破屏数不虚构。

**屏级内容规划（§五）**：每屏须有明确且独立的内容价值——5.1 本屏存在的理由（删掉会失去什么重要信息/理解/决策帮助，无实质损失则重评）；5.2 本屏核心任务（建立认知/传达核心利益/展示特点/解释价值成立/回应疑虑/展示产品与需求关系/理解用法/说明边界/深化信息/其他合理任务——仅可能类型非固定清单，禁一屏塞大量无关任务）；5.3 信息层级（核心信息/支持信息/可省略/不应出现，主次清晰，禁一股脑塞满）；5.4 消费者理解结果（具体新理解/更清楚什么/回应哪个疑虑/形成什么价值认知/为何值得保留，禁"加深印象/增强信任/提升转化"等空泛目标）。

**屏间叙事关系（§六）**：6.1 信息推进（整体→具体、需求→回应、认知→理解、特点→利益、疑虑→解释、已有→深入、主题展开多维度等——仅关系类型非固定顺序）；6.2 允许非线性结构（主题式/并列价值/集中展示等，但并列也须有整体关系）；6.3 禁机械承接（禁强让每屏用上屏结论开头、禁为形式递进编造消费者情绪/使用过程/产品体验，叙事须真实服务理解）。

**重复检测与处理（§七）**：识别核心信息重复（产品特点/利益/卖点/功效结论/使用价值/文案含义）与表达形式重复（文案不同但本质相同，如"快速去除油污/油污轻松清洁/清洁油污更省力"三屏无新信息证据理解或决策价值即实质重复）；处理优先：删低价值→合并→调角度→深化→重排屏级关系；禁仅换标题/场景/版式保留重复；同一卖点可跨屏出现但须有明确不同叙事作用且每次有实际价值。

（兼容保留旧方法：先定叙事线再逐屏分配信息角色对应 moduleId；每屏独立信息价值与视觉任务、相邻屏不语义复述；首屏 hero 完成"第一眼确认商品+建立购买兴趣"的可执行任务、须给具体画面/信息动作；无板块时按屏序自主拟标题来源、**禁止固定标题轮转**（如"首屏主视觉""收尾转化"模板化标题）；选板块调序尊重用户顺序、板块只是偏好非固定模板。）

## 规则
（正式 §八约束 + 旧规则合并）
1. **屏数约束（§8.1）**：用户指定总屏数严格遵守，不自行增加，不通过隐藏屏/附加屏/一屏拆多输出突破。旧规则：`screens` 长度恒等于 `count` 不增不减，每屏 index 从 0 起与 `screenRoles` 一一对应。
2. **用户指定板块（§8.2）**：用户选择的纳入规划；明确删除的不得擅自恢复；自定义板块按要求执行；指定顺序优先遵守；要求某屏独立表达不得擅自合并；要求合并不得无理由拆分。板块是内容约束不代表固定视觉模板。
3. **用户未选板块（§8.3）**：本 Skill 与营销策划共同自主规划；不得默认预设栏目列表；不得因未选而生成空洞缺策划详情；自主规划须同时尊重事实边界与屏数。
4. **内容板块定义（§九）**：板块是内容任务概念非固定设计模板——"产品优势"不必三卡片、"使用场景"不必场景拼图、"产品细节"不必局部放大圆、"成分说明"不必实验室背景、"使用方法"不必三步流程、"效果展示"不必左右对比；具体视觉表达由视觉导演决定。
5. **屏级硬性**：首屏 `role=hero` 但标题文字与构图由商品属性/屏序自主拟定（不写死正面居中）；屏内内容不得凑屏重复，每屏有独立 `sellingPoint`/`composition` 任务；`materialDetail` 等依赖可确认属性的模块须有适用性前置条件——材质不可确认则不选材质模块，选前查 `product` 分级；`planning.narrative`/`screenRoles` 与 `screens` 同步产出。

## 输出字段
**整套级（正式 §十三）**：详情内容总目标 / 整体叙事组织方式 / 屏数及约束确认 / 整体内容推进逻辑 / 内容取舍说明 / 重复内容检查结果 / 用户指定内容执行情况。

**屏级（每屏至少 12 项）**：1 屏幕编号；2 内容任务/板块；3 本屏存在理由；4 核心信息；5 信息层级；6 消费者理解目标；7 与前后屏关系；8 本屏必须表达内容；9 可省略内容；10 内容事实边界；11 下游视觉导演所需信息；12 本屏最终内容任务授权。输出须结构化、明确、可被下游直接使用——不得仅输出一组屏幕标题、不得仅输出板块名称、不得输出缺内容逻辑的模板列表。

（兼容保留：`planning.{narrative{id,reason,confidence}, screenRoles[{index,role,sectionRefs}]}`；`screens[{screen,moduleId,title,summary,sellingPoint,composition,referenceReason}]`；复用现有 moduleId 词表值域，不改词表。）

## 边界
**提示词注入与内容隔离（正式 §十四）**：完整分析/结构论证/重复审查/内部推理/质检清单及全部规则正文不得直接注入生图提示词。最终提示词只允许获取：当前屏经确认的内容任务、核心信息、必要信息层级、消费者理解目标（仅在有助画面表达时）、允许表达内容、禁止表达内容、与整套视觉连贯性有关的必要信息。禁止把整套规划/其他屏全部内容/内部叙事分析完整注入当前屏、禁止本 Skill 全文当提示词模板、禁止把"屏级叙事分析/结构审核/重复检测"内部过程变成图像可见文字或视觉元素。**四类内容分离**：planning_output（内部规划与下游协调）/ generation_instruction（仅当前屏实际需要且经授权的内容表达）/ audit_rules（内部审查）/ internal_analysis（内部分析）。

**协同边界（§十/§十一/§十二）**：与营销策划——营销负责需求/障碍/核心价值/主线/卖点优先级/表达方向，本 Skill 负责如何组织、哪些独立成屏/合并、每屏任务、先后关系、信息推进、取舍、重复检测；不得重新擅自定义卖点功效营销策略，信息不足时保守不编造填结构。与视觉导演——本 Skill 提供内容任务/核心信息/信息层级/理解目标/相邻关系/必须表达/自由空间/不应表达，不得提前限定固定背景/构图/产品摆放位置/视觉风格/图文结构/场景/视觉元素（除非用户明确指定或真实必要视觉约束）。与文案策划——本 Skill 定本屏表达什么/核心信息/文案解决什么理解任务/文案在信息层级位置/是否需要标题辅助说明，文案策划转化为具体表达；不得因叙事提前编造最终标题/卖点文案/营销口号；某屏无需文字也能完成内容任务时不强制加文字。

（兼容保留旧边界：只做叙事与屏序，不做视觉 DNA 六维构图→visual-art-direction、不写文案版式细则→ecommerce-copy-layout、不改模块词表 G-2 禁改；不改运行时。）

## 冲突处理
（正式 §十五失败处理 + 旧冲突规则合并）
商品事实不足/营销信息不足/用户选择与上下文冲突/屏数难承载/多屏无法消除重复/板块缺事实支持/上下文不完整时——**不得关闭本 Skill**，应：1 基于已确认信息规划；2 保留用户明确约束；3 优先信息价值最高内容；4 合并或删低价值内容；5 避免引入未确认内容；6 对无法合理规划部分内部标记；7 必要时最保守完成当前任务。除非确实需用户提供不可替代信息，否则不因规划问题阻塞生图。
- （旧）指定屏数与实际内容量不符：在屏数内合并/拆分信息角色，不减屏不硬凑重复（count 硬约束）。
- （旧）用户板块顺序 vs 叙事最优序：尊重用户顺序，叙事在其顺序内优化，不擅自重排。
- （旧）材质/参数不可确认但用户选了对应板块：保守表达或改选等效可确认模块，不虚构材质。

**最终执行原则（§十七）**：详情叙事不是把商品信息分成若干屏，而是根据商品真实价值与消费者理解需求，规划一套有内容逻辑、有信息推进、有明确屏级价值、没有无意义重复的详情内容——不套固定结构、不为凑屏数、不虚构商品信息、不强制每屏都有卖点/标题/场景/不同形式、不把内容规划提前变成视觉模板。每一屏都必须有存在的理由，每一屏都必须对整套详情产生实际价值。
