# Skill 01 · 商品理解与事实边界（product-understanding）

> **正式专业正文 V1.0**（SKILL 01，核心必需能力，执行模式 Mandatory，权威来源：正式 Skill 契约）。接入日期 2026-11-18，来源 ChatGPT 交付。
> 能力职责：建立商品是什么、能确认什么、不能确认什么的事实边界；下游＝营销策划、详情叙事、视觉导演、文案策划、专项能力、提示词编译器。
> 兼容保留：本文件身份/路径/接口/Schema/注册关系/marker（`JINGYIN_DETAIL_V2_SKILL_PRODUCT_UNDERSTANDING`）不变；阶段 A 旧规则中与正式定义不冲突者合并保留。
> 🔴 **图片为必选输入是工程约束**（前端拦截"请至少上传一张产品图"）；但**证据来源不唯一**——用户资料、标签、项目上下文均须纳入，正式定义覆盖旧的"图片唯一来源"专业表述。

## 职责
建立当前商品的准确认知，识别商品是什么、能够确认什么、不能确认什么，以及哪些信息可被后续创作使用。为下游所有专业能力提供可靠的商品事实边界。商品真实性高于营销创意。

**本 Skill 不负责**（正式定义 §一）：
- 为商品创造卖点；根据行业惯例补充功效；编造使用场景；判断消费者购买动机。
- 规划详情页分屏；设计画面；为丰富内容而补充未知商品信息。

商品信息不足时应保留未知状态，而不是将未知补成完整产品档案。
（兼容保留：阶段 A 旧职责"从商品图与可选资料提取事实并逐条分级，为下游提供唯一可信事实底座"并入本段。）

## 触发
**必须触发**（正式定义 §2.1）：新商品详情生成 / 整套详情重新规划 / 新增或更换商品图片 / 用户补充修改商品资料 / 用户要求修改涉及商品事实的内容 / 单屏修改涉及功效、使用对象、适用范围、成分、材质、使用方法或产品身份 / 后续能力发现事实冲突需重新核对。旧规则"每次策划必经，无板块/有板块均执行"与此一致，保留。

**不需要重复完整执行**（§2.2）：仅修改排版位置、字体大小、背景颜色、光影、画面比例、已确定构图或不涉及事实的局部视觉元素，且现有事实档案有效、素材未变时，可复用已有档案；不得为每次修改都重新输出完整分析。

**排除条件**（§2.3，不因以下因素额外推断商品信息）：用户要求画面更丰富 / 营销感更强 / 更多分屏 / 更有视觉冲击力；商品属于某常见行业；包装采用某颜色、形状或材质；模型对同类商品有常见知识。

## 输入
**来源分类与可信度**（正式定义 §三，五类）：
- A 用户明确提供：名称、资料、功效、成分、适用范围、使用方式、规格等；可作资料，但明显矛盾/夸张/不合理须标待核对，不机械视为已验证事实。
- B 商品图片可直接观察：包装形态、容器形状、颜色、标签可见文字、可观察视觉元素、商品数量、图片中明确展示的组合。
- C 图片文字识别：标签/说明/成分表/规格/品名；须考虑清晰、完整、遮挡、歧义、生成模糊或透视误读；不清晰文字不得强行识别为确定事实。
- D 已确认的项目上下文：用户此前确认的信息、修改记录、有效资料；须确认属于当前商品且仍有效，不混入其他商品。
- E 专业推断：可形成有限推断但保留推断性质，不得升级为已确认事实。

**必须识别的信息维度**（正式定义 §五，按资料实际情况，不要求每项有答案）：5.1 商品身份（禁按包装视觉或行业惯例猜具体身份）；5.2 包装信息（包装本身与功能信息分开，喷雾瓶不自动证明适用所有喷雾清洁场景）；5.3 使用对象（场景出现的对象不自动认定为适用对象）；5.4 作用目标（区分名称暗示/用户确认/标签描述/模型推测）；5.5 适用范围（含对象/材质/场景/条件/限制/前提，禁因行业相关就扩为适用对象）；5.6 使用方式（仅资料明确时记录步骤/用量/时间/稀释/擦拭冲洗/注意，禁按习惯补全）；5.7 成分与原理（仅明确资料，名称/品类/包装颜色/形态不能证明成分）；5.8 效果与证明（区分宣称与可验证证据，识别测试对象/条件/范围，未确认效果不得视觉制造为真结论）。

（兼容保留：现有 `product` 字段语义 `name`/`industryId`/`materials`/`colors`/`structureLocks`/`realSellingPoints`/`riskNotes`/`styleDirection`。）

## 判断方法
**事实等级**（正式定义 §四，证据强度管理）：
- **L1 明确确认**：用户明确提供或资料有清晰可靠依据且无明显冲突。允许详情使用、营销依据、在符合当前屏任务时进入画面提示词；仍不得超出原始信息含义。
- **L2 有限依据**：有合理线索但证据不足或部分可确认（如包装显示可能用于某清洁场景但适用范围未完整说明、标签模糊、场景中出现使用环境但不确定为正式适用范围）。允许内部参考、形成待确认问题、在不涉及功效/范围承诺时作创作方向；禁止写成确定卖点、编译为明确功效、扩大适用对象或范围。
- **L3 未确认**：缺有效依据，或仅由模型按行业惯例/常识/视觉联想推测。保持未知；不得作事实、确定卖点、进最终生图提示词作产品属性、被其他 Skill 加工成确定事实。

**运行时映射（兼容保留，不改枚举）**：L1→`visible`（图片直接可见或包装明确标示）、L2→`inferred`（有合理依据但不能完全确认，须显式标注）、L3→`mustNotClaim`（图片无法确认且涉及功效/认证/疗效/销量/品牌背书，禁止作确定事实）。验收不得仅依赖关键词过滤，须验证语义层面是否正确理解与使用（§十二）。

## 规则
**事实保护（正式定义 §六）**：
1. 禁止信息扩展（§6.1）：不得擅自扩大污渍类型、清洁对象、使用材质、适用范围、功效、成分、使用方法、适用场景、产品效果、安全性、使用限制；符合行业常识也不代表当前商品具备。
2. 禁止行业惯例代替商品事实（§6.2）：清洁剂不因是清洁剂就默认适用所有污渍、因衣物清洁就默认所有衣物材质、因名称含去油就默认所有厨房表面、因水垢清洁就自动加所有卫浴材质；服装不按款式猜面料成分/功能性/穿着性能；护肤品不按包装颜色品类推断成分/功效/常见护肤功效；其他行业同理。
3. 禁止场景元素变商品属性（§6.3）：参考图、生活场景、模特、道具、背景、环境材质不能自动转化为商品事实（画面有棉布≠适用棉布；有浴室≠适用所有卫浴材质；有人物≠适用于人体）。
4. 禁止跨商品污染（§6.4）：事实档案只用当前商品资料，不混用其他商品的成分/功效/适用对象/使用方式/标签/历史提示词。

（兼容保留旧规则：不得虚构材质、参数、认证、疗效、销量、品牌背书；中文标签与商品结构逐字核对不臆造；`mustNotClaim` 断言不得进入 `product` 确定事实或 `screens` 卖点；行业与使用场景分离——血渍清洗剂属日化清洁剂，"衣物"≠服装行业；不可确认项写入 `product.uncertainties` 供保守表达。）

## 输出字段
**逻辑输出至少包含**（正式定义 §九，适配现有数据结构，不新增 Schema/接口）：商品身份（确定身份及必要说明）；已确认事实（有依据信息附来源与可信等级）；有限依据（存在但不能确定，说明边界）；未确认信息（禁止作事实使用）；冲突信息（如有，列来源与处理状态）；商品保护约束（本次创作必须保持的视觉与事实信息）；下游授权信息（允许后续使用的范围）；不得使用信息（阻止下游把未知/不适用转为卖点、画面文字或生图指令）。

**向下游提供规则**（§八）：营销策划——只给已确认身份/用途/对象/价值/效果依据与可表达、禁止推断、关键未知，不给未确认内容作卖点素材；详情叙事——给可用信息范围，不要求覆盖所有维度；视觉导演——给视觉身份/包装形态/商品保护要求/可用真实信息/不许虚构改变的元素，不替其规划场景构图；文案策划——给可用事实/可表达利益/禁止夸大/谨慎信息，不替其生成标题文案；专项能力——给触发判断所需事实及证据状态，未知的成分/材质/结构/用法/效果不得成为有效触发依据。

（兼容保留：`product.{name, industryId, industryName, targetAudience, materials, colors, structureLocks, realSellingPoints, riskNotes, styleDirection, uncertainties[]}`；分级事实写入 `planning.facts[{claim, level}]`，level ∈ visible/inferred/mustNotClaim。）

## 边界
**提示词注入规则**（正式定义 §十）：本 Skill 不直接输出完整分析。仅当前屏任务需要时可传递：当前商品身份、必要包装保护要求、当前屏已授权事实、当前屏必要的使用对象/范围/方式、当前屏必须保持的商品元素。**禁止传递**：完整商品档案、内部推断过程、全部未知信息清单、与当前屏无关信息、其他商品资料、仅供内部审计的规则全文。未触发信息不进入提示词。

**失败处理**（§十一）：信息不足——不自动补全/不编造/不阻止整个创作，用已确认信息继续，可把不足转为创作边界，仅当缺失确实影响当前任务才请求补充；身份无法确定——不擅自选类别，可请求确认，用户要求先继续时在明确限制下用通用表达；资料冲突——重要冲突不静默处理，未解决冲突不进确定性文案与生图指令。

（兼容保留：本 Skill 只做理解与分级，不做行业规则选择→industry-routing、不做营销转化→consumer-marketing-strategy；不改运行时代码与 G-2 词表。）

## 冲突处理
正式定义 §七：1) 识别冲突字段；2) 保留不同来源及原始内容；3) 判断能否通过清晰标签、用户确认或有效资料解决；4) 未解决前不作为确定事实；5) 不自行选择更有营销价值的说法；6) 不融合成新的虚构事实。用户后续明确纠正/确认应更新事实档案及来源记录；涉及身份、核心功效、适用范围、成分、安全限制的重要冲突必要时请求确认；不影响当前创作的未知信息不频繁打断用户。

（兼容保留旧规则：图片与用户资料冲突——以图片可确认事实为准，资料作 `inferred`，冲突点写 `riskNotes`；资料齐全但图片仅白底——仍按可证性分级、资料标为外部提供而非图片可见；与旧链路冲突——旧 `product` 字段保留，本 Skill 只增补分级不改旧字节。）

## 测试案例
**质量验收标准（§十二，14 条）**：1 准确识别身份；2 正确区分包装信息与商品功能；3 正确区分用户资料/图片观察/有限推断/未知；4 不把包装视觉联想变事实；5 不把场景对象变适用范围；6 不扩展未确认功效/成分/材质/用法；7 不混用其他商品信息；8 重要冲突可识别；9 未知信息保持未知；10 下游能正确使用事实档案；11 内部分析不污染生图提示词；12 单屏修改复用有效事实避免重复分析；13 信息不足时仍能合理继续；14 用户补充/纠正时事实档案正确更新。验收不得仅依赖关键词过滤，须验证语义层面理解、使用与保护。

（兼容保留旧测试案例：案例 B 资料不足——单张白底清洗剂图不虚构材质/功效、不强制材质模块、`uncertainties` 非空；案例 A 行业路由——血渍清洗剂=日化清洁剂，不因"衣物"判服装；负向——包装无认证标识却输出"通过 XX 认证"须判 `mustNotClaim` 并拦截。）

**本 Skill 最终目标**：让后续所有能力充分发挥创意，但创意必须建立在真实商品信息之上；未知信息可以留白，不能由模型擅自填补。
