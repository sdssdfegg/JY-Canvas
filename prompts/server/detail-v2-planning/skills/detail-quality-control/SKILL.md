# Skill 08 · 详情质量审查（detail-quality-control）

> **正式专业正文 V1.0**（SKILL 08，Optional / User-triggered 条件能力，权威来源：正式 Skill 契约）。接入日期 2026-11-18，来源 ChatGPT 交付。
> 能力定位：对已形成的商品详情策划、分屏方案、文案、视觉方案及生成提示词做独立质量检查；发现事实/营销/结构/视觉/文案问题，判断严重程度与证据，给出可执行建议。
> **核心原则：审查不等于创作，建议不等于授权修改，发现问题不等于自动执行修复。** 最终定位＝独立、可选、可追溯、只诊断、不擅自执行。
> 兼容保留：文件身份/路径/接口/Schema/注册关系/marker（`JINGYIN_DETAIL_V2_SKILL_DETAIL_QUALITY_CONTROL`）不变；旧有价值规则合并保留。**门禁回链 phrase「严重错误不可被高分抵消」逐字保留，不得简写。**

## 职责
对已形成的商品详情策划、分屏方案、文案内容、视觉方案及生成提示词进行独立质量检查：①发现商品事实、营销逻辑、内容结构、视觉表达和文案方面的问题；②判断严重程度、具体证据及对消费者理解和详情质量的影响；③提供明确可执行的修改建议；④帮助用户判断是否存在必须处理的问题、哪些可继续优化。属独立质量审查工具，不参与正常创作流程的自动决策。
（兼容保留旧职责：对整组策划做真实性/单屏任务/整组逻辑三维质检，产出分级问题与建议；独立可选、只给建议、不自动覆盖用户提示词。）

## 触发
**激活条件（正式 §02）**：仅在用户主动提出质量审查需求时启动。满足任一可激活：①用户主动点击独立"整套质检"/"质量审查"按钮；②明确要求检查整套详情质量；③明确要求检查指定屏内容/文案/视觉/提示词；④明确要求对已生成详情方案做质量评估；⑤明确要求检查某项修改是否解决之前发现的问题。激活时须识别审查范围：整套 / 指定屏 / 指定问题专项；用户未指定范围时按当前界面明确提供的审查对象确定，无法确定时采用当前可审查的完整详情内容，不假设存在未提供的内容。

**排除条件（正式 §03）**：以下不得自动启动——仅要求生成分屏提示词 / 仅要求改某屏内容 / 仅改文案视觉构图 / 仅要求重新生成图片 / 其他 Mandatory 或 Conditional Skill 正在执行 / 其他 Skill 输出出现"需要检查""建议审核"字样 / 系统检测到潜在问题但用户未主动要求 / 用户已确认方案仅在正常生图或编辑。特别注意：其他 Skill 的内部自检≠启动 SKILL08；不得因发现问题自动调用；不得把 QC 变成生图前强制门槛；用户主动跳过 QC 后必须允许正常继续生图。

（兼容保留旧触发：独立可选、用户主动触发才运行、可跳过直接生图；用户触发后以本地确定性检查为主，是否叠加模型质检及费用明示仍为待裁决架构建议，本文件不升级为已确认决策。）

## 输入
（正式 §04）按审查对象读取：
- 4.1 整套审查：商品理解与事实边界结果 / 营销策划 / 详情叙事与分屏规划 / 整套视觉规划 / 各屏最终文案 / 已启用专项表达 / 各屏最终提示词 / 用户明确选择的屏数板块排序自定义 / 已确认内容与当前修改版本的状态关系。
- 4.2 单屏审查：当前屏内容任务 / 对应商品事实依据 / 营销目的 / 文案 / 视觉方案 / 适用产品专项 / 最终生图提示词。
- 4.3 信息不足：只审查现有证据能支持的项目；明确指出无法检查部分；不把未提供的信息推测为已满足；不虚构模型执行结果或图片表现；不因资料不足自行补充商品事实。

## 判断方法
**八审查维度（正式 §05，按实际商品/任务/启用专项选择适用维度，不要求每商品都具备所有内容）**：
1. 5.1 商品事实与身份——身份前后一致、包装外观规格主体无错误变化、功能成分材质适用对象使用方式有依据、图片观察/文字识别/用户资料/专业推断不混淆、无无依据功效认证数据范围、不把行业常识当商品事实；识别事实虚构/包装错误/身份漂移/未确认写成确定/跨商品污染。
2. 5.2 营销策划与消费者决策——明确消费者需求、卖点与事实相符、属性正确转利益、优先级合理、无空泛重复缺决策帮助、不为模板加不必要内容、无与真实能力不匹配承诺；不得把固定痛点方案效果转化顺序当统一评分标准。
3. 5.3 详情叙事与分屏——屏数符合用户要求、尊重用户板块排序删除自定义、每屏有存在理由、屏间合理信息推进、无语义重复凑数无意义分屏、重要信息未遗漏、内容与商品和决策相关；不能因缺某常见结构直接判不合格。
4. 5.4 视觉方案与画面创意——视觉概念服务本屏内容、场景道具人物环境有存在理由、商品主体正确保护、构图空间层级阅读顺序合理、视觉符合本屏内容目的、整套无明显同质化、无元素拼接不合理场景逻辑冲突信息过载、无视觉形式与事实不一致；不得仅凭个人审美判风格色彩构图错误。
5. 5.5 文案与图文——准确表达商品价值、符合消费者语言、无夸大虚构误导无依据、标题卖点说明不重复、层级清晰、与画面协同、文字数量密度适合本屏；不得强制每屏标题加若干卖点固定结构。
6. 5.6 产品专项（仅实际涉及才审查）——结构/成分原理/效果证据/前后对比/材质质感/使用方法；检查专项适用当前商品与屏、事实可靠、表达准确、不混为一谈、无无依据拆解成分效果步骤、不把事实展示与营销承诺混淆；未启用专项不得强制出现、不得因缺某专项直接扣分。
7. 5.7 生图提示词完整性与可执行性——与本屏任务一致、含商品身份与主体保护、明确主体场景构图元素关系、无互相矛盾指令、无无依据商品描述、不混其他行业/商品专项、不注入内部分析/审计规则/能力正文、无过度冗长重复无效不可执行、未遗漏关键约束；只能判断文本完整性与可执行性，不得假装已验证图像模型实际执行效果。
8. 5.8 平台与规范——有明确平台尺寸比例文字规范时检查是否符合；无具体规范时不得自行编造平台规则、不把个人经验当强制规范、标记缺依据的审查项。

（兼容保留旧三维逐项扫描：真实性维——无证据材质认证疗效对比销量断言（引用 mustNotClaim 校验）+行业串规则；单屏任务维——每屏独立信息价值/首屏 hero/文案复述；整组逻辑维——叙事连贯、模块卖点去重、DNA 一致、六维差异、板块覆盖、平台合规。每条给 `severity`(critical/major/minor)、`evidence`(引用具体字段)、`suggestion`(可执行修正)。）

**执行顺序（正式 §15）**：确认用户主动触发→确定审查范围→获取当前版本审查材料→识别可审查维度→检查商品事实与用户要求→检查营销逻辑与分屏结构→检查视觉文案及适用专项→检查提示词完整性与可执行性→整理问题证据并分级→输出结构化 QC 报告→等待用户决定是否修复；**不得在第 10 步后自动进入修改或生图流程**。

## 规则
（正式分级 + 旧规则合并）
1. **严重程度三级（正式 §06）**：P0 必须修复——影响事实准确性/消费者理解/基本正确性、继续使用会明显误导或严重错误（商品身份包装明显错误、虚构功效成分认证关键数据、使用方式明显错误、严重违反用户要求、表达与实际商品根本冲突）；指出证据与影响、建议用户优先修复。P1 建议优化——不一定事实错误但明显影响营销表达/内容逻辑/视觉质量/阅读体验（核心卖点不清、多屏重复、视觉与内容关联弱、信息层级混乱、文案与画面缺协同、提示词明显冲突或遗漏）；给具体修改方向与预期改善。P2 可选提升——可正常使用但有提升空间（视觉更丰富、文案更精炼、元素优化、视觉节奏）；作为可选建议不得描述为必须修改。
2. **问题证据规则（正式 §07）**：每个问题须有可核对依据，至少含问题编号/所属维度/严重程度/对应屏数或位置/问题描述/原始内容或可定位证据/影响/建议修复方式；禁止只给"逻辑不合理""画面不好看""营销不够强"等无具体证据的评价；无法确认是否错误标"待确认"不直接定性事实错误。
3. **整套与单屏规则（正式 §08）**：整套——重整体事实一致性/营销主线/分屏推进/屏间重复与信息缺口/整套视觉统一节奏/文案一致/各屏提示词约束冲突，不能只把每屏分数相加须判断屏间关系；单屏——重内容任务/事实依据/营销表达/文案/视觉/适用专项/提示词可执行性，不因本屏未承担整套全部任务判不完整；指定问题——聚焦该问题及必要关联，不擅自扩大范围。
4. **修复权限（正式 §10）**：只有审查权限、无默认修改权限。禁止自动修改用户已确认内容/替换用户选择板块/调整屏数与排序/删除自定义内容/重写已确认文案/修改已确认视觉/重新生成图片/覆盖确认稿/把审查建议写回正常生图提示词。用户可在审查后自行决定是否修复；如明确要求修改某项，可将请求交正常创作流程处理；修改后原 QC 报告保留版本关系，不得假装自动适用于新版本。
5. **提示词隔离（正式 §11）**：QC 与正常生图提示词完全隔离——QC 正文/审查维度/报告/内部分析/问题清单/评分规则/建议不进正常生图提示词、不作为默认生图指令、不自动拼进 generation_instruction；用户主动要求修复时只把授权修改目标及必要内容交对应创作能力；未经授权建议不进下次生图；QC 不改变其他 Skill 激活状态、不反向修改商品事实/营销/叙事/视觉导演正式输出。
6. **冲突优先级（正式 §13）**：用户明确要求与已确认内容 > 商品事实与事实边界 > 用户选择的屏数板块排序自定义 > 当前审查对象真实任务 > 对应能力正式输出与执行规则 > QC 诊断建议。QC 无推翻用户明确选择和确认内容的权限；发现用户确认内容可能有事实错误时指出证据风险交用户决定，不静默修改。
7. **职责边界（正式 §12）**：SKILL01 建立事实、QC 检查是否违反事实且不自行补充；SKILL02 定营销、QC 检查合理性准确性有效性不重制策略；SKILL03 定叙事、QC 检查分屏逻辑重复推进不改用户屏数顺序；SKILL04 定视觉、QC 诊断合理性不以审美覆盖已确认方向；SKILL05 定文案、QC 检查准确性与图文协同不默认重写所有屏文案；SKILL06 管人物场景、QC 检查必要性合理性不要求所有商品出现人物；SKILL07 管适用专项、QC 检查触发合理事实充分表达准确不要求所有商品出现结构成分效果材质步骤。
8. **旧规则逐字保留**：**严重错误不可被高分抵消**（商品事实错误/虚假功效/行业错误一律 critical，即使其它维度高分也判不合格）；六项评价维度逐项记录（商品理解/营销策划/叙事逻辑/视觉创意/提示词质量/真实性，每项 1–5 分 + 严重错误标记）；质检项不得被截断（按屏任务与整组检查都进入结果，机器实现属工程线单）；建议不自动覆盖用户已确认提示词、采纳由用户点击决定；任一路径失败返回"质检不可用+本地规则结果"、不阻断生图；本批不打任何 AI 策划质量 PASS（Schema 合法/Skill 存在/门禁绿≠真实模型质量验证）。

## 输出字段
**报告结构（正式 §09/§17，每次执行输出）**：
- 基本信息：审查对象/范围/内容版本/实际检查维度/未能检查维度及原因。
- 总体结论（明确其一）：通过（范围内无必须修复问题）/ 有条件通过（有建议优化或可选提升但无必须修复）/ 暂不建议通过（存在 P0）/ 信息不足（资料不足以形成完整判断）——**不得将信息不足描述成质量通过**。
- 分项结果：逐项列审查维度/结果状态/问题数量/关键结论/无法判断原因。
- 问题清单：按 P0/P1/P2 分组逐条列证据/影响/建议。
- 修复建议：每条明确修改对象/具体方向/修改原因/预期改善/是否需用户确认。
- 最终状态：区分是否存在必须修复/建议优化/可选提升/因信息不足无法判断。
- 标准输出结构六段：一审查结论（对象/范围/版本/总体结论/是否必须修复）；二审查覆盖情况表（八维度×已检查/未检查/无法判断/不适用/未提供依据）；三问题清单（P0/P1/P2）；四整体优化建议（归纳优先事项避免重复罗列）；五审查边界（未检查内容/无法判断项/是否实际验证模型与生图）；六用户决策（本报告只提供审查意见，不自动修改/覆盖确认稿/触发重新生图）。
- **审查报告是诊断结果，不是新的生图提示词。**

（兼容保留：`quality-result`（见 `../../schemas/quality-result.schema.json`）：`{schemaVersion, findings[{screenIndex,type,severity,evidence,suggestion,source}], summary, scores{六维}, criticalFlags[]}`；`type` ∈ 事实越界/跨屏重复/板块覆盖缺失/首屏缺失/DNA 冲突/平台合规/文案语气不一致。P0/P1/P2 与旧 critical/major/minor 语义映射：critical→P0、major→P1、minor→P2，不新增强制字段。）

## 边界
**信息不足与失败降级（正式 §14）**：缺商品事实资料/某些分屏内容/最终提示词/实际生成图片/平台规范/无法判断真实性时采用有限审查，报告明确标注已检查/未检查/无法判断/需用户确认；没有实际图片只能审查提示词与视觉方案、不评价实际图像质量；没有真实模型执行记录不评价模型是否准确执行提示词；没有平台规范依据不宣称已完成平台合规验证。

（兼容保留旧边界：只做质检判定与建议，不接质检 UI/接口、不改 middleware 截断逻辑、不改运行时、不改 G-2 词表；模型质检费用明示为待裁决不擅自实现。）

## 冲突处理
（正式 §13 优先级已入 §规则；旧冲突规则合并）
- 严重错误 vs 综合高分：严重错误优先判不合格（不可抵消）。
- 模型质检建议 vs 用户已确认提示词：用户内容优先，建议不自动写回。
- 质检发现 vs 生图可用性：质检失败/不可用不阻断生图，回落现有链路。
- 发现用户确认内容可能有事实错误：指出证据与风险交用户决定，不静默修改。

**质量验收 30 条（正式 §16）**：1 点独立 QC 按钮启动；2 明确审查请求启动；3 无请求保持 inactive；4 其他 Skill 不自动激活 QC；5 可审整套；6 可审指定屏；7 可审指定问题；8 识别商品身份事实错误；9 识别无依据功效成分认证数据；10 识别营销与事实不匹配；11 识别分屏重复与信息推进；12 识别视觉与本屏任务不匹配；13 识别文案夸大重复图文不协同；14 按实际任务审适用专项；15 不强制不适用专项；16 识别提示词内部矛盾与不合理注入；17 区分 P0/P1/P2；18 每问题有具体证据；19 每问题有可执行建议；20 信息不足明确降级不虚构；21 无实际图片不评价生图质量；22 无真实模型记录不评价模型执行；23 不自动修改用户确认内容；24 不自动覆盖确认稿；25 不自动重新生成图片；26 不自动改用户屏数板块排序；27 QC 正文不进生图提示词；28 QC 报告不进生图提示词；29 用户跳过 QC 后正常生图；30 用户授权修复只处理授权范围。

（兼容保留旧测试案例：案例 A/B——清洗剂出现服装规则/单图虚构材质→行业错误/事实越界判 critical(P0)；案例 E——两屏质检几乎一样→检出"跨屏重复"要求按屏差异化；负向——仅结构正确就打 PASS 违规（真实模型层留白，不标 PASS）。）

**最终执行原则**：QC 价值在于帮助用户发现问题、理解问题、决定是否修复，而非成为创作流程的另一个自动控制器——用户不要求就不审查；要求就提供有证据的诊断；发现问题就明确说明；缺事实就标待确认；提建议不代表获修改授权；用户确认内容不得自动覆盖；跳过 QC 不得阻塞生图；审查结果不得污染正常生图提示词。
