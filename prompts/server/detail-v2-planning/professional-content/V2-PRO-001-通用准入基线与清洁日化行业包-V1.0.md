## 一、这批内容要解决什么问题

本次交付不是简单增加一套清洁剂模板，而是建立一条明确的专业判断链：

1. 先判断用户提供的究竟是什么产品。
2. 再判断它属于哪个行业，不能被使用场景带偏。
3. 再判断消费者需要了解什么，以及哪些内容值得成为独立详情屏。
4. 最后决定用什么视觉方式表达已批准的内容任务。
5. 编译器只能执行已批准的任务，不得擅自增加行业结构、产品事实或视觉任务。

必须特别避免以下错误：

- 清洁剂因为出现"衣物"二字，就被归类成服装行业。
- 清洁剂详情被机械套入服装版型、面料、走线、领口等结构。
- 任何产品都被安排一屏"产品细节图"。
- 产品包装上的材质、颜色，被误认为使用对象的材质。
- 仅凭产品名称或图片，就扩大产品适用范围和功效。
- 为了凑屏数，安排与消费者购买决策无关的内容。
- 把策划分析原文直接塞进最终生图提示词。

## 二、第一层：通用产品理解与事实控制规则

### 2.1 必须区分的六类信息

所有行业统一使用以下产品理解维度，不允许混为一谈。

| 信息维度 | 定义 | 示例 |
|---|---|---|
| 产品身份 | 产品本身是什么 | 衣物血渍清洗剂 |
| 包装信息 | 瓶身、瓶盖、喷头、包装材质等 | 白色塑料瓶、喷雾头 |
| 使用对象 | 产品作用于什么对象 | 衣物 |
| 作用目标 | 产品要处理什么问题 | 血渍 |
| 适用范围 | 已确认可以使用的对象、污渍或场景 | 标签明确标注的适用范围 |
| 使用方式 | 产品如何使用 | 喷洒、浸泡、擦拭等 |

特别注意：

- 包装材质不等于使用对象材质。
- 使用对象不等于产品所属行业。
- 作用目标不等于完整适用范围。
- 场景中出现的物品，不自动成为产品适用对象。
- 图片可观察到的事实，不自动等于产品功效。

### 2.2 事实证据分级

事实证据分级与任务准入状态独立，不得混用。

**L1｜已确认**

来源包括用户明确提供的商品资料、产品标签中可清楚读取的信息、用户确认的信息，以及可靠验证资料。

允许用于产品定位、卖点和最终提示词，但仍不得超出原始信息含义。

**L2｜有限依据**

来源包括产品图片中可以直接观察到的信息，以及上下文能够有限支持的信息。

可以描述可观察事实，但不能把观察结果扩展成产品功效。

例如：

- 可以说"白色喷雾瓶"，不能据此说"采用食品级安全材质"。
- 可以说"瓶身带有喷头"，不能据此认定产品一定适用于所有表面。
- 可以描述图片中出现的污渍，不能据此认定产品能够清除该污渍。

**L3｜未确认**

包括无法读取的标签信息、用户没有提供的功效、未经证实的适用范围、成分、安全性、测试结果和性能数据。

不得作为确定事实进入最终提示词。

### 2.3 事实使用规则

1. L1 可以作为已确认产品信息使用。
2. L2 只能在其证据范围内使用，不能扩大解释。
3. L3 不得转化为确定性文案或视觉证明。
4. 图片生成模型不能被要求生成现实中尚未证实的功效证明。
5. 用户明确提供的信息优先于模型猜测；但若信息相互矛盾，应标记冲突，不得自行选择更夸张的说法。
6. 不能因为详情屏需要一个卖点，就创造一个卖点。

## 三、第二层：清洁日化行业识别与能力包

### 3.1 行业识别原则

清洁日化行业包的识别依据是产品本身的主要用途和作用对象，而不是画面场景词。

判断优先级：

1. 明确的产品名称、标签和用户商品资料。
2. 明确的主要功能与作用目标。
3. 明确的使用对象。
4. 使用场景和环境词仅作为辅助信息。

例如：

| 产品信息 | 正确行业 | 不允许的误判 |
|---|---|---|
| 衣物血渍清洗剂 | 清洁日化 | 服装 |
| 衣物果渍清洗剂 | 清洁日化 | 服装 |
| 厨房重油污清洁剂 | 清洁日化 | 厨具 |
| 浴室水垢清洁剂 | 清洁日化 | 卫浴产品 |
| T 恤 | 服装 | 清洁日化 |

**行业唯一性规则：**

- 每个产品只能有一个生效主行业。
- 展示行业与规则行业必须使用同一个生效行业标识。
- 使用对象、使用场景不能覆盖产品本身的行业判断。
- 无法可靠识别时使用 `generic`，不能同时加载多个行业包。
- 行业包只提供该行业的专业知识和任务规则，不直接决定所有详情屏的排列顺序。

### 3.2 清洁日化包的适用范围

第一版覆盖以下产品类型：

- 衣物清洁与去渍产品
- 厨房清洁产品
- 浴室及卫生间清洁产品
- 玻璃及多表面清洁产品
- 地面及家居清洁产品
- 其他明确属于清洁用途的日化产品

以下产品即使名称或场景中包含清洁相关词汇，也必须先判断产品本身，不得直接套用本包：

- 以个人护理为主要用途的产品
- 以化妆、护肤为主要用途的产品
- 以食品、饮料为主要用途的产品
- 无法确定主要用途的混合型产品

### 3.3 清洁日化产品的专业理解重点

清洁日化产品的详情规划，优先理解以下信息：

1. **清洁对象：** 衣物、厨房表面、卫浴表面、玻璃、地面等。
2. **处理问题：** 油污、水垢、锈渍、果渍、血渍等。
3. **使用方式：** 喷洒、滴涂、浸泡、擦拭、冲洗等。
4. **作用原理：** 只有成分、配方或可靠资料支持时才允许表达。
5. **效果表现：** 必须有事实依据，不能由画面创意反向推导产品功效。
6. **使用条件：** 适用材质、使用时间、是否需要稀释、是否需要冲洗等，均不能凭空补充。

### 3.4 清洁日化的禁止泛化规则

以下情况必须拦截：

- 衣物血渍清洗剂自动扩展为奶渍、蛋白质污渍清洗剂。
- 衣物清洁剂自动扩展为所有织物、所有衣物材质均适用。
- 厨房清洁剂自动扩展为所有厨房设备和所有材质均适用。
- 浴室清洁剂自动扩展为所有卫浴材质均适用。
- 仅凭"去油""清洁"等名称推导出杀菌、除菌、消毒等功效。
- 仅凭产品颜色、包装形态推导成分、配方或安全性。

如果用户资料只确认一种污渍，就只允许围绕该污渍策划。不得为了增加详情丰富度而扩展其他污渍。

## 四、第三层：内容任务与视觉任务准入规则

这是本次最重要的专业控制。

**内容任务决定这一屏为什么存在；视觉任务决定这一屏如何表达。两者必须分别判断，不能互相替代。**

### 4.1 任务准入四态

| 状态 | 含义 | 处理方式 |
|---|---|---|
| `admitted` | 有足够依据，任务合理 | 可以进入分屏规划 |
| `rejected` | 与产品无关、错误或存在事实风险 | 禁止进入规划和编译 |
| `pending` | 可能合理，但缺少必要信息 | 暂不作为确定任务 |
| `generic_fallback` | 专业信息不足，采用安全通用任务 | 允许有限规划，不得补造事实 |

任务准入不能只判断"能不能生成这张图"，还必须判断"这张图是否值得出现在这款产品的详情里"。

### 4.2 内容任务注册基线

以下是第一批通用内容任务。它们不是固定详情模板，也不是要求每款产品全部使用。

| 内容任务 ID | 内容任务 | 适用条件 |
|---|---|---|
| `product_identity` | 产品身份与定位 | 所有可识别产品优先考虑 |
| `core_value` | 核心价值与主要购买理由 | 有明确产品价值依据 |
| `problem_context` | 消费者问题与使用场景 | 产品与问题之间存在明确关联 |
| `usage_method` | 产品使用方式 | 使用方式已知或可从资料确认 |
| `application_scope` | 适用对象与范围 | 有明确适用范围依据 |
| `product_structure` | 产品自身结构与设计 | 存在值得展示的真实结构特征 |
| `effect_evidence` | 效果表现与证明 | 有可靠证据支持 |
| `ingredient_mechanism` | 成分或作用原理 | 成分和原理有可靠资料支持 |
| `usage_attention` | 使用注意事项 | 存在必要且已确认的注意信息 |
| `purchase_reassurance` | 购买顾虑与决策辅助 | 有真实、相关的消费者顾虑可解决 |

**注意：** 注册表中的任务是候选能力，不代表每个产品都要生成对应屏幕。

例如：

- 产品结构普通、没有特殊结构卖点，可以不安排 `product_structure`。
- 没有成分资料，不安排 `ingredient_mechanism`。
- 没有测试资料，不安排 `effect_evidence`。
- 使用方式没有得到确认，不得自行编造 `usage_method`。
- 产品没有特殊注意事项，不需要为了凑屏安排一屏注意事项。

### 4.3 清洁日化内容任务的行业规则

清洁日化包可在通用任务基础上增加以下专业判断：

**A. 清洁问题识别**

回答消费者遇到的具体清洁问题是什么。

准入条件：
- 问题与产品作用目标一致。
- 不扩大产品适用范围。
- 画面表现不能暗示产品能解决未确认的问题。

**B. 清洁使用过程**

回答消费者如何使用产品。

准入条件：
- 使用方法有明确依据。
- 不擅自添加使用时长、用量、稀释比例、冲洗步骤。
- 画面动作符合真实使用逻辑。

**C. 清洁前后效果**

回答产品使用后有什么变化。

准入条件：
- 有可靠的产品效果依据。
- 前后对比的对象、材质、光线和拍摄条件应保持合理一致。
- 不允许把纯视觉修饰伪装成真实功效证明。
- 没有可靠效果依据时，状态为 `pending` 或 `rejected`，不能自动准入。

**D. 适用对象与范围**

回答产品可以用于什么对象、什么范围。

准入条件：
- 必须有明确的标签、用户资料或可靠验证支持。
- 不能因为画面出现某种材质，就推断产品适用于该材质。
- 不得把一个具体对象扩展为所有相似对象。

**E. 产品形态与使用结构**

回答产品本身有什么值得消费者了解的结构。

准入条件：
- 产品确实存在可展示的结构特征。
- 该特征与使用体验或购买决策有关。
- 普通瓶身、普通瓶盖不应自动成为独立详情屏。

### 4.4 视觉任务注册基线

视觉任务与内容任务分开注册。第一版只建立以下有限能力：

| 视觉任务 ID | 视觉表达方式 | 使用边界 |
|---|---|---|
| `product_hero` | 产品主体与环境构图 | 表达产品身份、定位和核心价值 |
| `problem_scene` | 问题场景呈现 | 场景必须与真实作用目标一致 |
| `usage_demonstration` | 使用过程展示 | 动作、对象、工具和步骤必须合理 |
| `before_after_comparison` | 前后对比 | 需要可靠效果依据 |
| `product_structure_closeup` | 产品结构局部展示 | 必须存在真实且有价值的结构细节 |
| `application_scene` | 适用对象或环境展示 | 必须有适用范围依据 |
| `ingredient_visualization` | 成分或原理可视化 | 必须有成分或原理依据 |
| `information_layout` | 信息图文排版 | 适合承载已确认的说明信息 |

**重要限制：**

- 视觉任务不是内容任务的替代品。
- 不能先选一个视觉效果，再倒推产品应该讲什么内容。
- 不能因为有"产品细节图"能力，就给所有产品安排产品细节图。
- 不允许把服装行业的版型、面料、走线、领口等视觉任务加载到清洁日化产品。
- 没有准入的内容任务，不得通过换一种视觉表达方式绕过拦截。

## 五、第四层：分屏规划与最终提示词编译规则

### 5.1 分屏规划规则

每一屏必须有明确的任务身份。

规划时至少回答：

1. 这一屏要解决消费者的什么问题？
2. 为什么这款产品需要这一屏？
3. 该屏使用了哪些已确认产品事实？
4. 该屏为什么采用当前视觉表达方式？
5. 是否与其他屏幕重复？
6. 是否符合用户选择的屏数和内容偏好？

屏幕之间要有明确的信息推进关系，而不是简单罗列产品功能。

首屏必须围绕：

**产品身份 + 有依据的核心价值。**

首屏可以采用产品主体、使用场景、问题场景、效果表达或其他合理方式，不固定某一种模板。不得为了吸引眼球编造功效。

### 5.2 通用 fallback 规划

没有匹配行业包时，不代表 AI 失去规划能力。

通用 fallback 可以优先考虑：

- 产品是什么。
- 产品的外观和可观察特征。
- 用户提供的核心价值。
- 有依据的使用对象或场景。
- 已确认的使用方式。
- 有证据支持的购买决策信息。

但必须遵守：

- 不加载其他行业包凑数。
- 不使用与产品无关的专业任务。
- 不编造行业术语、材质、结构、成分或功效。
- 不因为缺少专业知识就堆砌"产品细节""品质展示""科技原理"等空泛内容。

### 5.3 编译器授权边界

最终提示词编译器只能执行规划阶段已经批准的任务。

编译器不得：

- 新增内容任务。
- 新增视觉任务。
- 将 `rejected` 或 `pending` 任务写进最终提示词。
- 把 L2 观察信息升级为 L1 产品事实。
- 把 L3 未确认信息转化为卖点。
- 将其他行业的结构、专业术语和表现方式带入当前产品。
- 为了画面丰富而擅自添加产品功效或适用范围。
- 将内部策划分析和消费者洞察原文直接输出给生图模型。

编译器应把已批准的策划结果转成简洁、具体、可执行的画面指令。

### 5.4 最终提示词质量标准

合格的最终提示词应做到：

- 产品主体明确。
- 画面构图明确。
- 视觉表达与内容任务一致。
- 场景和道具符合真实逻辑。
- 文案围绕消费者理解和购买决策。
- 产品事实没有被扩大。
- 不同屏幕之间有合理的信息分工。
- 不出现与行业无关的结构描述。
- 不出现策划分析、内部判断和无效形容词堆砌。
